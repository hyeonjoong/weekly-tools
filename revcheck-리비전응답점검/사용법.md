## 1. 설치 (한 번만)


이제 어디서든 `revcheck` 명령을 쓸 수 있습니다. (설치하기 싫으면 이 폴더에서

## 2. 내 리비전에 돌리기

준비물은 세 개입니다. **최초 제출본**, **개정본**, **응답서(point-by-point response)**.
`.docx` / `.md` / `.tex` / `.txt` 를 섞어 써도 됩니다.

```bash
revcheck --old 제출본.docx --new 개정본.docx --response 응답서.docx --out-dir 결과
```

### 예 1) 워드 파일 세 개 (가장 흔한 경우)

```bash
cd ~/Desktop/SERENE_revision
revcheck --old SERENE_submitted.docx --new SERENE_R1.docx \
         --response Response_to_Reviewers.docx --out-dir 점검결과
```

개정본에 변경내용 추적이 켜져 있으면 리포트 첫머리에 이렇게 나옵니다.

```
      ※ 개정본에 변경내용 추적 흔적이 있습니다(삽입 7 / 삭제 0) — 모두 수락된 상태로 읽었습니다.
```

원본(변경 거절) 기준으로 보고 싶으면 `--tracked reject` 를 붙이세요.

### 예 2) 응답서 형식이 특이해서 "판정불가"가 나올 때

```
[판정불가]
  응답서에서 리뷰어 코멘트 번호를 1건밖에 찾지 못했습니다(최소 3건 필요).
  번호 체계를 추측하지 않고 멈춥니다 — `--comments 1-1,1-2,...` 로 번호를 직접 알려 주면
  그 목록으로 점검합니다.
```

이럴 때는 번호를 직접 적어 주세요. 리뷰어 1의 3개, 리뷰어 2의 2개, 에디터 1개라면:

```bash
revcheck --old old.docx --new new.docx --response resp.docx \
         --comments 1-1,1-2,1-3,2-1,2-2,E-1
```

### 예 3) 마크다운/LaTeX 원고 (줄 번호까지 검증됩니다)

```bash
revcheck --old manuscript_v1.tex --new manuscript_v2.tex --response response.md --out-dir 결과
```

`.md`/`.tex`/`.txt` 는 줄 번호가 파일에 실제로 있으므로, 응답서에 적은
`lines 132-140` 이 **정말 그 줄이 바뀐 곳인지**까지 확인합니다.
(`.docx` 는 줄 번호가 파일에 없어서 "확인불가"로 정직하게 보고합니다.)

## 3. 결과 읽는 법

리포트는 위에서부터 **치명 → 경고 → 정보 → 커버리지 자백** 순서입니다.

- **치명** — 지금 고치지 않으면 리뷰어가 "저자가 거짓말했다"고 볼 수 있는 것.
  - 답하지 않은 코멘트 번호 (2-4 다음이 2-6)
  - 응답서가 인용한 문구가 개정본에 없음 — **특히 숫자가 다르면** 무조건 치명
  - 응답서에 언급 없이 **있던 값이 다른 값으로 바뀐** 문단
  - 제출본과 개정본의 본문이 똑같은데 "고쳤다"는 주장이 있음(파일 오첨부)
- **경고** — 눈으로 한 번 확인해야 하는 것. 표현만 다른 인용, 검증 수단이 없는 변경 주장,
  참고문헌 수량 불일치, 어긋난 위치 참조 등.
- **정보** — 알고만 있으면 되는 것. 분량 변화, 사소한 문장 다듬기.
- **커버리지 자백** — *가장 중요합니다.* `인용 문구 대조: 20건 → 확인 17건 / 건너뜀 3건
  (15자 미만 2건, 리뷰어 말 인용 1건)` 처럼 **무엇을 못 봤는지** 적습니다.
  이 블록이 없으면 리포트를 믿지 마세요.

종료코드는 0(정상) / 1(치명) / 2(경고) / 3(판정불가)입니다. **3은 '이상 없음'이 아니라
'확인하지 못했다'는 뜻입니다** — 파일을 못 읽었거나 코멘트 번호 체계를 못 잡았을 때 나옵니다.

## 4. 저장되는 파일

`--out-dir` 을 주면 네 개가 생깁니다.

| 파일 | 무엇 |
|---|---|
| `리비전점검.md` | 전체 리포트 |
| `문제목록.csv` | 지적 목록 (엑셀에서 열어 하나씩 지우며 작업) |
| `변경목록.csv` | 문단 단위 diff 전체 — "신고여부" 열로 정렬하면 미신고 변경만 볼 수 있습니다 |
| `추가문헌.csv` | 새로 넣은 참고문헌 — 그대로 `citecheck 추가문헌.csv` 에 넣어 DOI 를 확인하세요 |

## 5. 다음에 할 일

이 툴은 **응답서와 개정본의 관계**만 봅니다. 개정본 자체는 따로 점검하세요.

```bash
numcheck 개정본.docx --out-dir 검토      # 숫자 재계산
draftcheck 개정본.docx --out-dir 검토    # 인용↔참고문헌·그림표 번호·분량
citecheck 결과/추가문헌.csv              # 새로 넣은 문헌의 DOI (네트워크 필요)
```

## 6. 안심해도 되는 것

- **네트워크를 전혀 쓰지 않습니다.** 미공개 원고가 밖으로 나가지 않습니다.
- **원본 파일을 절대 고치지 않습니다.** 읽기 전용으로만 엽니다.
- 결과 폴더가 원고 파일을 덮어쓰게 되면 실행을 거부합니다.
