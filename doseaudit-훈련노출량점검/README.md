# doseaudit — 훈련 노출량 점검

피험자별 앱 훈련 로그 워크북 묶음(`.xlsx` 수십 개)을 통째로 펼쳐, **"이 피험자가
처방된 훈련을 실제로 얼마나 받았는가"** 를 **정의를 선언받아** 다시 세는 오프라인 CLI입니다.

> `logflow` 는 **제품이 얼마나 쓰였는지**를 보고, `doseaudit` 는 **이 피험자가 처방된
> 훈련을 실제로 얼마나 받았는지를 — 정의를 선언받아 — 다시 셉니다.**

순응/비순응을 판정하지 않고, 노출량과 결과의 관계도 보지 않습니다.
**분모가 무엇이었는지를 드러내고 끝납니다.**

---

## 목적 / Why this exists

**한국어.** 벤더가 피험자별 엑셀 한 묶음을 보내옵니다. 지금은 그 파일들을 하나씩 열어
`[요약]` 블록을 베끼거나 날짜를 눈으로 세어 `참여현황.xlsx` 의 `완료일수` 칸을 채웁니다.
30명 × 6모듈입니다. **이 손작업은 조용히 어긋납니다** — 실제 자료에서 30명 중 **23명**의
트래커 `완료일수` 가 로그와 달랐고, 차이는 **+1~+7일, 23명 전원 같은 방향**이었습니다
(`--active-day any-row --window enroll-to-cut --cut 2026-06-23` 기준입니다. 이 툴의 주제가
"정의를 적어라"인 만큼, 이 숫자도 **정의 없이는 숫자가 아닙니다** — 규칙·창을 바꾸면 19~26명 사이에서
움직이고, `min-seconds=60` 에서는 어긋나는 방향까지 뒤집힙니다).
한 방향으로만 어긋난다는 것은 오타가 아니라 **누군가 '완료'를 다른 기준으로 셌다**는 뜻이고,
**그 기준이 어디에도 적혀 있지 않다**는 뜻입니다. 더 나쁜 것은 벤더 `[요약]` 블록입니다.
산수는 맞습니다(150/150 재계산 일치). 그런데 `평균 0초`는 **0초 행 35.6%를 결측과 구분하지
않고 평균한 값**이고, 어떤 모듈은 `평균 0회 · 평균 0초`로 인쇄되는데 실제로는 **데이터가
한 행도 없습니다.** 그대로 베끼면 "수행량이 0이었다"가 되고, 진실은 "**측정되지 않았다**"입니다.
논문에서 이 둘은 전혀 다른 문장입니다. 그리고 노출량은 *dose–response* 문단의 결론을
떠받치는 변수입니다 — 노출 변수에 계통 오차가 있으면 상관은 0 쪽으로 희석되고,
`ρ = −0.02` 라는 귀무 결론이 **측정 잡음의 산물일 수 있습니다.**

**English.** A digital-therapeutic trial exports one spreadsheet per participant, and the
"adherence" paragraph of the CSR is then written from a hand-maintained tracker. That path is
not reproducible. In the real dataset this tool was built against, the tracker's
"days completed" disagreed with the logs for **23 of 30 participants** — always in the same
direction, which is the signature of an undeclared definition rather than a typo. (That count is
itself definition-dependent, which is the point: under `--active-day any-row --window enroll-to-cut
--cut 2026-06-23` it is 23; across the declarable rules and windows it ranges from 19 to 26, and
under `min-seconds=60` even the direction stops being uniform.) Meanwhile the
vendor's own summary block is *arithmetically correct* yet semantically misleading: it averages
zero-second rows (35.6% of all rows) together with real durations, and prints `mean 0 s` for a
module that in fact contains **no rows at all**. doseaudit refuses to guess. It **requires you
to declare** what an active day is and what the denominator window is, recounts exposure under
that declaration, reports every mean as three numbers (overall / excluding-zeros / zero-rate),
never collapses "no data" into "zero", diffs the result against your tracker with signed
differences, and shows how far the median moves when the definition changes. It writes the
declared definition straight into a drafted Methods paragraph, KR and EN.

**누구를 위한 것인가.** BELL-002(와우핏) 청각재활 앱의 임상 데이터를 다루는 연구자 —
확증임상을 앞두고 **같은 앱이 같은 형식의 로그를 더 큰 N으로 다시 뱉는** 자리에서
두 번, 세 번 열리도록 만들었습니다.

### `logflow` 와 정직하게 구분하기

`logflow` 에는 이미 `--adherence-days N`(주 N일 이상이면 준수) 과 `--adherence-weeks`
(관찰 창 고정) 가 있고, 활성일을 **"이벤트가 하나라도 있던 날"** 로 셉니다 — 이 툴의
`any-row` 와 같은 정의입니다. **겹치는 부분이 있습니다.** 숨기지 않고 적어 둡니다.

그래서 이 툴이 실제로 다른 지점은 네 가지뿐이고, 그게 전부입니다:

| | `logflow` | `doseaudit` |
|---|---|---|
| **입력** | 평평한 이벤트 로그 1장 (CSV·JSONL·`.gz`) | **피험자별 워크북 묶음**(6시트 × 수십 개 파일) |
| **정의** | `any-row` 상당이 코드에 고정 | **선언받는다. 미선언이면 판정 없이 exit 2** |
| **분모** | `--adherence-weeks` 로 고정 가능 | 선언한 창을 **분자에도 똑같이 적용**하고, 정의를 바꾸면 중앙값이 얼마나 움직이는지 표로 보여 준다 |
| **0의 의미** | 인지하고 자백함 — 단일 이벤트 세션을 0분으로 세고, 개요와 군 표가 그 0을 다르게 다룬다고 README 에 적어 둠 | 한 걸음 더 — 모든 평균이 `전체 · 0제외 · 0행비율` **세 값**이고, 데이터 0행 모듈은 `평균 0` 이 아니라 `데이터 없음` |
| **손으로 만든 표** | 다루지 않음 | 참여현황 트래커와 **부호 붙은 차이**로 대조 |

한 가지 더 솔직하게: 이 툴의 **뼈대**(선언 강제·커버리지 자백·KR/EN Methods 초안·
산출물 4종·표준 라이브러리 전용·`실행.command`)는 이 저장소의 `joinaudit`·`visitaudit`
와 공유하는 틀입니다. **틀은 재사용이고, 알맹이는 아닙니다.**

`joinaudit`·`visitaudit` 과는 겹치지 않습니다. `joinaudit` 은 이미 평평한 표들을 붙이고,
`visitaudit` 의 "창"은 **예정일 둘레의 허용 구간**이라 이 툴의 "사람-시간 분모"와 다른
물건입니다(이름만 같습니다).


## 이 툴이 하지 않는 것 (그리고 코드가 할 수 없게 막아 둔 것)

| 안 하는 것 | 강제장치 |
|---|---|
| **고치지 않습니다** — 중복 제거·결측 대체·트래커 수정본 생성 안 함 | 패키지에 삭제/이동 함수도 `shutil` import 도 없음을 AST 로 확인 |
| **순응/비순응을 판정하지 않습니다** — 임계값을 코드에 박지 않음 | `순응함`·`비순응`·`adherent`·`충분히 사용`·`탈락함` 이 **부정 표지 없이**(같은 줄 아무 데나가 아니라 바로 옆에) 등장하면 테스트 실패. CSV 에는 단 한 번도 없음 |
| **효과를 보지 않습니다** — 상관·회귀·군간검정 안 함 (→ `statwise`·`longistat`·`medpath`) | 검정/상관 함수의 정의·호출 부재를 AST 로 확인, `scipy`/`numpy`/`pandas` import 0 |
| **이름을 읽지 않습니다** — 트래커 `환자명`·`Login ID` 는 열지 않음 | 전 산출물에서 실명·Login ID 0건을 테스트로 고정 |
| **세션을 추론하지 않습니다** — 최소 단위는 **날짜** (→ `logflow`) | — |
| **탈락 시점을 추정하지 않습니다** — 마지막 활동일만 인쇄 | — |
| **훈련 내용의 정오답을 보지 않습니다** — 얼마나 받았는지만 셉니다 (→ `jamoscore`) | 리포트의 `[커버리지 자백]` 에 `검사 안 함` 으로 매번 인쇄 |
| **`D1`…`DN` 일자별 격자를 읽지 않습니다** — 기준점이 문서화돼 있지 않음 | 격자 열은 읽기 전에 버리고, 몇 열을 안 읽었는지 자백에 인쇄 |

애매하면 `[치명]` 이 아니라 `[경고]`, 경고가 애매하면 `대조불가` 입니다.

## 설치

```bash
cd ~/Downloads/02_프로젝트/깃헙/doseaudit-훈련노출량점검
python3 -m pip install -e .
```

외부 의존성 **0개**(표준 라이브러리만), 네트워크 호출 **0회**, **입력 읽기 전용**.
`.xlsx` 는 `zipfile` + `xml.etree` 로 직접 읽으므로 pandas·openpyxl 이 필요 없습니다. Python 3.9+.

### 2) 깨끗한 자료 — **조용해야 정상입니다**

## 선언할 수 있는 것들

| 인자 | 뜻 | 값 |
|---|---|---|
| `--active-day` **(필수)** | '이 날은 훈련한 날인가'의 정의 | `any-row` · `min-rows=N` · `min-modules=K` · `min-seconds=S` |
| `--window` **(필수)** | 분모의 창 | `enroll-to-cut --cut YYYY-MM-DD` · `enroll-to-last` · `fixed-weeks=N` (N×7 이 **정수 일수**여야 합니다 — 이 툴의 최소 단위가 날짜라, `1.5` 같은 값은 조용히 자르지 않고 거절합니다) |
| `--enroll` | 관찰 시작일의 출처 | `tracker`(기본, 트래커가 있을 때) · `first-activity` — **어느 쪽이든 리포트에 인쇄됩니다** |
| `--target-per-week` | 처방된 주당 훈련일수 | 주면 노출률(%)과 정의 민감도 표가 나옵니다. 안 주면 셈만 합니다 |
| `--cap` | 노출률 상한 절단 | **줄 때만** 절단하고, 절단된 인원수를 인쇄합니다 |
| `--criterion` | 프로토콜이 정한 기준(%) | **줄 때만** 충족/미달을 표시합니다 — 이 툴이 정한 값이 아닙니다 |
| `--pool-types` | `REGULAR`·`INDIVIDUAL` 합산 | 기본은 분리. 합산하면 리포트 머리에 "합산함"이 인쇄됩니다 |

| `모듈별요약.csv` | 모듈 × (행수 · 0행비율 · **전체평균 · 0제외평균** · 훈련유형 분리) |
| `트래커불일치.csv` | 코드 · 트래커값 · 재계산값 · **부호 붙은 차이** · 사유 (**불일치만**) |

### 다음 툴로 넘기기

`피험자별노출량.csv` 의 키 열 이름이 `subject_id` 인 것은 우연이 아닙니다 —
`joinaudit` 이 이 이름을 피험자 키로 자동 인식합니다.

```bash
# 배정표와 붙인 뒤 통계로
joinaudit 결과/피험자별노출량.csv 배정.csv \
    --date 피험자별노출량.csv=첫활동일 --out-dir merged
statwise merged/merged.csv --value 피험자별노출량_활동일수 --group 배정_arm
```

> `--date 피험자별노출량.csv=첫활동일` 이 필요한 이유: 첫/마지막 활동일을 **둘 다**
> 내보내므로 `joinaudit` 이 "어느 쪽이 시점인가"를 묻습니다. 그쪽도 추측하지 않는 툴이라
> 그렇습니다. 이 한 줄을 그대로 쓰면 됩니다.

| 코드 | 의미 |

## 한계 / Notes

- **판정이지 확정이 아닙니다.** 트래커 불일치가 나왔다고 트래커가 틀렸다는 뜻이 아닙니다 —
  이 툴이 말할 수 있는 것은 "선언된 규칙으로 세면 이 숫자다"까지입니다. 어느 쪽이 맞는지는
  데이터 검토 회의에서 사람이 정합니다.
- **벤더가 틀렸다고 말하지 않습니다.** 실제 자료에서 벤더 `[요약]` 블록은 150/150 재계산
  일치했습니다. **산수는 맞고 의미가 다를 뿐입니다.**
- **0초의 진짜 소요시간은 이 툴이 모릅니다.** 0인지 미기록인지 로그가 말하지 않으므로
  세 값을 나란히 내보내고 판단은 사람에게 넘깁니다.
- **헤더 5열 규격이 깨지면 판정하지 않습니다.** 앱이 개편되면 그렇게 됩니다. 조용히
  거짓말하는 것보다 낫지만, **형식이 두 번 연속 바뀌면 이 툴을 접고 벤더에게 CSV 규격을
  요구하는 편이 맞습니다.**
- **트래커의 `D1`…`DN` 일자별 격자는 읽지 않습니다.** 145열의 기준점(가입일인지 연구
  시작일인지)이 어디에도 적혀 있지 않아, 읽으면 추론이 되고 추론하면 조용히 거짓말합니다.
- **날짜는 연도-먼저 형식만 읽습니다.** `05.02.2026` 은 해석하지 않습니다. 시각은 버리고
  자백합니다 — 이 툴의 최소 단위는 날짜입니다.
- **다음 두 데이터셋에서 연속으로 치명 0건이면 이 툴은 접는 게 맞습니다.** 지금은
  23/30 · 빈 모듈 30/30 · 0초 35.6% 가 잡혀 있어 그럴 상황이 아닙니다.
- **트래커의 `Access Code` 칸에 Login ID 를 적어 넣으면 그 값은 인쇄됩니다.** 실제
  Login ID(`tjdnj5`)와 실제 Access Code 는 둘 다 영숫자라 생김새로 구분할 방법이
  없습니다. 이 툴이 지키는 약속은 "`환자명`·`Login ID` **열**을 열지 않는다"이고,
  그건 지켜집니다 — 다만 이 잔여 경로는 알고 계셔야 합니다.
- **로그의 `훈련유형` 칸에 적힌 자유 텍스트는 `모듈별요약.csv` 로 그대로 나갑니다.**
  유형별로 나눠 세는 것이 이 열의 일이라 걸러 내지 않습니다.
- **`--inspect` 의 복사용 실행 줄에는 입력한 경로가 그대로 찍힙니다**(셸 안전하게
  인용됩니다). 화면에만 나오고 산출물에는 들어가지 않지만, 스크린샷을 공유할 때는
  경로에 이름이 없는지 확인하세요.
- **번들 예제는 전부 합성이며 실제 피험자 자료가 아닙니다.** 실데이터·실명·Access Code 는
  이 저장소에 들어오지 않습니다. `.gitignore` 가 워크북·표·산출물을 통째로 막습니다.
