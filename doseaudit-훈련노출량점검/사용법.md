# 사용법 (빠른 시작)

## 가장 쉬운 방법

이 폴더의 **`실행.command` 더블클릭** → 예제 네 가지가 종료코드 **0 → 1 → 3 → 2** 순서로
차례로 돌아갑니다. 이 툴이 언제 조용하고 언제 멈추는지를 한 번에 볼 수 있습니다.

## 이 툴이 답하는 질문

> **"이 피험자가 처방된 훈련을 실제로 얼마나 받았는가 — 그리고 그 분모는 무엇이었는가?"**

순응/비순응을 판정하지 않습니다. 노출량과 결과의 관계도 보지 않습니다.
`logflow` 는 제품이 얼마나 쓰였는지를 보고, 이 툴은 **처방 대비 노출량**을 셉니다.

---

## 내 데이터로 돌리기 (터미널)

먼저 한 번만 설치(선택):

```bash
cd ~/Downloads/02_프로젝트/깃헙/doseaudit-훈련노출량점검
python3 -m pip install -e .
```

### 1단계 — 먼저 `--inspect` 로 "어떻게 읽었는지"를 봅니다

```bash
doseaudit --inspect --logs ~/Downloads/02_프로젝트/임상데이터/"M&Q임상 결과"/wowfit_project17_excels/
```

(설치하지 않았다면 이 폴더 안에서 `python3 -m doseaudit ...` 로 똑같이 됩니다.)

여기서 확인할 것:

- 워크북 몇 개를 읽었는지 (기대한 수와 같은가)
- 헤더가 `날짜 · 레벨 · 훈련유형 · 반복횟수 · 소요시간(초)` 5열과 같은지
- 파일명에서 뽑은 **피험자 코드**가 맞는지 (조인은 이것만 씁니다)
- **데이터가 0행인 모듈이 있는지** — 벤더 `[요약]` 은 그걸 `평균 0` 으로 인쇄합니다
- 그리고 맨 아래, **고를 수 있는 활동일 규칙과 각각의 결과값**

마지막 표를 보고 규칙 하나를 고르십시오. **고르는 행위 자체가 산출물입니다** —
고른 규칙이 Methods 문장에 그대로 들어갑니다.

### 2단계 — 정의를 선언하고 셉니다

`--inspect` 화면 맨 아래에 **복사해서 그대로 쓸 수 있는 실행 줄**이 규칙마다 하나씩
찍혀 있습니다. 거기서 골라 붙이고 `--cut` 날짜만 채우면 됩니다:

```bash
doseaudit --logs ~/Downloads/02_프로젝트/임상데이터/"M&Q임상 결과"/wowfit_project17_excels/ \
    --active-day any-row \
    --window enroll-to-cut --cut 2026-06-23 \
    --target-per-week 3 \
    --out-dir 결과_202609
```

정의를 선언하지 않으면 **판정하지 않고 종료코드 2 로 멈춥니다.** 일부러 그렇게 만들었습니다 —
"며칠 훈련했는가"는 데이터가 아니라 **정의**가 답하는 질문이기 때문입니다.

### 3단계 — 손으로 관리한 트래커와 대조합니다

```bash
BASE=~/Downloads/02_프로젝트/임상데이터/"M&Q임상 결과"
doseaudit --logs "$BASE"/wowfit_project17_excels/ \
    --tracker "$BASE"/참여현황_2026-06-21.xlsx \
    --active-day any-row --window enroll-to-cut --cut 2026-06-23 \
    --target-per-week 3 --out-dir 결과_202609
```

트래커의 `환자명`·`Login ID` 열은 **열지 않습니다.** `Access Code` 로만 조인합니다.

## 결과 읽는 법

### `[치명]` — 그대로 보고하면 안 되는 것

- **트래커 `완료일수` 가 로그와 다릅니다.** 콘솔에는 최대 5명만 보이고 전체는
  `트래커불일치.csv` 에 있습니다. **차이의 부호가 전원 같으면** 오타가 아니라
  **정의 차이**입니다 — 누군가 '완료'를 다른 기준으로 셌고, 그 기준이 적혀 있지 않습니다.
- **`OOO` 모듈: 데이터 없음.** 벤더 `[요약]` 은 `평균 0회 · 평균 0초` 로 인쇄하지만
  실제로는 행이 하나도 없습니다. **"0을 측정함"이 아니라 "측정되지 않음"입니다.**

### `[경고]` — 문장을 쓰기 전에 알아야 하는 것

- **0초 행 N건.** 0초가 "0초 걸렸다"인지 "기록되지 않았다"인지 로그가 말하지 않습니다.
  그래서 모든 평균이 **전체평균 · 0제외평균 · 0행비율** 세 값으로 나옵니다.
  0행비율이 100%인 모듈은 **평균을 단일 숫자로 내보내지 않습니다**(`대조불가`).

### `[정보] 정의 민감도` — 여기가 이 툴의 핵심입니다

같은 데이터에서 **활동일 규칙(분자)** 과 **분모의 창** 을 각각 바꿔, 중앙값 노출률을
나란히 세운 표입니다. 실제 자료에서는 이렇게 나왔습니다:

```
[활동일 규칙 을 바꿨을 때]   any-row 51% · min-modules=2 47% · min-seconds=60 16%
[분모의 창 을 바꿨을 때]     enroll-to-last 90% · fixed-weeks=8 75% · fixed-weeks=12 64%
→ 같은 데이터에서 중앙값이 16% ~ 90% 사이를 움직입니다.
```

**분모의 창이 더 큰 지렛대입니다.** 활동일 규칙보다 창을 무엇으로 잡느냐가 최종
숫자를 더 크게 바꿉니다 — CSR 의 adherence 문단을 쓸 때 반드시 적어야 하는 것이
바로 이 창입니다.

**어느 값이 옳은지 이 툴은 말하지 않습니다.** 이 표의 용도는 한 문장입니다 —
**"정의를 문서에 적지 않으면 이 중 어느 값이든 될 수 있습니다."**

### `[커버리지 자백]` — 항상 맨 아래, 없으면 리포트가 아예 안 나옵니다

무엇을 읽었고, 무엇을 못 읽었고, 무엇을 **일부러 안 봤는지**가 적혀 있습니다.
**리포트에 안 나온 항목이 "일치"라는 뜻이 아닙니다.**

| 코드 | 의미 | 무엇을 해야 하나 |
|---|---|---|

## 자주 막히는 곳

**Q. `--active-day` 를 뭘로 골라야 할지 모르겠습니다.**
A. 먼저 `--inspect` 를 돌리세요. 고를 수 있는 규칙과 **각각으로 셌을 때의 결과값**이
나옵니다. 보고 고르면 됩니다. 실제로는 대부분 `any-row` 로 시작해서, 리포트의 민감도
표를 보고 "이 정의로 보고해도 되는가"를 판단하게 됩니다.

**Q. 종료코드 2 로 "헤더가 5열 규격과 다릅니다" 가 나옵니다.**
A. 앱이 개편돼 로그 형식이 바뀐 것입니다. 이 툴은 **추측해서 세는 대신 멈춥니다.**
벤더에게 규격을 확인하세요. **형식이 두 번 연속 바뀌면 이 툴을 접고 CSV 규격을 요구하는
편이 맞습니다.**

**Q. 내 파일을 이 폴더에 두고 돌려도 되나요?**
A. 돌려도 되지만 **저장소에 올라가지는 않습니다.** `.gitignore` 가 `.xlsx`·`.csv`·
산출물 폴더를 통째로 막습니다(번들 예제만 예외). 실데이터는 이 저장소에 들어오지 않습니다.

**Q. 원본이 바뀌지 않나요?**
A. 이 툴은 **입력을 절대 쓰지 않습니다.** 패키지에 삭제·이동 함수가 없다는 것을 테스트가
AST 로 확인하고, 출력 자리에 심볼릭/하드 링크가 있으면 **쓰지 않고 거절**합니다.
