### 고친 것 — 치명적 (판정을 틀리게 만들던 것)

**C1. 분자와 분모가 서로 다른 구간을 보고 있었다.** `dose.py`
활동일(분자)은 워크북 **전체**에서 세면서 관찰일수(분모)만 선언된 창으로 잡고
있었습니다. 가입 이전·데이터컷 이후의 활동이 분자에만 들어가, 노출률이 부풀었습니다.
재현: 가입 2026-03-01, `--cut 2026-03-14`, 활동일 6일 중 창 안은 2일 →
툴은 `활동일수 9 · 주당활동일 4.5 · 노출률 150%` 를 인쇄했고, 올바른 값은
`2일 · 1.0 · 33.33%` 였습니다. `--criterion` 판정이 이 오차로 뒤집히는 것도
확인됐습니다. → `Window.bounds()` 를 만들어 **분자와 분모가 같은 창을 쓰게** 하고,
창 밖 활동일은 버리지 않고 `창밖활동일수` 로 세어 CSV·콘솔에 인쇄합니다.
*(실데이터 30명에서는 창 밖 활동이 0일이라 23/30 회귀는 영향받지 않았습니다.)*

**C2. 시작일을 모르는데 고정 주수 분모를 만들고 있었다.** `rules.py`
`fixed-weeks=N` 이 `enroll is None` 검사보다 **먼저** `weeks*7` 을 돌려주고
있었습니다. 트래커에 행이 없는 피험자가 `관찰일수 7 · 노출률 66.67` 을 받았습니다 —
시작점 없는 비율입니다. → 시작일을 모르면 창이 없습니다(`(None, None)`).

**C3. 벤더 `[요약]` 대조가 사실상 무검사였다.** `dose.py`
`abs(재계산 − 인쇄값) < 1.0` 으로 보고 있었습니다. 평균이 1~3인 반복횟수 열에서는
**45% 오차를 눈감아 주는 규칙**입니다(재계산 2.9 vs 인쇄 2 가 '일치'). 더 나쁜 것은
`재계산값 없음 + 인쇄값 0` → '일치' 였다는 점입니다. **미측정을 0으로 읽는 것**은
이 툴이 존재하는 이유 그 자체인데, 대조기가 그 사고를 저지르고 있었습니다.
→ **인쇄된 자릿수로 반올림해 비교**합니다. 여기서 실측 하나가 드러났습니다:
벤더는 소요시간을 **소수 둘째 자리**로(`4.34초`), 반복횟수를 정수로 인쇄합니다.
자릿수를 정수로 고정하면 150 중 68 이 '불일치'로 둔갑합니다. 재계산할 값이 없으면
이제 `대조불가` 이고 일치로 세지 않습니다. **150/150 일치는 이 엄격한 규칙에서도
유지됩니다.**

**C4. 원고에 붙으라고 만든 문장이 거짓을 말할 수 있었다.** `report.py`
KR/EN Methods 초안이 `comparison["uniform_sign"]` 을 보지 않고 **언제나**
"전원 같은 방향" / "all in the same direction" 을 붙였습니다. 콘솔은 제대로
확인하고 있었기에 **문서만 거짓말하는** 형태였고, 하필 이 문장이 이 툴의 핵심
추론("한 방향이면 오타가 아니라 정의 차이")입니다. → 실제로 한 방향일 때만 씁니다.

**C5. 단위가 다른 값을 조용히 환산 없이 받아들였다.** `values.py`
`소요시간(초)` 열의 `'5분'` 이 `5.0`(초)으로 읽혔습니다 — **60배 축소**가
경고 한 줄 없이 일어나고, `--active-day min-seconds=S` 판정이 뒤집힙니다.
음수(`-100초`)도 그대로 평균에 들어가 `평균 소요시간 -21.67초` 를 인쇄했습니다.
→ **열마다 기대 단위를 지정**해 부르고, 차원이 다르면 이름을 붙여 거절하며,
음수와 `nan`/`inf` 는 해석 실패로 셉니다(버리지 않고 자백에 싣습니다).

**C6. 없는 열로 "검증했다"고 주장했다.** `tracker.py` / `audit.py`
트래커에 `진행률(%)`·`현재까지 일수` 열이 아예 없으면 `progress_bad` 가 비고,
그 빈 목록을 "전원 재현됩니다"로 읽어 **하지 않은 검증을 주장**했습니다.
→ 실제로 확인한 사람 수를 세고, 한 명도 확인하지 못했으면 아무 말도 하지 않습니다.

**C7. 소수점 `완료일수` 를 잘라 고칠 데가 없는 치명을 만들었다.** `tracker.py`
`int(3.5)` → 3 으로 표시하면서 비교는 3.5 로 해, `트래커 3일 ↔ 로그 3일 (+0)`
이라는 치명이 인쇄됐습니다. → 온 값 그대로 인쇄합니다(`3.5`, `-0.50`).

### 고친 것 — 안전·개인정보

가능했습니다: ① `QR33ST44_realloginid7788_9.csv` 의 **Login ID** 와
`김철수.pdf` 의 **실명**이 공유용 `노출량점검.md` 로 유출 ② 파일명에 개행을 심어
**리포트 0열에 `[치명]` 줄을 위조** ③ `[커버리지 자백]` 헤더 자체를 위조.

`.xlsx` 경로만 통과시켜 **마스킹되는 쪽만** 검사하고 있었습니다.
→ 수집 시점에 마스킹하고, 두 공격 모두 회귀 테스트로 고정했습니다.

**S2. Access Code 자리의 한글 이름이 그대로 인쇄됐다.** `sanitize.py`
`mask_filename` 이 가운데 토큰만 가려서, `홍길동_hong1234_1.xlsx` 가
`홍길동_…_1.xlsx` 로 인쇄됐습니다. 코드가 **이미** "이건 Access Code 규격이 아니다"
라고 판정한 값을 그대로 내보내고 있었던 셈입니다. → `mask_head=True` 로 첫 토큰도
`?` 로 가립니다.

**S3. 트래커의 Access Code 는 아무 검증도 받지 않았다.** `tracker.py`
파일명에는 규격 검사가 있는데, **손으로 관리해 신뢰할 수 없다고 README 가 말하는**
트래커에는 없었습니다. 코드 칸의 `이순신` 이 콘솔·CSV·마크다운으로 전파됐습니다.
→ 같은 규격으로 검사하고, 아니면 값을 읽지 않고 자백에만 적습니다.

**S4. 개인정보 열 탐지를 쉽게 피할 수 있었다.** `tracker.py`
`^성명$`·`^이름$`·`^name$` 이 앵커돼 있어 `환자 성명`·`성명(한글)`·`Patient Name`·
`참여자명`·`수급자 성함` 이 모두 통과했습니다. 값이 새지는 않았지만(읽는 열이
고정이라), `dropped_columns` 가 비어 **하지 않은 비식별화를 리포트가 주장**했습니다.
→ 앵커를 풀고 범위를 넓혔으며, 읽지 않은 열 전부를 자백에 인쇄합니다.

**S5. 보이지 않는 접두사가 수식 방어를 비껴갔다.** `csvout.py`
`"﻿=cmd|'/c calc'!A1"` 이 **따옴표 없이** CSV 로 나갔습니다.
→ `﻿`·`​`·`⁠`·`­` 등을 무해화 대상에 넣고, 첫 글자 판정 전에
비가시문자와 공백을 건너뜁니다.

**S6. 산출물 하나가 링크면 앞의 세 장은 이미 쓰인 뒤였다.** `artifacts.py`
반쯤 채워진 결과 폴더는 완전한 결과로 오해됩니다. → 네 개를 **쓰기 전에 한 번에**
검사하고(`preflight`), 하나라도 막히면 아무것도 쓰지 않습니다.

### 고친 것 — 유용성·정직성 (문서 감사)

**U1. 민감도 표가 정작 분모를 흔들지 않았다.** — 이번 라운드에서 가장 값어치 있는
지적입니다. 실측에서 활동일 규칙은 중앙값을 **51% → 16%** 로 움직였지만, 분모의
창은 **51% → 64% → 75% → 90%** 로 움직입니다. 이 툴의 한 줄 요약이
*"분모가 무엇이었는지를 드러내고 끝난다"* 인데 분모를 흔들어 보이지 않으면 그
문장이 빕니다. 게다가 `any-row` 와 `min-rows=5` 가 실데이터에서 **같은 값**을
내서, 선언 강제가 연극처럼 보였습니다. → 표를 **두 축**으로 나눠 분모의 창도
흔들고, "같은 데이터에서 중앙값이 16% ~ 90% 사이를 움직입니다" 한 줄을 덧붙입니다.

**U2. `logflow` 와의 경계 주장이 과장이었다.** `logflow` 에는 이미
`--adherence-days`·`--adherence-weeks`·`--adherence-target` 이 있고, 활성일을
**"이벤트가 하나라도 있던 날"**(= 이 툴의 `any-row`)로 셉니다. → README 에 겹치는
부분을 표로 적고, 실제로 다른 네 지점만 남겼습니다. 뼈대(선언 강제·자백·Methods
초안·산출물 4종)가 `joinaudit`·`visitaudit` 과 공유하는 틀이라는 것도 함께 적었습니다.

**U3. 실데이터 상수가 코드에 박혀 있었다.** `inspect.py` 가 어떤 자료에서든
`"180장 중 한 장이라도…"` 를 인쇄했습니다(30 × 6 = 180 은 사용자의 실데이터 값).
→ `bundle.n_sheets` 로 바꿨습니다.

**U4. 계산해 놓고 인쇄하지 않던 값들.** `--cap` 의 절단 인원수와 `--criterion` 의
충족 인원수는 문서가 "인쇄합니다"라고 했지만 콘솔에 없었습니다(`--no-files` 로는
영영 못 봄). → 둘 다 `[정보]` 로 인쇄하고, 기준 충족 인원은 **Methods 초안 문장**
으로도 넣었습니다 — CSR adherence 문단이 실제로 필요로 하는 문장입니다.

**U5. 분포를 범위로만 말했다.** `범위 2–188%` 는 쓸 수 있는 산포가 아닙니다.
→ Methods 초안에 **중앙값 [IQR]** 을 함께 씁니다. 이 때문에
`test_강제장치.py` 의 `statistics` 허용 목록에 `quantiles` 를 **의도적으로**
추가했습니다(`correlation`·`covariance`·`linear_regression` 은 여전히 금지이고,
그것이 그 테스트가 지키는 선입니다).

**U6. 중복의심이 실데이터에서 61.5%(27,868행 중 17,128건) 를 표시했다.** 그 비율
에서는 신호가 아닙니다. → 모듈별로 나눠 인쇄해 **어디가 유별난지** 보이게 했습니다
(제거하지 않는다는 원칙은 그대로입니다).

**U7. 영문 초안에 한글 모듈명이 그대로 섞였다.** → `Module 6 (발성훈련)` 형태로
자리번호를 붙입니다.

**U8. 선언 강제의 진입 장벽.** 리뷰어의 지적: 네 개의 인자를 매번 다시 타이핑하게
두면 선언은 결정이 아니라 상용구가 되고, 사용자는 alias 로 숨겨 버립니다.
→ `--inspect` 가 **복사해서 바로 쓸 수 있는 실행 줄**을 규칙마다 한 줄씩 인쇄하고,
분모의 창 선택지도 한 줄 설명과 함께 보여 줍니다. **게이트는 유지하되 순응 비용을
낮췄습니다.**

### 강제장치 — 4개 중 3개가 우회 가능했다

안전 감사가 세 개의 백도어를 **동시에** 심고도 1,037개 전부 초록을 받았습니다.

1. **입력 쓰기 금지(AST)** — `ast.Name` 의 `open` 만 봐서 `io.open(p,"w")`·`os.open(...,O_TRUNC)`·

   2298→0 바이트로 만들어 보였습니다.

2. **판정 어휘 금지(grep)** — 부정 표지가 **같은 줄 아무 데나** 있으면 면제였습니다.

   위 공격 문장이 이제 잡히는 것을 테스트로 확인했습니다.
3. **검정·상관 금지(AST)** — `from statistics import correlation as _assoc` 가 통과했습니다
