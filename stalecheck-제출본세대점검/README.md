# stalecheck — 제출본 세대 점검

투고 봉투(`submission/`·`제출용/`) 안의 파일이 **작업 폴더의 최신 원본과 같은 세대인지**를
내용 해시로 대조해, **한 세대 뒤처진 파일만** 찍습니다.

> `packlist` 는 봉투 안이 약속대로 채워졌는지를 보고, **`stalecheck` 는 그 봉투가 며칠 전 세계를
> 담고 있는지를 봅니다. 봉투는 완벽하게 채워진 채로 한 세대 낡을 수 있습니다.**

---

## 목적 / Why this exists

**한국어.** 투고 버튼을 누르기 직전, 리젝 후 다른 저널 패키지로 갈아탈 때, 리비전을 재제출할 때,
재현성 예치본을 올릴 때 — 사람들은 봉투 폴더를 열어 "이게 최신 맞나?"를 눈으로 확인합니다.
그림 8장 × 2포맷 + 분석 스크립트 21개 + 원고·커버레터를 하나씩. 이 저장소 주인의 논문 트리에서는
**16개 논문 폴더 중 6개, 245쌍 중 38쌍이 실제로 갈라져 있었습니다.**
(245쌍은 아카이브 폴더를 포함해 센 값입니다. 출시 기본값은 아카이브를 빼므로 237쌍이고, **갈라진 38쌍과 확장자 분포는 두 기준에서 같습니다.**) 그중에는 재현성 예치본에서
*논문이 보고하는 세 값을 계산하는 29행짜리 블록이 통째로 빠진* 사례와, 저널이 요구하는
`pdf.fonttype = 42`(TrueType 임베딩) 설정이 예치본 그림 스크립트에만 빠져 **Type 3 폰트 그림이
나오는** 사례가 있었습니다. 이 툴은 그 245쌍을 눈으로 대조하는 일을 대신하고, **고치지는
않습니다** — 어느 쪽이 옳은지는 사람만 압니다.

**English.** Right before hitting submit, when repackaging for another journal after a
rejection, when resubmitting a revision, or when uploading a reproducibility deposit,
researchers open the submission folder and eyeball whether everything in it is current.
`stalecheck` hashes both trees, normalizes away render-only metadata in PDF/DOCX, pairs
files conservatively, and reports **only the pairs where the envelope is a generation
behind** — plus which direction the evidence points. It never edits, copies, moves or
deletes anything; deciding which side is right is a human's job.

**누구에게.** 여러 편을 동시에 투고·개정하는 임상/제약 연구자. 특히 한 논문에 봉투를
여러 벌 유지하는 경우(`SUBMISSION/`·`SUBMISSION_BRM/`·`SUBMISSION_JPBA/`).

## 왜 `diff -r` 로는 안 되나

| 대안 | 왜 안 되는가 |
|---|---|
| `diff -r 작업폴더 봉투폴더` | ① 폴더 구조가 달라 짝이 안 맞습니다(`figures/` vs `submission/05_Figures/`) ② PDF·DOCX 는 **다시 렌더만 해도 "differ"** — 실측 49건 중 **11건이 전부 이 오탐**이었습니다 ③ **어느 쪽이 낡았는지 말하지 않습니다** |
| `fdupes` / `jdupes` | 정반대 질문에 답합니다. *같은* 파일을 찾아 줍니다. 우리가 찾는 건 *같아야 하는데 갈라진 쌍*입니다 |
| git | 원고 트리가 git 이 아닌 경우가 대부분입니다. git 을 도입하자는 제안이 아니라, **지금 상태에서 답을 주는 도구**입니다 |
| `packlist` | 봉투 **안**을 봅니다(약속·한도·고아 파일). 봉투 **밖**(작업 폴더)을 보지 않아, 봉투가 완결적이면서 전부 구버전인 상태를 통과시킵니다 |

### 인접 툴과의 경계

| 툴 | 입력 | 답하는 질문 |
|---|---|---|
| `packlist` | 봉투 + 원고 | 봉투가 **약속한 것을 담고 있는가** |
| `tracecheck` | 원고 + 산출물 | 원고의 **숫자가 산출물에 있는가** |
| `revcheck` | 제출본·개정본·응답서 | 응답서가 **개정본과 맞는가** |
| **`stalecheck`** | **작업 폴더 + 봉투** | **봉투 안 파일이 작업 폴더 원본과 같은 세대인가 — 어느 쪽이 낡았는가** |

## 설치

의존성이 없습니다(파이썬 표준 라이브러리만). 네트워크를 쓰지 않습니다.

```bash
cd stalecheck-제출본세대점검
python3 -m pip install -e .
```

설치하지 않고도 폴더 안에서 `python3 -m stalecheck …` 로 바로 쓸 수 있습니다.
맥에서는 **`실행.command` 를 더블클릭**하면 합성 예제로 동작과 종료코드 4가지를 보여 줍니다.

## 사용법

```bash
# 0) 무엇을 읽을지부터 확인 — 판정하지 않습니다
python3 -m stalecheck --work "논문폴더" --inspect

# 1) 봉투 후보만 인쇄하고 거절 (--package 를 추론하지 않습니다)
python3 -m stalecheck --work "논문폴더"

# 2) 판정
python3 -m stalecheck \
    --work    "논문폴더" \
    --package "논문폴더/submission" \
    --out-dir ~/Desktop/세대점검_20260918

# 3) 봉투가 여러 벌이면 --package 를 반복
python3 -m stalecheck --work "논문폴더" \
    --package "논문폴더/SUBMISSION_BRM" --package "논문폴더/SUBMISSION_JPBA"
```

### 실제 출력 (번들된 합성 예제)

```

  작업 폴더 : 예제_논문폴더   (대상 파일 8개)
  봉투      : submission   (대상 파일 7개)
  짝지음 5쌍 · 일치 3쌍 · 그중 메타데이터만 달랐던 것 2쌍

[치명] 봉투가 구세대 — 2쌍

  analysis/03_분석.py
      작업 2026-07-31 10:39 (519 B)  >  봉투 2026-07-30 11:10 (240 B)   (+6행 / -1행)
      봉투 안: submission/analysis/03_분석.py
      + # 03_분석.py — 작업 폴더의 최신판(7월 31일)
      + 
      + # --- 원고가 보고하는 두 값을 표에서 베끼지 않고 여기서 계산한다 ---
  figures/그림1_결과.png
      작업 2026-07-31 10:39 (83 B)  >  봉투 2026-07-30 11:10 (83 B)   (대조불가(바이너리))
      봉투 안: submission/05_Figures/그림1_결과.png

[경고] 봉투가 더 최신 — 0쌍
[판정불가] — 0쌍

[경고] 빌드 누락 — 1건
  manuscript/본문.md (2026-07-31 10:39)  >  manuscript/본문.docx (2026-07-30 11:10)
[경고] 그림 형제 세대 불일치 — 1건
  figures/그림1_결과.png (2026-07-31 10:39)  >  figures/그림1_결과.pdf (2026-07-30 11:10)

[커버리지 자백]
  읽음: 15/15 파일 (못 읽음 0 · 크기초과 건너뜀 0)
  셈의 범위: 같은 파일명으로 짝지어진 5쌍만. 이름이 다른 사본은 짝짓지 않았습니다.
    · 이름은 다르지만 내용이 똑같아 낡았을 수 없는 파일 1개는 판정에서 제외했습니다.
  짝 없음: 봉투에만 1개 · 작업폴더에만 2개 (봉투에 넣지 않은 파일 — 정상일 수 있습니다)
  짝지음 비율: 86% (기준 0%)
  제외한 폴더(아카이브/구버전): _이전

  이 툴은 봉투가 최신이라고 보증하지 않습니다 — 위에 적힌 짝에 대해서만 말합니다.
```

### 산출물 (`--out-dir` 안에만)

| 파일 | 내용 |
|---|---|
| `세대점검.md` | 위 리포트 전문 |
| `세대불일치.csv` | `판정, 작업경로, 봉투경로, 작업mtime, 봉투mtime, 작업크기, 봉투크기, 행추가, 행삭제, 정규화적용, 짝짓기근거, 사유` |
| `짝없음.csv` | 봉투에만 / 작업폴더에만 있는 파일, 이름중복으로 판정하지 않은 파일 |
| `일치목록.csv` | 일치 쌍 — **오탐 억제 회귀 자산**. 다음 데이터셋에서 툴이 조용해졌는지 확인하는 유일한 방법입니다 |
| `형제점검.csv` | 빌드 누락 · 그림 형제 세대 불일치 |

### 종료코드

| 코드 | 의미 |
|---|---|
| `0` | 치명 0건 · 판정불가 0건 (경고는 있을 수 있습니다) |
| `1` | 치명 N건 — 봉투가 구세대인 쌍이 있습니다 |
| `2` | **판정 없이 거절** — 봉투 폴더 미특정 · `--work`/`--package` 폴더 없음 · 둘이 같거나 포함관계가 아님(심볼릭 링크를 풀어 확인) · `--package` 두 개가 서로 포함관계 · `--out-dir` 이 입력 폴더 안이거나 파일·링크·권한 없음 · 인자 값이 범위 밖 · **`--inspect`(판정하지 않으므로)** |
| `3` | **판정 불가** — 읽지 못한 파일/폴더가 있거나 · 비교한 쌍이 0인데 봉투에 파일이 있거나 · **이름이 겹쳐 판정하지 못한 봉투 파일이 있거나** · `[판정불가]` 쌍이 있거나 · 짝지음 비율이 `--min-coverage` 미만. **3이 1보다 우선합니다** |

`--inspect` 는 판정하지 않으므로 항상 `2` 로 끝납니다 — `stalecheck --inspect && 제출` 이
낡은 봉투를 통과시키지 않게 하려는 것입니다.

주요 옵션: `--inspect` `--ext` `--max-bytes`(기본 60MB) `--mtime-tolerance`(기본 2초)
`--min-coverage`(기본 0 = 사용 안 함) `--no-siblings` `--include-archives` `--quiet`

## 어떻게 판정하나

1. **메타데이터 정규화가 먼저입니다.** PDF 는 `/CreationDate`·`/ModDate`·`/ID` 와 XMP 패킷의
   `xmp:CreateDate`·`xmp:ModifyDate`·`xmp:MetadataDate`·`xmpMM:InstanceID`·`xmpMM:DocumentID` 를
   지우고(**전부 길이 제한이 걸린 패턴** — 제한 없는 와일드카드는 스트림 안의 우연한 일치로 본문을
   삼켜 진짜 차이를 숨깁니다), DOCX/XLSX/PPTX 는 `docProps/` 를 뺀 엔트리명+내용으로 해시합니다
   (엔트리마다 길이를 접두사로 붙여 `name+content` 이어붙이기 충돌을 막습니다). 그 외는 원시 바이트.
   사용자의 실제 논문 트리에서 **원시 불일치 49쌍 중 11쌍(전부 PDF)** 이 이 단계에서 사라집니다.
   이것이 `diff -r` 대비 유일한 우위이고, 무너지면 이 툴은 매번 우는 체커가 됩니다.
2. **짝짓기는 보수적으로.** 파일명 완전 일치(NFC·대소문자 무시)만 판정 대상입니다.
   이름이 다르지만 내용이 똑같은 파일은 "낡았을 수 없다"로 보고 판정에서 빼고 `일치목록.csv` 에만
   적습니다. **유사 이름 추측 짝짓기는 하지 않습니다** — 조용히 거짓말하는 경로입니다.
3. **방향은 증거가 있을 때만.** 정규화 해시가 다르고 `작업본 mtime > 봉투 mtime`(2초 초과)이면
   `[치명] 봉투가 구세대`, 반대면 `[경고] 봉투가 더 최신`(봉투에서 손으로 고쳤다는 뜻이고 그 수정은
   작업 폴더에 없습니다), 그 밖에는 `[판정불가]`. **추측하지 않습니다.** mtime 이 못 미더워도
   **불일치 사실 자체는 여전히 보고됩니다.**
4. **텍스트는 몇 줄이 다른지까지.** `.py`·`.md`·`.csv` 등은 `+N/-N` 행수와 추가된 첫 3행을 보여 줍니다.
   바이너리는 크기 차이만. **`+N/-N` 은 표시용 참고값**입니다 — 줄이 대량으로 재배치되거나
   같은 줄이 여러 번 나오면 GNU `diff -u` 보다 큰 수가 나올 수 있고, **판정과 종료코드에는
   쓰이지 않습니다.**

## 한계 / Notes

- **고쳐 주지 않습니다.** 복사·덮어쓰기·이동·삭제가 없습니다(`shutil` 미import와 파괴적 `os` 호출
  부재를 AST 테스트로 강제). 의도적입니다 — **봉투에서 손으로 고친 경우가 실제로 있고**
  (`[경고] 봉투가 더 최신`), 자동 복사는 그 수정을 되돌릴 수 없게 덮어씁니다.
- **이름이 바뀐 사본은 짝짓지 못합니다.** `fig1_checksum_corruption.png` → `Figure1.png` 같은
  개명 복사는 v1에서 "양쪽에만 있음"으로 빠집니다. **알려진 사각지대이고 커버리지 자백에 적힙니다.**
  (내용이 완전히 같으면 잡아냅니다. 내용까지 바뀐 개명은 못 잡습니다.)
- **mtime 을 믿을 수 없는 환경이 있습니다.** 클라우드 동기화·`cp` 는 mtime 을 갈아 치웁니다.
  그래서 방향 판정이 `[치명]`/`[판정불가]` 두 갈래입니다.
- **픽셀/의미 비교를 하지 않습니다.** 그림이 "같아 보이는지"는 묻지 않습니다. 바이트가 다르면
  다르다고만 합니다.
- **`.hwp` 는 기본 확장자가 아닙니다.** `--ext hwp` 를 주면 해시는 되지만 내용 diff 는
  `대조불가` 로 자백합니다.
- **기본으로 보는 확장자는 6종뿐입니다** (`.png .pdf .docx .md .py .csv`).
  `.tif`·`.eps`·`.jpg`·`.xlsx`·`.tex`·`.txt`·`.zip`·`.doc`·`.hwp` 는 기본 스캔 대상이 아닙니다.
  **세지 않고 넘어가지는 않습니다** — 커버리지 자백에 `확장자가 대상 밖이라 보지 않은 파일` 로
  개수와 확장자가 인쇄되고, 그래서 비교한 쌍이 하나도 없으면 `0`(=깨끗함)이 아니라 **`3`(판정 불가)**
  으로 끝납니다. 포함하려면 `--ext tif --ext xlsx` 처럼 지정하세요.
- **형제 점검(`빌드 누락`·`그림 형제`)은 작업 폴더만 봅니다.** 봉투 안에서 `.md` 만 고치고
  `.docx` 를 다시 굽지 않은 경우는 잡지 못합니다.
- **`--min-coverage` 는 기본이 0(끔)입니다.** 봉투에만 있는 파일(커버레터·체크리스트)이 정상이라
  기본값을 올리면 매번 울기 때문입니다. 실제 논문 폴더의 짝지음 비율은 40~70%가 보통이므로,
  **봉투 파일의 30~60%는 비교되지 않은 채 남습니다** — 그 수는 자백에 인쇄됩니다.
- **같은 이름의 작업본이 여럿이고 내용이 서로 다르면 판정하지 않습니다.** 어느 것이 봉투의
  원본인지 알 수 없기 때문입니다. 그 경우 `짝없음.csv` 에 `이름중복으로 판정 안 함` 으로 적고
  **종료코드 3**(판정 불가)으로 끝냅니다 — `0`(치명 없음)으로 끝내면 "보지 않은 것"이
  "괜찮은 것"으로 읽힙니다.
- **숨김 파일(`.` 으로 시작)과 심볼릭 링크는 읽지 않습니다.** 둘 다 개수를 자백에 인쇄합니다.
- **원고 내용·숫자·저널 규정을 보지 않습니다.** → `tracecheck`·`numcheck`·`packlist`
- **이 툴은 봉투가 최신이라고 보증하지 않습니다.** 짝지은 쌍에 대해서만 말합니다.
  봉투에만 있는 파일, 이름이 바뀐 사본, 크기 초과로 건너뛴 파일은 전부 자백에 적힙니다.
- **PDF 정규화의 전제.** Info 딕셔너리가 **압축된 객체 스트림(`/ObjStm`, PDF 1.5+)** 안에 들어 있는
  PDF 에서는 정규화가 개입하지 못하고 "실제 불일치"로 올라옵니다. stdlib 만으로 객체 스트림을 풀 수
  없기 때문이고, 과잉 정규화로 진짜 차이를 숨기는 것보다 낫다고 판단했습니다. 어떤 정규화가 적용됐는지는
  `세대불일치.csv`·`일치목록.csv` 의 `정규화적용` 열에 그대로 적힙니다(`pdf-meta`/`zip-docprops`/
  `zip-container`/`none`).
- **압축을 푼 크기가 512MB 를 넘는 zip(docx 등)은 정규화하지 않고 원시 바이트로 비교합니다.**
  작은 파일이 수 GB 로 부푸는 경우를 막기 위한 상한입니다. 한 쪽만 상한을 넘으면 두 파일이
  **서로 다른 기준으로 해시되어** 내용이 같아도 불일치로 올라옵니다(`정규화적용` 열이
  `none`/`zip-docprops` 로 갈리는 것으로 알 수 있습니다).
