# tracecheck 빠른 사용법

## 0. 제일 빠른 방법

폴더 안의 **`실행.command` 를 더블클릭**하세요. 합성 예제 두 벌(정상 원고 / 결함 3건이 심어진 원고)이 바로 돌면서 결과가 어떻게 생겼는지 보여 줍니다.

## 1. 이걸 언제 쓰는가

> 통계 담당이 재분석 결과 폴더를 새로 보내왔다. 원고에 숫자가 200개인데, 그중 어느 것이 **옛 분석에서 온 값**인지 모르겠다.

이때 씁니다. 원고 하나 + 분석 출력 폴더(있으면 옛 폴더도) 만 있으면 됩니다.

## 2. 내 파일로 실행하기

```bash
# 설치(한 번만)
cd ~/Downloads/02_프로젝트/깃헙/tracecheck-원고수치출처추적
python3 -m pip install -e .

# 실행 — 재분석 전후 두 폴더를 함께 주는 것이 가장 강력합니다
tracecheck 원고.docx \
  --outputs 분석출력_2026-08-18/ \
  --previous 분석출력_2026-08-03/ \
  --out-dir 출처대조결과
```

- `--outputs` : **지금** 기준이 되는 분석 산출물 폴더 (CSV/TSV/JSON/XLSX/MD/TXT 를 재귀로 다 읽습니다)
- `--previous` : 재분석 **이전** 폴더. 이걸 줘야 "옛 값이 원고에 남아 있다"를 잡습니다
- `--out-dir` : 결과 파일 4개가 여기에만 생깁니다

### 예제 A — 옛 출력 폴더가 없을 때

```bash
tracecheck 원고.docx --outputs 분석출력/
```

"출처 없는 숫자"는 그대로 잡히지만, 리포트에 **"구버전 잔존 검사는 수행되지 않았습니다"** 가 크게 찍힙니다. 다음부터는 옛 폴더를 지우지 말고 남겨 두세요 — 이 툴의 가장 큰 값은 거기서 나옵니다.

### 예제 B — 먼저 무엇을 대조하는지 눈으로 보기

```bash
tracecheck 원고.docx --dump-text
```

대조 대상으로 뽑힌 숫자와 건너뛴 숫자(사유 포함)를 그대로 보여 줍니다. 표 셀이 제대로 읽히는지, 절 분류가 맞는지 30초면 확인됩니다. (번들 없이 실행됩니다.)

### 예제 C — Methods 절까지 보고 싶을 때

```bash
tracecheck 원고.docx --outputs 분석출력/ --sections abstract,results,tables,captions,methods
```

기본값에 Methods 는 없습니다. 표본수·용량·기기 사양이 섞여 있어 '출처 없음'이 늘기 때문입니다.

### 예제 D — 치명을 다 고친 뒤, 고찰까지 한 번 더

```bash
tracecheck 원고.docx --outputs 분석출력/ --previous 옛분석출력/ \
  --sections abstract,results,tables,captions,discussion
```

고찰 첫 문단에 주요 결과를 다시 적는 일이 많은데, 기본 설정에서는 그 숫자를 보지 않습니다(선행연구 인용값이 섞여 있어서). **마지막 한 번은 고찰까지 포함해 돌리세요.** 인용값 때문에 '출처 없음'이 몇 건 늘 수 있으니, 늘어난 것만 눈으로 거르면 됩니다.

## 3. 결과 읽는 법

리포트 맨 위 **커버리지 자백**부터 보세요.

```
추출 숫자        43개
  대조 대상      33개  (Abstract 10 · Results 17 · 표 6)
  건너뜀         10개
      표·그림 번호 참조       1
      유의수준 관용구         3
      ...
  대조 결과      매칭 31 · 미매칭 2  (미매칭율 6.1%, 임계 30% 이내)
읽지 못한 파일   0개
```

- **대조 대상**이 너무 적으면(예: 5개 미만) 절 분류가 안 된 것입니다 → `--dump-text` 로 확인
- **읽지 못한 파일**이 0 이 아니면, 거기 있던 값이 '출처 없음'으로 잘못 잡힐 수 있습니다
- **미매칭율**이 30%를 넘으면 판정을 내리지 않고 멈춥니다(폴더를 잘못 지정한 경우가 대부분)

그 다음 등급별로 봅니다.

| 등급 | 뜻 | 무엇을 해야 하나 |
|---|---|---|
| **치명** | 현재 출력 어디에도 없음. 또는 이전 출력에만 있음 | 원고를 고칠지, 번들에 빠진 파일이 있는지 확인 |
| **경고** | 백분율↔비율 환산으로만 맞음 / 어느 값을 반올림한 건지 확정 불가 / 우연 매칭 의심 | 단위·자릿수를 눈으로 한 번 확인 |
| **정보** | 출처 확인됨 (파일·행·열 표시) | `대조표.csv` 에서 근거 확인 |

## 4. 만들어지는 파일

| 파일 | 언제 보나 |
|---|---|
| `출처대조.md` | 전체 리포트. 논문 재현성 문단 초안(한/영)도 여기 |
| `문제목록.csv` | 치명·경고만 모아 놓은 할 일 목록 |
| `대조표.csv` | 숫자 하나하나의 판정과 출처 좌표. **건너뛴 숫자도 사유와 함께 전부** 들어 있어, "왜 이건 안 봤지?"를 직접 확인할 수 있습니다 |
| `요약.txt` | 한 화면 요약 |

엑셀에서 바로 열립니다(UTF-8 BOM).

## 5. 종료 코드 (스크립트에서 쓸 때)

| 코드 | 뜻 |
|---|---|
| 0 | 전부 출처 확인됨 |
| 1 | 치명 발견 |
| 2 | 경고만 있음 · 또는 입력·인자 오류 |
| 3 | 판정불가(대조 가능 숫자 부족 / 미매칭율 초과) — **1보다 우선** |

## 6. 자주 겪는 상황

**Q. 치명이 20건 넘게 떴습니다.**
번들 폴더를 잘못 지정했을 가능성이 가장 큽니다. 미매칭율이 30%를 넘으면 애초에 판정을 안 하고 멈추지만, 그 아래라도 리포트의 '가장 가까운 값'을 보세요 — 전혀 다른 값이면 폴더가 틀린 것입니다.

**Q. `.docx` 표가 안 읽힙니다.**
표가 이미지이거나 세로 병합이 많은 경우입니다. `--dump-text` 로 몇 개나 복원됐는지 확인하고, 안 되면 표만 CSV 로 내보내 `--outputs` 쪽이 아니라 원고 대체본으로 쓰세요.

**Q. p < 0.001 은 어떻게 대조하나요?**
부등호를 그대로 읽어 출력값이 0 초과 0.001 미만인지 봅니다. `p < 0.05` 처럼 **유의수준 선언**으로 보이는 표기는 건너뛰고 그 사실을 자백합니다.

**Q. 원고를 고쳐 주나요?**
아니요. 읽기 전용입니다. 어느 값이 맞는지는 사람이 판단해야 합니다.

## 7. 안 하는 것

- 산술 재계산(비율·p·GRIM) → `numcheck`
- 투고 형식·인용 참조 점검 → `draftcheck`
- 개정본·응답서 대조 → `revcheck`
- PDF 읽기 (v2 1순위), `.xls`·암호 워크북 읽기
- 값의 **의미** 판단 — "이 12.4 가 ISI 평균이 맞는가"는 확인하지 않습니다
