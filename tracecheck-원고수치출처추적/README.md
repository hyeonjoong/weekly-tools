# tracecheck — 원고 수치 출처 추적

원고(`.docx`/`.md`/`.tex`/`.txt`) 하나와 **분석 출력 파일 묶음**(CSV/TSV/JSON/XLSX/MD/TXT 가 든 폴더)을 함께 읽어, Abstract·Results·표·캡션에 적힌 숫자가 **실제로 그 출력 안에 존재하는지** 반올림 자릿수를 감안해 전수 대조하는 오프라인 CLI. 어느 출력에도 없는 숫자(= 출처 불명)와 **이전 출력에만 있는 숫자**(= 재분석 후 갱신 누락)를 찾아 파일·행·열까지 찍어 줍니다.

---

## 목적 / Why this exists

**한국어.** 데이터 락 후 통계 담당이 "3명이 PP 에서 빠져 재분석했습니다" 하고 새 출력 폴더를 보내옵니다. 목요일 오후, 투고 마감은 다음 주 월요일. 원고 Results 본문·초록·Table 2·그림 캡션에 흩어진 숫자가 **수백 개**인데, 그중 어느 것이 옛 분석에서 온 값인지 알 방법이 없습니다. 지금 하는 일은 새 CSV 를 열어 놓고 Ctrl+F 를 200번 누르는 것이고, 40분쯤 지나면 집중력이 끊겨 "표는 통계 담당이 다시 붙였으니 괜찮겠지" 하고 본문만 훑게 됩니다. **그래서 초록의 평균 하나가 옛 값으로 남습니다.** 리뷰어도 에디터도 저널 조판도 이걸 못 잡습니다 — 잡히는 건 게재 후 누가 표와 본문을 대조했을 때입니다. tracecheck 는 그 대조를 결정론적으로, 전수로, **몇 개를 못 봤는지 자백하면서** 대신 합니다.

**English.** After database lock, the statistician re-runs the analysis and sends a new output folder. The manuscript contains hundreds of numbers scattered across the abstract, results text, tables and figure captions, and there is no way to tell which of them came from the *previous* run. The usual fallback — Ctrl+F, two hundred times — fails silently: attention runs out long before the numbers do, and one stale mean survives in the abstract. tracecheck reads the manuscript and the analysis-output bundle together and checks, exhaustively and reproducibly, that every reported number actually exists in the outputs — reporting the file, row and column where it was found, and confessing how many numbers it did not check and why.

**누구에게 / when to reach for it.** 임상·약학 연구자가 (1) 재분석을 받은 직후, (2) 투고·리비전 직전 최종 점검에서, (3) 공저자가 표를 갈아 끼운 뒤 본문과 어긋났는지 확인할 때. 유효성 데이터가 아니라 **이미 만들어진 분석 산출물 파일**만 있으면 됩니다.

**이 저장소의 다른 툴과의 경계.**

| 툴 | 답하는 질문 | tracecheck 와의 차이 |
|---|---|---|
| `numcheck` | "원고 안의 숫자들끼리 산술이 맞나?" | numcheck 는 **원고 밖을 보지 않습니다.** 옛 분석 결과가 내부적으로 정합적이기만 하면 GRIM 도 p 재계산도 전부 통과합니다 — 그 숫자들은 *한때 진짜였기* 때문입니다. tracecheck 는 원고 **밖**(분석 출력)을 보고, 산술은 한 줄도 재계산하지 않습니다. |
| `draftcheck` | "투고 형식·한도·인용 참조가 맞나?" | 값의 출처는 보지 않습니다. |
| `revcheck` | "개정본이 응답서대로 고쳐졌나?" | 원고 3종끼리 비교합니다. 분석 출력은 읽지 않습니다. |
| `citecheck` | "DOI 가 실존하나?" | 참고문헌 영역입니다. |

> **경계를 지키는 강제 장치:** `--outputs` 없이 실행하면 **아무 판정도 하지 않고 exit 2** 로 종료합니다. 번들 없이 도는 순간 이 툴은 numcheck 의 열등한 재탕이 되기 때문입니다.

## 실제 명령과 실제 출력

### 1) 결함 3건이 심어진 예제 (번들 예제 그대로 재현됩니다)

```bash
tracecheck examples/flawed/원고.md \
  --outputs examples/flawed/분석출력_2026-08-18/ \
  --previous examples/flawed/분석출력_2026-08-03/ \
  --out-dir 출처대조결과
```


### 2) 원고와 출력이 일치할 때 — **조용해야 합니다**

```bash
tracecheck examples/clean/원고.md --outputs examples/clean/분석출력_2026-08-18/
```

```
  대조 결과      매칭 34 · 미매칭 0  (미매칭율 0.0%, 임계 30% 이내)
…
[치명] 0건 — 없음

[경고] 0건 — 없음

[정보] 매칭 34건 → 대조표.csv 참조

판정: 대조 대상 34개 전부 출처 확인됨. 종료 코드 0
```

(`…` 는 커버리지 자백 블록과 `--previous` 미지정 안내를 줄인 자리입니다.)

이 예제(“크라잉울프 테스트”)를 **다른 기능보다 먼저** 만들었습니다. 정상 원고에서 '치명 30건'이 뜨는 체커는 한 번 열리고 버려지기 때문입니다.

### 3) 번들 폴더를 잘못 지정했을 때 — 치명 200건 대신 멈춥니다

```
[판정불가] 미매칭율이 100.0% 로 임계(30%)를 넘습니다 — 이 번들이 이 원고의 분석 결과가 아닐 가능성이 높습니다(폴더를 잘못 지정한 경우가 가장 흔합니다). 치명 목록을 쏟아내지 않고 멈춥니다.

판정: 판정불가. 종료 코드 3
```

### 4) 먼저 무엇을 대조 대상으로 뽑는지 보고 싶을 때

```bash
tracecheck 원고.docx --dump-text
```

절 분류와 표 셀 복원이 이 원고에서 실제로 되는지 30초 만에 확인하는 진단 모드입니다(대조는 하지 않음). 목록에 인용값·용량이 섞여 나오면 `--sections` 로 범위를 좁히세요.

## 산출물

`--out-dir` 안에만 만듭니다(기본 `출처대조결과/`).

| 파일 | 내용 |
|---|---|
| `출처대조.md` | 리포트 전문 + 커버리지 자백 + 읽지 못한 파일 + 재현성 문단 초안(한/영) |
| `문제목록.csv` | `줄번호,절,등급,원문,추출값,판정,설명,권고` — 치명·경고만 |
| `대조표.csv` | `줄번호,절,원문,추출값,정규화값,판정,매칭수,매칭방식,출처파일,출처위치,출처원문값,반올림자릿수,등급,설명` — **건너뛴 숫자도 사유와 함께 전부** |
| `요약.txt` | 한 화면 요약 |

CSV 는 엑셀에서 바로 열리도록 UTF-8 BOM 으로 씁니다. 수식 인젝션(`=cmd|...`)은 `'` 로 무력화하되, `-3.47` 같이 **숫자로 읽히는 값은 건드리지 않습니다**(그래야 대조표에서 정렬·계산이 됩니다).

## 종료 코드

| 코드 | 의미 |
|---|---|
| 0 | 대조 대상 전부 출처 확인됨 |
| 1 | 치명 발견(출처 없음 / 구버전 잔존) |
| 2 | 경고만 있음 · 또는 입력·인자 오류(`--outputs` 미지정 포함) |
| 3 | 판정불가 — 대조 가능 숫자가 `--min-comparable`(기본 5) 미만, 미매칭율이 `--max-unmatched`(기본 30%) 초과, 또는 원고·번들 처리 불가 |

**3 은 1 보다 우선합니다.** 대조율이 낮은 상태에서 낸 치명은 신뢰할 수 없기 때문입니다.

## 주요 옵션

| 옵션 | 기본값 | 설명 |
|---|---|---|
| `--outputs 폴더` | (필수) | 현재 분석 출력 번들. 여러 번 지정 가능 |
| `--previous 폴더` | 없음 | 재분석 **이전** 번들. 이 툴의 킬러 기능이므로 되도록 함께 지정하세요 |
| `--sections` | `abstract,results,tables,captions` | 대조할 절. `all`/`methods` 등으로 확장 |
| `--max-unmatched` | 30 | 미매칭율이 이 %를 넘으면 exit 3 |
| `--min-comparable` | 5 | 대조 가능 숫자가 이보다 적으면 exit 3 |
| `--chance-matches` | 12 | 같은 값이 번들 N곳 이상 + 자릿수 낮음 → 우연 매칭 경고 |
| `--max-files` / `--max-bytes` / `--max-cells` | 500 / 20MB / 200,000 | 번들 읽기 상한(초과분은 '읽지 못한 파일'로 자백) |
| `--dump-text` | | 대조 없이 추출 목록만 (번들 불필요) |
| `--no-files` | | 파일을 만들지 않고 화면에만 |

## 어떻게 판정하는가 (요약)

1. **절 분류** — 헤딩을 읽어 Abstract/Introduction/Methods/Results/Discussion/References 로 나눕니다. 기본 대조 대상은 **Abstract · Results · 표 · 캡션**뿐입니다. Introduction·Discussion 은 선행연구 인용값이 대부분이라 크라잉울프의 원천입니다.
2. **건너뜀 규칙(12종)** — 연도 / 인용 표기 내부 / 표·그림 번호 참조 / 유의수준 관용구(`p < 0.05`, `95% CI` 의 95) / 척도 범위 선언 / 시점·기간 표기(`8주`, `week 8`, `at 8 weeks`, `12 months`) / 날짜·시각 / 배정비(`1:1`) / 척도·진단명 안의 숫자(`PHQ-9`, `SF-36`, `ICD-10`) / 본문의 자명한 소정수(0·1·2 — **표 셀 안이면 대조**) / 순수 식별자(NCT·IRB·DOI) / 자릿수 상한 초과. **전부 사유별로 세어 리포트에 자백**합니다 — 조용히 빼는 규칙은 하나도 없습니다.
3. **반올림 인지 매칭** — 원고가 소수 `d`자리면 출력값을 `d`자리로 반올림해 비교하되, half-up · half-even · half-down · 부동소수 반올림을 **모두 허용**합니다(`12.35` → `12.4` 도 `12.3` 도 인정). 없는 출처를 있다고 하는 것보다 있는 출처를 없다고 하는 쪽이 훨씬 비싸기 때문입니다.
4. **등급** — 치명(현재 번들에 없음 / 이전 번들에만 있음) · 경고(백분율 환산으로만 매칭, **부호만 다름**, 자릿수 상충, **라벨 문자열에서만 매칭**, 우연 매칭 의심) · 정보(출처 확인).
5. **커버리지 자백** — 리포트 첫 블록에 추출·대조·건너뜀(사유별)·매칭·미매칭·미매칭율이 반드시 나옵니다. **이 블록이 없으면 리포트 자체를 출력하지 않습니다**(코드로 강제, 테스트로 고정).

## 한계 — 솔직하게

이 목록은 짧게 쓸 수 있었지만 그러지 않았습니다. 체커가 무엇을 **안 하는지** 모르면 '이상 없음'이 무슨 뜻인지 알 수 없습니다.

- **부호를 무시하지 않습니다 — 대신 경고로 알려 줍니다.** 원고가 "14.6분 **감소**"라고 쓰고 출력이 `-14.63` 이면 값으로는 다릅니다. 이걸 치명으로 올리면 실제 원고에서 거짓 치명이 쏟아지므로(적대적 검토에서 거짓 치명 18건 중 13건이 이 원인이었습니다) **경고로 내리고 부호가 뒤집히지 않았는지 물어봅니다.** 방향이 진짜로 뒤집힌 사고는 이 경고를 읽어야 잡힙니다.
- **번들의 라벨 문자열 안에 있는 숫자도 색인합니다.** `phq9_change`, `week8`, `sf36_pcs` 같은 열 이름에서 9·8·36 이 나옵니다. 값이 **오직 그런 자리에서만** 매칭되면 '출처 확인'이 아니라 **경고(라벨문자열매칭)** 로 내립니다. 단위가 붙은 진짜 값(`12.4mmHg`)은 값으로 봅니다.
- **경고는 큰 번들에서 흔합니다.** 수치 셀이 수백 개면 `11.6` 이 `11.61`·`11.62` 두 곳에서 나오는 일이 자주 생기고, 그때마다 '자릿수 상충' 경고가 붙습니다. 이건 오작동이 아니라 설계이며(어느 출력에서 왔는지 확정할 수 없다는 뜻), 종료 코드도 1이 아니라 2입니다. 치명만 먼저 보고 경고는 `문제목록.csv` 에서 훑으세요.
- **값만 봅니다. 의미는 보지 않습니다.** `12.4` 가 ISI 평균인지 나이 평균인지 추정하지 않습니다. 라벨 매칭을 시작하면 LLM 의 열등한 복제품이 됩니다. 대신 매칭된 **곳의 개수**(`매칭수`)와 **좌표**를 남겨, 20곳에서 매칭된 값은 사람이 의심할 수 있게 합니다.
- **우연 매칭이 있을 수 있습니다.** 번들에 수치 셀이 수천 개면 `0.02` 같은 값은 어디에나 있습니다. `--chance-matches` 로 경고를 내지만, 낮은 자릿수 값의 '출처 확인'은 근거가 약합니다. 그래서 출처 위치를 항상 함께 적습니다.
- **산술을 재계산하지 않습니다.** 비율·p·GRIM 은 `numcheck` 영역이고, 겹치는 코드는 0줄입니다.
- **단위를 환산하지 않습니다.** min↔h, ms↔s 는 매칭 실패로 둡니다. 환산을 시작하면 매칭이 헐거워져 '출처 확인됨'이 의미를 잃습니다.
- **PDF 를 읽지 않습니다 — v2 1순위.** 표준 라이브러리만으로 만드는 PDF 파서는 반쯤만 동작하고, 반쯤 되는 파서는 커버리지 자백을 거짓말로 만듭니다. `numcheck`·`revcheck` 와 같은 판단입니다.
- **`.xls`, 암호 걸린 워크북, 이미지 안의 표는 읽지 못합니다.** 대신 못 읽은 파일의 개수와 사유를 반드시 자백합니다.
- **어느 파일이 '정본'인지 추론하지 않습니다.** 파일 수정시각으로 신·구를 판단하지 않습니다 — 신·구는 `--outputs`/`--previous` 로 사람이 선언합니다.
- **원고를 고쳐 주지 않습니다.** 읽기 전용이고, 옛 값을 새 값으로 치환하지 않습니다. 어느 값이 맞는지는 연구자의 판단입니다.
- **`.docx` 표 파싱은 완벽하지 않습니다.** 병합 셀(gridSpan)은 열 번호를 밀어 좌표를 유지하지만, 세로 병합·중첩 표·이미지 표는 좌표가 어긋나거나 아예 안 읽힙니다. 변경내용 추적이 켜진 파일은 **개정 후(삽입 반영·삭제 제거) 상태**로 읽습니다.
- **고찰(Discussion)은 기본 대조 대상이 아닙니다 — 그 따름결과에 주의하세요.** 고찰 첫 문단에 주요 결과를 다시 적는 것은 거의 관행인데, 기본 설정에서는 그 숫자를 보지 않습니다(선행연구 인용값이 대부분이라 크라잉울프의 원천이라서). **치명을 다 고친 뒤 `--sections abstract,results,tables,captions,discussion` 으로 한 번 더 돌리세요.**
- **저자가 직접 계산한 숫자는 '출처 없음'으로 잡힙니다.** `88+84=172`, `172/274=62.8%`, `274×20=5,480` 처럼 원고에서만 만들어진 값은 어느 출력 파일에도 없습니다. 정의상 맞는 판정이지만 실무에서는 소음으로 읽힙니다 — 자동으로 지우면 진짜 결함도 같이 지워지므로 그대로 둡니다(적대적 검토 실측: 원고 숫자 187개 중 4건).
- **큰 번들은 메모리를 씁니다.** 수치 셀 20만 개(`--max-cells` 기본값) 색인에 약 360MB · 4.7초. 더 큰 번들은 `--max-cells` 를 조정하면 되고, 잘린 사실은 '읽지 못한 파일'에 자백됩니다.
- **번들에 파일이 없으면 이 툴은 입력이 없습니다.** 분석이 SPSS 화면 안에서만 살고 파일로 저장된 적이 없다면 쓸 수 없습니다(그래서 v1 이 `.txt` 붙여넣기 출력까지 받습니다).
- **날짜·인코딩**: 원고 인코딩은 UTF-8 → CP949 → EUC-KR 순으로 시도하고, 판별 실패 시 그 사실을 리포트에 적습니다.

## 개인정보·보안

- **완전 오프라인.** `socket`/`urllib`/`http`/`subprocess` 를 import 하지 않으며, 이 사실을 소스 AST 를 파싱하는 테스트(`tests/test_offline.py`)로 매 실행 검증합니다.
- 입력은 읽기 전용입니다(테스트가 실행 전후 바이트와 mtime 을 비교합니다). 산출물은 `--out-dir` 안에만 만들고, 입력 파일을 덮어쓰게 되는 경로는 거부합니다.
- 산출물 폴더가 번들 폴더 **안**이면 거부합니다(다음 실행 때 자기 리포트를 대조하게 되므로).
- 심볼릭/하드 링크로 들어온 원고는 거부하고, 번들 안의 심볼릭 링크는 읽지 않고 자백합니다.
- `.docx`/`.xlsx` 는 zip 폭탄(항목 수·해제 크기·압축률)과 XML 엔티티 폭탄(DTD 선언), zip 경로 탈출을 열기 전에 차단합니다.
- 오류 메시지에 원고 본문을 넣지 않습니다(파일명과 사유만).
- 예제 데이터는 **전부 합성**입니다. 실제 환자 자료·실제 원고는 들어 있지 않습니다.

## 테스트

```bash
cd tracecheck-원고수치출처추적 && python3 -m pytest -q
```

260개 테스트. 반올림 경계값은 손으로 계산해 못 박아 두었고(`tests/test_match.py`), 예제 두 벌은 인수 기준 그대로 검증합니다 — clean 은 치명 0·경고 0, flawed 는 심어 둔 **정확히 그 3건**. `tests/test_hardening.py` 는 적대적 검토 2라운드에서 실제로 재현된 결함 40여 건의 회귀 테스트입니다(지수 표기 `1.5e-05`, CSV 안의 줄바꿈, UTF-16 로 숨긴 엔티티 폭탄, 1MB 한 줄 원고, `<.001` 표기 등).

적대적 서브에이전트 병렬 하드닝 기록은 `HARDENING.md` 에 있습니다.
