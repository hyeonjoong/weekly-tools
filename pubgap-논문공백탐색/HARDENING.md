# HARDENING & 개선 로그 — pubgap

이 문서는 pubgap 도구를 **더 유능하고 견고하게** 만들기 위해 수행한 기능 개선과
적대적(adversarial) 하드닝 라운드를 날짜별로 기록합니다.

> 읽는 법: 아래의 구체적 수치(메모리·소요시간·실제 PubMed 편수 등)는 **하드닝 당시
> 리뷰어가 수정 전 코드/네트워크에서 실측한 값**입니다. 수정 후에는 그 조건이 사라져
> 저장소에서 그대로 재현되지 않습니다 — 회귀 테스트로 고정한 것은 *동작*(거부하는가,
> 어떤 종료코드인가)이지 그 숫자가 아닙니다.

## 2026-07-30 — 심층 개선 2차 + 하드닝 라운드 1–3

### A. 기능 개선 / 확장

**크래시 수정 — RIS 입력이 아예 동작하지 않았다**
- `records.py` 의 `parse_records()` 는 RIS 를 감지하면 `parse_ris()` 를 호출했지만
  **그 함수가 정의돼 있지 않았다**(NameError). EndNote/Zotero/Scopus 에서 내보낸 RIS 를
  주면 무조건 실패했다. 실제 RIS 파서를 구현: `TY`/`ER` 레코드 분리(ER 누락 시 다음 TY 로
  복구), 이어짐 줄 결합, 태그 간격 흔들림 허용, 제목/저널/연도 태그 우선순위,
  숫자 ID → PMID / 없으면 DOI 식별, `TY`·`M3` → PublicationType 매핑.
- KW 해석은 **코퍼스 단위**로 한 번만 결정한다(레코드마다 다르게 해석하면 같은 개념이
  어떤 논문에선 주제, 어떤 논문에선 키워드로 갈려 공동출현 통계가 조용히 깨진다).

**새 입력 형식 — CSV/TSV(Scopus·WoS·Covidence·엑셀 편집본)**
- 헤더 별칭 정규화(`Source title`/`Journal/Book`/`Publication Year`…), 구분자 자동 추정
  (줄마다 개수가 **일정한** 후보 우선), 헤더 앞 안내문 줄 건너뛰기, 열 수가 들쭉날쭉한 행,
  `2019.0`·`Mar-2019`·`2020년 3월` 연도 표기, 다중값 셀(`;`/`|` 만 — MeSH descriptor 자체가
  쉼표를 포함하므로), 구분자 뒤 공백(`skipinitialspace`).
- 번들 예시 `examples/sleep_export.csv` 추가 — 일부러 지저분하게 만든 CSV 가 원본 XML 과
  **첫 줄(입력 경로 라벨)을 뺀 전부가 동일한** 리포트를 내는지 회귀 테스트로 고정.

**죽어 있던 핵심 기능을 되살림 — 근거 공백(연구 설계 축)**
- `evidence_profile`/`topic_evidence` 는 구현돼 있었지만 `build_report` 가 호출하지 않아
  **어떤 출력에도 나타나지 않았다**. 리포트 절·JSON 키·CSV 표로 전면 노출.
- "논문은 많은데 RCT·임상시험은 유의하게 적은 주제 = 시험을 설계할 자리".

**공백 통계 심화**
- `부족(deficit) = 기대−관측` — 연구자 단위의 효과크기('있었어야 하는데 없는 편수').
  **기본 정렬을 `deficit` 으로 변경**(문서는 이미 deficit 을 권하는데 기본은 lift 라 모순).
- Jaccard·Ochiai(cosine)·nPMI 추가(JSON/CSV), `--gap-sort {lift,deficit,q,expected,npmi}`.
- 공백의 **시간 추이**: 동시등장을 초기/최근으로 나눠 구간 크기로 정규화해 비교
  → `완전공백`/`메워짐`/`벌어짐`/`판단불가`.
- **PubMed 검증 링크 2종**(MeSH 색인 기준 / 제목·초록 자유어 기준)을 각 공백에 첨부.
  두 결과 수가 크게 다르면 그 공백은 색인 artifact — 가짜 후보를 가장 싸게 거르는 방법.
- **Theil–Sen 기울기** 추가(로버스트). CAGR 은 양끝 한 해에 휘둘려 평평한 분야를
  "연평균 −17%" 로 보고했다 — 헤드라인에서 내리고 JSON 에만 남김.

**새 옵션**: `--gap-sort`, `--exclude-term`/`--exclude-terms-file`, `--top-evidence`,
`--no-evidence`, `--csv-section {gaps,yearly,journals,mesh,emerging,declining,evidence,topic-evidence}`,
`--no-meta`. 리포트 하단에 **재현용 실행 정보**(버전·시각·입력 sha256·모든 분석 옵션).

### B. 하드닝 라운드 1 — 병렬 리뷰어 5종(정확성/엣지케이스/유용성/문서정직성/테스트·보안)

리뷰어 중 하나는 **실제 PubMed 에 질의**해 데모 데이터가 가리고 있던 결함들을 드러냈다.

**[HIGH] 통계가 실제로 틀렸던 것**
- **공백 분모에 주제어 없는 논문이 포함**: `n = len(articles)` 라, MeSH 가 아직 안 붙은
  논문(실제 조회에서 30~40%)이 기대값을 낮추고 lift 를 부풀려 **진짜 공백을 가렸다**.
  실측: 같은 쌍의 p 가 0.069 → 0.012 로 바뀌어 결론이 뒤집혔다. → 분모를 주제어 보유
  논문으로 한정.
- **설계 커버리지가 항상 ~100%**: `pub_types` 가 비었는지로 '설계 미상'을 판정했는데,
  PubMed 레코드는 사실상 전부 `Journal Article` 을 단다. 그래서 "설계 미상은 분모에서
  제외했다"고 말하면서 실제로는 44% 의 미분류 논문을 분모에 두고 개입연구 비율을
  희석했다. → `evidence_tier(...) != 'other'` 로 판정, `n_unknown` 보고, tier 표에서
  'other' 제거.
- **개입연구 판정이 대표 tier 기반**: `Meta-Analysis + RCT` 논문이 개입연구에서 누락됐다.
  → 설계 태그의 **존재 여부**로 판정(`is_interventional`).
- **관찰연구가 통째로 '설계 미상'**: NLM 은 코호트·후향·환자대조 연구를 PublicationType
  이 아니라 **MeSH** 로 색인한다. → PublicationType 에 설계 신호가 없을 때만 연구설계
  MeSH 를 보조 신호로 사용. 이 신호는 체크 태그를 떼기 **전** 에 읽도록 리포트 경로 수정.

**[HIGH] 잘린 표본을 추세로 보고**
- `esearch` 가 `<Count>` 를 버려, 검색 결과 2,431편 중 최신 300편만 받고도 그 연도 분포를
  분야 추세로 보고했다 — 실측에서 **"48.8배 성장"** 이라는 순수 절단 산물이 나왔고,
  부상 주제 표는 모든 행이 `초기 0` 이었다. → `fetch_articles()` 가 전체 편수를 함께
  반환하고, 잘렸으면 리포트가 그 사실을 명시하며 **추세·성장률·부상/쇠퇴를 생략**한다.

**[HIGH] 리포트가 스스로의 기준을 어겼다**
- q ≤ 0.05 를 권하면서 **q=1.000 짜리 후보를 굵게 추천**했다. 게다가 기본 설정에서는
  m≈49 라 q ≤ 0.05 가 **산술적으로 도달 불가능**했고, 빈 결과일 때의 안내는
  `--gap-min-expected` 를 낮추라고 권했는데 그러면 m 이 늘어 **q 는 더 나빠진다**.
  → 다중검정 예산(m)과 필요한 p 를 표시, 도달 못 하면 그렇다고 말하고, 추천에 경고를
  달고, 안내 문구를 올바른 방향으로 수정.
- 근거공백 표 제목은 "개입연구가 비어 있는 주제"인데 상위 K 주제를 전부 실어,
  개입연구가 **과밀한** 주제가 q=0.000 으로 가장 눈에 띄는 자리에 있었다. → 진짜 공백만
  본문에, 과밀 주제는 접힘 블록으로 분리.
- `코퍼스 평균` 열은 실제로 leave-one-out 비교군 비율이었다(본문의 39% 와 표의 58% 가
  같은 이름으로 3줄 간격) → `그 외 논문` 으로 정정.
- 저자 키워드 폴백을 쓰고도 리포트는 "MeSH 주제어 보유", "MeSH 기반 휴리스틱"이라고
  말했다 → `topic_source` 를 리포트까지 전달해 정직하게 표기.

**[HIGH] 방법론 MeSH 가 결과를 점령**
- 실제 조회에서 상위 15개 주제 중 7개가 주제가 아니었고(`Treatment Outcome`,
  `Randomized Controlled Trials as Topic`, `Surveys and Questionnaires`…), 최상위 추천이
  `RCTs as Topic × Surveys and Questionnaires` 였다. → `METHOD_TAGS` + `… as Topic`
  접미사 규칙으로 기본 제외.
- 가교(ABC)는 원시 편수로 순위를 매겨 **항상 검색어 자체가 1위**였다("A는 당신이 검색한
  그 단어를 통해 B와 연결됩니다"). → `lift(A,C)×lift(C,B)` 로 순위, 유병률 80% 초과·
  지지도 2편 미만 제외.

**[HIGH] 크래시·오작동(엣지케이스 리뷰어)**
- `--out` 이 예외 보호 밖에 있어 디렉터리/없는 경로/권한 오류 시 **원시 트레이스백 + rc 1**
  → 한국어 오류 + rc 2.
- **UTF-16 입력이 조용히 틀린 리포트를 냈다**: latin-1 폴백이 어떤 바이트열도 '성공'시켜,
  엑셀의 '유니코드 텍스트' 내보내기가 NUL 섞인 mojibake 로 파싱되고(2편 → 3편, 연도·PMID
  전부 유실, 출력에 NUL 바이트) rc 0 이었다. → BOM 우선 판별.
- **gzip 폭탄**: 509KB 파일이 1.6GB RSS 를 잡았다(279바이트 → 50MB 중첩 폭탄도 확인).
  → 증분 해제 + 512MB 상한.
- **입력 파일을 두 번 읽음**: FIFO·프로세스치환(`--from-file <(...)`)이 영구 정지했고 큰
  파일 I/O 가 두 배였다. → 한 번만 읽고 해시까지 재사용.
- `--gap-top-k` 상한 없음 → O(K²·N) 폭발(K=200·2만편 = 229초) → 상한 200 + 안내.
- 주제에 `|` 가 들어가면 **Markdown 표가 통째로 밀렸다**(RIS `KW - Sleep | Wake` 로 실제
  발생, 오류 없이 조용히 틀린 표) → 셀 이스케이프 + 모든 표의 칸 수 불변식 테스트.
- `_extract_mesh` 등이 리스트 멤버십으로 중복을 검사해 **주제 수에 대해 2차**
  (200편×5000 MeSH = 20.5초, 그중 파싱만 21.1초) → set 사용, 8배 이상 단축.
- 연도 정규식이 `1719878400`(epoch)에서 1987 을, `S32019456` 에서 2019 를 뽑아 **없는
  발행연도를 만들어** 추세검정·CAGR·구간분할에 밀어 넣었다 → 숫자열 경계 lookaround.
- 형식 판별 실패가 조용히 0편 → "검색어를 바꿔 보세요"(진짜 원인 은폐) → 명시적 오류.
- CSV 필드 128KiB 상한(초록 포함 내보내기에서 흔함) 원시 영문 오류, 네임스페이스 XML 0편,
  `.tsv` 확장자가 내용 판별을 덮어씀, 헤더 줄 재출현이 유령 논문, `ER  -` 만 있는 파일이
  1편으로 계수 — 모두 수정.

**[MEDIUM] 통계 위생**
- `_classify_gap_trend` 가 **1편 차이로 방향을 뒤집고**, 동시등장 0/0 을 '→ 유지'로 위장했다
  (가장 강한 신호를 중립으로 보이게) → `완전공백` 상태 + 3편 최소 근거 + 연도 미상 가드.
- 부상/쇠퇴 p 에 다중검정 보정이 없었다(문서는 FDR 을 설파하면서) → BH q 추가 + 선택편향
  명시.
- 성장 배수가 **창 길이 차이를 성장으로 착각**(2016–2026, split 2021 → 초기 5년 / 최근 6년;
  완전히 평평해도 1.2배) → 연평균 편수 기준으로 정규화.
- `growth_summary({})` 가 정상 경로와 **다른 키 집합**을 반환(JSON 소비자 파손) → 통일.
- Fisher/초기하가 음수 칸에 대해 조용히 `0.0`(=최대 유의)/`1.0` 을 반환 → 명시적 예외.

**[보안]** gzip 폭탄 상한, HTTP 응답 크기 상한(256MB), `<!ENTITY>` 가드를 네트워크 경로와
**공유**(예전엔 파일 경로에만 있었다), 리다이렉트를 **https + NCBI 호스트**로 제한,
예외 메시지의 `api_key`/`email` **마스킹**, CSV 수식 주입 방어, `--save-xml` 오류 처리.

**[문서]** README/사용법의 계산식 표를 구현과 1:1 대조해 정정, 한계 절에 미공개 사항 8건

### C. 하드닝 라운드 2 — 새 패널 5종(라운드 1 코드에 대한 재공격)

라운드 1에서 **새로 넣은 코드**에서 결함이 나왔다. 고친 것을 다시 검증받는 것이 왜
필요한지 보여 준다.

**[CRITICAL] 내가 인쇄한 수식이 틀렸다 — `q ≥ p×m`**
- 라운드 1에서 '다중검정 예산을 솔직히 밝히자'며 넣은 문구가 **수학적으로 거짓**이었다.
  BH 는 `q_(i) = min_{j≥i}(m·p_(j)/j)` 이므로 q 는 `p×m` 보다 **작을 수 있다** — 그리고
  번들 예시의 네 행이 전부 반례였다(p=0.008·m=9 → p×m=0.069 인데 q=0.034). 게다가 그
  거짓 하한으로 '필요한 p ≤ 0.0056' 을 역산해 인쇄했는데, 바로 위 표에 p=0.0076 짜리가
  q=0.034 로 기준을 통과해 **리포트가 스스로를 반증**하고 있었다.
  → 하한 주장과 역산을 모두 제거하고, **실제로 달성한 최소 q** 만 보고한다.

**[CRITICAL] 완전한 코퍼스를 '잘렸다'고 표시**
- 절단 판정을 `total_available > len(articles)` 로 했는데 `len(articles)` 는 **연도 필터
  적용 후** 값이다. 그래서 `--min-year` 로 기간을 좁힌 **완전한** 표본까지 '최신순으로
  잘림' 으로 찍히고, 추세·성장·부상/쇠퇴가 통째로 사라졌으며, 안내문은
  "`--min-year/--max-year` 로 기간을 좁히세요" — 사용자가 방금 한 일을 다시 권했다.
  → 실제로 **받아온 편수(n_fetched)** 와 비교하도록 수정.

**[HIGH] CSV 수식 주입 방어가 숫자 열을 매 행 망가뜨렸다**
- 접두 목록에 `-` 가 있어 음수 지표(`npmi`, declining 의 `delta`)가 **모든 행에서**
  `'-1.0000` 으로 나갔다. `float()` 는 예외를 던지고 pandas 는 object 로 읽는다 —
  스프레드시트/파이프라인용이라는 출력이 정작 파이프라인에서 못 쓰였다.
  기존 테스트는 헤더와 텍스트 주입만 봐서 놓쳤다.
  → 숫자로 파싱되는 값은 방어 대상에서 제외 + **모든 숫자 열을 float() 로 왕복**하는 테스트.

**[HIGH] BOM 없는 UTF-16 이 rc 0 으로 조용히 틀린 리포트**
- 라운드 1의 BOM 판별은 **BOM 이 있을 때만** 동작한다. BOM 없는 UTF-16 CSV 는 latin-1 로
  떨어져 유령 논문 1편이 생기고, PMID 전부 `?`, 연도 전부 유실, 출력에 NUL 바이트가
  찍힌 채 rc 0 이었다(`.nbib`/`.ris` 는 0편 파싱이 예외를 내 우연히 막혔다).
  → 디코드 후 **NUL 검사**로 형식·확장자와 무관하게 차단. BOM 판별 루프의 `break` 도
  `continue` 로 수정(UTF-16LE 가 `ff fe 00 00` 로 시작해 UTF-32 항목에 먼저 걸리면
  UTF-16 을 아예 시도하지 못했다).

**[HIGH] 압축 상한이 메모리를 못 막았고, 가드 자체가 DoS 였다**
- 512MB 상한을 통과하는 356KB `.gz` 가 **2.5GB RSS** 를 썼다(디코드 사본 + splitlines +
  Article 객체). 게다가 `fh.read(MAX+1)` 한 방 읽기가 703바이트 입력으로 1GB 를 잡았다.
  → 상한을 64MB 로 낮추고 청크 단위로 읽으며, 비압축 입력에도 같은 상한을 적용.
  (실측: 100MB 폭탄 → 99MB RSS 로 거부.)

**[HIGH] `pubgap … | head` 가 트레이스백 + rc 1**
- `print(output)` 이 예외 보호 밖이라 `BrokenPipeError` 가 그대로 노출되고, 종료코드가
  1('결과 없음')이 되어 래퍼 스크립트를 오도했다(`| true` 는 rc 120). → 안전한 출력 래퍼.

**[MEDIUM] 그 외**

### C-2. 하드닝 라운드 3 — 라운드 2에서 새로 넣은 코드의 결함

같은 패턴이 반복됐다: **직전 라운드에서 추가한 코드**가 다음 라운드의 주 결함원이었다.

**[MEDIUM] 검증 조회가 코퍼스와 다른 기간을 봤다**
- 전수 검증(`esearch_count`)에 날짜 필터를 안 걸어, `--years 10` 코퍼스에 대해
  **PubMed 전체 역사**의 편수를 세고 있었다(`--min-year/--max-year` 도 무시).
  결과적으로 1990년대에 활발했지만 최근 10년엔 비어 있는 조합이 'artifact' 로 판정돼
  **리포트가 다루는 기간에 대해서는 진짜인 공백이 버려졌다.** 문서와 리포트 본문 모두
  "같은 검색 제한 안에서"라고 말하고 있었으므로 명백한 거짓이었다.
  → `reldate/datetype` 전달 + 연도 범위는 `("YYYY"[dp] : "YYYY"[dp])` 절로 재현.
  (`--from-file --verify-gaps` 는 질의가 없어 전체 PubMed 를 모집단으로 쓴다 — 문서에 명시.)

**[MEDIUM] 검증 검색식에 주제어를 그대로 끼워 넣었다**
- `report.pubmed_pair_url` 은 따옴표를 제거하는데(그 이유까지 주석에 적혀 있다),
  새로 만든 `_mesh_clause` 는 하지 않았다. 저자 키워드에 `"` 가 있으면 인용이 조기
  종료돼 **최상위 OR** 가 만들어지고, 동시등장 편수가 개별 편수를 넘는 값(20M)이 나와
  진짜 공백이 artifact 로 폐기됐다. → 따옴표·제어문자 제거 + **`cab ≤ min(ca,cb) ≤ total`
  일관성 검사**(어기면 판정하지 않고 `unknown`).

**[MEDIUM] 층화 표집이 표본을 조용히 줄였다**
- 남은 자리를 **중복 제거 전** 개수로 계산해, 연도 경계에서 겹친 PMID 때문에
  6편을 채울 수 있는데 3편만 반환했다. → 중복 제거 후 예산 계산 + 이미 뽑은 것과도 대조.
- `retmax < 연수` 면 균등 할당이 1 로 고정돼 **가장 오래된 해들만** 뽑히고(층화도
  최신순도 아니다) 쓰지도 않을 요청을 연수만큼 보냈다. → 최신 연도부터 자른다.

**[MEDIUM] 층화의 전체 편수가 부풀려져 헛된 '절단' 판정**
- NLM 은 전자·인쇄 발행일을 모두 `pdat` 로 검색 가능하게 해서, 연말/연초에 걸친
  레코드가 두 해에 중복 계수된다. 연도별 Count 를 합산하니 **전수를 다 받아왔는데도**
  `truncated=True` 가 되어 추세·성장·Mann–Kendall·부상/쇠퇴가 통째로 사라졌다.
  → 전체 편수는 단일 `esearch` 의 `<Count>` 로 얻는다.

**[LOW] 표시 문구·판정의 자기모순**
- 기본 표집을 층화로 바꿔 놓고 절단 경고는 여전히 "최신순으로 잘림", "**최신 논문만**
  받았으므로" 라고 말했다(정반대) → 문구 수정.
- "모두 artifact 입니다" 라고 경고한 **바로 다음 줄**에서 그중 하나를 추천했다 →
  그 경우 제안·검증·가교 블록을 통째로 생략.
- `_is_numeric` 이 `-inf`/`-nan` 을 숫자로 보고 CSV 방어에서 면제했는데, 엑셀은 이를
  `-` 로 시작하는 수식으로 읽어 `#NAME?` 를 낸다 → 유한한 값만 면제.

정정: 리뷰어가 재확인한 것 — `expected=ca·cb/total`·`lift=cab/expected` 는 표본 통계의
정확한 일반화이고, `_combine()` 괄호 처리·`all[sb]` 폴백·0 분모 가드·`_gunzip_limited`
청크 회계(경계값 포함)·`_YEAR_RE` 의 모든 PubMed 날짜 형식·`_classify_gap_trend` 의
다섯 상태 도달 가능성은 전부 무결했다.

**[HIGH] 문서에 적힌 안전장치가 실제 경로에 없었다**
- README 는 "입력 파일 64MB … 넘으면 rc 2 로 거부" 라고 했지만, 그 가드는
  `load_articles()` 안에 있었고 **CLI 는 그 함수를 쓰지 않았다**(직접 `read_bytes()`).
  84MB 파일이 rc 0 으로 307MB RSS 를 쓰며 통과했다. 회귀 테스트조차 `load_articles` 를
  직접 불러서 초록이었다. → 공용 `read_source()` 로 두 경로를 합쳤다.

**[HIGH] 절단 안내가 불가능한 방법을 권했다**
- "`--min-year/--max-year` 로 기간을 좁혀 전수를 받으세요" — 그런데 이 두 옵션은 조회
  **이후** 필터라, 이미 잘린 표본을 더 줄일 뿐 절대 늘릴 수 없었다. 라운드 2는 절단
  *판정*만 고쳤고 *안내*는 그대로였다. → `--min-year/--max-year` 가 **esearch 질의 자체**
  (`mindate/maxdate`)를 제한하도록 바꿔, 안내가 실제로 성립하게 만들었다. 덤으로
  '고정된 과거 구간의 전수' 라는 워크플로가 처음으로 가능해졌다.

**[HIGH] 고쳤다고 적어 놓고 두 곳에 남아 있던 거짓 수식**
- 라운드 2에서 제거했다고 기록한 `q ≥ p×m` 이 `사용법.md` 와 `count_gap_tests` 독스트링에
  그대로 있었다(사용자가 실제로 읽는 파일 쪽에). → 제거.

**[MEDIUM] 재현 정보가 재현에 부족**
- `--sample`(어떤 300편을 받았는지를 결정하는 핵심)과 `--verify-gaps` 가 실행정보에
  없었고, 수집해 둔 `years`·`max_records`·`total_available` 은 Markdown 렌더러가
  버리고 있었다. → 조회 범위 줄 추가, 두 옵션 기록, **기본값과 다른 옵션만** 강조
  (16개 기본값 나열은 아무도 읽지 않는다).

**[HIGH] 데이터에서 온 연도 하나가 도구를 멈췄다**
- XML 의 `<Year>99999</Year>`(오타·손상)를 그대로 받아, 조밀 시계열이 10만 원소가 되고
  Mann–Kendall(O(n²))이 사실상 멈췄다(실측: `20201` → 22초, `99999` → 45초+ 무응답).
  CLI 는 사용자 입력 연도를 1500~2200 으로 검증하면서 **데이터에는 같은 검증을 안 했다**.
  → `plausible_year()` 로 데이터 경로도 동일 범위로 제한(범위 밖은 '연도 미상').

**[MEDIUM] 문서에 없는 종료코드·트레이스백이 stdio 에서 남아 있었다**
- `저장 완료:` 와 `--count-only` 는 여전히 bare `print()` 라, 파이프가 닫히면 **rc 120**
  (문서의 0/1/2/3 어디에도 없다). → 모든 stdout 쓰기를 같은 래퍼로.
- 닫힌/쓸 수 없는 stdout(`>&-`, 읽기전용 fd)은 `BrokenPipeError` 가 아니라 `OSError`/
  `AttributeError` 라 트레이스백이 그대로 나오고 **rc 1**('결과 없음')이 됐다 — 리포트는
  정상 생성됐는데 래퍼는 '빈 결과'로 읽는다. → 예외 범위 확대 + `stdout is None` 가드.

**[MEDIUM] 기본 표집 경로에만 응답 형식 가드가 없었다**
- `esearch()` 는 속도제한 HTML 을 잡아내는데 `esearch_year()` 에는 그 가드가 없어,
  429 응답이 조용히 '검색 결과 0편'이 되고 rc 1 + "검색어를 바꿔 보세요" 가 떴다.
  하필 **기본값인 층화 표집**이 가드 없는 쪽이었다. → 공용 `_assert_esearch_result()`.

**[MEDIUM] 오타 하나가 NCBI 를 수만 번 두드릴 수 있었다**
- `--years` 에 상한이 없어 `--years 2020`('2020년 이후' 라는 뜻으로 쓴 오타)이 연도마다
  요청을 보내 **2,020회**(예절 대기 포함 11분+), `--years 100000` 은 10만 회였다.
  `--gap-top-k` 에 상한을 둔 것과 같은 이유인데 여기만 빠져 있었다. → 100년 상한.
- 전수 검증도 쌍 수에 상한이 없어, 느슨한 임계 하나로 2만 쌍 ≈ 2시간이 될 수 있었다
  → 상위 30쌍으로 제한하고 그 사실을 알린다.

**[MEDIUM] 나머지 OSError 가 rc 3 으로 새어 나갔다**
- 심볼릭 링크 루프·경로 중간이 파일·너무 긴 파일명 등이 "데이터를 가져오지 못했습니다"
  (네트워크 오류처럼 읽힌다) + rc 3 이었다. `--out`·`--exclude-terms-file` 은 같은 상황을
  rc 2 로 처리하고 있어 일관성도 없었다. → `OSError` 를 rc 2 로.

**[LOW] NUL 검사 창 / 마크다운 주입**
- NUL 검사가 앞 65,536자만 봐서 그 뒤의 NUL 이 리포트까지 흘러갔다 → 전체 검사.
- 검색어·경로·제외어의 개행이 제목·실행정보 줄을 쪼개 **가짜 절**을 만들 수 있었다
  (표 셀은 이미 안전했지만 그 바깥이 남아 있었다) → CLI 문자열도 `clean_value` 통과.

**[MEDIUM] 검증 결과를 CSV 로 거를 수 없었다**
- 사용법은 "`❌` 인 줄은 버리세요" 라고 하는데 `--csv-section gaps` 에 `verdict` 열이
  없었다. 부상/쇠퇴 CSV 도 `q_value` 를 빠뜨렸다. → 둘 다 추가.

**[MEDIUM] 리포트가 길고, 접힘 블록이 터미널에서 안 접혔다**
- `<details>` 는 터미널에서 HTML 태그 그대로 찍혀, '숨겼다고 생각한' 21줄이 그대로
  보였다 — 그중 12줄은 절 제목과 **반대되는** 내용(개입연구 과밀 주제)이었다.
  → `<details>` 제거, 과밀 주제·쇠퇴 주제는 한 줄 요약 + 전체는 JSON/CSV 안내,
  저널 기본 5개. 138줄 → **122줄**.

### D. 새 기능 (라운드 2 리뷰가 요구한 것)

리뷰어가 실제 PubMed 3개 쿼리를 돌려 보니 **1순위 추천이 전부 틀렸다.** 원인은 통계가
아니라 **입력**이었다 — 표본이 한 해로 붕괴하고, 후보가 색인 규칙의 그림자인지 확인하지
않았다. 두 기능으로 대응했다.

**전수 검증(`--verify-gaps`, 조회 경로 기본 켜짐)**
- 표시할 각 공백쌍을 **같은 검색 제한 안에서 PubMed 전체**를 대상으로 다시 센다
  (`esearch&retmax=0` 로 `<Count>` 만; 12쌍이면 약 23회 호출).
- 표본이 아니라 전수로 기대·lift 를 재계산하므로, 상하위어 쌍은 `C_AB ≈ C_child` 라
  lift 가 1 이상으로 나와 **자동으로 걸러진다** — MeSH 트리 파일 없이(무의존 유지)
  계층 artifact 를 없앤다. 실측 사례: 표본 0편 ↔ 전수 563편, 표본 13편 ↔ 전수 21,673편.
- 표에 `PubMed 전수` / `판정`(✅ 진짜 공백 / ⬜ 전수 0편 / ❌ 색인 artifact) 열이 붙고,
  **"제안:" 줄은 검증을 통과한 첫 후보**를 가리킨다(전부 artifact 면 그렇다고 말한다).

**연도 층화 표집(`--sample stratified`, 기본) + `--count-only`**
- 기존 최신순 표집은 활발한 분야에서 표본을 한 해로 붕괴시켰다(실측: 10년 검색인데
  300편의 98%가 올해 — '48.8배 성장'의 진짜 원인). 이제 연도마다 `mindate/maxdate` 로
  esearch 를 돌려 균등 할당하고, 모자란 해의 몫은 재분배한다. efetch 비용은 동일하다.
- `--count-only` 는 1초 만에 전체 편수를 알려 줘 `--max-records` 를 얼마로 둘지 정할 수
  있게 한다(전에는 잘린 리포트를 한 번 만들어 봐야 알 수 있었다).

## 2026-07-16 — 심층 개선 + 하드닝 라운드 1

### A. 기능 개선 / 확장 (임상·제약 연구자 관점의 실제 니즈)

**통계적 엄밀성 (핵심 강화)**
- **BH-FDR q-value**: 공백 탐색은 상위 주제쌍 수십 개를 *동시에* 검정하므로 raw p 만
  보고하면 다중검정 함정에 빠진다. Benjamini–Hochberg 절차(`benjamini_hochberg`)를
  순수 표준라이브러리로 구현하고, **검정한 모든 후보쌍**(기대≥`min_expected`)에 대해
  q-value 를 계산해(필터 이전에) 각 공백에 함께 보고. `--gap-max-q` 로 "통계적으로 유의한
  공백만" 필터 가능. 리포트/JSON/CSV 모두에 q 컬럼 추가.
- **Mann–Kendall 단조추세 검정**(`mann_kendall`/`trend_test`): 발행량이 시간에 따라
  *유의하게* 증가/감소하는지를 초기/최근 2분할 비율보다 견고하게 판정. 동률 보정
  분산, 연속성 보정 z, tau-b, 양측 p. 빠진 해를 0 으로 채운 조밀 시계열 사용.
- **CAGR**(연평균 성장률): `growth_summary` 에 추가. 양끝 해 잡음에 민감함을 문서화하고
  유의성 판단은 Mann–Kendall 에 위임.

**입력 형식 / 실세계 견고성**
- **MEDLINE/NBIB 파서**(`parse_medline_nbib`): PubMed 웹의 *Save → PubMed format* 과
  인용 관리자 내보내기 포맷을 직접 분석. MH 별표(descriptor `*Sleep`, qualifier
  `Heart Rate/*physiology`)로 대표주제 판별, OT 키워드, 6칸 이어짐, 다양한 연도 태그.
- **자동 형식 판별 + gzip + 인코딩 관대화**(`load_articles`/`decode_bytes`/`detect_format`):
  XML/NBIB 를 내용으로 판별, `.gz` 자동 해제, UTF-8→latin-1 폴백, BOM 처리.
- **PMID 중복 제거**(`dedup_articles`): efetch 배치 병합/재수출로 생기는 중복 논문 제거.

**MeSH 처리 심화**
- Article 에 `mesh_major`(대표주제), `keywords`(저자 키워드) 필드 추가(XML/NBIB 공통).
- `--major-topics-only`: 별표 대표주제만으로 분석(정밀도↑).
- `--include-keywords`: MeSH 미부여 최신 논문 대비, 저자 키워드를 대소문자 무시로 병합.

**출력 / CLI**
- `--format {md,json,csv}`(`--json` 은 구버전 별칭). CSV 는 엑셀 한글 대비 UTF-8 BOM.
- `--min-year/--max-year` 연도 범위 필터.
- 효율적 공동출현 집계(`_cooccurrence`): 한 번의 스캔으로 상위 주제쌍 관측수 계산.
