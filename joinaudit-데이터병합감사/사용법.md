# joinaudit 빠른 사용법

## 0. 제일 빠른 길

폴더 안의 **`실행.command` 를 더블클릭**하세요. 번들 예제 두 벌(깨끗한 것 / 결함 심은 것)을
순서대로 돌려 보여 주고, 내 데이터로 쓰는 명령어까지 안내합니다.

한 번만 설치해 두면 어디서나 `joinaudit` 로 부를 수 있습니다:

```bash
cd ~/Downloads/02_프로젝트/깃헙/joinaudit-데이터병합감사
python3 -m pip install -e .
```

## 1. 내 데이터로 — 3단계

### ① 무엇을 키로 잡는지 먼저 본다

```bash
joinaudit 워치.csv 수면일기.xlsx 설문.csv --inspect
```

파일마다 **피험자 키 열 / 날짜(또는 시점) 열 / 행 수 / 고유 ID 수**를 찍어 줍니다.
여기서 엉뚱한 열이 잡혔으면 병합해도 소용없습니다. 그때는 직접 알려 주세요:

```bash
joinaudit 워치.csv 수면일기.xlsx --key 수면일기.xlsx=피험자번호 --date 워치.csv=측정일시 --inspect
```

### ② 병합한다

수면 자료(자정을 넘기는 타임스탬프)라면 **반드시** `--align night` 를 쓰세요.
`--align` 의 기본값은 `date` 라, 그대로 두면 한 밤이 두 날짜로 갈라져 **정상 자료가
중복 키로 잡힙니다**(툴이 이 상황을 감지해 `--align night` 를 권합니다):

```bash
joinaudit 워치.csv 수면일기.xlsx 설문.csv --align night --out-dir 결과
```

방문 기반(기저/4주 등)이라면 `--align visit`. 두 경우로 나뉩니다.

**(a) 파일 안에 시점 열이 있을 때** — 그냥 `--align visit`:

```bash
joinaudit 설문.csv 수면지표.csv --align visit --out-dir 결과
```

**(b) 파일 하나가 곧 한 시점일 때**(Phase-3 설문의 표준 모양) — `--visit-label` 로
파일마다 라벨을 붙입니다. 이걸 빼면 시점이 빈 칸으로 남아 하류 툴에 못 씁니다:

```bash
joinaudit 설문_기저.csv 설문_4주.csv --align visit \
  --visit-label 설문_기저.csv=기저 --visit-label 설문_4주.csv=W4 --out-dir 결과
```

라벨도 사전 정의표를 거치므로 `기저`→`baseline`, `W4`→`week4` 로 정규화되어
다른 파일의 `baseline` 과 그대로 맞물립니다.

### ③ `문제목록.csv` 를 먼저 연다

`merged.csv` 보다 먼저 봐야 합니다. **심각** 한 줄이라도 있으면 표를 그대로 믿지 마세요.

## 2. 결과 읽는 법

화면에 세 블록이 나옵니다.

```
[입력]        ← 무엇을 키/날짜로 잡았는지. 여기가 틀리면 나머지가 다 틀립니다.
[키 정규화]   ← ID 표기를 몇 건 어떻게 고쳤는지 (추측이 아니라 계측값입니다)
[N 흐름]      ← 입력 몇 행이 들어와 몇 행이 쓰였고, 나머지는 왜 빠졌는지
```

**종료코드**

| 코드 | 뜻 | 할 일 |
|---|---|---|
| 0 | 문제 없음 | `merged.csv` 를 하류 툴에 넣으세요 |
| 2 | 경고 있음(병합은 됨) | `문제목록.csv` 를 보고 판단하세요 |
| 3 | **병합 불가** | 툴이 추측을 거부했습니다. 메시지가 시키는 대로 옵션을 주세요 |
| 1 | 실패 | 파일을 못 읽었거나 옵션이 잘못됐습니다 |

**만들어지는 파일 4개**

- `merged.csv` — 분석용 표 (1행 = 피험자 × 시점). `--out-dir` 을 생략하면
  현재 폴더 아래 `결과/` 에 만듭니다
- `병합감사.md` — N-흐름·커버리지·적용 규칙·**Methods 초안(한/영)**
- `문제목록.csv` — 조치할 목록
- `키매칭표.csv` — 누가 어느 파일에 없는지

## 3. 자주 만나는 상황

### "피험자 ID 후보가 여러 개입니다" (종료코드 3)
툴이 추측을 거부한 겁니다. `--key 열이름` 으로 알려 주세요.

### "두 파일에 공통으로 존재하는 피험자가 한 명도 없습니다"
가장 중요한 경고입니다. 표는 만들어지지만 두 파일이 **나란히 붙어 있을 뿐** 아무것도 합쳐지지
않았다는 뜻입니다. `문제목록.csv` 의 권고 칸을 보세요 — 대개 둘 중 하나입니다.

- ID 머리말만 다르다(`S07` vs `BELL-001-07` vs `07`) → `--unify-id-heads`
  (켜기 전에 두 파일이 정말 같은 코호트인지 확인!)
- 규칙으로 못 붙는다 → `--alias 대응표.csv`

`대응표.csv` 는 이렇게 생겼습니다:

```csv
파일,원본ID,표준ID
수면일기.xlsx,피험자1,S01
설문.csv,BELL-001-01,S01
```

### "중복 키" (심각)
같은 피험자·같은 시점이 한 파일에 두 번 들어 있습니다(재측정/재업로드). 기본값에서는
**그 키를 통째로 빼고** 알려 줍니다. 원본을 확인한 뒤 정책을 명시하세요:

```bash
--dup-policy first    # 첫 기록만
--dup-policy last     # 마지막 기록만
--dup-policy mean     # 수치형은 평균
```

어느 경우에도 **행이 늘어나지 않습니다.** (pandas `merge` 는 여기서 조용히 행을 곱합니다.)

### "날짜 형식을 확정할 수 없습니다" (종료코드 3)
`03/01/2026` 이 3월 1일인지 1월 3일인지 열 전체를 봐도 모르겠다는 뜻입니다.
`--date-format dmy` (또는 `mdy`, `ymd`) 로 알려 주세요.

### "서로 다른 시간대 표기가 섞여 있습니다" (종료코드 3)
어떤 행에만 `+09:00` 이 붙어 있습니다. 이 툴은 타임존을 변환하지 않습니다 — 그대로 계산하면
결과가 조용히 9시간 밀리기 때문입니다. 원본을 한 시간대로 통일한 뒤 다시 돌리세요.

### "파일마다 서로 다른 ID 접두어가 자동 제거될 뻔했습니다" (심각)
`BELL-001-01` 과 `BELL-002-01` 처럼 사이트/코호트가 다른 파일이 섞였습니다. 접두어를
떼면 양쪽이 `01` 로 줄어들어 **남남이 한 사람으로 병합**되므로, 툴이 자동 제거를
취소했습니다. 접두어가 사이트를 뜻한다면 그대로 두는 것이 맞습니다.

### "파일마다 시간대 표기가 다릅니다" (종료코드 3)
파일 A는 전부 `+09:00`, 파일 B는 전부 `+00:00` 인 경우입니다. 각 파일은 일관돼
보이지만 같은 순간이 서로 다른 날짜로 귀속되어 두 파일이 한 행에서 만나지 못합니다.

### "최종 표가 0행입니다" / "미매칭과다" (심각·경고)
병합은 돌았는데 조건을 만족하는 피험자·시점이 없거나 거의 없습니다. `--how inner` 를
`outer` 로 바꾸거나, `--inspect` 로 각 파일의 키·시점이 정말 같은 것을 가리키는지
확인하세요.

### "단위 의심" (정보)
`총수면시간_시간`(7.1)과 `총수면시간_min`(421)처럼 약 60배 차이 나는 같은 이름의 변수를
찾았습니다. **자동 변환은 하지 않습니다.** 어느 쪽이 맞는지는 사람이 정하세요.

## 4. 다음 단계 — 하류 툴로

`--align night`/`date` 로 만든 `merged.csv` 는 **1행 = 피험자 × 시점**입니다.
반복측정을 반복측정으로 다루는 툴에는 그대로 들어갑니다:

```bash
longistat 결과/merged.csv --id subject_id --time timepoint --value watch_hrv_rmssd_ms
```

> ⚠️ **`statwise` 와 `table1` 에는 그대로 넣지 마세요.** 두 툴은 **1행 = 1피험자**를
> 전제합니다. 16명 × 10밤 = 160행짜리 표를 그대로 넣으면 같은 사람의 10개 행이 서로
> 독립인 관측으로 취급되어 N이 80/80으로 부풀고 p값이 실제보다 작아집니다
> (유사반복, pseudoreplication). **먼저 피험자당 한 행으로 요약**한 뒤에 넣으세요 —
> 기저값이 맞는지, 평균이 맞는지, 변화량이 맞는지는 연구 질문에 달려 있어서
> joinaudit 이 대신 정해 주지 않습니다. `병합감사.md` 의 §8 이 실행마다 이 경고를
> 다시 계산해 보여 줍니다.

시점 열이 없는 파일만 합쳤다면(예: ISI + 인구학 정보) 결과가 이미 1행 = 1피험자이므로
`table1`/`statwise` 에 바로 넣을 수 있고, `병합감사.md` §8 이 그렇게 안내합니다.

`병합감사.md` 의 **Methods 초안** 은 논문 Methods 와 IRB 자료에 그대로 넣을 수 있습니다.
숫자는 이 실행에서 실제로 센 값이지만, 제외 사유가 연구 프로토콜과 맞는지는 꼭 사람이
확인하세요.

## 5. 안심해도 되는 것

- **원본 파일을 절대 수정하지 않습니다.** 출력은 `--out-dir`(기본 `결과/`)에만 쓰고,
  출력 경로가 입력 파일과 겹치면 거부합니다.
- **네트워크를 쓰지 않습니다.** 환자 데이터가 밖으로 나가지 않습니다.
- **CSV 수식 인젝션을 막습니다.** `=`/`+`/`-`/`@` 로 시작하는 비숫자 셀 앞에 `'` 를 붙입니다
  (숫자는 그대로 두므로 `-3.2` 가 망가지지 않습니다).
- **번들 예제는 전부 난수 합성 데이터입니다.** 실제 환자 자료가 아닙니다.
