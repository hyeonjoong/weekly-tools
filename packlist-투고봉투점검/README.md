# packlist — 투고 봉투 점검

**`draftcheck` 는 원고가 스스로 말이 되는지를 보고, `packlist` 는 원고가 약속한 파일이 봉투 안에 실제로 있는지를 본다.**
저널 포털에 올리기 직전, 또는 공저자에게 폴더를 넘기기 직전의 **폴더 하나**를 통째로 읽어,
본문이 약속한 것(Fig. 4, S5 Table, 보충자료, 커버레터)이 **봉투에 실제 파일로 있고 docx 안에 실제로 앵커돼 있는지**를 대조한다.
글자를 읽는 것이 아니라 **zip 내부 구조와 폴더 목록**을 읽는다. 명령 한 줄, 1초.

---

## 목적 / Why this exists

**한국어.** 원고 판본은 하루에도 스무 번씩 바뀌고, 그때마다 공저자와 왕복한다. 그 과정에서 Word 는
사람 눈에 보이지 않는 사고를 낸다 — 그림 파일이 패키지 안에 남은 채 **본문 앵커만 끊어지는** 것이다.
화면에는 빈 줄로 보일 뿐이라 훑어보면 그냥 넘어간다. 실제로 이 저장소 주인의 npj Digital Medicine 원고에서
Fig. 4 두 장이 `수정5`(10:32)에 앵커를 잃고 `수정10`(12:14)까지 **여섯 판본·1시간 42분** 동안 그대로 돌아다녔고,
그 사이 공저자에게 나갔다. 사람이 우연히 알아챈 것이 열 판본 뒤였다. `packlist` 는 그 1초짜리 확인을 자동화한다.
투고 전 · 공저자 발송 전에 폴더를 가리키고 한 번 돌리면 된다.

**English.** Word silently orphans images: the picture file stays inside the `.docx` package while the
anchor in `document.xml` disappears. On screen it looks like an empty line, so proof-reading misses it.
In the repository owner's own npj Digital Medicine manuscript two Fig. 4 images lost their anchors in
revision 5 and travelled through six revisions (1 h 42 min) — and out to a co-author — before a human
happened to notice. `packlist` reads the zip structure and the folder listing, not the prose, and tells
you in one second whether every figure the manuscript promises is actually anchored and whether every
supplementary file it cites actually exists in the envelope you are about to upload or hand over.
It is for a clinical/pharma researcher at the moment of submission, and it never modifies anything.

### 인접 툴과의 경계

| 툴 | 보는 것 |
|---|---|
| `draftcheck` | 원고 **한 개의 텍스트**가 스스로 말이 되는가 (문장·형식·인용 표기) |
| `numcheck` | 원고 안 숫자의 **산술** |
| `tracecheck` | 원고의 숫자 ↔ **분석 산출물** |
| `revcheck` | **같은 원고의 다른 판본** 비교 |
| `irbpack` | **IRB 패킷 안 다른 문서의 같은 항목** (내용 정합) |
| **`packlist`** | **원고가 약속한 첨부물 ↔ 봉투 안에 실제로 있는 파일과 앵커** (패키지·파일시스템 층) |

`packlist` 는 IRB 패킷을 받으면 판정하지 않고 `irbpack` 을 가리키며 종료코드 2 로 물러난다.
`.docx` 파일 하나를 직접 넘기면 `draftcheck` 를 가리키며 역시 2 로 물러난다.

## 설치

```bash
cd packlist-투고봉투점검
python3 -m packlist examples/02_고아있음      # 설치 없이 바로 실행
python3 -m pip install -e .                  # `packlist` 명령으로 쓰고 싶을 때만
```

`pip install -e .` 는 콘솔 스크립트를 파이썬의 `bin` 폴더에 놓는다. 그 폴더가 `PATH` 에 없으면
`packlist: command not found` 가 나는데, 그때는 그냥 `python3 -m packlist` 를 쓰면 된다 — 기능은 같다.

의존성 없음(`dependencies = []`). 표준 라이브러리만 쓴다
(`zipfile` · `xml.etree` · `hashlib` · `urllib.parse`(퍼센트 인코딩 해제 전용) · `json` · `unicodedata` 등).
네트워크에 접속하지 않으며 **입력을 읽기만 한다**. 설치가 싫으면 `python3 -m packlist` 로 바로 실행해도 된다.

## 사용법

```bash
# 0) 봉투가 어떻게 읽혔는지부터 인쇄 — 사람이 1초에 틀렸음을 안다 (판정하지 않음)
packlist 투고본_2026-08-19/ --inspect

# 1) 기본 — 봉투에 docx 가 여럿이면 원고를 지정한다(실제 투고 봉투는 대개 그렇다)
packlist 투고본_2026-08-19/ --manuscript 원고_최종.docx --out-dir 봉투점검_0911

# 2) 지난 회차 대비 — 앵커 회귀 검출 (이 툴의 존재 이유)
packlist _이전본/ --manuscript 원고_수정10.docx \
         --baseline _이전본/ --baseline-manuscript 원고_수정4.docx

# 3) 저널 규정·제출목록을 입력으로 받아서
packlist 투고본/ --limits 저널규정.json --expect 제출목록.json --out-dir 봉투점검_0911

# 4) 표제 3종 대조가 거슬리면 끈다 / 버전 확인
packlist 투고본/ --skip-frontmatter
packlist --version
```

`--inspect` 는 판정하지 않으므로 `--out-dir` 를 무시한다(그 사실을 알려 준다).
`--out-dir` 는 **봉투 바깥**이어야 한다 — 봉투 안에 쓰면 폴더째 압축할 때 리포트까지 올라간다.

봉투에 `.docx` 가 두 개 이상이면 **어느 것이 원고인지 추측하지 않고** `--manuscript` 를 요구한다.

### 실제 출력 (`examples/02_고아있음`) — 아래는 붙여 넣은 그대로입니다

산출물에는 **절대경로가 들어가지 않는다**(basename 만). CSV 셀이 `=`/`+`/`-`/`@` 로 시작하면
엑셀 수식 실행을 막기 위해 `'` 를 앞에 붙인다. 산출물 자리에 심볼릭/하드링크가 있으면
따라가지 않고 거절한다(입력 파일이 조용히 덮어써지는 사고 방지).

| 3 | **판정 불가** — 원고 docx 가 손상·암호화됐거나, 지원하지 않는 압축 방식이거나, `document.xml` 파싱에 실패했거나, 봉투 안에 읽을 수 없는 파일이 있다. **3이 1보다 우선한다** — 다 읽지 못했으면 "치명 2건"은 거짓말이다. (원고가 아닌 **부속** docx 하나를 못 읽는 것은 판정을 막지 않고 자백에 실린다.) |

## 무엇을 어떻게 세는가 (규칙을 숨기지 않는다)

* **봉투** = 지정한 폴더의 **바로 아래 파일들**. 하위폴더(`_이전본/` 등)와 **심볼릭 링크**는 봉투로 보지 않고,
  둘 다 커버리지 자백에 이름을 적는다. 하위폴더는 "폴더째 압축하면 함께 올라간다"는 경고도 함께 낸다.
* **고아 미디어** = `word/media/*` 중, 그 Id 를 `r:embed`/`r:link` 등으로 **실제로 부르는 파트가 하나도 없는** 파일.
  머리글·바닥글·각주·미주의 `.rels` 까지 전부 훑고 나서 판정하므로 **로고와 워터마크는 고아가 아니다**.
  선언만 있고 아무도 부르지 않는 관계(지워진 파트가 남긴 유령 `.rels`)는 앵커로 세지 않는다.
  같은 Id 가 두 번 선언되면 Word 와 같이 **마지막 선언만** 앵커로 세고, 그 사실을 경고로 알린다.
* **중복 미디어** = 같은 SHA-256, 다른 이름. Word 가 흔히 만들기 때문에 **언제나 경고**이고 치명으로 올리지 않는다.
* **캡션 문단** = 문단이 `Fig. 1.` / `Table 2:` 처럼 **번호 뒤 구두점**으로 시작할 때만 캡션으로 본다.
  구두점을 요구하지 않으면 `Table 1 lists the sample.` 같은 평범한 첫 문장이 전부 캡션으로 잡힌다. 넓히지 않고 좁힌다.
* **Fig 인용** = 캡션의 머리 라벨을 뺀 본문 언급. `Fig.`/`Fig`/`Figure`/`Figs.` 를 모두 받고,
  `Fig S3` 같은 보충자료 표기는 본문 그림으로 세지 않는다.
  `Figs. 2-4` · `Fig. 2, 3 and 4` 같은 묶음 표기는 **풀어서 각각 한 번씩** 센다(범위는 20 이내만).
* **번호 체계** = 캡션이 있는 번호 중 빠진 번호, 같은 번호의 캡션이 두 번 나오는 경우,
  본문 첫 등장 순서가 번호 순이 아닌 경우, 본문이 부르는데 캡션에 없는 패널 라벨 — 전부 **경고**다.
* **본문이 부르지 않는 파일** = 봉투 안 파일 중 (a) 파일명이 본문에 나오지도 않고,
  (b) 커버레터·하이라이트·체크리스트 같은 **표준 제출물 이름**도 아니고,
  (c) `Fig3.tif`·`Table_2.pdf` 처럼 **본문이 부르거나 캡션이 있는 번호**를 달고 있지도 않은 것.
  (c) 때문에 캡션만 있고 본문 인용이 없는 그림의 파일도 "부르지 않는 파일"로는 세지 않는다.
* **문단 수** = `word/document.xml` 의 `<w:p>` 개수. **빈 문단·표 안 문단·텍스트 상자 문단을 모두 포함**하고,
  `mc:AlternateContent` 의 Fallback 가지는 제외한다. 사람이 Word 화면에서 세는 값(211/212 등)과는 다르게 나온다 —
  **일부러 맞추지 않았다.** 조용히 맞추면 어떤 규칙으로 센 숫자인지 알 수 없게 되고, 그게 더 나쁘다.
* **보충자료 토큰** = `S1 Table` · `Table S1` · `Supplementary Table 3` · `Appendix A` 등.
  봉투 안 파일명과 대조하고, `Supplementary_Material.docx` 같은 **docx 통합본** 안에 해당 항목이
  적혀 있으면 `있음(통합본)` 으로 판정한다(v1 은 docx 만 열므로 PDF 통합본은 `대조불가` 다).
  `--expect` 의 `elsewhere` 목록에 적은 항목은 `별도제출` 로 보고 경고하지 않는다.
* **표제 3종** = 원고 제목·저자 순서·원고번호. 제목은 다른 문서가 **따옴표나 `entitled` 로 명시한**
  문자열과 비교하고(따옴표 후보는 정확히 같아야 하며, 문장형 후보는 제목을 통째로 품으면 일치),
  저자 순서는 성(姓)이 나오는 순서열 안에 원고의 순서가 부분수열로 들어 있는지로 본다.
  판단이 서지 않으면 불일치가 아니라 `대조불가` 다. `--skip-frontmatter` 로 끌 수 있다.

## 한계 — 못 하는 것을 먼저 말한다

1. **고치지 않는다.** 고아 삭제·중복 병합·용량 최적화를 하지 않는다. 감사와 수정을 한 툴에 넣으면
   사람이 리포트를 안 보고 수정만 돌리게 된다. (코드가 zip 을 쓰기 모드로 열지 못하도록 테스트로 막아 두었다.)
2. **저널 규정을 모른다.** 용량 상한·필수 제출물은 `--limits` / `--expect` 로 **받을 때만** 판정한다.
   받지 않으면 "검사 안 함"이라고 자백한다. 저널명이나 용량 상한 숫자는 코드에 한 글자도 들어 있지 않다(테스트로 고정).
   용량 상한을 넘겨도 **경고**일 뿐이다 — 상한은 입력받은 값이고, 최종 판단은 사람이 한다.
3. **그림 안의 글자를 읽지 못한다.** OCR 이 없다. 그림 이미지 안에 잘못 찍힌 `*p < 0.012` 같은 표기는 **못 잡는다.**
   (이미지 디코딩 라이브러리를 import 하지 못하도록 테스트로 막아 두었다.)
4. **PDF 조판을 보지 않는다.** v1 은 `.docx` 만 연다. PDF·PPTX·HWP 는 목록과 용량만 세고 "내부 미검사"로 자백한다.
5. **이미지와 그림 번호를 짝지어 주지 않는다.** 패키지에 그 정보가 없다. "Fig. 4 의 그림이 사라졌다"가 아니라
   "앵커된 이미지가 캡션 수보다 적다"까지만 말한다.
6. **원고 텍스트의 품질·산술·인용 DOI 는 보지 않는다.** 각각 `draftcheck` · `numcheck` · `citecheck` 의 일이다.
   다만 **그림/표 번호 체계**(빠짐·중복 캡션·첫 등장 순서·패널 라벨)와 **표제 3종**은 본다 —
   이건 문장 품질이 아니라 *봉투가 지킨다고 한 약속*의 일부이기 때문이다.
7. **익명 심사인지 알 수 없다.** 그래서 작성자/최종수정자 잔존은 `[정보]` 로만 찍고 경고로 올리지 않는다.
   올리는 옵션도 두지 않았다 — 저널 규정은 이 툴이 모르는 외부 지식이다.
8. **매번 뜨는 것이 정상인 경고가 둘 있다.** 보충자료를 저널 포털로 따로 올린다면
   `본문이 부르는 보충자료 N종을 봉투에서 찾지 못했습니다` 는 영원히 뜬다
   (`--expect` 의 `elsewhere` 목록으로 끌 수 있다). `.DS_Store` 는 Finder 가 계속 다시 만든다.
   이 둘은 "고쳐지지 않는 것이 정상"이며, 실패로 읽지 말아야 한다.
9. **애매하면 올리지 않고 내린다.** 치명이 애매하면 경고, 경고가 애매하면 `대조불가` 다.
   그리고 **리포트에 나오지 않은 항목이 "일치"라는 뜻이 아니다** — 그래서 커버리지 자백이 없으면
   리포트 자체를 출력하지 않도록 코드로 강제했다(`ReportIntegrityError`).

이 툴을 **접어야 할 신호**: 다음 봉투 세 번 연속으로 치명이 0건이면, 이 사고는 이미 끝난 것이다.

## 예제와 테스트

```bash
python3 examples/_make_examples.py   # 합성 봉투 5종 생성 (실제 원고는 절대 복사하지 않는다)
python3 -m pytest -q                 # 588개
```

예제 봉투는 **100% 합성**이며 저장소에 커밋되지 않는다(`.gitignore` 가 문서 확장자를 통째로 막는다 —
실제 연구 자료가 실수로도 커밋되지 않게 하려는 것이다).

실제 원고에서 측정한 값은 `tests/test_known_answers_real.py` 에 **수치와 판본 번호로만** 들어 있다 —
원고 파일도, 사람 이름도 저장소에 들어오지 않는다(판본 파일명은 glob 으로 이 컴퓨터에서만 풀린다).
코퍼스 경로는 `PACKLIST_REAL_CORPUS` 환경변수로 바꿀 수 있고, 폴더가 없으면 그 파일은 통째로 skip 된다.
