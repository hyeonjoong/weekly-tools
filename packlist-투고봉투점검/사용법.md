# packlist 빠른 시작 (한국어)

## 한 줄 요약

**투고 포털에 올리기 직전 · 공저자에게 폴더를 넘기기 직전**, 그 폴더를 가리키고 한 번 돌린다.
원고가 약속한 그림과 보충자료가 **봉투 안에 실제로 있는지**, 그림이 **본문에 실제로 붙어 있는지** 1초에 알려 준다.

## 1. 더블클릭으로 맛보기

`실행.command` 를 더블클릭하면 합성 예제 봉투 5종을 차례로 점검하며
종료코드 **0 → 1 → 3 → 2 → 1** 이 어떤 상황인지 보여 준다. 설치 없이 돌아간다.
마지막 ⑤ 번이 이 툴의 핵심인 **앵커 회귀**(지난 회차엔 붙어 있던 그림이 떨어진 것) 시연이다.

## 2. 내 봉투에 쓰기

설치는 필요 없다. 이 폴더에서 바로 실행하면 된다.

```bash
cd packlist-투고봉투점검

# 먼저 '어떻게 읽혔는지'부터 본다 (판정하지 않는다)
python3 -m packlist ~/논문/투고본_2026-08-19/ --inspect

# 점검하고 리포트를 남긴다
python3 -m python3 -m packlist ~/논문/투고본_2026-08-19/ --out-dir 봉투점검_0911
```

봉투에 docx 가 여럿이면(원고 + 커버레터 + 보충자료…) 어느 것이 원고인지 묻는다.
알려 주는 대로 `--manuscript 원고파일.docx` 를 붙이면 된다.
`--out-dir` 는 **봉투 바깥**을 가리켜야 한다. 표제 3종 대조가 거슬리면 `--skip-frontmatter` 로 끈다.

`python3 -m packlist` 대신 짧게 `packlist` 라고 쓰고 싶으면 한 번만
`python3 -m pip install -e .` 를 돌린다. 그래도 `command not found` 가 나오면
파이썬 `bin` 폴더가 `PATH` 에 없다는 뜻이니 그냥 `python3 -m packlist` 를 쓰면 된다.
아래 예시의 `packlist` 는 모두 `python3 -m packlist` 로 바꿔 써도 똑같이 동작한다.

`--inspect` 가 인쇄하는 **파일 목록 · 미디어 개수 · Fig 인용/캡션 수**를 먼저 훑어보라.
여기서 숫자가 이상하면 뒤의 판정도 믿을 수 없다. 1초면 알아챌 수 있다.

## 3. 세 가지 현실적인 예

**(가) 공저자 왕복 후, 지난 회차와 비교한다 — 가장 중요한 사용법**

```bash
packlist 판본폴더/ --manuscript 원고_수정10.docx \
         --baseline 판본폴더/ --baseline-manuscript 원고_수정4.docx
```

`[치명] 지난 회차엔 앵커돼 있던 그림 2개가 이번 회차에서 고아가 됐습니다` — 이 한 줄이 이 툴의 존재 이유다.
공저자 편집본은 왕복할 때마다 중복 미디어를 다시 만들고, 때때로 그림 앵커를 끊는다.

**(나) 저널이 요구하는 제출물 목록을 넣고 본다**

`제출목록.json`:

```json
{ "required": ["S1 Table", "S2 Table", "S1 Fig"], "optional": ["Cover Letter"] }
```

```bash
packlist 투고본/ --expect 제출목록.json
```

`--expect` 를 주지 않으면 보충자료 실물 대조는 **`대조불가`** 로 남는다(치명이 아니다).
저널 포털에 따로 올리는 게 정상 절차일 수 있기 때문이다.
`required` 에 적은 항목만 `없음` = 치명이 되고, 나머지는 그대로 `대조불가` 다.

보충자료를 **포털에 따로 올리는 게 늘 정상**이라면 그 경고를 아예 끌 수 있다:

```json
{ "elsewhere": ["S1 Table", "S2 Table", "S1 Fig"] }
```

이러면 `별도제출` 로 찍히고 경고하지 않는다. 매 회차 같은 줄이 뜨는 것이 이 툴을
두 번 안 열게 만드는 가장 큰 이유라서 둔 장치다.

**(다) 봉투에 원고 docx 가 여러 개다**

```
packlist: 봉투에 .docx 가 3개입니다 — 어느 것이 원고인지 추측하지 않습니다.
  --manuscript 로 지정하세요:
    --manuscript 원고_수정20.docx
```

추측하지 않는다. 알려 준 대로 하나만 더 붙이면 된다.

## 4. 결과 읽는 법

```
[치명] 고아 이미지 2개 — 패키지에 있으나 어디에도 앵커 없음
[경고] 중복 이미지 3쌍 — 같은 바이트, 다른 이름 (6.20 MB 낭비)
[정보] Fig 인용 14회 (Fig2×5 Fig3×2 Fig4×7) · 캡션 5종 · 본문 앵커 이미지 6개
```

* **치명** = 봉투를 이대로 보내면 그림이 빠지거나 깨진다. 고쳐야 한다.
* **경고** = 알고는 있어야 하지만 그대로 보내도 그림이 사라지지는 않는다. 중복 미디어는 Word 가 흔히 만든다.
* **대조불가** = 판정이 아니다. "이 문서에서 찾지 못했다"는 뜻이지 "같다"는 뜻이 아니다.

**고쳐지지 않는 것이 정상인 경고 둘**: 보충자료를 포털에 따로 올린다면
`보충자료 N종을 봉투에서 찾지 못했습니다` 는 매번 뜬다(위 `elsewhere` 로 끌 수 있다).
`.DS_Store` 는 Finder 가 계속 다시 만든다. 이 둘을 실패로 읽지 말 것.
* **정보** = 숫자 확인용. 캡션 수보다 앵커 이미지가 적으면 눈여겨볼 것.

마지막 **`[커버리지 자백]`** 을 꼭 읽어라. *무엇을 안 봤는지*가 적혀 있다.
**리포트에 안 나온 항목이 "일치"라는 뜻이 아니다.**

## 5. 종료코드

| 코드 | 뜻 | 그때 할 일 |
|---|---|---|
| 0 | 치명 없음 | 경고를 훑어보고 넘어간다 |
| 1 | 치명 있음 | 고치고 다시 돌린다 |
| 2 | 판정하지 않고 물러남 | 메시지가 시키는 대로 한다(`--manuscript` 지정 등) |
| 3 | 판정 불가 | docx 가 손상됐거나 폴더를 다 못 읽었다. 파일부터 확인한다 |

## 6. 안심해도 되는 것들

* **입력을 읽기만 한다.** 원고를 고치거나 지우지 않는다(코드가 zip 을 쓰기 모드로 열지 못하도록 막아 두었다).
* **네트워크에 나가지 않는다.** 임상 자료가 밖으로 갈 일이 없다.
* **산출물은 `--out-dir` 안에만** 쓰고, 그 자리에 링크가 있으면 따라가지 않고 거절한다.
* 리포트에 **절대경로(내 컴퓨터 사용자 이름)가 들어가지 않는다.**
  사람 이름(작성자·최종수정자·저자 목록)은 **리포트 파일에서만 가려진다**(`김 현중` → `김 현*`).
  콘솔에는 그대로 나온다 — 콘솔은 본인만 보고, 파일은 공저자에게 전달되기 때문이다.

## 7. 이 툴이 아닌 것

원고 **텍스트**가 스스로 말이 되는지(번호·인용·형식)는 `draftcheck`,
숫자의 산술은 `numcheck`, IRB 패킷 문서 간 내용 정합은 `irbpack` 이 본다.
`packlist` 는 **파일과 앵커**만 본다.
