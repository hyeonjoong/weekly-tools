* README 의 "실제 출력" 블록이 실제 출력과 두 줄 달랐다(자백 한 줄 누락 포함)

  (`pip install -e .` 이 놓는 스크립트 폴더가 `PATH` 에 없는 환경이 실제로 있다).

### 3. 이 라운드에서 새로 넣은 기능 (검토에서 나온 요구)

* `--expect` 의 `elsewhere` 목록 — 보충자료를 저널 포털로 따로 올리는 것이 정상 절차인 워크플로에서
  같은 경고가 **매 회차 영원히** 뜨는 문제를 끈다(`별도제출` 로 표시). 검토자가 지목한
  "두 번 열지 않게 만들 가장 큰 이유"였다.
* `Figs. 2-4` · `Fig. 2, 3 and 4` 묶음 표기 해석 — 안 하면 Fig. 3·4 가 매번
  '아무도 안 부르는 그림'으로 잘못 걸린다.

**라운드 2 결과: 테스트 530개 → 588개.** 실데이터 회귀 45건은 라운드 1·2 수정 전후 모두 통과한다.

## 남아 있는 것 (알고도 안 고친 것)

* `_referenced_ids` 는 XML 주석이나 본문 텍스트에 적힌 `r:embed="rId7"` 도 참조로 본다.
  원고가 OOXML 마크업을 인용하는 경우에만 성립하고, 방향이 **고아를 가리는 쪽**이라
  거짓 치명은 아니다. 정확히 하려면 XML 파서 수준의 속성 수집이 필요해 v1 에서는 두었다.
* 이미지와 그림 번호를 짝지어 주지 않는다. 패키지에 그 정보가 없다 — 기획의 의도적 제외 항목이다.
* PDF·PPTX·HWP 내부는 열지 않는다. `있음(통합본)` 판정도 docx 통합본에서만 가능하다.
