### 고친 결함

**치명 · 보안**

**치명 · 크래시**

2. **`OverflowError` 로 죽으면서 종료코드 1(=취약)을 냈다.** 값이 1e308 근처면
   `mean` 의 `math.fsum` 이 터지는데, `prepare()` 는 `SkipScenario` 만 잡고
   있었다. 크래시와 "취약 판정"이 스크립트에서 구분되지 않았다.
   → `mean` 을 척도 불변으로 고치고, `prepare()` 도 수치 예외를 잡아 그
   시나리오만 사유와 함께 건너뛰게 했다.
3. **1e250 근처에서 `variance` 가 터졌다.** 평균의 1 ulp 오차가 제곱되며
   오버플로. → `variance`/`stdev` 를 척도 불변으로 재작성하고, 배정도를 벗어나면
   추측 대신 사유를 남기고 건너뛴다.
4. `welch_t_test` 의 자유도 분모가 언더플로로 0 이 되어 `ZeroDivisionError`.
   → 유한성 검사 추가.

**치명 · 판정이 거짓말을 함**

5. **귀무 결과를 넣을 때마다 울었다.** ③④ 가 유의성과 무관하게 발동해,
   r ≈ 0 인 합성 자료 40건 중 **39건이 '주의' 또는 '취약'** 으로 나왔다.
   `r = 0.121 (p = .524)` → `r = −0.123` 을 "효과 방향 반전 · 치명"으로 부른 것.
   결론("차이를 확인하지 못했다")은 조금도 바뀌지 않았는데.
   → **양쪽 다 비유의면 ③④ 를 아예 보지 않는다.** 실측 재확인: 40건 중 6건,
   강한 효과(d ≈ 1.5)는 여전히 40/40 견고.
6. **소표본 비모수에서 수학적으로 강제된 뒤집힘.** n=3/3 이면 Mann–Whitney 의
   최소 양측 p 는 .100 이라 alpha = .05 에 도달할 수 없다. 완전히 분리된 두 군

   → `nonparametric_p_floor()` 를 만들어, 도달 불가능한 시나리오는 계산해서
   세는 대신 사유와 함께 건너뛴다(축 B 의 `sd_rule_note` 와 같은 처리).
7. **로그 척도의 g 와 원척도의 g 를 등급 비교했다.** `effects.py` 가 검정 축에

   비교를 하고 있었다. → 척도가 다르면 ④ 를 판정하지 않는다(③ 은 유지).
8. **논문에 붙일 문장이 정반대를 주장했다.** ② 만 발생한 경우에도 "유의성은

### 테스트 품질 (돌연변이 검사)

98종 중 **32종이 기존 567개 테스트를 통과**했다. 가장 뼈아팠던 것:

| 살아남은 돌연변이 | 왜 안 잡혔나 |
|---|---|
| `render_scenarios_csv` 에서 `csv_safe` 호출 제거 | 인젝션 방어를 **함수 단위로만** 테스트했고, 실제 산출 경로로 payload 를 흘려 본 테스트가 없었다 |
| `sort_key` 에 p 를 끼워 넣기 | 픽스처의 p 순서와 축 순서가 **우연히 같아** 정렬 회귀가 보이지 않았다 |
| `render_report` / `render_markdown` 의 자백 게이트 제거(각각) | 게이트 함수를 직접 호출해서만 테스트했다 |
| ±3SD → 2SD / 2.5SD | 픽스처에 |z| ∈ (2, 3] 인 관측치가 하나도 없었다 |
| `MIN_COMPUTED_SCENARIOS` 5 → 1 | 테스트가 양쪽 분기에서 모두 참인 쌍조건이었다 |
| `--alpha` 무시 | `assert code in (0, 1)` 로만 확인했다 |
| 처리 순서 뒤집기(이상치 → 로그) | 리포트에 인쇄하는 규칙인데 검증이 없었다 |

→ `tests/test_invariants.py` 를 신설해 **호출 지점에서** 막았고(자백 게이트 4종,
인젝션 end-to-end, p-정렬이 드러나는 전용 픽스처, z ∈ (2,3] · (3,4) 경계 픽스처,
alpha 실효성, 처리 순서, 산출물 심볼릭 링크·덮어쓰기·절단), 지적된 무의미한 단언
(`assert p < .05 or p >= .05`, `try/except: return`, `in (0, 1, 3)`, 30초 성능
한계 등)을 실제 기대값으로 바꿨다. 검토자의 방법론 경고 — **바이트코드 캐시를
끄지 않으면 돌연변이 검사가 거짓으로 95% 검출률을 보고한다**(CPython 의 pyc
검증이 `(초 단위 mtime, 크기)` 라서) — 도 함께 기록해 둔다.

### 회귀로 확인된 것 (수정이 옳았음)

- `mean`/`variance`/`stdev` 척도 불변 재작성: 25,000건 대조에서 일반 자료 최대
  상대오차 **4.4e-16**(순진한 식 4.2e-16 — 정확도 손해 없음). 파국적 상쇄
  케이스(1e9 ± 1e-6 등)에서는 numpy 와 **비트 단위 동일**. Welch/Student/대응
  t/Pearson 은 여전히 scipy 와 ≤1.6e-13.
- `plan_loo` 예산 거부: 확인 문구가 그대로 인쇄되고, 등급·종료코드가 여전히 정합.
- `safe_join`/`open_for_write`: 심볼릭 링크인 out-dir(정상 사용)·중첩 링크·상대
  경로·`--out-dir .`·후행 슬래시 모두 정상 동작, 미리 심어 둔 링크는 차단.
  일반 음수(`-0.71`)는 여전히 따옴표가 붙지 않는다.
- `_identical_to_baseline`: 12,570쌍 검증, 거짓 주장 0 · 누락 0.
- `same_scale` 배선, `_fmt_alpha`, 결정성, 행 셔플 불변성, `n + 제외 == N`
  불변식(500개 입력 × 모든 결측 패턴), 콘솔↔CSV 수치 일치: 전부 통과.
- 성능: 200,000행 3.8초, 200,001행은 깨끗한 exit 2, 5MB 단일 필드도 exit 2.

### 고친 결함

**치명 — 라운드 1 수정이 만든 것**

1. **`nonparametric_p_floor` 가 n ≳ 1030 에서 `OverflowError`.** `C(1030, 515)`
   가 배정도를 넘어 `2.0 / <huge int>` 가 터졌고, 잡히기는 하되 **"검정 불가
   (수치범위 초과)"** 라는 엉뚱한 사유로 비모수 축 전체가 사라졌다. `--no-log`
   와 겹치면 1,200명짜리 (p < .001, g = −0.80) 자료가 **판정불가 exit 3**.
   200,000행도 마찬가지. → 비트 길이로 거르고 0.0 을 돌려준다.
2. **경계 off-by-one — 라운드 1 결함 #6 이 그대로 재현.** 유의 판정이
   `p < alpha` 인데 가드는 `floor > alpha` 였다. `--alpha 0.10` · n=3/3 이면
   floor 가 정확히 .100 이라 가드가 발동하지 않아, 완전히 분리된 두 군
   (g = −87.9)에 `치명 6건 · 취약 · exit 1`. → `floor >= alpha`.
3. **정확분포를 타지 않는데도 하한을 적용.** 동점·0차이가 있으면 정규근사로
   내려가 하한 아래로 얼마든지 내려간다(실측: MWU n=3/3 동점 자료 p = .047,
   Wilcoxon n=5 p = .025). 그런데 하한을 들이대 **계산 가능한 시나리오를 거짓
   사유로 지웠다** — 정수 임상 척도에서 일상적으로 발생. 진짜 ① 하나가 함께
   묻혔다. → 정확분기 조건(동점·0 없음 + n 상한)을 확인한 뒤에만 적용.
4. **공변량 시나리오에까지 Mann–Whitney 하한을 적용.** 공변량이 있으면 비모수
   축은 Quade 순위 ANCOVA(순위 잔차 t)라 그 하한과 무관한데, 가드가 분기 앞에
   있어 p = .081 로 잘 계산되는 시나리오를 지웠다(→ exit 3). → 분기 안으로 이동.

**치명 — 유니코드**

5. **NFC/NFD 를 구분해 한 군이 두 군이 됐다.** macOS 가 만든 한글 CSV 는 NFD 로
   저장되는 일이 흔한데, 정규화가 없어 화면에 똑같이 보이는 `치료군` 이 두 개의
   레벨이 됐다. 결과: `arm(치료군 n=7, 치료군 n=7)`, `t = 6.869, p < .001,
   g = +3.437`, **견고 · exit 0** — 자기 자신과의 비교를 축복해 준 것이다.
   같은 이유로 NFC `김철수` 와 NFD `김철수` 가 중복 ID 검사를 통과해 **한 사람이
   두 명**으로 들어왔다(제로폭 문자를 넣은 ID 도 마찬가지).
   → `read_table` 에서 셀마다 NFC 정규화 + 비가시 문자 제거.

**심각 — 정직성**

6. **뒤집힘 0건일 때 "방향이 유지되었다"고 썼다.** 라운드 1 수정 #5(양쪽 비유의면
   ③④ 판정 안 함)가 `flips == []` 를 만들고, 문장 생성기가 그걸 *방향에 대한
   단언*으로 바꿔 버렸다. 실측: 기준선 g = +0.395 → 시나리오 g = −0.885 인데
   초안이 "the direction … were unchanged" 라고 썼다. 라운드 1 수정 #8 이
   막으려던 바로 그 사고가 수정 #5 를 통해 되돌아온 것.
   → 무판정 문장을 **유의성 한정**으로 바꾸고, 억눌린 부호 이동을
   `Analysis.silent_effect_shifts` 로 세어 리포트와 초안 양쪽에 개수를 밝힌다.
7. **유럽식 소수점이 섞인 열이 조용히 반토막 났다.** 라운드 1 수정 #10 은
   "결측으로 두고 자백한다"고 했는데, 자백이 `시나리오표.csv` 의 제외 열에만
   들어가 `--no-files`(README 대표 명령!)에서는 보이지 않았다. 24명 중 16명이
   사라지고 `n = 8` 로 **견고 · exit 0**. → 열별 "숫자로 못 읽은 칸" 수를 세어
   리포트 첫머리에 인쇄.
8. **② 접기가 세 경로로 새어 나갔다.** (a) `②+④` 시나리오는 접지 않아 p 가 그대로
   인쇄됐고(실측: 접힌 실행 51건 중 33건), (b) leave-one-out 줄이 같은 p 를
   다시 찍었으며, (c) 바로 아래 LOO-extra 블록이 접힌 시나리오의 p 를 그대로
   나열했다. "값은 CSV 에만 남긴다"는 문장이 같은 리포트 안에서 거짓이 됐다.
   → ② 가 하나라도 있으면 접고, LOO 줄도 기준선이 비유의면 값을 감춘다.
9. **산출물이 반만 쓰이고 종료코드가 화면과 어긋났다.** 파일별 쓰기 실패는 여전히
   리포트 인쇄 뒤에 일어나, 화면에는 `종료코드 0`, 프로세스는 2. 게다가 앞의 두
   파일은 새로 쓰이고 뒤의 두 개는 **이전 실행 내용**이 남아 두 실행이 섞인 폴더가
   됐다. → 임시 파일에 전부 쓴 뒤 한꺼번에 `os.replace`, 그리고 **파일을 먼저 쓰고
   리포트를 나중에 인쇄**한다.

### 남겨 두는 것 (의도된 한계, 문서에 명시)

- N ≈ 2,000 · 뒤집힘 다수면 leave-one-out 이 1분 가까이 걸린다. 그 규모에서는
  1명 제외로 결론이 바뀌지 않으므로 `--loo-max-n 0` 를 쓰라고 README 에 적었다.
- Quade 순위 ANCOVA 는 대조할 표준 구현이 없어 손계산과 단조변환 불변성으로만
  검증했다. README 에 그렇게 적혀 있다.
- Spearman 이 |ρ| = 1 에서 p = 0.0 을 돌려준다(scipy 는 1.4e-24). 검토자도
  robustcheck 쪽이 더 방어 가능한 값이라고 판단했다.
