# robustcheck — 결과 견고성 점검

분석용 CSV 한 장과 **이미 정해 둔 주(主) 분석 하나**를 받아, 그 결론이 분석 선택을 흔들어도 살아남는지 수십~수백 번 다시 계산해 보고 **뒤집히는 조합만** 찍어 주는 오프라인 CLI입니다.

> ### ⚠ 먼저 읽어야 하는 경고
> **이 툴은 '가장 유의한 조합'을 절대 추천하지 않습니다.** 시나리오 정렬 기준은 *뒤집힘 여부*이지 유의성이 아닙니다.
> 여기 나온 조합 중 p 가 작은 것을 골라 논문에 쓰는 것은 **p-해킹**이고, 이 툴은 그 용도로 만들어지지 않았습니다.
> 마찬가지로 leave-one-out 에서 이름이 뜬 피험자는 **'빼야 할 사람'이 아닙니다.** 피험자를 빼는 근거는 사전에 정한 규칙(프로토콜·이상치 정의)뿐입니다.
> 이 툴의 값어치는 조합을 고르는 데 있지 않고, **Results 문단을 쓰기 전에 결론이 얼마나 얇은 얼음 위에 있는지 아는 데** 있습니다.

---

## 목적 / Why this exists

**한국어.** 목요일 밤, ISI 변화량의 군간 비교에서 `p = .043` 이 나왔습니다. Results 를 쓰려는데 손이 멈춥니다 — N은 34명이고, 3주차에 여행 갔다가 수면일기가 엉망이었던 그 한 명을 빼면 이게 `.08` 이 되는 건 아닐까. 확인하려면 SPSS에서 케이스를 하나씩 지우고 34번 돌려야 하고, 여기에 이상치 규칙 3종 × 결측 처리 3종 × 검정 2종을 곱하면 600회가 넘습니다. **사람은 이걸 안 하는 게 아니라 못 합니다.** 그래서 대부분 그냥 쓰고, 4개월 뒤 *"the authors should demonstrate that the reported effect is not driven by a small number of participants"* 라는 Reviewer 2 코멘트를 받은 뒤에야, 마감 압박 속에서 손으로 돌립니다. **결과가 뒤집히는 걸 논문 제출 후에 알게 되는 것** — 그게 이 툴이 막으려는 사고입니다. 임상·제약 연구자가 **투고 전**, 그리고 **리비전 응답서를 쓸 때** 여는 도구입니다.

**English.** You already have a primary analysis and a p value. `robustcheck` does not produce a new conclusion — it re-computes *your* analysis across every combination of pre-specified analytic choices (outlier rule, missing-data handling, parametric vs. non-parametric test, log transform) and across leave-one-out exclusion of every participant, then reports only the specifications where the conclusion **flips**. It is built for small clinical samples (N in the tens), where leave-one-out fragility is real and where R's `specr`/`multiverse` demand that you write the analysis function yourself. Offline, standard library only, never writes to your input file, and — by design — never ranks specifications by significance.

### 이 툴이 답하지 않는 질문 (경계)

| | 답하는 질문 | 툴 |
|---|---|---|
| 검정을 골라 줘 | "이 데이터에 맞는 검정은 뭔가" | `statwise` |
| 추이를 봐 줘 | "시간에 따른 변화가 있는가" | `longistat` |
| 여러 연구를 합쳐 줘 | "연구를 빼면 통합효과가 어떻게 되나" | `metapool` |
| **결론이 버티나** | **"이미 나온 그 결론이 분석 선택을 바꿔도 살아남는가"** | **`robustcheck`** |

경계는 말이 아니라 **코드로** 지켜집니다:

1. `--design` 과 그 설계가 요구하는 열이 없으면 **아무 판정도 하지 않고 exit 2**. 검정 선택은 `statwise` 의 몫입니다.
2. 기준선(주 분석)의 p·효과크기는 리포트에 **딱 한 줄**만 인쇄됩니다. 나머지는 전부 그 한 줄 대비 *변화*입니다.
3. 지원하지 않는 설계(3군 이상, 반복측정, 다변량 공변량)는 **조용히 근사하지 않고 거절**합니다.

## 설치

```bash
cd robustcheck-결과견고성점검
python3 -m pip install -e .
```

외부 의존성이 **하나도 없습니다**(`dependencies = []`). 네트워크를 쓰지 않고, 입력 파일을 절대 수정하지 않습니다. 설치하지 않고 `python3 -m robustcheck ...` 로 바로 써도 됩니다.

## 입력

와이드 형식 — **1행 = 1피험자**. `joinaudit` 의 `merged.csv` 스키마를 그대로 받습니다(UTF-8 BOM, cp949 자동 감지).

```csv
subject_id,arm,isi_baseline,isi_week4,rmssd_ms
S001,active,18,11,42.3
S002,active,21,9,38.1
S003,sham,19,18,29.7
S004,sham,17,,31.2
S005,active,22,14,
```

시점별 long 포맷(같은 `subject_id` 가 여러 행)이면 첫 행을 몰래 고르지 않고 **exit 2 로 거절**하면서 `--timepoint timepoint=week4` 사용법을 알려 줍니다.

## 사용법

```bash
# 1) 군간 비교 (필요하면 기저값 보정 ANCOVA)
robustcheck data.csv --design two-group --group arm --value isi_week4 \
    --covariate-baseline isi_baseline --out-dir 결과/

# 2) 전후 대응표본
robustcheck data.csv --design paired --pre isi_baseline --post isi_week4 --out-dir 결과/

# 3) 두 연속변수 상관
robustcheck data.csv --design corr --x rmssd_ms --y isi_week4 --out-dir 결과/
```

## 무엇을 흔드는가

| 축 | 수준 | 비고 |
|---|---|---|
| **A. Leave-one-out** | 피험자 N명 전수 | 주 시나리오 + *뒤집힌* 시나리오에만 적용 (조합 폭발 억제) |
| **B. 이상치 규칙** | 없음 / ±3SD / IQR 1.5배 | 제외 인원 수와 **ID 를 함께** 보고 |
| **C. 결측 처리** | 완결자만 / LOCF / 평균대체 | **paired 설계 전용** (그 사실을 리포트에 인쇄) |
| **D. 검정** | 모수 ↔ 비모수 | Welch ↔ Mann–Whitney, 대응 t ↔ Wilcoxon, Pearson ↔ Spearman, ANCOVA ↔ Quade 순위 ANCOVA |
| **E. 로그변환** | 미적용 / 적용 | 값이 전부 양수일 때만. 아니면 **건너뛴 사유를 자백** |

처리 순서는 **결측(C) → 로그(E) → 이상치(B) → 검정(D)** 로 고정되어 있고 리포트에 인쇄됩니다(순서가 결과를 바꾸므로 말없이 바꾸지 않습니다). 격자 크기는 `paired` 36개, `two-group`/`corr` 12개이고, `--no-log` 를 주면 각각 18개 / 6개가 됩니다.

**ISI 처럼 로그변환이 애초에 말이 안 되는 지표라면 `--no-log` 를 쓰세요.** 0–28 정수 척도를 로그로 보내는 분석 명세는 어떤 리뷰어도 요구하지 않는데, 그 축이 리포트 뒤집힘의 대부분을 만들어 냅니다(합성 예제 실측: paired 설계 뒤집힘 6건 중 6건). 축을 뺐다는 사실은 리포트 첫머리에 그대로 인쇄됩니다.

### 주요 옵션

| 옵션 | 뜻 |
|---|---|
| `--alpha` | 유의수준 (기본 0.05) |
| `--equal-var` | 모수 검정을 Welch 대신 등분산 Student t 로 (※ `--covariate-baseline` 과 함께 쓰면 ANCOVA 라 무시됩니다) |
| `--no-log` | 로그변환 축(E)을 통째로 제외 |
| `--id` | 피험자 ID 열 이름 (기본 `subject_id`) |
| `--timepoint 열=값` | 시점별 long 포맷에서 한 시점만 선택 |
| `--quiet` / `--no-files` | 판정 한 줄만 / 파일을 쓰지 않음 |
| `--loo-max-n` · `--loo-budget` | leave-one-out 재계산 상한 (넘으면 **돌리지 않고 그 사실을 자백**) |

## 뒤집힘 판정과 등급

| 코드 | 판정 | 심각도 |
|---|---|---|
| ① | 유의 → 비유의 | **치명** |
| ② | 비유의 → 유의 | 경고 (※ "이렇게 하면 유의해진다"는 뜻이 **아닙니다**) |
| ③ | 효과크기 부호 반전 | **치명** |
| ④ | 효과크기 등급 변화 | 경고 |

```
취약 = (치명 ① 또는 ③) ≥ 1  또는  단독 뒤집기 피험자 ≥ 1
주의 = 치명 0 이면서 경고(② 또는 ④) ≥ 1
견고 = 뒤집힘 0건
판정불가 = 유효 N < 6 또는 계산된 시나리오 < 5   ← 다른 무엇보다 우선
```

**③④ 는 세 겹으로 좁혀 놨습니다.** 셋을 다 만족해야 셉니다:

1. **최소 변화폭** — d 0.10 / r 0.05 이상. `g = 0.499 → 0.501` 처럼 경계를 스치는 변화는 세지 않습니다.
2. **한쪽은 유의해야 합니다** — 기준선도 시나리오도 비유의라면, 결론("차이를 확인하지 못했다")은 그대로 유지된 것입니다. 이 조건이 없으면 귀무 결과를 넣을 때마다 '취약'이 뜹니다(실측: r ≈ 0 인 합성 자료 40건 중 39건 → 조건 추가 후 6건).
3. **④ 는 같은 척도끼리만** — 로그변환 여부가 다르면 효과크기 등급을 비교하지 않습니다. 로그 스케일의 g 와 원척도의 g 는 단위가 다르고, 이 툴이 검정 축에 대해 금지하는 바로 그 비교이기 때문입니다.
   (③ 부호 반전은 척도를 바꿔도 뜻이 있으므로 남기되, 양쪽 효과크기가 모두 '小' 이상일 때만 셉니다.)

규칙을 넓히지 않고 **좁혔습니다** — 매번 우는 체커는 두 번째부터 아무도 열지 않기 때문입니다.

## 한계 / Notes

- **커버리지 자백 블록이 없으면 리포트를 아예 출력하지 않습니다**(코드로 강제, `ReportIntegrityError`). 몇 개를 왜 못 돌렸는지 모르는 리포트보다 못생긴 리포트가 낫습니다.
- **다중비교 보정을 하지 않습니다.** 여기 나오는 수십 개 p는 독립 가설이 아니라 *같은 가설의 재계산*입니다. 보정하면 오히려 거짓말이 됩니다. 이 문장은 리포트에 항상 출력됩니다.
- **반복측정·혼합모형·다변량 공변량 모형은 흔들지 않습니다**(`longistat` 영역). 지원 공변량은 `--covariate-baseline` 하나뿐이고, 그 밖의 설계는 근사하지 않고 exit 2 로 거절합니다.
- **부트스트랩 신뢰구간을 만들지 않습니다.** leave-one-out 과 목적이 겹치고, 난수 시드가 재현성 리스크를 새로 만들기 때문입니다. 패키지 안에 난수는 한 줄도 없습니다(테스트로 강제).
- **그림을 그리지 않습니다**(specification curve 플롯 포함). 저장소 전체가 텍스트/CSV 관례입니다.
- **결측을 상상해서 채우지 않습니다**(MICE·회귀대체 없음). 지원하는 3종은 전부 논문 Methods 에 그대로 적을 수 있는 단순 규칙입니다.
- **±3SD 는 n ≤ 10 에서 수학적으로 아무도 배제할 수 없습니다**(최대 |z| = (n−1)/√n < 3). 그 경우 "이상치 0명"으로 조용히 넘기지 않고 사유를 남깁니다.
- 극단적 크기의 값(|v| ≳ 1e150 또는 ≲ 1e-150)은 분산이 배정도 범위를 벗어나므로 **추측하지 않고 사유와 함께 그 시나리오를 건너뜁니다**.
- 자체 구현 p 값은 scipy 와 **≤ 1e-9** 일치합니다 — t / Welch / 대응 t / Mann–Whitney(정확·근사) / Wilcoxon(정확·근사) / Pearson / Spearman. **ANCOVA 는 scipy 가 아니라 numpy OLS 로 교차검증**했고, Quade 순위 ANCOVA 는 대조할 표준 구현이 없어 손계산과 불변성(단조변환)으로만 검증했습니다. 기대값은 `tests/_scipy_expected.py` 에 하드코딩되어 테스트가 완전 오프라인으로 돕니다.
- **유럽식 소수점(`3,14`)은 숫자로 읽지 않고 결측 처리합니다.** 콤마를 천단위 구분자로 지워 314 로 읽으면 결론이 조용히 100배 어긋나기 때문입니다(`1,234.5` 같은 천단위 형태만 받습니다).
- 비모수 검정이 **원리적으로 alpha 에 도달할 수 없는** 소표본(예: n=3/3 이면 Mann–Whitney 최소 양측 p = .100)에서는 그 시나리오를 계산해 '뒤집힘'으로 세지 않고 사유와 함께 건너뜁니다. 세면 완전히 분리된 두 군에도 "유의 → 비유의"가 뜹니다.
- 이 초안의 명세 조합은 **이 도구가 정의한 것**이지 연구계획서에 사전 명시한 것이 아닙니다. 문장 초안에도 그렇게 적혀 있으니, 논문에는 어느 것이 사전 명시였는지 직접 밝혀 주세요.
- 예제 데이터 4종은 **전부 합성**입니다. 실제 환자 자료가 아닙니다(`examples/_예제생성.py` 로 시드 고정 재생성 가능). `examples/joinaudit_merged.csv` 는 `joinaudit` 산출물과 같은 스키마(UTF-8 BOM, `subject_id`, `<파일>_<열>` 접두)로 만든 피험자당 1행 표이며, 열 이름이 `isi_arm`/`isi_isi_total` 인 것도 그 관례 그대로입니다.
- **N ≈ 2,000 이상은 느립니다.** leave-one-out 이 O(N × 뒤집힌 시나리오) 라서, N=2,000 · 뒤집힘 다수면 1분 가까이 걸립니다(기본 상한 `--loo-max-n 2000`, `--loo-budget 20000`). 그 규모에서는 애초에 1명 제외로 결론이 바뀌지 않으므로 `--loo-max-n 0` 로 끄는 편이 낫습니다.
- **macOS 가 만든 한글 CSV(NFD)** 는 읽을 때 NFC 로 정규화합니다. 정규화하지 않으면 화면에 똑같아 보이는 `치료군` 이 두 개의 군이 되고, 같은 피험자가 두 명으로 들어옵니다.
- `longistat` 에도 결측 민감도(관측/LOCF/BOCF)가 있습니다. **반복측정 자료에서 결측 처리만 흔들고 싶다면 `longistat`** 이 맞고, **단일 시점 주 분석 하나를 네 축으로 흔들려면** robustcheck 입니다.
- 뒤집힘 0건이 두 번 연속 나온다면, 당신의 데이터는 이미 충분히 튼튼하고 이 툴은 없어도 됐던 것입니다. 그때는 접는 게 맞습니다 — 민감도 분석 문단 초안만 챙기고 닫으세요.
