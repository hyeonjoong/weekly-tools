# robustcheck 빠른 사용법

## 0) 이 툴을 언제 여는가

**Results 문단을 쓰기 직전**, 그리고 **리비전 응답서를 쓸 때** 엽니다.

`p = .043` 을 보고 "저 한 명 빼면 .08 되는 거 아냐?" 라는 생각이 스쳤다면 그때가 이 툴을 열 때입니다.
확인은 3초면 끝나고, 안 하면 4개월 뒤 Reviewer 2 가 대신 물어봅니다.

> ⚠ **이 툴은 '가장 유의한 조합'을 골라 주지 않습니다.** 뒤집히는 조합을 보여 줄 뿐입니다.
> 그중 마음에 드는 걸 골라 논문에 쓰면 p-해킹입니다. 이름이 뜬 피험자도 '빼야 할 사람'이 아닙니다.

## 1) 가장 빠른 방법 — `실행.command` 더블클릭

폴더 안의 **`실행.command`** 를 더블클릭하면 합성 예제 3종으로 툴이 실제로 어떻게 동작하는지 보여 줍니다
(견고 케이스 / 취약 케이스 / 판정불가 케이스 + 주 분석을 안 줬을 때의 거절).

## 2) 내 데이터로 돌리기

터미널에서 폴더로 들어간 뒤 한 번만 설치합니다.

```bash
cd ~/Downloads/02_프로젝트/깃헙/robustcheck-결과견고성점검
python3 -m pip install -e .
```

그다음:

```bash
# 군간 비교 — 4주차 ISI 를 군끼리 비교했고, 기저 ISI 로 보정했다면
robustcheck 내데이터.csv --design two-group --group arm --value isi_week4 \
    --covariate-baseline isi_baseline --out-dir 결과

# 전후 비교 — 같은 사람의 기저 vs 4주차
robustcheck 내데이터.csv --design paired --pre isi_baseline --post isi_week4 --out-dir 결과

# 상관 — RMSSD 와 ISI 가 관련 있다고 썼다면
robustcheck 내데이터.csv --design corr --x rmssd_ms --y isi_week4 --out-dir 결과
```

CSV 는 **1행 = 1피험자** 여야 합니다. 첫 열은 `subject_id`(다르면 `--id 열이름`), 결측은 빈 칸으로 두면 됩니다.
`joinaudit` 의 `merged.csv` 를 그대로 넣어도 되고, 시점이 여러 행으로 들어 있으면 `--timepoint timepoint=week4` 로 한 시점을 고릅니다.
한글 CSV(cp949)도 그대로 읽습니다.

## 3) 결과 읽는 법

화면과 `결과/견고성점검.md` 에 같은 리포트가 나옵니다. 위에서부터 이렇게 읽습니다.

1. **`[기준선]`** — 당신이 지정한 주 분석의 결과입니다. **한 줄만** 나옵니다.
   이건 "결과"가 아니라 기준점입니다. (검정을 골라 주는 툴이 필요하면 `statwise` 를 쓰세요.)
2. **`[시나리오 전수 대조]`** — 이상치·결측·검정·로그변환을 흔들어 본 전수 결과 중 **뒤집힌 것만** 나옵니다.
   `치명` 은 유의성이 사라졌거나 효과 방향이 뒤집힌 것, `경고` 는 효과크기 등급이 바뀐 것입니다.
   **정렬은 뒤집힘 여부 순이며 p 순이 아닙니다.**
3. **`[Leave-one-out]`** — 한 명씩 빼 본 결과입니다. `⚠ 단독으로 결론을 뒤집음` 이 붙은 사람이 있으면
   그 사실을 **논문에 그대로 쓰세요**. (그 사람을 빼라는 뜻이 절대 아닙니다.)
4. **`[커버리지 자백]`** — 몇 개를 계산했고 몇 개를 왜 못 했는지. 이 블록이 없으면 리포트가 아예 출력되지 않습니다.
5. **`판정:`** — `견고` / `주의` / `취약` / `판정불가`. 산출식이 바로 위에 인쇄되어 있습니다.

`견고성점검.md` 맨 아래에는 **민감도 분석 문단 초안(한/영)** 이 있습니다. 리뷰어 응답서에 그대로 붙일 수 있고,
실제로 돌린 숫자만 들어갑니다.

## 4) 실전 예 3가지

```bash
# ① SERENE 1차 지표가 진짜 버티는지 (투고 전)
robustcheck 분석표.csv --design two-group --group arm --value isi_change --out-dir 투고전점검

# ② Reviewer 2 가 "소수 피험자가 결과를 끌고 간 것 아니냐"고 물었을 때
robustcheck 분석표.csv --design two-group --group arm --value isi_week4 --out-dir 리비전
#   → 피험자영향.csv 를 그대로 supplementary 로 붙이고, 견고성점검.md 의 EN 초안을 응답서에 붙입니다.

# ③ 유의수준을 .01 로 잡은 논문이라면
robustcheck 분석표.csv --design corr --x rmssd_ms --y sws_min --alpha 0.01 --out-dir 결과
```

## 5) 종료코드

| 코드 | 뜻 | 그때 할 일 |
|---|---|---|
| 0 | 견고 / 주의 (치명 0건) | 민감도 분석 문단만 챙겨 넣고 진행 |
| 1 | **취약** | 뒤집히는 조건을 논문에 정직하게 보고. 결론 문장의 강도를 낮출지 판단 |
| 2 | 입력·인자 오류 | 메시지가 무엇이 빠졌는지 알려 줍니다 (`--design` 은 반드시 필요) |
| 3 | 판정 불가 | 유효 N < 6 이거나 계산된 시나리오 < 5. 견고성 이전에 자료를 먼저 확인 |

## 6) 자주 막히는 곳

- **"피험자 ID 가 중복입니다"** → 시점별 long 포맷입니다. `--timepoint 열=값` 으로 한 시점을 고르세요.
- **"군이 정확히 2개여야 합니다"** → 3군 이상은 이 툴의 범위가 아닙니다(`statwise`).
- **"--design 이 필요합니다"** → 일부러 그렇습니다. 이 툴은 검정을 골라 주지 않습니다.
- **"로그변환 불가" 가 절반을 차지함** → 값에 0 이나 음수가 있습니다. 정상이며, 사유가 자백 블록에 남습니다.
- **`±3SD` 로 아무도 안 빠짐** → n ≤ 10 에서는 수학적으로 불가능합니다(최대 |z| = (n−1)/√n < 3). 리포트가 그렇게 말해 줍니다.

궁금한 세부는 `README.md`, 적대적 검토 이력은 `HARDENING.md` 에 있습니다.
