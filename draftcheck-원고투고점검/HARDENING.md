검토자: ① 정확성 감사 ② 엣지케이스 파괴자 ③ 문서 정직성·유용성 비평 ④ 안전성·테스트 품질 감사.
④는 툴 폴더를 `/tmp`에 복사해 **변이 테스트 52건**을 수행했다(37건 사멸, 등가 변이 제외 시 약 76%).

검토 시작 시점: 테스트 194개 통과. 검토 종료 시점: **테스트 274개 통과**.

### 가장 중요한 발견 — 대표 점검이 사용자의 진짜 원고에서 죽어 있었다

③이 사용자의 실제 BELL-001 원고로 돌려 본 결과, 참고문헌 31개가 멀쩡히 있는데도
**"점검 불가"** 가 떴다. 원인은 제목 한 줄이었다.

```
References (Vancouver style; 번호 유지, 추가된 것들 최종적으로 정리필)
Introduction / ref26 to be deleted later
Discussion 가설이 많아서 어렵지만 일단 굵직한걸 적음
```

작업 중인 원고의 제목에는 **메모가 붙는다.** `heading_key` 는 정확히 일치할 때만 제목으로 봤기 때문에
참고문헌 섹션을 놓쳤고, 인용 교차 대조가 통째로 실행되지 않았다. 초록도 서론까지 삼켜
**초록 1,126단어**(실제 약 280)를 사실처럼 출력했다.

→ 제목이 정확히 안 맞으면 **뒤에 붙은 메모(괄호·슬래시·대시·한글 주석)를 떼고 한 번 더** 대조하도록
고쳤다. 문장을 제목으로 오인하지 않도록 마침표로 끝나는 줄은 제외한다.
같은 원고에서 **치명 17건**(존재하지 않는 문헌을 가리키는 인용 8건, 한 번도 인용되지 않은 문헌 9건)이
드러났다 — 정확히 리뷰어가 지적할 부류다. (`docio.py: heading_key`, `tests/test_hardening.py`)

### 조용히 통과시키던 경로 (이 툴이 가장 하면 안 되는 일)

| 발견 | 결과 | 조치 |
|---|---|---|
| 구조화 초록의 소제목(`Background`/`Methods`…)이 섹션 제목과 같아 초록이 0줄이 됨 | 초록 0단어로 **조용히 통과**, 표본수 대조가 사라짐 | 뒤에 같은 절이 또 나오는 라벨을 따라 초록 경계를 되살림. 그래도 비면 "초록을 읽지 못했습니다"로 **명시 보고**하고 관련 점검을 건너뜀 |
| 인용 번호를 3자리로 제한 (`\d{1,3}`, 값 ≤ 300) | 체계적 문헌고찰에서 `[350]` 이 목록에 없어도 **아무 말 없이 통과**. 반대로 500개 목록에서는 200건의 거짓 "미인용문헌" | 번호 4자리·값 2000까지, 범위 폭 300까지 허용 |
| 자기 커버리지 보고("인용 N개 인식")가 교차 대조를 못 할 때만 사라짐 | 사용자가 "목록이 딴 파일이라 정상"인지 "파서가 깨진 것"인지 구별 불가 — **가장 필요한 순간에 사라짐** | 항상 출력하도록 이동 |
| 깊게 중첩된 `.docx` XML → `RecursionError` 트레이스백, 종료 코드 **1** | 스크립트가 "치명 결함 발견(1)"과 "툴이 죽음"을 구별할 수 없음 | 깊이 200 제한 + 깔끔한 한국어 오류 + 종료 코드 2 |
| `word/footnotes.xml` 하나가 깨지면 원고 전체 점검이 중단 | 각주 때문에 본문을 못 봄 | 선택 파트는 메모만 남기고 계속 |

### 거짓 양성 (한 건이면 이 툴은 두 번 다시 안 열린다)

- `N = 45.` 문장 끝 마침표 때문에 인식 실패 → **거짓 치명** "초록의 45가 본문에 없음". 전방탐색 수정.
- 초록의 선별 인원("We screened 60 patients") 을 표본수로 셈 → 거짓 치명. 선별/제외/모집 문맥 제외.
- Springer `Table 1 Baseline…` / Nature `Figure 1 | Flow` 캡션을 인식 못 해 **거짓 치명 2건**. 구분자 확장.
  단, `Table 1 shows the…`(소문자로 이어지는 본문 문장)는 캡션이 아니어야 하므로 **대문자 조건**을 넣었다.
  (이 조건은 `re.IGNORECASE` 때문에 처음에 무력화됐다 — 자체 테스트가 잡아 `(?-i:[A-Z])` 로 고쳤다.)
- 로마숫자 표(`Table I`)는 캡션만 인식하고 언급은 못 해 표마다 거짓 치명 → 언급에도 로마숫자 지원.
- 한국어 "지표 3개", "발표 2회", "목표 5개"의 **'표'가 표 번호로** 잡힘 → 앞 한글·뒤 단위 차단.
- LaTeX `Figure~1` 이 언급으로 안 잡혀 거짓 치명 → 묶음 공백 허용.
- 앞머리 계수 줄 `Figures 5; tables 2` 하나가 **경고 5건**을 만듦 → 복수형은 번호 2개 이상 요구.
- 알파 선언의 흔한 표현(`two-sided`, `taken to indicate significance`)을 결과 문장으로 오인 → 패턴 추가.
- 그림 범례의 `*p < 0.05, **p < 0.01` 과 표 셀의 p값에 경고가 붙음 → 표·캡션·범례는 경고 대상에서 제외.
  (`p = 0.000` 같은 치명은 표 안에서도 계속 잡는다 — 테스트로 고정.)
- `CBT-I`가 `CBT`로 잘려 "정의 없음", `BELL-001`이 **`BELL-00`** 으로 보고돼 `--abbrev-ok`로도 끌 수 없었음
  → 접미부까지 한 토큰으로.
- 번호 없는 참고문헌 목록에서 `van der Berg…`(소문자 시작)와 저자 14명짜리 긴 항목이 **병합**되어
  개수가 틀리고 거짓 "인용누락"이 생김 → "앞 항목에 이미 연도가 있는가"로 판정.

### 소음 (진짜 경고를 묻는다)

실제 원고 한 편에서 **경고 34건 중 27건이 약어**였고, 그 대부분이 감사의 글의 **저자 이니셜**(CM, DJ, EC)과
학회·데이터베이스 이름(PROSPERO, MEDLINE, AASM)이었다.

- 감사의 글·저자 기여·이해상충 절을 약어 검사에서 제외.
- "끝까지 정의 없음"은 고유명사와 구별할 방법이 없으므로 **경고 → 정보**로 낮추고 사용 3회 이상으로 상향.
  ("정의보다 먼저 사용"은 확실하므로 경고 유지.)
- 인용 순서 역전이 4곳 이상이면 원인은 하나이므로 **한 건으로 합쳐** 보고.
- '점검 불가'가 상자와 치명 목록에 **두 번** 세어져 원고 결함이 아닌 것이 "치명 1건"으로 보였음 → 분리 집계.

실제 원고 두 편 기준: 경고 47 → 24, 22 → 6.

### 안전

- **CSV 수식 인젝션**: 검토자가 `=`, `@`, `+`, `-`, `\cite{=EVILKEY}`, 선행 TAB/CR 등 모든 경로를 시도해
  뚫지 못했다. 다만 `"\t=1+1"` 처리 순서에 사각이 있어 제어문자 제거 후 판정하도록 정리하고 테스트 추가.
- **터미널 제어문자**: 원고 안의 ESC 시퀀스가 콘솔·리포트·CSV로 그대로 나가 화면을 지우거나 터미널 제목을
  바꿀 수 있었다 → 출력 경로 전체에서 제어문자 제거(`sanitize`).
- **출력이 원고를 덮어씀**: 원고 이름이 하필 `점검결과.md` 이면 산출물이 원고를 파괴했다(자료 손실).
  또 `--out-dir` 안에 심볼릭 링크가 놓여 있으면 링크를 따라 바깥에 썼다 → 둘 다 거부.
- **XML 폭탄 가드 우회**: DTD/ENTITY 검사가 앞 4KB만 봐서 긴 주석으로 밀어내면 통과했다 → 전체 검사.
- **메모리 증폭**: 338KB짜리 `.docx`가 RSS 1.17GB를 썼다(압축 해제 한도 400MB가 과도) → 40MB로.
- **`--limits`**: `Infinity`/`NaN` 은 `OverflowError` 트레이스백, CP949로 저장된 한도 파일은
  `UnicodeDecodeError` 트레이스백 → 둘 다 깔끔한 오류로. (원고와 같은 인코딩 폴백 사용.)
- **BrokenPipe**: README가 안내하는 `--dump-text | less` 에서 less 를 먼저 닫으면 트레이스백 → 조용히 종료.
- **`--out-dir ""`**: 아무것도 안 쓰고 성공(0)으로 끝나 사용자를 속임 → 오류.
- 네트워크·텔레메트리 0건, 원고를 쓰기 모드로 여는 경로 없음, 경로 순회 불가는 재확인됐다.

### 성능

- `sentences()` 가 O(n²) — `"A vs. B vs. …"` 가 이어진 1MB 한 줄에 **27초**. 누적 문자열 대신
  직전 조각만 검사하도록 바꿔 선형화(테스트로 고정).
- 참고문헌 번호 중복 검사의 `list.count` 가 O(n²) → `Counter`.

### 표시

- '점검 불가' 상자가 한글 폭 계산을 안 해 **오른쪽 선이 20칸 튀어나왔다**(이 툴의 간판 기능인데도).
  `east_asian_width` 기준으로 다시 계산.
- 줄바꿈 함수가 앞 들여쓰기를 지워 애써 맞춘 줄번호 정렬이 화면에서 전부 왼쪽에 붙었다 → 보존.
- 폭을 문자 수로 계산해 80칸 터미널에서 실제 103칸까지 나갔다 → 터미널 폭에 맞춤(60~100).
- 한국어 조사 오류(`표 2을`, `48가`, `이(가)` 자리표시자) → 받침 판정 함수로 교체(숫자 읽기 포함).

### 문서

- README의 "실제 출력"이 **손으로 다듬은 것**이었다. 이 툴의 명분이 "조용히 얼버무리지 않는다"이므로
  가장 먼저 고쳐야 할 정직성 결함이다 → 실행 결과를 그대로 붙여 넣었다.
- `references.csv`가 citecheck 스키마와 "동일"하다고 썼지만 `parse_ok` 열이 하나 더 있다 →
  "citecheck가 그대로 읽는 형식"으로 정정.
- `실행.command` 가 실행하지 않는 명령을 출력하고 있었다 → 실제 경로를 출력.

### 테스트 (변이 테스트가 드러낸 구멍)

- `_citing_lines` 의 참고문헌 제외는 **교차 대조 전체를 떠받치는 한 줄인데 테스트가 없었다.**
  번들 예제가 `1. Author…` 형식뿐이라, 제외를 지워도 194개가 전부 통과했다.
  `[1] Author…` 형식 목록으로 회귀 테스트 추가.
- `test_markdown_report_escapes_pipes` 가 **무의미**했다(픽스처에 파이프가 든 셀이 아예 없었고,
  단언식도 표 구분자를 세고 있었다) → 특정 셀을 직접 검사하도록 교체.
- 결과 절단 요약(`_cap`), 키워드 줄 제외, UTF-16 원고, `.tex`/`.txt`/저자-연도/`\cite` 스타일의
  **깨끗한 대조본**에 테스트가 없었다 → 전부 추가.

**남은 알려진 한계** (문서화됨, 결함 아님): 저자-연도 스타일은 2급 지원이며 매칭률을 스스로 보고한다.
`.docx`의 줄번호는 문단 번호다. 표본수 점검은 초록→본문 한 방향만 본다.
