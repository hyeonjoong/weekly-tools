# HARDENING — stimaudit 적대적 검토 기록

이 툴은 사람 검토 없이 배포되므로, 기획서가 요구한 대로 **실제 서브에이전트**로
적대적 검토를 돌리고 그 결과를 여기에 남깁니다. 라운드 0 은 코드를 한 줄도 쓰기
전에 한 실측입니다 — 기획서 "실패할 수 있는 지점" 1번이 이 툴 전체의 전제였기 때문입니다.

## 라운드 0 (2026-08-28) — 코드 이전의 10분: "정말 어긋나 있는가?"

기획서의 첫 번째 실패 시나리오는 **"사운드 담당자가 이미 음량을 맞춰 놨다"** 였습니다.
요즘 DAW 는 −14/−16 LUFS 라우드니스 노멀라이즈가 기본이라, 만약 실물 자산이 이미
0.5 LU 안에 들어와 있다면 이 툴은 매번 "치명 0건"만 뱉고 두 번 다시 안 열립니다.
그래서 **한 줄도 쓰기 전에** `ffmpeg -af ebur128` 로 실물을 재 봤습니다.

| 세트 | 파일 | 통합 라우드니스 | 트루피크 |
|---|---|---|---|
| RESONATE (4조건, `S3_pink` 가 대조군) | `S1_SO-CLAS.wav` | **−20.2 LUFS** | **+1.5 dBTP** |
| | `S2_spindle-target.wav` | −26.1 LUFS | −13.0 |
| | `S3_pink.wav` (대조군) | **−31.8 LUFS** | −15.7 |
| | `S6_breath-pacing.wav` | −29.7 LUFS | −22.7 |
| OPGG v1 (2026-07-29) | `bi_(360-400Hz).wav` | −8.2 LUFS | −7.5 |
| | `uplift_02.wav` | −19.5 LUFS | −5.8 |
| OPGG v2 싱잉볼 (2026-08-03) | `싱잉볼_bi_(360+400Hz).wav` | −16.2 LUFS | −1.4 |

**결론: 가설이 맞았고, 예상보다 훨씬 심했습니다.**

- RESONATE 의 활성 조건 `S1_SO-CLAS` 와 대조군 `S3_pink` 는 **11.6 LU** 차이입니다.
  0.5 LU 는커녕 자릿수가 다릅니다. 이 세트로 나온 결과에서 "SO-CLAS 가 효과 있다"는
  **"소리가 더 컸다"와 원리적으로 구분되지 않습니다.**
- `S1_SO-CLAS.wav` 는 16비트 파일인데 **트루피크가 +1.5 dBFS** 입니다 — 표본이 만점에
  붙어 잘려 있다는 뜻입니다(나중에 자체 구현이 클리핑 구간 33곳·143샘플로 확인).
- OPGG v1 5개는 −8.2 ~ −19.5 LUFS 로 **11.3 LU** 산포. v2 싱잉볼 3개는 −14.9 ~ −16.2 로
  **1.3 LU** 산포 — 즉 새 버전이 실제로 나아졌고, 그 사실이 파형을 눈으로 봐서는 보이지 않습니다.

기획서가 지시한 대로 이 결과를 근거로 **① 레벨 매칭을 이 툴의 심장으로 유지**했고,
기본 문턱은 실측 분포를 보고 **좁게**(경고 1.0 LU · 치명 2.0 LU) 못 박았습니다.

## 라운드 0.5 — 자체 구현 검증 (구현 첫날, 기획서 실패지점 5번)

기획서는 "BS.1770 구현이 미묘하게 틀리면 나머지 전부가 거짓 정밀도가 된다,
≤0.1 LU 가 안 나오면 그 자리에서 멈추고 계수부터 고쳐라" 라고 지시했습니다.
실제로 **그 자리에서 멈춰야 했습니다.**

**발견 A — K-weighting 고역선반 공식이 틀렸음 (0.25 LU 전역 편향).**
일반적인 RBJ 고역선반 공식으로 유도했더니 1 kHz 응답이 +0.4382 dB 였는데
BS.1770-4 표의 값은 **+0.6977 dB** 였습니다. 차이 0.2595 dB 가 그대로 모든 LUFS 에
실려 1 kHz 사인이 −20.00 대신 **−20.25 LUFS** 로 나왔습니다. ITU/libebur128 유도식
(`Vh = 10^(G/20)`, `Vb = Vh^0.4996667741545416`, `K = tan(pi*f0/fs)`)으로 바꾸자
계수가 BS.1770-4 의 48 kHz 표와 **8.9e-16** 까지 일치했습니다.
→ `tests/test_filters.py::test_k_weighting_matches_itu_table_at_48k` 로 고정.

**발견 B — A-weighting 이 대역통과가 아니라 저역통과 모양이었음 (최대 30 dB 오차).**
6차 전달함수를 통째로 쌍선형 변환한 뒤 근을 찾아 SOS 로 분해했는데, 20.6 Hz 이중극점이
z=1 에 너무 가까워 근 찾기가 무너졌고 분자의 s⁴ 영점이 사라졌습니다. 100 Hz 에서
규격 −19.1 dB 대신 **+0.85 dB** 가 나왔습니다. 아날로그 단계에서 **이미 인수분해된
2차 섹션 3개를 각각** 변환하는 방식으로 바꾸자 4 kHz 까지 0.13 dB 이내로 맞았습니다.
→ `tests/test_filters.py::test_a_weighting_matches_iec_61672_up_to_4khz`,
  `::test_a_weighting_shape_is_bandpass` 로 고정.

**발견 C — 다이내믹 레인지가 2290 dB 로 나옴.**
앞뒤에 디지털 무음이 붙은 파일에서 100 ms 창 레벨의 5 백분위가 −2300 dB 로 내려가
p95−p5 가 수천 dB 가 됐습니다. 무음/암소음 창(LAmax − 60 dB 미만)을 제외하도록 고쳤습니다.
→ `tests/test_levels.py::test_dynamic_range_excludes_digital_silence`.

**발견 D — 클리핑된 파일에서 트루피크를 0.9 dB 과소평가.**
후보 창을 최소힙에 모았다가 마지막에 보간하는 방식이었는데, 표본이 정확히 만점(1.0)에
붙으면 동점 후보가 수천 개 나와 힙이 먼저 들어온 것들로 가득 차고 **실제로 가장 크게
튀는 지점(인덱스 82575)이 버려졌습니다.** 보류하지 않고 즉석에서 보간하고, 클리핑 문턱을
넘는 표본은 전부 추가 후보로 넣도록 고쳤습니다. `S1_SO-CLAS.wav` 에서 +0.61 → **+1.54 dBTP**
(ffmpeg 값 +1.5).
→ `tests/test_analyze.py::test_true_peak_on_clipped_file_exceeds_zero`.

**발견 E — 정상 톤이 "주기적으로 변조된 자극"으로 오인됨.**
파일 양끝의 페이드인/아웃 자체가 파일 길이만큼 긴 초저주파 변조로 보여, 8초짜리 정상
톤(20 ms 페이드)에서 0.014 Hz 가 상대강도 0.96 으로 잡혔습니다. 포락선 FFT 의 하한을
`1.5주기 / 길이` 로 올리고, 주장 대조는 **실측 변조율에 3주기 이상 들어갈 때만** 판정하도록
바꿨습니다(못 재면 값을 지어내지 않고 판정불가).
→ `tests/test_claims.py::test_mod_claim_on_steady_tone_is_undecidable`.

**발견 F — `0.00 dBFS` 가 `nan` 으로 인쇄됨.**
`m.sample_peak_dbfs or float("nan")` — 표본 피크가 정확히 0.0 dBFS(클리핑된 파일의
정상적인 값)일 때 falsy 로 걸려 "표본 피크 nan dBFS" 가 나왔습니다.
→ `setcheck._db_text()` 로 교체.

**발견 G — 한국어 표 정렬이 어긋남.**
`"{:<14s}".format()` 은 **문자 수**로 채워서 한글이 2칸을 차지하는 터미널에서 열이
밀립니다. `unicodedata.east_asian_width` 기반 `lj/rj/clip` 으로 전부 교체했습니다.
(그 뒤에도 `트루피크 여유 부족B_clipped_dc.wav` 처럼 유형 칸이 딱 맞아 공백이 사라지는
경우가 있어 칸 너비를 18 → 20 으로 넓혔습니다.)

**발견 H — 하드링크 검사 전에 파일을 비워 버림.**
`os.open(..., O_TRUNC)` 를 먼저 주는 바람에, 산출물 자리에 하드링크가 있으면 거절은
하지만 **원본은 이미 0바이트가 된 뒤**였습니다. `O_TRUNC` 를 빼고 `fstat` 로 `st_nlink`
를 확인한 **뒤에** `ftruncate` 하도록 순서를 바꿨습니다.
→ `tests/test_safeio.py::test_hardlinked_artifact_refused` 가 내용 보존까지 검사.

**발견 I — CSV 수식 인젝션이 앞 공백으로 우회됨.**
`" =cmd|..."` 는 앞 문자가 공백이라 통과했는데 Excel 은 앞 공백을 무시하고 수식으로
읽습니다. 판정 전에 `lstrip(" ")` 하도록 고쳤습니다.

## 라운드 1 (2026-08-28) — 서브에이전트 4종 병렬 검토

Agent 툴로 실제 서브에이전트 4개를 **병렬** 기동했습니다:
① 정확성 감사(제1원리 재계산 + ffmpeg 교차검증) ② 엣지케이스·견고성 파괴자
③ 문서 정직성 + 유용성 비평 ④ 안전성 + 테스트 품질 감사(뮤테이션 테스트 포함).

네 명이 돌려준 것은 "대체로 괜찮습니다"가 아니었습니다. **툴의 치명 판정 네 축 중
셋에서, 정확히 그 판정이 필요한 상황에 침묵하는 경로**가 나왔습니다.

### 발견 J — 파일 **전체**가 클리핑된 자극이 "클리핑 0건"으로 통과 (정확성 감사)

`_scan_clipping` 은 문턱 아래 샘플이 나와야 구간을 닫습니다. 그래서 마지막 샘플까지
만점에 붙어 있는 파일(= 완전히 뭉개진 렌더, 이 검사가 존재하는 바로 그 병리)은
구간이 열린 채로 버려졌습니다. 3초짜리 사각파 전체가 `clip_run_count = 0` 이었고
경고는 "트루피크 2.1 dBTP" 하나뿐이었습니다.
→ 블록 루프 뒤에 열린 구간을 닫습니다. `tests/test_round1_fixes.py` 의 EOF 구간
테스트 7종(최소길이 1/2/3/17샘플 · 중복계수 금지 · 블록크기 4종 불변)으로 고정.

### 발견 K — 핑크노이즈 대조군에 **가짜 반송주파수**가 붙음 (정확성 감사)

두드러짐(prominence)을 `최대빈 / 전체빈 중앙값` 으로 쟀는데, 1/f 스펙트럼은
최대 빈이 맨 아래·중앙값 빈이 한가운데라 이 값이 사실상 **스펙트럼 기울기**였습니다.
번들 예제의 핑크노이즈가 32.3 dB 로 "뚜렷한 반송음 있음" 판정을 받았고,
`carrier_hz` 주장이 걸리면 **"실측 5.38 Hz"** 라는 지어낸 숫자로 치명이 떴습니다.
스테레오 잡음에서는 좌우 피크 차로 **없는 맥놀이 2.70 Hz** 까지 만들어 냈습니다.
대조군이 핑크노이즈인 실험에서 이건 오작동이 아니라 **대조군을 거짓으로 기소하는 것**입니다.
→ 피크 탐색에 가청 하한(20 Hz)을 두고, 두드러짐을 **국소 이웃(±1 옥타브, 피크 스커트 제외)**
대비로 바꿨습니다. 실측 분포가 잡음 2.7~6.0 dB / 음높이 있는 자극 94~119 dB /
실제 음악 트랙 17.4 dB 로 갈라져, 문턱을 그 사이 빈 구간인 **12 dB** 로 올렸습니다.

### 발견 L — NaN 한 샘플이 **핵심 판정을 조용히 껐음** (엣지케이스 파괴자)

32비트 float WAV 에 NaN 이 하나 들어가면 라우드니스가 NaN → `lufs_i = None` 이 되고,
그 조건은 대조에서 통째로 빠졌습니다. **같은 오디오에서 NaN 한 샘플의 유무가
exit 1 ↔ exit 0 을 뒤집었습니다.** 전 구간 NaN 인 파일은 "전 구간 무음"이라는
**틀린 진단**을 받아, 사운드 담당자가 NaN 을 만드는 체인 대신 무음을 고치러 갔을 것입니다.
→ 유한하지 않은 표본이 나오면 그 파일을 **못 읽은 것으로 세고 exit 3**.

### 발견 M — 400 ms 미만 자극이 음량 판정을 통째로 끔 (엣지케이스 파괴자)

BS.1770 게이팅 블록이 하나도 안 나오는 짧은 파일은 LUFS 가 정의되지 않는데,
`d is None` 을 "허용 안"과 **똑같이** 건너뛰고 있었습니다. LAeq 표에는 38.5 dB 차이가

### 발견 N — 완전히 죽은 채널만 좌우 검사를 빠져나감 (엣지케이스 파괴자)

잡히는데 **가장 나쁜 경우만** 조용했습니다.
→ 죽은 채널을 `죽은 파일` 치명으로 잡습니다(새 등급을 만들지 않고 기존 네 축 안에서).

### 발견 O — 인코딩 사고가 "치명 발견"으로 보고됨 (엣지케이스 파괴자)

### 발견 P — 산출물이 **입력 파일을 파괴** (안전성 감사 A1)

심볼릭·하드 링크는 막고 있었는데 "이 경로가 이번 실행의 **입력**인가"는 묻지 않았습니다.

→ 입력 WAV·설계 JSON·매니페스트·기준 폴더 파일을 전부 '덮어쓰기 금지'로 등록하고,

### 발견 Q — 파일 이름의 개행으로 **가짜 `[치명]` 줄을 심을 수 있음** (안전성 감사 A2)

찍히고 맨 아래 결론은 "치명 0건" 이었습니다.

### 발견 R — 낮은 샘플레이트에서 LAeq 300 dB (엣지케이스 파괴자)

A-가중은 1 kHz 에서 0 dB 가 되도록 이산영역에서 재정규화하는데, fs 가 낮아 1 kHz 가
나이퀴스트에 붙으면 그 지점 응답이 −400 dB 라 정규화 계수가 10^20 으로 폭주합니다.
물리적으로 불가능한 값(dBFS > 0)이 표에 인쇄됐습니다.
→ `MIN_A_WEIGHTING_FS = 8000` 미만에서는 **아예 계산하지 않고** 자백합니다.

### 발견 S — 리포트가 자기 산수를 설명하지 못함 (문서 정직성 비평)

헤드라인은 5.7). → 조건 평균과 최악 쌍을 **함께** 인쇄합니다.

### 발견 T — 문장초안이 못 읽은 파일을 숨김 (문서 정직성 비평 P0/P1)

읽지 못한 파일이 있어도 초안에는 아무 경고 없이 **"모든 자극의 길이는 3.0초였다"**
가 들어갔습니다. 사용자가 원고에 그대로 붙이라고 안내받는 바로 그 파일에서요.

**"조건 간 최대 차이"** 라고 써서, 하지 않은 실험 통제를 했다고 주장했습니다.
