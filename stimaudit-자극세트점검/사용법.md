# 사용법 (빠른 시작)

## 0. 제일 빠른 길

`실행.command` 를 **더블클릭**하세요. 번들된 합성 예제 3세트로 전체 흐름이 한 번 돕니다
(맞은 세트 → 어긋난 세트 → 판정불가 세트). 뭐가 나오는지 30초면 감이 옵니다.

## 1. 내 자극 파일로 훑어보기 (판정 없음, 파일 안 만듦)

```bash
stimaudit 내자극폴더/*.wav --inspect
```

무엇이 얼마나 어긋났는지 **값만** 보여줍니다. 조건을 모르니 판정은 하지 않습니다.
`stimaudit` 이 없다고 나오면 `python3 -m stimaudit` 로 바꿔 쓰면 됩니다.

## 2. 설계 JSON 만들기

```bash
stimaudit 내자극폴더/*.wav --inspect --emit-design > 설계.json
```

`--emit-design` 은 표준출력을 JSON 전용으로 씁니다(리포트는 화면에 그대로 나옵니다).
나온 `설계.json` 을 열어 **조건별로 파일을 나눠 담으세요**. 이게 이 툴의 핵심 입력입니다.

```json
{
  "study": "RESONATE-pilot",
  "conditions": {
    "active":  ["S1_SO-CLAS.wav", "S2_spindle-target.wav"],
    "control": ["S3_pink.wav"]
  },
  "claims": {
    "S1_SO-CLAS.wav": { "carrier_hz": 200.0, "duration_s": 20.0 }
  }
}
```

- `conditions` — 어느 파일이 어느 조건인가. **대조군을 반드시 넣으세요.**
- `claims` — 설계서가 주장하는 값. 넷만 지원합니다: `carrier_hz`(반송주파수),
  `beat_hz`(좌우 맥놀이), `mod_hz`(포락선 변조율), `duration_s`(길이).
  빈 객체 `{}` 로 두면 검사하지 않습니다.
- 파일은 **이름만** 적습니다(경로 X). 러프니스·샤프니스는 여기 못 적습니다 — 이 툴이 재지 않습니다.
- **양이 맥놀이 파일의 `carrier_hz` 는 좌우 평균**입니다. L 360 / R 400 이면 `carrier_hz: 380`,
  `beat_hz: 40` 으로 적으세요. 한쪽 채널 값(360)을 적으면 불일치로 나옵니다.
- `mod_hz` 는 **20 Hz 까지**만 검사합니다. 그보다 빠른 변조는 DEBUSSY 소관입니다.

## 3. 본 판정 + 자극 기술표

```bash
stimaudit 내자극폴더/*.wav --design 설계.json --out-dir 자극점검_202608
```

`자극점검_202608/` 에 6개 파일이 생깁니다(`--manifest` 를 붙이면 `교란후보.csv` 까지 7개).
논문 쓸 때 여는 건 `자극기술표.md` 와 `문장초안.md` 입니다.
**치명이 남아 있으면 `문장초안.md` 맨 위에 "아직 붙이지 마십시오" 경고가 붙습니다** — 그대로 복사해
붙이는 순간 리포트가 잡은 결함이 원고에서 사라지기 때문입니다.

## 4. 새 버전이 나아졌는지 보기

```bash
stimaudit 싱잉볼버전_20260803/*.wav --baseline "OPGG_원우님 사운드/" \
  --design 설계.json --out-dir 버전대조
```

이름이 같은 파일끼리 짝지어 음량·클리핑·길이·포맷이 어떻게 움직였는지 냅니다.
이름이 바뀌었으면 설계 JSON 에 `"pairs": {"새이름.wav": "옛이름.wav"}` 를 적으세요.

## 결과 읽는 법

**맨 아래 한 줄부터 보세요.**

- `치명 N건. 이 상태로 실험에 태우면 안 됩니다.` → 고치고 다시 받으세요.
- `치명 0건 · 경고 N건.` → 경고를 읽고 판단하세요. 대개는 알고 넘어가면 되는 것들입니다.
- `판정불가 — 못 읽은 파일이 N개` → **다 못 들었으므로 "괜찮다"는 결론을 낼 수 없습니다.**

**치명은 넷뿐입니다** (좁게 못 박았습니다):

| 치명 | 왜 |
|---|---|
| 조건 간 음량 차이 > 2.0 LU | "효과"와 "소리가 더 컸다"를 구분할 수 없게 됩니다 |
| 주장 불일치 | 설계서와 실제 자극이 다릅니다 — 논문에 적을 값이 틀립니다 |
| 클리핑 | 파형이 잘려 왜곡이 들어갑니다 |
| 죽은 파일 | 전 구간 무음 / 전 구간 DC / **한 채널이 통째로 무음** — 자극이 (온전히) 전달되지 않습니다 |

**치명이 아닌 판정들도 뜻이 있습니다** (전부 경고 또는 정보):

| 유형 | 뜻 |
|---|---|
| `음량 판정불가` | 그 조건의 통합 라우드니스를 **잴 수 없어 음량 대조에서 뺐습니다**(예: 400 ms 미만 자극). "치명 0건"이 그 조건을 덮지 않습니다 — LAeq 표를 직접 보십시오. |
| `주장 판정불가` | 설계 JSON 의 주장을 신호에서 **확인할 수 없었습니다**(예: 뚜렷한 반송음이 없는 잡음). 값을 지어내지 않습니다. |
| `조건 내 음량 산포` | 같은 조건 파일끼리 2.0 LU 넘게 벌어져 조건 평균이 구성원을 대표하지 못합니다. |
| `길이 불일치` | 세트 안에서 노출 시간이 다릅니다 — 그 자체가 교란 변수입니다. |
| `조건 미지정 파일` | 설계 JSON 의 어느 조건에도 없는 파일 — 위생 점검만 받고 음량 판정에서 빠집니다. |
| `트루피크 여유 부족` | 재생 체인의 리샘플링·코덱에서 클리핑이 생길 수 있습니다. |

**`[정보] 논문 참조값 대조` 는 판정이 아닙니다.** `50 ms`·`0.3 asper`·`60–80 BPM` 같은 숫자는
논문 개정본이 **reference value 로 재라벨**한 것이라, 이 툴은 측정값과 나란히 놓기만 하고
준수/위반을 찍지 않습니다. 파일별 티어 판정이 필요하면 `bell_acoustic_qc.py` 로 가세요.

**`[커버리지 자백]` 을 꼭 보세요.** "검사 안 함" 목록에 무엇이 있는지가
"치명 0건"이라는 문장의 범위를 정합니다. 러프니스·샤프니스는 `--manifest` 없이는 검사되지 않습니다.

## 자주 걸리는 것

| 증상 | 원인 / 해결 |
|---|---|
| `파일이 1개뿐입니다` (종료 2) | 이 툴은 **세트**를 봅니다. 파일 하나는 DEBUSSY / `bell_acoustic_qc.py` 로. |
| `--out-dir 가 필요합니다` (종료 2) | 판정 없이 값만 보려면 `--inspect` 를 붙이세요. |
| `설계 JSON 이 입력에 없는 파일을 가리킵니다` | 설계 JSON 에는 **파일 이름만** (경로 X). 오타도 확인하세요. |
| `서로 다른 폴더에 같은 이름의 파일` | 리포트가 이름으로 대조하므로 구분이 안 됩니다. 한 번에 한 폴더씩 돌리세요. |
| `압축 코덱 … 직접 읽지 못함` (종료 3) | MP3 등은 `ffmpeg` 이 있어야 열립니다. `brew install ffmpeg` 하거나 WAV 로 변환하세요. |
| 진행 표시가 거슬린다 | `--quiet` 를 붙이면 "분석 중 (3/12)" 줄이 사라집니다. |
| `LRA` 가 전부 `—` 다 | 파일이 4초 미만이면 3초 블록이 2개 안 나와 계산하지 않습니다. |
| 매번 경고가 뜬다 | 기본 문턱이 빡빡하면 `--lufs-tol 1.5 --lufs-crit 3.0` 처럼 넓힐 수 있습니다. 다만 **좁히는 쪽이 안전합니다.** |
| 54 MB 파일이 느리다 | 순수 파이썬입니다. 24bit/48k 스테레오 200초 ≈ 13~14초. 파일이 많으면 한 번 걸어두고 커피 드세요. |
