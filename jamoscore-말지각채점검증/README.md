# jamoscore — 말지각검사 채점 엑셀 문항 단위 재계산·정합 점검

사람이 손으로 채점한 **말지각검사(자음·모음·일음절) 문항 단위 엑셀**을 읽어, 요약표의 %를 문항에서 전수 재계산하고, 목표음소 규칙 채점과 사람 채점이 갈리는 문항만 골라내고, 아무도 계산하지 않는 **음소 혼동 행렬**과 **개인 내 변화의 이항 임계차**를 내놓는 오프라인 CLI입니다.

> `tracecheck` 는 원고와 산출물을 대조하고, **`jamoscore` 는 그 산출물이 원 문항에서 다시 나오는지를 봅니다.**

---

## 목적 / Why this exists

**한국어.** 병원(분당서울대·한림대)이나 연구보조원에게서 *채점이 끝난* 엑셀을 받아, 논문 표나 CSR에 넣을 %를 쓰기 직전이 이 툴을 여는 순간입니다. 실제 파일 하나에 피험자 시트가 35개, 문항이 4,688개, 손으로 옮겨 적은 요약 셀이 336개인데 그걸 두 번 검산하는 사람은 없습니다. 그리고 사람 채점은 *생각보다 자기 규칙에 일관적입니다* — 자음·모음 검사 2,169문항을 목표음소 규칙과 대조했더니 갈린 것이 **4문항(0.2%)** 뿐이었습니다. 그러니 문제는 "채점이 엉망인가"가 아니라 **"남은 0.2%와, 아무도 안 보는 4,000문항 밑의 정보가 무엇인가"** 입니다. 청각재활(BELL-002 와우핏) 쪽으로 같은 모양의 엑셀이 계속 들어오고 — 소아 KoBio IRB 승인, 확증임상, K-CNC MCID 델파이 — 그때마다 `--inspect` 한 번이면 구조가 보입니다.

그 실제 파일에서 이 툴이 찾은 것: **요약표에 행이 아예 없는 피험자 7명**(그 표로 논문 표를 만들면 7명이 빠집니다), **한 열이 한 행씩 밀려 붙여넣어진 자리 4곳**(s29 자리에 s30의 값이, s30 자리에 s31의 값이…), 한 발화를 단어 채점과 음소 채점에서 다르게 옮겨 적은 2건, 같은 (제시, 응답)에 서로 다른 점수가 붙은 7종. 시트 안팎의 요약 % 셀 612개 중 나머지는 **전부 맞았습니다** — 이 툴은 그 사실도 소리 내어 말합니다.

**English.** Speech-perception test workbooks arrive already scored by hand: one sheet per participant, thousands of items, and a summary table whose percentages were typed across by a person. Nobody recomputes those percentages, and no Korean package knows the scoring conventions of audiological speech tests (the consonant subtest scores only the medial consonant; the vowel subtest only the first-syllable vowel), so naive string comparison produces dozens of false alarms on correct scoring. jamoscore recomputes every subtest from the items, reconciles the summary cells, flags only the items where a declared target-phoneme rule and the human scorer disagree, and surfaces two things nobody computes today: a jamo-level confusion matrix and an exact-binomial within-subject critical difference. It never edits scores and never runs a group comparison.

**이 툴이 안 하는 것 (코드로 강제):** 점수를 고치지 않습니다(쓰기 경로 부재를 AST 테스트로 확인). "확인 필요"·"동일 쌍 다른 채점" 외의 판정 어휘를 쓰지 않습니다(금지어 테스트). 군간·시점간 검정을 하지 않습니다(검정 함수 부재를 AST로 확인 — 그건 `statwise`·`longistat`의 일입니다). 식별정보 시트는 **열지 않습니다**. MCID를 추정하지 않고, 음원 파일을 보지 않습니다(→ `stimaudit`).

### 인접 툴과의 경계

| 툴 | 입력 | 답하는 질문 |
|---|---|---|
| **jamoscore** | **문항 단위** 채점 엑셀/CSV | "이 %는 문항에서 다시 나오는가? 사람 채점이 자기 규칙에 일관적인가? 어떤 음소를 혼동하는가?" |
| `joinaudit` | 여러 파일 | "붙이는 과정에서 사람이 사라지거나 뻥튀기됐는가?" |
| `tracecheck` | 원고 + 산출물 폴더 | "원고 숫자가 산출물에 있는가?" |
| `statwise` / `longistat` | long CSV | "군/시점 간 차이가 있는가?" |
| `stimaudit` | 자극 **음원 파일** | "들려준 소리들이 서로 비교 가능한가?" |

## 설치

의존성이 **하나도 없습니다**(Python 3.9+ 표준 라이브러리만). 네트워크를 쓰지 않고, 원본 파일을 읽기 전용으로만 엽니다.

가장 쉬운 방법은 이 폴더의 **`실행.command` 더블클릭** — 번들 예제 4종이 순서대로 돌아갑니다.

터미널에서는 설치 없이 그대로 쓸 수 있습니다(아래 예시가 전부 이 형태입니다):

```bash
cd ~/Downloads/02_프로젝트/깃헙/jamoscore-말지각채점검증
python3 -m jamoscore ...
```

`jamoscore` 로 줄여 쓰고 싶으면 `python3 -m pip install -e .` 를 한 번 하세요. 다만 파이썬 설치 위치에 따라 콘솔 스크립트가 `PATH` 에 없을 수 있습니다(`which jamoscore` 로 확인). 없으면 `python3 -m jamoscore` 를 그대로 쓰면 됩니다.

## 사용법

### 1단계 — 먼저 구조부터 본다 (`--inspect`)

**이 툴은 채점 규칙도 문항수도 추론하지 않습니다.** 추론하는 순간 조용히 거짓말을 하기 때문입니다. 그래서 먼저 무엇이 보이는지 인쇄합니다.

```bash
python3 -m jamoscore 본실험_결과.xlsx --inspect \
    --subtest "자음:목표=2음절초성,문항=18" \
    --subtest "모음:목표=1음절중성,문항=14" \
    --subtest "일음절:단위=단어,목표=전체,문항=18" \
    --subtest "일음절:단위=음소,목표=초중종,문항=18,만점=3" \
    --subject-pattern "^s[0-9]+$" \
    --answer-key 언어검사_정답 --summary total-최종
```

(아래 출력은 실제 임상 파일에서 나온 것을 **줄여 옮긴** 것입니다.)

```
[검사 명세]
   자음(단어)           목표=2음절초성        문항=18     만점=1 단위=단어
   모음(단어)           목표=1음절중성        문항=14     만점=1 단위=단어
   일음절(단어)          목표=전체           문항=18     만점=1 단위=단어
   일음절(음소)          목표=초중종          문항=18     만점=3 단위=음소
   시점: 사전, 사후

[입력] 시트 59개 → 피험자 시트 35개 인식
   피험자 시트: s01, s02, s03, s04, s05, s06, s07, s08, s09, s10, s11, s12 …(+23)
   정답 시트: 언어검사_정답
   요약 시트: total-최종
   식별정보로 보여 **열지 않은** 시트: 개인정보
   건너뛴 시트 21개: 목차, Normality, MCI점수_상하집단, 사용시간, …

[블록별 문항수·분모]
   모음       사전   단어    피험자 35명 · 문항수 14(35명) · 분모 14(35명)
   일음절      사전   단어    피험자 35명 · 문항수 18(35명) · 분모 18(35명)
   일음절      사전   음소    피험자 35명 · 문항수 0(2명) / 18(33명) · 분모 0(2명) / 54(33명)
   자음       사전   단어    피험자 35명 · 문항수 18(35명) · 분모 18(35명)
   시트가 스스로 적어 둔 요약 % 셀: 276개
```

> `일음절` 블록의 **분모가 18과 54로 갈린다**는 사실이 여기서 바로 보입니다 — 한 블록을 단어 단위와 음소 단위로 두 번 채점했기 때문입니다. 그 사실은 파일 어디에도 적혀 있지 않습니다.

### 2단계 — 본 실행

`--inspect` 를 빼고 `--out-dir` 을 붙이면 됩니다.

```bash
python3 -m jamoscore 본실험_결과.xlsx \
    --subtest "자음:목표=2음절초성,문항=18" \
    --subtest "모음:목표=1음절중성,문항=14" \
    --subtest "일음절:단위=단어,목표=전체,문항=18" \
    --subtest "일음절:단위=음소,목표=초중종,문항=18,만점=3" \
    --subject-pattern "^s[0-9]+$" \
    --answer-key 언어검사_정답 --summary total-최종 \
    --map 매핑.json \
    --out-dir 채점검증_0911
```

[경고] `개인정보` 시트는 식별정보로 보여 **열지 않았습니다**. 내보내기 전 deidaudit 을 돌리세요.

**이 실행에서 실제로 확인된 것.** 시트 안의 요약 276셀은 **전부 맞았습니다** — 피험자 시트 안에서 손으로 적은 %는 정확했습니다. 문제는 그 위, `total-최종` 표였습니다: **7명은 아예 행이 없고**, `일음절2_차이` 열은 **s29부터 한 행씩 밀려** 있습니다(s29 자리에 s30의 값이…). 그리고 아무도 안 보던 곳에서 한 발화를 두 번 다르게 전사한 2건, 같은 (제시, 응답)에 다른 점수가 붙은 7종, 그리고 음소 혼동 행렬이 나왔습니다.

> **`일음절2_차이` 는 기본 실행에서는 대조되지 않습니다.** 열 이름을 해석할 수 없어 "대조하지 못한 열"로 자백만 하고 넘어갑니다(억지로 맞추면 가짜 불일치가 쏟아지기 때문입니다). 위 실행은 `--map` 으로 그 열이 *음소* 차이임을 알려 준 것입니다:
>
> ```json
> { "요약열": { "일음절2_차이": { "검사": "일음절", "단위": "음소", "종류": "차이" } } }
> ```
>
> 매핑을 틀리게 주면(예: `"단위": "단어"`) 같은 열에서 26건이 어긋나는데, 그때는 개별 소견 대신 **`[치명] 요약표 열 매핑 의심`** 한 건으로 묶어 "자료보다 매핑을 의심하라"고 말합니다.

### `--subtest` 문법

```
검사이름:목표=규칙[,문항=N][,만점=M][,단위=단어|음소]
```

| 목표 규칙 | 뜻 |
|---|---|
| `전체` | 제시 문자열과 응답 전사가 통째로 같아야 1점 |
| `2음절초성` | 2번째 글자의 **초성만** 비교 (자음검사) |
| `1음절중성` | 1번째 글자의 **중성만** 비교 (모음검사) |
| `1음절종성` | 1번째 글자의 종성 비교 (받침 없음도 하나의 값, 리포트에는 `∅`) |
| `초중종` | 1번째 글자의 초·중·종을 각 1점 (만점 3) |

**같은 검사 이름을 두 번 쓰면 세로로 쌓인 두 번째 채점(패스)** 으로 봅니다. `단위=단어` / `단위=음소` 로 구분하세요. 만점은 **추론하지 않고** 명시한 값이 규칙과 맞는지 검사합니다.

### 그 밖의 옵션

| 옵션 | 뜻 |
|---|---|
| `--timepoints 사전,사후` | 시점 이름 (기본 `사전,사후`) |
| `--subject-pattern '^s[0-9]+$'` | 피험자 시트 이름 정규식 |
| `--answer-key 시트` | 자극 리스트 정답 시트 |
| `--summary 시트` | 요약표 시트 |
| `--features 자질표.csv` | 조음위치·조음방법 묶음 집계 (**주지 않으면 분류하지 않음**). 형식은 `examples/자질표.csv` 참고 — `자모` 열 + 자질 열들 |
| `--min-count 3` | 혼동 행렬에 남길 최소 관측수 |
| `--alpha 0.05` | 임계차의 유의수준 |
| `--min-coverage 80` | 문항 대조율이 이 값 미만이면 판정 불가(exit 3) |
| `--map 매핑.json` | 요약표 열 이름을 손으로 매핑 (모르는 키는 조용히 무시하지 않고 exit 2) |
| `--pii-sheet 이름조각` | 식별정보로 보고 열지 않을 시트 이름 추가 |
| `--non-response 말` | 전사가 아니라 '반응 없음'으로 볼 응답 표현 추가 (기본: 모름·무응답·없음·못들음 등) |
| `--response-alias` / `--score-alias` | 응답·점수 열 헤더로 인정할 이름 추가 |
| `--long`, `--long-id` 등 | 문항 단위 long CSV 입력 |

### long CSV 입력

한 행 = 한 문항인 CSV도 같은 코드로 처리합니다.

```bash
python3 -m jamoscore trial_CNC.csv --long \
    --subtest "CNC:목표=전체" \
    --long-id s_account --long-time testset \
    --long-stim target --long-response resp --long-score word_corr \
    --timepoints test01,test02
```

검사 열이 따로 없으면 `--long-test` 를 빼면 됩니다(선언한 검사 하나로 봅니다).
**점수 열의 척도와 `만점=` 이 어긋나면** — 예를 들어 0/1 인 `word_corr` 에
`만점=3` 을 선언하면 — 규칙 대조가 통째로 잡음이 되므로, 어긋난 비율이 80%를
넘는 순간 개별 소견 대신 **`[치명] 채점 선언 의심`** 한 건으로 묶어 실제 최댓값과
선언한 만점을 같이 보여 줍니다.

**요약 %만 든 파일은 판정 없이 거절하고** `statwise`·`longistat` 를 가리킵니다(종료코드 2).

## 한계와 정직한 고백

- **어느 쪽이 맞는지 판정하지 않습니다.** 사람 점수와 규칙 점수가 갈리면 "확인 필요"라고만 합니다. 목표음소 규칙은 사용자가 선언한 것이고, 검사에 따라 다르며, 사람 채점자가 옳을 때가 많습니다.
- **임계차는 문헌 표가 아닙니다 — 그보다 좁습니다.** 이 툴은 **사전 점수 하나**의 Clopper–Pearson 정확 구간을 계산하고 사후 점수가 그 밖인지만 봅니다. 말지각 점수를 이항변수로 보는 모형(Thornton & Raffin, 1978, *J Speech Hear Res* 21:507–518, [doi:10.1044/jshr.2103.507](https://doi.org/10.1044/jshr.2103.507); Raffin & Schafer, 1980, 23:570–575, [doi:10.1044/jshr.2303.570](https://doi.org/10.1044/jshr.2303.570) — 2026-09-11 PubMed 원문 대조)에서 나온 임계차 **표**는 *두 점수의 차*가 갖는 분포에서 나오는데, 여기에는 **사후 점수의 표본오차가 들어 있지 않습니다.** 그래서 이 구간은 그 표보다 좁고, 같은 자료에서 '오차 범위를 벗어남'이 **더 많이** 나옵니다(실측: 이 툴 12건 vs 두 점수 정확검정 9건). 논문에 쓸 때는 계산 방식을 그대로 적거나 원 표를 직접 찾아 쓰고, **이 값을 그 표의 값이라고 적지 마세요.** `Methods_초안.md` 에 이 경고가 함께 들어갑니다. 임계차는 하락·상승 방향을 따로 내고, 바닥·천장에 붙어 그 방향으로 벗어날 수 없으면 `—` 로 비워 둡니다. **음소 점수에는 적용하지 않습니다** — 한 단어 안의 세 음소는 서로 독립이 아닙니다.
- **음운론을 스스로 주장하지 않습니다.** 혼동 행렬은 카운트만 냅니다. 조음위치·조음방법 묶음은 `--features` 로 자질표를 **받을 때만** 하고, 없으면 "분류 안 함"으로 자백합니다.
- **리스트 난이도 동등성 검정을 하지 않습니다.** 사전·사후가 같은 목록인지만 봅니다. 같은 목록·같은 순서는 단일 목록 검사(K-CNC 계열)에서 정상이므로 `[경고]` 이고, **자극도 응답도 한 글자도 다르지 않을 때만** `[치명]` 입니다.
- **어느 자극 리스트를 썼는지 정해 주지 않습니다.** 사전·사후에 리스트를 맞바꾸는 상쇄균형 설계가 흔하므로, 어느 리스트를 썼는지는 자료가 말하게 두고 `[정보]` 로 몇 명이 어느 리스트를 썼는지만 보여 줍니다.
- **미실시로 보이는 블록은 하류로 넘기지 않습니다.** 응답 칸이 하나도 없는데 점수가 전부 0 인 블록은 `0%` 가 아니라 `[경고]` 로 내고, `statwise`·`longistat` 입력 CSV 에서 뺍니다 — 그 0 이 실제 수행으로 분석에 들어가면 결론이 바뀝니다.
- **MCID를 추정하지 않습니다** (K-CNC MCID는 별건 델파이 프로젝트입니다).
- **식별정보 시트는 시트 부분을 읽지 않습니다.** 이름이 `개인정보`·`명단`·`연락처` 류면 그 시트의 셀을 **한 번도 열지 않고**(`--pii-sheet` 로 이름 조각을 추가할 수 있습니다), 열어 본 시트라도 열 이름이 이름·연락처·생년월일이면 읽자마자 버립니다. 다만 **정직하게 적어 둡니다**: 엑셀은 모든 시트의 문자열을 하나의 공유 테이블에 담으므로, 열지 않은 시트의 문자열도 메모리에는 올라옵니다(인덱스를 푸는 것은 연 시트뿐이라 산출물로는 나가지 않습니다). 그리고 **전사 칸에 적혀 들어온** 전화번호·주민등록번호·생년월일은 리포트와 모든 CSV에서 모양만 남기고 가립니다(`010-****-****`) — 이 마스킹은 합성 픽스처에 실제로 그 패턴을 심어 놓고 테스트합니다. 사람 **이름**은 어떤 패턴으로도 잡을 수 없으니, 시트 이름이 곧 사람 이름인 파일은 `--subject-pattern` 으로 거르고 내보내기 전에는 반드시 `deidaudit` 를 돌리세요.
- **`[커버리지 자백]` 블록 없이는 리포트가 출력되지 않습니다**(코드로 강제 — `ReportIntegrityError`). 리포트에 안 나온 항목이 "이상 없음"이라는 뜻이 아닙니다.
- **시점은 두 개까지만 지원합니다.** 세 시점 이상은 `차이` 열의 뜻과 임계차의 기준 시점이 자료마다 달라져 추측하면 조용히 틀린 값을 냅니다 — `exit 2` 로 멈추고 `longistat` 를 가리킵니다.
- **`--inspect` 가 한 번에 못 읽는 파일이 계속 나온다면**, 그건 입력 규격을 일반화하지 못했다는 뜻입니다. 그때는 이 툴을 접는 것이 맞습니다.
