#### B. 이름 탐지가 사전에 있는 헤더에서만 동작

`담당간호사`·`주치의`·`평가자` 열의 실제 한국 이름이 통째로 미검사 → exit 0.
→ 헤더 사전을 확장하고, **내용 기반 판정**을 추가했습니다(고유값의 60% 이상이
한국 성명 형태면 이름 열로 보고, 그렇게 판정했다는 사실을 자백에 남김).
유선·`070`·`+82` 번호도 탐지 대상에 추가(지역번호 고정 목록 + 구분자 필수).

#### C. 리포트 자체가 유출 경로가 되던 3가지

| 무엇이 | 왜 문제인가 | 고친 방법 |
|---|---|---|
| `문제목록.csv` 가 사본과 **같은 폴더**에 있고 행 번호가 1:1 로 맞음 | 두 파일을 나란히 놓으면 `P001 = 김씨, 1988년생, 번호 끝 89` 가 복원됨 — 마스킹이 무의미 | 사본을 만들면 리포트를 **`<out-dir>_점검리포트/` 로 분리**, 전부 `0600`, `--report-dir` 이 `--out-dir` 안이면 exit 2 |
| 엑셀 **정의된 이름**을 원문 그대로 증거에 실음 | `연락처_01023456789` 같은 이름이 실제로 존재(엑셀 "선택 영역에서 만들기") | 마스킹 + 길이만 표기. 이 동작을 잠그던 기존 테스트도 함께 교체 |
| 헤더 없이 저장된 CSV 의 **열 이름**이 원문 그대로 실림 | 첫 행이 헤더로 소비되어 이메일·전화번호가 '열' 칸에 남음 | `헤더 행이 데이터` 를 치명으로 지적하고 열 이름을 가림. 단 `이름`·`연락처`·`연령대` 처럼 **첫 음절이 성씨인 흔한 헤더**를 데이터로 오판하지 않도록 헤더 사전으로 걸러냄 |

부수적으로: 키 파일 전체 경로가 요약에 적히던 것 → 파일명만. 실행 명령의 전체 경로
(계정명 포함) → 파일명만. `mask_generic(keep=1)` 이 한국 이름의 **뒤 음절**(정보가
더 많은 쪽)을 남기던 것 → `keep=0`.

#### D. 키 파일 격리를 문자열 비교로만 하던 것

macOS(APFS/HFS+)는 대소문자와 유니코드 정규화를 구별하지 않는데 `realpath` 는
둘 다 그대로 둡니다. 그래서 다음이 전부 통과해 **키 파일이 내보낼 폴더 안에**
떨어졌습니다:

- `--out-dir /x/OUT` + `--key-out /x/out/키.csv` (대소문자)
- `--out-dir <NFC 내보내기>` + `--key-out <NFD 내보내기>/키.csv` (정규화)
- 미리 만들어 둔 **하드링크** (realpath 로는 잡히지 않음)

→ 경로 비교를 NFC + casefold 로 정규화하고, 키 파일을 **쓴 뒤 inode 로 다시 확인**해
`--out-dir` 안의 파일과 같은 실체이면 **지우고 exit 2**.

#### E. 자체검증이 검증하지 않던 것

리뷰어가 **모든 검사를 통과하는 잘못된 변환 3종**을 만들어 보였습니다.

1. 날짜는 옮기고 **ID 만 원본으로 되돌리기** → 통과 (ID 열을 아무도 안 봄)
2. `score` 열을 통째로 `999` 로 덮기 → 통과 (신고된 날짜 열만 대조)
3. 아무것도 안 옮기고 **"옮길 열이 없었다"고 신고** → 통과 (검증 범위를 피검증
   대상이 스스로 정함)

→ 검증 범위를 **원본 프로파일에서 다시 계산**하고, ID 열이 실제로 가명이 됐는지,
**그 밖의 모든 셀이 한 글자도 안 바뀌었는지**를 추가로 확인합니다. 세 공격을
전부 회귀 테스트로 고정했습니다.

#### F. `--pseudonymize` / `--shift-dates` 가 조용히 아무 일도 안 하던 것

- ID 열을 못 찾은 표는 **원본 ID 를 그대로 내보내면서** `치명 0건 · 내보내도 되는
  상태`(exit 0). `KHJ-1988` 같은 이니셜+생년 코드가 그대로 나감
  → 사본을 만들기 **전에** exit 2 로 거부하고, 그 표에 어떤 열이 있는지 보여 줌.
- `미상`·`N/A` 가 섞여 80% 임계를 못 넘긴 날짜 열은 이동 대상에서 빠지고 경고도
  없이 **원본 날짜 그대로** 나감 → `부분적으로만 날짜인 열` 경고 + 자백,
  `--shift-dates` 를 요청했다면 **내보내기 취소(exit 3)**.
- `--drop-columns 이름` 이 중복 헤더(`이름#2`)를 놓쳐 그 열이 그대로 나감
  → 중복 제거 **전** 원래 헤더로도 매칭.

#### H. 오탐 폭발 — 우는 늑대 (가장 채택률에 치명적)

현실적인 **이미 가명화된 BELL 스타일 파일**(34명 × 4시점, 자유기술 `비고` 포함)에

```
'연구간호사 확인함'      → …연○ 간호사…   ← 한국 임상 메모에 가장 흔한 문장
'지도 교수 검토 완료'    → …지○ 교수…
'심리 상담사 면담 병행'  → …심○ 상담사…
(현실적 24문장 중 14문장이 오탐)
```

→ (a) 호칭 앞에 **공백을 필수**로 하고, (b) 역할·부서 수식어 60여 개를 스톱워드로

`박서연 간호사` 는 그대로 잡힙니다. 14문장 전부 회귀 테스트입니다.
대가로 `김철수씨`(붙여쓰기)를 놓치며, 그 한계를 README·`사용법.md`·`실행.command`

### 테스트 품질에 대한 지적과 조치

리뷰어가 손으로 26곳을 변이시켜 **9개가 살아남는 것**(테스트가 못 잡음)을 확인했고,
공허한 테스트 4개를 지목했습니다.

- `test_scan_ratio_threshold_is_a_named_constant` 는 리터럴 산술만 검사 —
  프로덕션이 `cells_skipped` 를 아예 증가시키지 않는다는 사실과 무관하게 통과.
  → A5 를 고치고 실제 경로를 검사하도록 교체.
- `assert names == ["명단범위"]` 는 **유출 동작을 잠그고** 있었음 → 마스킹 검사로 교체.
- 주석·작성자 마스킹 검사가 `"원문" not in evidence` 라는 부분 문자열 검사여서
  일부만 남기는 변이를 못 잡음 → 형태(`\*+`)를 직접 단언.
- `ensure_not_input` 이 내보내기 경로에 **연결돼 있는지**를 검사하는 테스트가 없었음
  → 산출물이 입력을 덮어쓰려는 실제 실행으로 검사.

테스트 **183개 → 222개**. 새로 덮은 영역: 자유텍스트 통계 판정(헤더 사전 밖의 `Q7`),
파일시스템 별칭(NFC/NFD·대소문자·하드링크)에서의 키 격리, XLSX 를 통한 리포트 안전성,
ID 열 미인식 거부, 파일명 충돌, `--max-detail`, 솔트 파일 권한, zip bomb,
`DATE_COLUMN_MIN_RATIO`, 검증 공격 3종, 오탐 억제 14문장.
