# deidaudit — 공유 전 비식별화 점검

피험자 단위 CSV/TSV/XLSX 를 **밖으로 내보내기 직전에** 전수 스캔해서 — 직접식별자, 자유텍스트에 숨은 인명, 엑셀 숨김 시트·숨김 열·작성자 메타데이터, 그리고 **가명화해도 남는 재식별 위험(정확 날짜 + 준식별자 조합 k)** 을 파일·시트·행·열까지 찍어 보고하고, 요청하면 분석을 깨지 않는 방식으로 가명화·날짜이동한 내보내기 사본을 만든 뒤 **그 사본을 처음부터 다시 감사합니다.**

---

## 목적 / Why this exists

**한국어.** 금요일 오후, 공동연구자에게서 "그 데이터 좀 보내주세요"가 옵니다. 엑셀로 열어 이름 열을 지우고, 전화번호 열을 지우고, ID를 `S01…`로 바꾸고, 메일에 첨부합니다. 5분이면 끝납니다. **지우지 못한 것**: 수면일기 `비고` 열 187행의 "○○○ 간호사한테 얘기함", 자유응답에 본인 전화번호를 적은 피험자 한 명, 방문 날짜 열 전체(병원 방문 기록과 대조하면 그대로 특정됩니다), 그리고 XLSX 안에 **숨겨진 시트에 남아 있는 원본 명단**. 이 중 어느 것도 열어봐서는 알 수 없고, 메일은 이미 나갔습니다. `deidaudit` 은 그 5분 앞에 30초를 넣어, **셀 하나까지 전수로** 확인하고 "이 파일을 밖으로 보내도 되는가"에만 답합니다. 임상시험·유저테스트 데이터를 공동연구자·저널·리포지토리로 내보내는 연구자를 위한 툴입니다.

**English.** Before a subject-level dataset leaves your machine, this tool scans every cell of every sheet for direct identifiers (Korean RRN with checksum validation, mobile numbers, e-mail, Korean personal names, dates of birth, ages over 89), screens free-text columns for person references, and digs into the parts of an XLSX that opening the file never shows you — hidden sheets, hidden columns and rows, cell comments, and `docProps` author metadata. It then computes what pseudonymisation cannot remove: the equivalence-class sizes (k) of the quasi-identifiers you name, and which column you would have to drop to reach k ≥ 5. Optionally it writes a de-identified copy — deterministic pseudonyms consistent across files, per-subject fixed date offsets — and **re-audits that copy from scratch**. Fully offline, standard library only, inputs are never modified.

## 다른 방법 대비 무엇이 다른가

| 대안 | 왜 이 툴이 이기는가 |
|---|---|
| **엑셀에서 손으로 열 삭제** | 사람은 열 헤더만 봅니다. 4만 개 셀을 한 칸씩 못 봅니다. 자유텍스트·숨김 시트·문서 메타데이터는 **구조적으로 눈에 안 띕니다.** 그리고 실패가 조용합니다 — 잘못했다는 사실을 영원히 모릅니다. |
| **Presidio / ARX / anonympy** | Presidio 는 영어 NER 모델 기반이라 한글 이름·주민등록번호·`010` 번호를 신뢰성 있게 못 잡고 모델 다운로드(네트워크)가 필요합니다. ARX 는 자바 GUI 의 GDPR 일반론 도구라 "피험자 × 시점 다중 CSV + 야간 귀속" 이라는 우리 파일 형태를 모릅니다. **둘 다 엑셀 숨김 시트와 작성자 메타데이터를 보지 않습니다.** |
| **LLM 에 붙여넣기** | 여기서는 편의 문제가 아닙니다. **식별 가능한 피험자 데이터를 LLM 에 붙여넣는 행위 자체가 사고입니다.** 붙여넣어도 되는지 판정하는 것이 이 툴의 목적인데, 판정하려고 붙여넣으면 목적이 무너집니다. 게다가 LLM 은 4만 셀을 전수로 세지 못하고, 못 셌다는 사실도 모릅니다. |
| **아무것도 안 함 (그냥 보냄)** | 실패 비용이 비대칭입니다. 1000번 무사하다가 1번 터지면 IRB 사건이고 논문 철회 사유입니다. |

### 저장소 안 인접 툴과의 경계

| | 답하는 질문 | 입력 | 출력 |
|---|---|---|---|
| `joinaudit` | 이 파일들을 하나로 합쳐도 되는가 | 여러 원본 | `merged.csv` + 병합 감사 |
| `visitaudit` | 방문이 프로토콜을 지켰는가 | 방문 날짜 + 프로토콜 | 이탈 목록 |
| `logflow --anonymize` | 로그 지표는 무엇인가 (부수적으로 ID 해싱) | 이벤트 로그 | 리텐션·퍼널 |
| **`deidaudit`** | **이 파일을 밖으로 보내도 되는가** | 내보낼 파일들 | 위험 목록 + 안전한 사본 |

**경계를 코드로 강제합니다.**

1. **조인 금지.** 파일을 여러 개 받되 **절대 합치지 않습니다.** `--link-id` 는 파일 간 같은 피험자에게 같은 가명을 주기 위해서만 쓰이고 행을 결합하지 않습니다. `--join`/`--merge`/`--on`/`--how`/`--concat` 등을 주면 `exit 2` 로 "joinaudit 을 먼저 쓰세요"를 출력하고 멈춥니다.
2. **분석 지표 계산 금지.** 평균·검정·리텐션 등 어떤 통계도 출력하지 않습니다. 출력에 나오는 숫자는 전부 **개수**(건수·k·셀 수)입니다.
3. **키 파일은 `--out-dir` 안에 절대 쓰지 않습니다.** `--pseudonymize`/`--shift-dates` 사용 시 `--key-out` 이 필수이고, 그 경로가 `--out-dir` 하위면 `exit 2`. 심볼릭 링크, **대소문자만 다른 경로, 유니코드 정규화(NFC/NFD)만 다른 경로**(macOS 파일시스템은 둘 다 구별하지 않습니다), 그리고 **하드링크**(파일을 쓴 뒤 inode 로 다시 확인)까지 막습니다. 내보낼 폴더를 통째로 압축해 보내는 것이 정상 사용 패턴이라, 매핑표가 그 안에 있으면 툴이 사고의 원인이 됩니다.
4. **리포트는 내보낼 폴더 밖에 씁니다.** 사본을 만들면 리포트는 `<out-dir>_점검리포트/` 로 갑니다(`--report-dir` 로 변경 가능, `--out-dir` 안은 거부). 리포트의 행 번호는 사본의 행과 1:1 로 맞기 때문에, 둘이 함께 나가면 *"가명 P001 = 성이 김, 1988년생, 번호 끝 89"* 가 복원됩니다 — 마스킹이 무의미해집니다. 리포트 파일은 전부 `0600` 으로 만듭니다.
5. **리포트 자체가 PII 가 되지 않습니다.** 증거 문자열은 원문에서 잘라 오지 않고 **마스킹된 파생값 + 이 툴의 고정 어휘로 합성**합니다(`010-****-**89`, `김○○`, `…○○○ 간호사…`). 엑셀 정의된 이름·셀 주석·작성자도 마스킹합니다(`연락처_01023456789` 같은 이름이 실제로 있습니다). 헤더 없이 저장된 CSV 처럼 **열 이름 자체가 식별자일 때는 열 이름도 가립니다.** `재식별위험.csv` 에는 동치류의 **크기만** 쓰고 값은 쓰지 않습니다.

### 2단계. 안전한 사본 만들기

```bash
deidaudit examples/수면일기_원본.csv examples/UT로그.xlsx \
  --quasi birth,sex,visit_date --link-id subject_id \
  --pseudonymize --shift-dates --shift-weeks \
  --drop-columns name,phone,birth,담당자,이름,주민등록번호,연락처 \
  --out-dir 보낼폴더_2026-08-27 --key-out ~/보안/키_2026-08-27.csv
```

세 곳에 나눠 씁니다 — **섞이면 안 되기 때문입니다.**

```
보낼폴더_2026-08-27/내보내기/     ← 이 폴더만 보냅니다
보낼폴더_2026-08-27_점검리포트/   ← 내 컴퓨터에만 (0600)
~/보안/키_2026-08-27.csv         ← 절대 함께 보내지 않습니다 (0600)
```

`--shift-weeks` 는 이동량을 7의 배수로 맞춰 **요일을 보존**합니다. 수면 연구에서 주중/주말은 TST·SE 의 공변량이라 요일이 바뀌면 분석이 달라집니다(대신 오프셋 후보가 360개 → 50개로 줄어 보호 강도는 조금 낮아집니다 — 그 맞바꿈을 사용자가 고르도록 기본값은 일 단위입니다).

사본을 만든 뒤 **그 사본을 처음부터 다시 감사**하고, 종료코드는 **사본 기준**으로 냅니다:

```
==================================================================
[내보낸 사본 재감사] — 방금 만든 사본을 처음부터 다시 검사했습니다
  ※ 날짜를 이동한 열은 여전히 '정확 날짜 열' 경고로 잡힙니다. 값은 이동됐지만
     형태는 날짜이기 때문입니다 — 이동 사실은 비식별화_요약.md 에 있습니다.

[치명] 1종 · 1건
  휴대전화                       내보내기/UT로그__응답.csv  자유응답 열  010-****-**45
...
  ※ 숨김 시트는 사본에 내보내지 않았습니다: UT로그.xlsx!원본명단

내보낸 사본: 치명 1건 발견. 이 상태로 내보내면 안 됩니다.
```

남은 치명 1건은 **자유응답 칸에 피험자가 직접 적은 전화번호**입니다. 이 툴은 자유텍스트를 자동으로 지우지 않습니다 — 위치만 찍고, 지울지 말지는 사람이 정합니다.

### 출력 파일

| 파일 | 내용 |
|---|---|
| `점검결과.md` | 한국어 리포트 + 열 판정표 + 커버리지 자백 |
| `문제목록.csv` | 파일·시트·행·열·유형·심각도·**마스킹된** 증거 |
| `재식별위험.csv` | 준식별자 조합별 동치류 **크기 분포**(값은 쓰지 않음), 열 제거 시나리오 |
| `비식별화_요약.md` | 무엇을 바꿨는지 + 자체검증 통과 항목 + KR/EN Methods·Data Availability 초안 |
| `내보낸사본_문제목록.csv` | 사본 재감사 결과 |
| `내보내기/` | 변환된 파일 사본 (XLSX 는 **보이는 시트만** 시트별 CSV 로) |
| `--key-out` 경로 | 원본ID↔가명ID + 피험자별 날짜 오프셋 (`0600`). **`--out-dir` 밖 강제** |

`내보내기/` 를 제외한 위 파일들은 **`<out-dir>_점검리포트/`** 에 씁니다(모두 `0600`).

### 종료코드

| 코드 | 의미 |
|---|---|
| 0 | 치명 0건 — 내보내도 됨 |
| 1 | 치명 발견 |
| 2 | 입력/옵션 오류 (`--out-dir` 없음·폴더 아님, `--key-out` 없음/위치 위반, 병합 옵션, 존재하지 않는 열 이름, `--pseudonymize` 인데 ID 열을 못 찾음, 일반 파일이 아닌 입력) |
| 3 | 판정불가 (**읽지 못한 파일·시트가 하나라도 있음**, 파싱 실패, 인코딩 불명, 검사율 80% 미만, 날짜 이동 자체검증 실패, `--shift-dates` 인데 못 옮긴 날짜성 열이 있음) |

**3 이 1 보다 우선합니다.** 다 못 봤으면 "치명 0건"은 거짓말이기 때문입니다. 파일 5개 중 1개가 암호 워크북이면 **비율로 봐주지 않고** 종료코드 3 입니다 — 못 읽은 그 하나가 명단 파일일 수 있습니다.

### 자유텍스트 열 자동 판별

평균 글자수 ≥ 10, 평균 공백 ≥ 0.5, 고유값 비율 ≥ 40% (또는 헤더가 `비고`·`메모`·`자유응답`·`note` 계열). **판별된 열은 전 행 스캔하고, 판별 결과 자체를 리포트에 자백합니다** — 무엇을 자유텍스트로 봤고 무엇을 안 봤는지, 근거 수치와 함께.

### 표를 읽는 단계에서 잡는 것들

파일을 잘못 읽고 "치명 0건"이라고 말하는 것이 이 툴의 최악의 실패입니다. 그래서 파싱 단계에도 방어가 있습니다.

- **구분자 추정은 일관성 우선.** `두통|어지럼|불면|…` 처럼 셀 안에 있는 `|` 가 쉼표를 이겨 표 전체가 1열로 뭉개지면, 이름·전화번호가 통째로 검사 대상에서 빠집니다. 첫 줄이 헤더라고 가정하지 않고(제목 줄이 흔합니다) **본문 최빈 열 수의 일관성**으로 고릅니다.
- **인코딩은 '예외 없이 디코드됐다'로 판단하지 않습니다.** cp1252·latin-1·UTF-16 은 어떤 바이트열이든 조용히 디코드합니다. 결과가 ASCII·한글로 얼마나 이루어졌는지 점수를 매겨 고릅니다(BOM 없는 UTF-16 도 엔디안을 비교해 고름).
- **제목 줄·빈 줄이 표 위에 있어도** 진짜 헤더 행(= 최빈 폭에 처음 도달하는 행)을 찾습니다. 첫 행을 무조건 헤더로 쓰면 열 이름이 전부 `열2`, `열3` 이 되고 헤더 기반 규칙이 통째로 죽습니다. **건너뛴 제목 줄도 버리지 않고 스캔합니다.**
- **읽지 못한 시트와 비어 있는 시트를 구분합니다.** 시트 XML 이 깨져 있으면 "빈 시트"가 아니라 판정불가입니다.
- **행 번호는 원본 파일의 물리 행 번호**입니다(빈 줄이 섞여 있어도 그 번호로 파일에서 찾아갈 수 있습니다).
- **엑셀 상한(1,048,576행 / XFD열)을 넘는 셀 참조는 무시하고 자백**합니다. 시트 맨 아래에 서식만 남은 셀 하나로 12KB 파일이 수 GB 를 먹는 일을 막습니다.

### 엑셀 숨은 내용 (zipfile + ElementTree 직접 파싱)

숨김 시트(`hidden`/`veryHidden`) · 숨김 열 · 숨김 행 · 셀 주석(레거시 + 스레드) · `docProps/core.xml` 의 작성자/최종수정자 · `docProps/app.xml` 의 회사/관리자 · 정의된 이름. 날짜 일련번호는 `styles.xml` 의 서식을 읽어 실제 날짜로 되살립니다(초 단위 반올림 포함).

### 재식별 위험 (k)

`--quasi birth,sex,visit_date` 를 주면 동치류 크기 분포를 계산해 `min k`, `k=1`, `k<5`, 그리고 **어느 열을 빼면 k ≥ 5 가 되는지**를 보고합니다.

**반복측정 함정을 피합니다.** long 형식(피험자 × 시점)에서 행 단위로 k 를 세면 같은 사람의 12개 행이 "동치류 크기 12"로 보여 안전한 것처럼 보입니다. 피험자 ID 열을 알 수 있으면 **행이 아니라 서로 다른 사람 수**로 세고, 어느 쪽으로 셌는지 리포트에 적습니다.

### 날짜 이동 자체검증

내보내기 전에 다음을 **독립적으로 다시 계산**하고, 하나라도 깨지면 내보내기를 통째로 취소합니다(`exit 3`).

1. 행 수 · 열 구성이 보존되었는가
2. **이동해야 할 날짜 열이 하나도 빠짐없이 이동했는가** — 검증 범위를 변환 결과가 스스로 신고한 목록이 아니라 **원본 프로파일**에서 다시 계산합니다(자기 신고로 검사하면 "아무것도 안 하고 아무것도 안 했다고 신고"하는 변환이 통과합니다)
3. 모든 날짜값이 정확히 `원본 + 피험자 오프셋` 인가
4. 피험자 내 날짜 **간격**이 이동 전후 완전히 동일한가
5. **야간 귀속**(정오 기준, 자정 넘김) 라벨이 오프셋만큼만 이동했는가 — 23:40 과 다음날 03:20 은 같은 밤
6. 가명화 대상 ID 열이 실제로 가명으로 바뀌었는가
7. **그 밖의 모든 셀이 한 글자도 바뀌지 않았는가**
8. 가명 매핑이 단사이고 파일 간 일관되는가

## 한계 (하지 않는 것)

- **자유텍스트를 자동으로 치환·삭제하지 않습니다.** 위치(파일·시트·행·열)만 찍고 사람이 결정합니다. 자동 마스킹은 의미를 조용히 훼손하고, 놓친 부분에 거짓 안심을 줍니다.
- **k-익명성 자동 일반화·억제를 하지 않습니다.** 나이를 5세 구간으로 묶는 변형은 분석을 바꿉니다. 보고만 하고 실행은 사람이.
- **파일을 합치지 않습니다.** `joinaudit` 영역입니다.
- **어떤 통계도 계산하지 않습니다.**
- **PDF·DOCX 를 읽지 않습니다.** v1 은 표 형식(CSV/TSV/XLSX)만. 원고 안의 식별자는 별개 문제입니다.
- **연-월-일 순서가 아닌 날짜를 읽지 않습니다.** `03/14/2026` 과 `14/03/2026` 은 구별할 방법이 없고, 잘못 읽으면 날짜 이동이 조용히 분석을 깨뜨립니다. 읽지 않고 자백합니다.
- **영문·한자 이름을 이름으로 잡지 못합니다.** 성씨 사전 기반이라 한글 이름만 봅니다.
- **자유텍스트의 이름은 호칭이 있을 때만 잡습니다.** `김철수 씨`·`김철수님`·`○○○ 간호사`·`남궁민수 교수`는 잡지만, **호칭이 없으면 놓칩니다**(`박서연이 재측정 시행`). 그리고 긴 호칭(간호사·교수·상담사)은 앞에 띄어쓰기가 있어야 잡습니다 — 붙여쓰기를 허용하면 `연구간호사`·`담당자` 같은 직함이 전부 이름으로 잡혀 매 행마다 울기 때문입니다.
- **날짜 이동은 요일과 계절(월)을 보존하지 않습니다** — `--shift-weeks` 를 쓰면 요일은 보존되지만 계절은 여전히 바뀝니다. 생성되는 Methods 초안에 이 사실을 그대로 적습니다.
- **숨김 시트는 사본에서 빼지만, 숨김 열·행은 데이터이므로 그대로 내보냅니다.** 비대칭이라 실행할 때마다 알려 줍니다.
- **리포트의 '파일·시트·열' 칸은 원칙적으로 원문 그대로입니다.** 어느 열·어느 시트인지 모르면 고칠 수 없기 때문에 의도한 예외입니다(전화·이메일·주민번호가 들어 있으면 그때는 가립니다). 시트 이름에 사람 이름이 있으면 가리는 대신 `시트 이름에 인명` 경고로 알리고, **사본 파일명만** `시트N` 으로 바꿉니다. 리포트를 원본과 같은 취급으로 다뤄 주세요(그래서 `0600` 으로 만들고 내보낼 폴더 밖에 씁니다).
- **`YYYYMMDD` 형태의 8자리 코드를 날짜로 오인할 수 있습니다.** `검체번호` 같은 열이 날짜 열로 잡히면 `--shift-dates` 가 값을 바꿉니다 — `정확 날짜 열` 경고에 그 열 이름이 나오니 확인하세요.
- **`.xls`(구형식)·암호 워크북을 읽지 않습니다.** 못 읽으면 건너뜀으로 자백하고, 검사율이 80% 미만이면 `exit 3`.
- **주소의 정확도(동/읍/면 단위)를 판정하지 않습니다.** 헤더가 주소 계열이면 경고만 냅니다.
- **네트워크를 쓰지 않고 원본을 수정하지 않습니다.** 산출물은 `--out-dir` 아래에만 씁니다.
- **탐지되지 않은 것이 없다고 보장하지 않습니다.** 이 툴은 *사람이 구조적으로 볼 수 없는 것*을 보여 주는 장치이지, 비식별화의 최종 승인 도장이 아닙니다. IRB·기관 규정이 우선합니다.

### 예제 데이터에 대하여

`examples/` 는 전부 합성입니다. 예제의 주민등록번호는 성별자리 3(2000년대 출생) + 생년 `88` 조합이라 **2088년 출생**으로 해석되어, 체크섬은 통과하지만 현실에서 발급될 수 없는 번호입니다. 예제를 다시 만들려면 `python3 examples/_make_examples.py`.
