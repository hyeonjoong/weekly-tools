# powerplan 빠른 사용법 (한글)

**"이 연구, 몇 명 필요할까?"에 답해서 프로토콜 문장까지 만들어 주는 도구입니다.**

## 0. 가장 빠른 시작

폴더 안의 **`실행.command`를 더블클릭**하세요. 예제 9개(두 군 비교·ANCOVA·사전연구 CSV·ICC/LoA·반복측정·생존분석·중간분석·무익성 경계·검정력 역산)가 차례로 나옵니다 — 700줄 남짓이니 위로 스크롤해 보세요.

내 값으로 계산하려면 터미널에서:

```bash
cd ~/Downloads/02_프로젝트/깃헙/powerplan-표본수설계
python3 -m pip install -e .        # 한 번만
powerplan ttest2 --d 0.5 --power 0.8
```

설치가 귀찮으면 `python3 -m powerplan.cli ttest2 --d 0.5 --power 0.8` 로도 됩니다.

## 1. 어떤 명령을 쓸까

| 내 상황 | 명령 |
|---|---|
| 두 군(디바이스 vs sham) 평균 비교 | `ttest2` |
| 같은 사람 전후(baseline → 8주) 비교 | `paired` |
| 기준값·규준과 비교 (한 군만 있음) | `onesample` |
| 3군 이상 비교 | `anova` |
| 같은 지표를 **여러 시점에 반복 측정** (4·8·12주) | `repeated` |
| 반응자 비율(반응률) 비교 | `prop2` |
| 두 변수 상관 (HRV × 수면지표 등) | `corr` |
| 재발·사망까지의 **시간** | `survival` |
| 같은 사람의 두 이분형 판정 비교 | `mcnemar` |
| "기존보다 나쁘지 않다"를 보이려면 | `noninf` (연속형 `--sd` / 이분형 `--p1 --p2`) |
| "같다"를 보이려면 | `equiv` (연속형 `--sd` / 이분형 `--p1 --p2`) |
| 센서 vs PSG 같은 **일치도 연구** (연속형) | `icc`, `loa` |
| 판정이 **범주형**일 때의 일치도 | `kappa` |
| 대조군 없이 **성능목표치**와 비교 (기기 확증시험) | `prop1` |
| 같은 사람이 두 처치를 **모두** 받음 (교차설계) | `crossover` |
| 민감도·특이도를 추정 (유병률 반영) | `diag` |
| 사전연구 데이터가 이미 있다면 | `pilot` |
| **중간분석**을 계획한다면 | 위 설계에 `--interim 1` 추가 (`anova`·`equiv`·`prop1`·`crossover` 제외) |
| DSMB 헌장에 **무익성 중단 규칙**을 넣어야 한다면 | `--interim 1 --futility obf` |

## 2. 실전 예시 4개

### (1) 두 군 비교 — ISI 3점 차이를 보고 싶다 (SD 6점, 탈락 15% 예상)

```bash
powerplan ttest2 --mean1 8 --mean2 5 --sd 6 --power 0.8 --dropout 0.15
```

읽는 법:
- **필요한 분석 표본수** = 통계적으로 필요한 인원 (끝까지 참여한 사람)
- **모집 표본수** = 탈락을 감당하려면 실제로 모아야 하는 인원 ← 프로토콜에는 이 숫자를 씁니다
- **프로토콜용 문장** = 연구계획서에 그대로 복사

효과크기(d)를 직접 아는 경우엔 `--d 0.5` 처럼 넣어도 됩니다.

### (2) 사전연구 CSV가 있다 — 거기서 효과크기를 뽑아 본연구 설계

```bash
# 전후 비교 (와우핏 훈련 전/후) — 한 군만 골라서!
powerplan pilot examples/wowfit_pilot.csv --pre 훈련전_단어인지도 --post 훈련후_단어인지도 --filter 군=중재 --power 0.8

# 두 군 비교 (device vs sham) + 기저값 상관·탈락률까지 추정
powerplan pilot examples/serene_pilot.csv --value isi_week8 --group arm --baseline isi_baseline --power 0.8
```

읽는 법:
- 표본수는 기본적으로 **신뢰구간 하한**(보수적)으로 계산됩니다 — 사전연구에서 우연히 크게 나온
  효과크기를 그대로 믿으면 본연구가 "차이 없음"으로 끝나기 쉽기 때문입니다.
  관측값 그대로 보고 싶으면 `--plan-on observed`.
- `⚠ 신뢰구간이 0을 포함` 이 뜨면 사전연구만으로는 효과크기를 확정할 수 없습니다.
  그때는 임상적으로 의미있는 최소 차이(MCID)를 직접 정해 `ttest2`/`paired`로 계산하세요.
- 출력에 나오는 `--dropout 참고값`(관측 결측률)과 `--baseline-r`(기저값 상관)을 그대로
  다음 명령에 넣으면 됩니다.
- **여러 군이 한 파일에 있으면 `--filter 군=중재` 로 한쪽만 고르세요.** 안 그러면 중재군과
  대조군의 전후 변화가 섞여 무의미한 효과크기가 나옵니다.

CSV는 엑셀에서 "CSV로 저장"한 파일이면 됩니다. 쉼표·세미콜론·탭 자동 인식, 한글 열이름 OK,
`NA`/빈 칸은 결측 처리. utf-8과 한국어 엑셀(cp949)은 자동 인식하지만, 그 밖의 인코딩은
오류 없이 깨진 글자로 읽힐 수 있으니 열 이름이 이상하게 보이면 UTF-8로 다시 저장하세요.
파일은 한 줄씩 스트리밍으로 읽으므로 100만 행짜리도 문제없습니다.

### (3) 센서 검증 연구 — 비접촉 호흡 vs PSG

```bash
powerplan icc --icc 0.8 --width 0.15 --raters 2      # ICC를 좁은 신뢰구간으로 추정하려면
powerplan loa --sd-diff 2.0 --half-width 0.5         # Bland-Altman 일치한계 정밀도 기준
```

이 두 개는 "차이가 있다"를 검정하는 게 아니라 **얼마나 정밀하게 추정할지**로 표본수를 정합니다.
일치도 연구에서 검정력 계산을 쓰는 건 흔한 오류입니다.

### (4) 기저값(사전 측정)이 있는 두 군 비교 — ANCOVA로 표본수 줄이기

```bash
powerplan ttest2 --d 0.309 --power 0.8 --analysis ancova --baseline-r 0.711
```

추적값만 비교하면 군당 166명이지만, 기저값을 공변량으로 보정하면 **군당 83명**입니다.
`r`은 사전연구에서 `--baseline` 옵션으로 추정할 수 있습니다(위 (2)번).
SAP에 "ANCOVA로 분석한다"고 쓸 계획이면 이 숫자가 맞는 숫자입니다.

### (5) 중간분석을 할 계획이다 (군차별설계)

```bash
powerplan ttest2 --d 0.5 --power 0.9 --interim 1                 # 중간분석 1회 + 최종
powerplan ttest2 --d 0.5 --power 0.9 --interim 2 --spending pocock --timing 0.4,0.7
powerplan ttest2 --d 0.5 --power 0.9 --interim 1 --futility obf     # 무익성 중단 경계까지
```

중간에 한 번 들여다보고 "효과가 확실하면 조기 종료"할 계획이라면, 그냥 두 번 검정하면
1종오류가 0.05 → 0.083으로 부풉니다. `--interim`을 주면 α 소비함수로 각 시점의 임계값을
나눠 전체 1종오류를 0.05로 지킵니다. 출력의 **중간분석 경계** 표가 그대로 프로토콜에
들어갑니다 — 각 시점의 누적 N, Z 경계, 명목 유의수준, 조기중단 확률.

- `--spending obf`(기본): 초반을 아껴 최대 표본수가 거의 안 늘어납니다 — 중간분석 1회면
  0.8%, 2회면 2.1% 정도. 규제 제출의 기본값.
- `--spending pocock`: 초반에 넉넉히 써 조기중단 확률이 높지만 최대 표본수가 늘어납니다
  (중간분석 1회에 검정력 0.9면 11%, 0.8이면 12%).
- **최대 표본수**(모집 목표)와 **기대 표본수**(조기중단 감안)가 함께 나옵니다. 예산은 최대로, 기대는 설명용으로 쓰세요.

#### 무익성(futility) 중단 경계 — `--futility obf`

중간분석에서 보는 건 "효과가 확실한가"만이 아닙니다. DSMB는 **"이대로 가도 가망이 없나"**도
봅니다. `--futility`를 주면 그 경계를 함께 계산합니다.

```
  중간 1        0.500            97   2.1570    0.03101   0.0310    63.1%    0.3849    65.0%
```

맨 오른쪽 두 칸이 새로 생긴 것입니다.

- **무익성 Z = 0.3849** — 중간분석에서 Z가 이 값보다 작으면 중단을 권고합니다.
- **65.0%** — 약이 실제로 효과가 없다면 중간분석에서 멈출 확률. 이게 무익성 경계를 넣는
  이유입니다. 효과 없는 시험을 절반 지점에서 접으니, 효과가 없을 때 기대 표본수가
  187명 → 129명으로 줄어듭니다.
- 그 아래 줄의 **조건부 검정력 39% (추세대로면 1%)** — "경계값을 봤을 때 최종에 유의해질
  확률"입니다. DSMB 회의에서 실제로 오가는 숫자가 이쪽이니, 헌장에는 Z 대신 이 값을
  기준으로 적어도 됩니다.

값을 치르는 곳은 표본수입니다. 무익성 규칙을 지키면 검정력이 90.0% → 89.5%로 내려가므로,
그만큼 되찾도록 표본수를 190명 → 194명으로 늘립니다(`--futility pocock`이면 214명 —
초기에 더 적극적으로 멈추는 만큼 더 물어야 합니다).

**비구속적(non-binding)입니다.** DSMB가 무익성 경계를 넘고도 "계속 간다"고 하면 그래도
됩니다 — 전체 1종오류율은 0.05를 넘지 않게 설계했습니다. 규제기관이 선호하는 방식이고,
이 툴은 구속적(binding) 경계를 지원하지 않습니다.

주의: 양측설계에서는 무익성 경계가 **해(harm) 방향 경계까지 덮습니다**. Z가 −2.157보다
낮으면 그건 '무익'이 아니라 '통계적으로 유의한 해'이므로, DSMB에는 둘을 구분해 보고하도록
헌장에 적으세요.

### (6) 사건까지의 시간이 결과변수라면 (생존분석)

```bash
powerplan survival --hr 0.7 --median1 12 --accrual 18 --followup 12 --power 0.8
```

생존분석의 검정력은 **사건 수**가 결정합니다. 위 명령은 필요한 사건 수(247건)를 먼저 구하고,
"대조군 중앙생존 12개월 · 18개월 등록 · 추가 12개월 추적"이면 몇 명을 등록해야 그 사건이
모이는지 역산해 줍니다. **추적기간을 늘리는 쪽이 등록을 늘리는 쪽보다 싼 경우가 많으니**
`--followup` 값을 바꿔 가며 비교해 보세요.

### (7) 대조군 없이 성능목표치와 비교한다면 (기기 확증시험)

```bash
powerplan prop1 --p1 0.60 --p0 0.45 --power 0.8      # 95명, 반응자 53명 이상이면 성공
```

정확 이항검정이라 **"몇 명 이상이면 성공"** 이라는 판정 기준이 함께 나옵니다. 그대로
프로토콜의 성공/실패 규칙으로 쓰세요.

### (8) 민감도·특이도를 추정한다면 (센서 vs PSG 판정 정확도)

```bash
powerplan diag --sens 0.9 --spec 0.85 --prevalence 0.2 --half-width 0.05
```

민감도는 **질환이 있는 사람에서만** 추정됩니다. 유병률 20%에서 질환자 199명을 모으려면
전체 995명을 등록해야 합니다 — 이 나눗셈을 빼먹는 것이 가장 흔한 실수입니다.
(기본값은 Wilson 구간입니다. 고전 Buderer 공식의 Wald 기준 숫자가 필요하면 `--method wald`.)

### (9) 같은 사람이 두 처치를 다 받는다면 (2×2 교차설계)

```bash
powerplan crossover --diff 3 --sd-within 6 --power 0.8
```

`--sd-within`은 **개인 내** SD입니다(사람들 사이의 SD가 아님). 같은 사람을 두 번 잰
차이의 SD가 σ_diff라면 σ_w = σ_diff/√2 입니다.

### (10) 같은 지표를 여러 번 잰다면 (반복측정 / MMRM)

```bash
powerplan repeated --d 0.4 --post 3 --baseline-n 1 --rho 0.6 --power 0.8
```

**여기서 `--estimand`가 결정적입니다.**

- 기본값 `last` = "1차 평가변수는 **마지막 방문(12주)** 시점의 군간 차이" — 실제 프로토콜이
  거의 항상 쓰는 정의입니다. 위 예에서 군당 **65명**. 이때 중간 방문을 몇 번 하든 표본수는
  줄지 않습니다(마지막 시점의 분산은 그대로이기 때문). 중간 방문은 탈락자 정보를 살리는
  데 값어치가 있고, 그 이득은 계산에 넣지 않았습니다 — 그만큼 보수적입니다.
- `--estimand average` = "1차 평가변수는 **사후 방문들의 평균**" — 군당 **39명**.

65명 대 39명, 40% 차이입니다. **SAP에 '마지막 방문'이라 쓸 계획이면 반드시 기본값(last)으로
계산하세요.** average로 계산해 놓고 마지막 방문을 분석하면 그대로 미검출로 끝납니다.

`--d`는 언제나 **1회 측정의 SD** 기준이고, `--rho`는 측정 간 상관입니다(사전연구에서
추정하거나 문헌값; 가장 먼 두 시점의 상관을 넣으면 보수적입니다).

## 3. 자주 쓰는 옵션

| 옵션 | 뜻 |
|---|---|
| `--power 0.8` | 목표 검정력 → **표본수**를 계산 |
| `--n 30` | 확보 가능한 인원(1군 기준) → **검정력**을 계산 |
| `--dropout 0.15` | 탈락률 15% → 모집 인원을 늘려 계산 |
| `--sensitivity` | 가정이 틀렸을 때 표본수가 어떻게 변하는지 표로 |
| `--alpha 0.01` / `--sides 1` | 유의수준 / 단측검정 |
| `--ratio 2` | 배분비 1:2 (2군을 1군의 2배로 배정) |
| `--analysis ancova --baseline-r 0.7` | 기저값 보정(ANCOVA) — 표본수가 크게 줄어듭니다 |
| `--n-total 100` | 확보 가능한 **총** 인원 (배분비에 맞춰 자동으로 나눔) |
| `--comparisons 3` | 주요 비교가 3개 → α 보정(Bonferroni) |
| `--interim 1 --spending obf` | 중간분석 1회 → 경계·팽창계수 계산(군차별설계) |
| `--futility obf` | 무익성(futility) 중단 경계도 함께 (β 소비함수, 비구속적). `--interim` 필수 |
| `--n 40` (icc/loa/kappa/diag) | 확보 가능한 인원 → **정밀도**를 거꾸로 계산 |
| `--cluster-size 10 --cluster-icc 0.05` | 병원/학급 단위 배정(군집 무작위배정) |
| `--format md -o 표본수.md` | 결과를 Markdown 파일로 저장 |

**옵션이 설계마다 다릅니다 — 의미가 없는 옵션은 아예 등록되어 있지 않으니, 정확한 목록은
언제나 `powerplan <설계> --help`입니다.**

- `icc`·`loa`·`kappa`·`diag`는 정밀도 기준이라 `--alpha`와 `--n`만 받습니다
  (`--power`/`--dropout`/`--cluster-*`/`--comparisons`/`--interim` 없음 — 탈락은 직접
  나눠서 보정하세요). `--n`을 주면 "그 인원으로 얻는 정밀도"를 거꾸로 계산합니다.
- `anova`·`noninf`·`equiv`는 `--sides`가 없습니다(검정 방향이 설계로 고정).
- `--interim`이 **없는** 설계: `anova`·`equiv`·`prop1`·`crossover`.
- `--cluster-*`가 **없는** 설계: `paired`·`onesample`·`mcnemar`·`prop1`·`crossover`
  (군집을 *군에 배정*하는 구조가 아닙니다).

## 4. 결과를 논문/IRB에 쓸 때

1. `■ 프로토콜용 문장`의 [KR] 또는 [EN]을 복사합니다.
2. 아래 `■ 확인하세요(가정과 한계)`를 읽고, 해당되는 가정을 프로토콜에 함께 적습니다.
3. 명령어 자체를 부록이나 통계분석계획서(SAP)에 남기면 그대로 재현됩니다.

읽을 때 헷갈리기 쉬운 두 줄:
- `실제 달성 80.1%` — 표본수는 정수라 목표(80%)를 조금 넘습니다. 프로토콜에는 이 값을 쓰면 됩니다.
- `민감도 분석` 표 — 가로는 효과크기 가정을 ±20% 흔든 것, 세로는 목표 검정력입니다.
  "효과가 20% 작으면 몇 명 더 필요한가"를 미리 답해 두면 심사에서 편합니다.
