# HARDENING — logflow

이 문서는 logflow 도구를 심화 개선·강화한 내역을 날짜별로 기록한다.
각 회차는 (1) 실질 기능 개선/확장과 (2) 병렬 적대적 리뷰(여러 독립 리뷰어)로
발견한 결함 수정 + 회귀/속성 테스트 추가로 구성된다.

## 2026-07-16 — 통계·출력 심화 + R1/R2 적대적 하드닝

시작 상태: 세션화·집계·DAU/WAU/MAU·리텐션·퍼널을 텍스트로 출력하는 표준라이브러리 전용
도구. 테스트 32개 통과.

### 1) 실질 기능 개선 · 확장 (연구자 관점의 새 역량)

- **비율 신뢰구간(Wilson score interval)**: 리텐션·퍼널 전환율에 95%(설정 가능) 신뢰구간을
  함께 계산·표시. 코호트/표본이 작을 때(임상 유저테스트에서 흔함) Wald 근사보다 안정적이고
  0%/100% 근처에서도 구간이 붕괴하지 않는다. 논문·리포트에 비율을 실을 때 필요한 정직한 불확실성.
  - 새 모듈 `logflow/stats.py`: `wilson_interval`, `z_for_confidence`(+정규 역CDF Acklam 근사),
    `quantile`(numpy type-7 선형보간과 일치), `median`, `describe`. 순수 함수·의존성 없음.
- **퍼널 단계별 소요시간(중앙값)**: 직전 단계→다음 단계에 걸린 시간의 중앙값을 함께 보고
  (도달한 사용자 대상, 조건부). "어디서 얼마나 오래 걸려 이탈하는지"를 파악.
- **세션 분포의 정직한 요약**: 치우친 로그에서 평균만 보면 오해하므로 세션 길이·세션당
  이벤트를 **중앙값**과 함께 표시하고, JSON 에는 사분위수·p90 까지 포함.
- **활동 시간대 분석**: 시(0–23)·요일(월–일)별 이벤트 분포와 피크 시간대. 수면앱처럼 사용
  시간대가 중요한 로그에 유용. 텍스트 리포트에 요일 막대·시간 스파크라인으로 표시.
- **JSON 출력(`--json`) + 파일 저장(`--out`)**: 텍스트 대신 기계가독 JSON 으로 전체 결과를
  출력해 R/엑셀/파이썬 다운스트림 분석·원고 작성에 바로 연결. 텍스트와 JSON 은 단일 결과
  객체(`analyze.Analysis`)에서 렌더링되어 항상 일치.
- **실데이터 관용 로딩**: CSV 구분자 자동감지(콤마/세미콜론/탭/파이프), 헤더 열 이름의
  앞뒤 공백·대소문자 차이 허용, 완전 중복 행 제거(`--dedup`), 기간 필터(`--from`/`--to`).
- **신뢰수준 옵션(`--confidence`)**.

새 CLI 옵션: `--confidence`, `--delimiter`, `--dedup`, `--from`, `--to`, `--json`, `--out`.
README/사용법.md/옵션표/지표정의를 실제 동작에 맞춰 갱신(예시 출력 블록 포함).

### 2) 적대적 하드닝 — Round 1 (4개 독립 패널: 정확성·엣지·문서·테스트/보안)

발견·수정한 결함:

- **[HIGH] 리텐션 큰 day-N 오버플로**: `--retention 3000000` 등에서 `date + timedelta(days=N)`
  가 오버플로해 트레이스백. → date 연산 대신 **정수 비교**(`n > (max_day - c).days`)로 판정하도록
  변경해 오버플로를 원천 차단(의미는 완전 동일). CLI 예외 처리에 `OverflowError` 추가.
- **[LOW-MED] 비유한/극단 입력**: `--gap-min nan/inf`, `--tz-offset nan`, 거대한 `--tz-offset`
  이 애매한 오류/트레이스백을 냄. → CLI 에서 `math.isfinite` 검증 추가, `OverflowError` 를
  깔끔한 오류로 처리.
- **[LOW] 음수 epoch 무단 수용**: `-1000000000` 이 1938년으로 조용히 해석(도크스트링과 모순).
  → `_looks_numeric` 이 부호 붙은 값을 epoch 로 보지 않도록 수정 → 명확한 파싱 오류.
- **[문서] README Usage 의 `logflow` 단축 명령**: 무설치 경로를 안내하면서도 예시는 설치가
  필요한 단축 명령을 씀. → 설치 필요/대체 명령 주석 추가.
- **[문서 nit]** `_inv_norm_cdf` 오차 한계 도크스트링 정정(~3e-9).
- **[보안/PII]** 네트워크·코드실행·외부쓰기 없음 확인(순수 오프라인). 출력에 원시 사용자 ID가
  포함되고 `--out` 이 경로를 덮어쓴다는 점을 README 에 명시(정상 동작이나 공유 시 주의).

테스트: 32 → 109개. `stats.py` 참조값 검증, 활동/퍼널타이밍/세션분포, dataio 구분자·중복·기간·
헤더해석·비UTF8, JSON/`--out`, 그리고 **속성/불변식 테스트**(히스토그램 합=이벤트수,

회귀 테스트(오버플로·비유한·음수epoch·경계) 추가. 전부 통과.

## 2026-07-31 — 군(arm) 비교 기능 추가 + 적대적 하드닝 Round 4

### 1) 기능 확장 — 군 비교 · JSONL/gzip 입력

`stats.py` 에는 Newcombe 구간·Fisher 정확검정·Mann-Whitney·Kaplan-Meier·log-rank 가
구현돼 있었지만 **어디에서도 쓰이지 않았고 테스트도 없었다**. `Event.group` 필드도
채워진 적이 없었다. 이번에 이를 실제 기능으로 연결했다.

- **`--group-col`(+`--ref-group`, `--churn-days`, `--only-groups`)**: 새 모듈 `logflow/groups.py`.
  군별 기술통계(모두 **사용자 단위**), day-N 리텐션·퍼널 완주율의 **위험차 + Newcombe CI +
  Fisher 정확검정**, 사용자당 참여도의 **Mann-Whitney + rank-biserial**, 이탈까지의 시간에 대한
  **Kaplan-Meier + log-rank**, 그리고 이 모든 검정에 **Holm–Bonferroni** 보정.
  군이 3개 이상이면 검정을 생략하고(다중비교 부풀리기 방지) `--only-groups` 로 두 군을 고른다.
  리텐션 관찰 지평은 **전체 데이터 기준**으로 통일해 군 간 분모를 공정하게 맞춘다.
- **입력 형식**: JSONL/NDJSON, gzip(매직바이트로 감지 — 확장자가 달라도 동작), `--format`.
  `dataio` 모듈 docstring 이 예전부터 이 둘을 **주장만 하고 구현하지 않았던 것**을 구현으로 해소.
- **출력**: 리포트 `[ 군 비교 ]` 절, JSON `groups` 블록, CSV 표 3종(`group_summary`,
  `group_tests`, `group_survival_km`). 2군 예시 데이터 `examples/trial_events.csv`(24명·3주) 추가.
- **안전장치**: `--max-rows`(압축 로그 메모리 폭주 방지).

### 2) 적대적 하드닝 Round 4 (4개 독립 패널 병렬: 정확성 · 엣지 · 문서정직성 · 테스트품질/PII)

교차검증 결과 — Fisher/Mann-Whitney/log-rank/KM/Holm/Newcombe 를 scipy·lifelines·statsmodels 및
브루트포스와 대조: **수치 불일치 0건**(총 ~1만 3천 케이스). 세션화·리텐션·퍼널의 군별 합이 전체와
정확히 일치. 그 외 발견돼 **수정한** 결함:

- **[HIGH] log-rank 의 군별 O/E 가 서로 뒤바뀌어 보고됨** (`stats.py`): `observed1`/`expected1` 은
  "위험집합 2명 이상" 시각만 누적하는데 `observed2`/`expected2` 는 **제한 없는 총합에서 빼서**
  계산했다. 한 군만 남은 시점의 사건이 상대 군에 떠넘겨져, 무작위 2군 데이터의 약 9%에서
  O1/O2 가 역전됐다(같은 JSON 안의 `n_churned` 와도 모순). → 두 군을 같은 제한 조건으로 누적.
  이제 `(O1−E1)+(O2−E2)=0` 이 정확히 성립. chi2·p 는 원래 옳았고 영향 없음.
- **[HIGH] `--csv-dir` 이 입력 로그를 조용히 파괴** (`cli.py`): 표 이름이 고정(`users.csv`,
  `events.csv` …)이라 입력이 같은 이름이면 덮어써 원본이 사라졌다. → 쓰기 **전에** 전 경로를
  입력과 대조해 하나라도 겹치면 아무것도 쓰지 않고 중단(부분 저장 없음). 기존 파일을 덮어쓴
  경우도 개수를 안내.
- **[HIGH] 손상 입력 5종이 트레이스백을 그대로 노출** (`cli.py`): 잘린 `.gz`, gzip 아닌 `.gz`,
  폴더 경로, 권한 없음, 초장문 CSV 필드 → 설치 경로가 담긴 파이썬 스택이 출력됐다.
  → 각각 한국어 한 줄 오류로 변환.
- **[MED] 절단(censoring) 시간이 관찰되지 않은 기간까지 포함** (`groups.py`): 이탈자는 (마지막
  활동−첫 활동), 절단자는 (관찰종료−첫 활동)이라 **서로 다른 시계**를 썼다. 절단자는 마지막
  활동 이후를 본 적이 없으므로 "종료일까지 참여했다"는 근거 없는 주장이었다. → 두 경우 모두
  (마지막 활동−첫 활동)으로 통일하고, 남는 informative censoring 한계를 docstring 에 명시.
- **[MED] 중복 day-N 이 Holm family 를 부풀림**: `--retention 1,1,1` 이 같은 가설을 3번 세어
  보정 p 가 3배가 됐다. → `_int_list` 와 `compare_groups` 에서 중복 제거.

- **프로토콜 준수도 분석 `--adherence-days N`** (`logflow/adherence.py`, 신규):

### 리뷰 1라운드(리뷰어 4명 병렬)에서 고친 것

- **[HIGH] 준수 참여자 지표가 등록 시점에 교란됨**: 참여자마다 분모(관찰된 주 수)가 달라,
  1주만 관찰된 사람이 "1/1 = 100%" 로 완주자를 이겼다. 두 군이 관찰된 주에서 **똑같이**

  분모에 넣고 제외 인원을 `!` 로 보고한다. 창을 고정하지 않으면 분모 범위(`2~3주`)를
