# 사용법 (빠른 시작)

사용자 이벤트 로그(CSV/JSONL) → **세션 · DAU/WAU/MAU · 리텐션 · 퍼널 · 프로토콜 준수도**를
한 번에 요약하고, 군(arm) 열이 있으면 **중재군 vs 대조군 비교**까지 함께 냅니다.
리포트를 남에게 보내야 하면 `--anonymize` 로 사용자 ID를 가명으로 바꿀 수 있습니다.

## 가장 쉬운 방법
- 이 폴더의 **`실행.command`** 파일을 더블클릭하세요.
- 번들 예시 두 개가 자동 실행됩니다: 기본 분석(수면앱 로그 6명)과
  **군 비교 + 준수도 예시**(2군 24명·3주, `examples/trial_events.csv`).

## 내 데이터로 돌리기 (터미널)
CSV에 **사용자/이벤트/시각** 세 열이 있으면 됩니다. (기본 열 이름: `user_id`, `event`, `timestamp`)

```bash
# 1) 기본 실행
python3 -m logflow.cli 내로그.csv

# 2) 퍼널까지 보기 (단계는 순서대로)
python3 -m logflow.cli 내로그.csv --funnel app_open,breathing_start,breathing_complete

# 3) 열 이름이 다를 때 + 리텐션 day-1/3/7
python3 -m logflow.cli 내로그.csv \
    --user-col uid --event-col action --time-col ts --retention 1,3,7

# 4) 결과를 JSON 파일로 저장 (엑셀/R/파이썬으로 이어서 분석)
python3 -m logflow.cli 내로그.csv --json --out 결과.json

# 5) 실데이터가 지저분할 때: 세미콜론/탭 자동감지 + 중복 행 제거 + 기간 자르기
python3 -m logflow.cli 내로그.csv --dedup --from 2026-01-01 --to 2026-01-31

# 6) 표(DAU/리텐션 등)를 엑셀로 붙일 CSV 로 저장 + 롤링 리텐션
#    (퍼널 표는 --funnel 을, 군 비교 표는 --group-col 을 준 경우에만 만들어집니다)
python3 -m logflow.cli 내로그.csv --csv-dir 표출력 --retention-mode rolling

# 7) 군 비교 (중재군 vs 대조군) — 군 라벨 열 이름을 --group-col 로
python3 -m logflow.cli 내로그.csv --group-col arm --ref-group 대조군 \
    --funnel app_open,breathing_complete

# 8) 군이 3개 이상일 때 비교할 두 군만 고르기
python3 -m logflow.cli 내로그.csv --group-col arm --only-groups 중재군,대조군

# 9) JSONL 이나 gzip(.gz) 로그도 그대로 (확장자로 자동 판별)
python3 -m logflow.cli 내로그.jsonl.gz --group-col arm

# 10) 프로토콜 준수도 — "주 5일 이상 사용" 규약, 8주까지
python3 -m logflow.cli 내로그.csv --adherence-days 5 --adherence-weeks 8

# 11) 준수율까지 군 비교에 넣기
python3 -m logflow.cli 내로그.csv --group-col arm --adherence-days 5

# 12) 리포트를 남에게 보내야 할 때: 사용자 ID를 U001··· 가명으로
python3 -m logflow.cli 내로그.csv --anonymize --out 공유용.txt
```

타임스탬프는 `2026-01-01T22:00:00` 같은 ISO 형식이나 epoch 숫자 모두 됩니다.
인코딩이 깨지면(예: 엑셀 한글 CSV) `--encoding cp949` 를 붙이세요.

## 결과 읽는 법
- **개요**: 총 이벤트/사용자, 기간, 세션 수, 세션당 이벤트·길이(평균과 **중앙값**).
- **활성 사용자**: 날짜별 DAU(당일)·WAU(7일)·MAU(28일). 맨 아래 점착도 = 평균DAU/평균MAU.
- **리텐션**: `day-1 : 50.0% (retained 3/6, 95%CI 18.8–81.2%)` = 첫날 쓴 6명 중 다음날 다시 온
  3명 = 50%. 괄호의 **95%CI** 는 표본이 작을 때 실제 값이 있을 법한 범위(넓으면 그만큼 불확실).
- **퍼널**: 단계별 도달 인원·전환율(직전/1단계 대비)과 **직전 단계까지 걸린 시간의 중앙값**.
  어디서, 얼마나 오래 걸려 이탈하는지 한눈에.
- **프로토콜 준수도**(`--adherence-days` 준 경우): "주 N일 이상 사용" 규약을 얼마나 지켰는지.
  - 주차 표의 `1  24  18  75.0%` 행 = 1주차를 **온전히 관찰할 수 있었던** 24명 중 18명이
    그 주에 N일 이상 썼다는 뜻입니다. 뒤쪽 주차는 늦게 등록한 사람이 빠져 **대상이 줄어듭니다**
    (관찰 종료일에 걸친 부분 주는 "아직 쓸 시간이 없었던" 것이라 분모에서 뺍니다). 그래서
    주차끼리의 비교에는 사람 구성 변화가 섞여 있습니다.
  - `활성일(중앙)` 은 그 주 **대상 전원(0일 사용자 포함)** 의 중앙값이라, 준수율 25%인 주에
    0.0 이 나올 수 있습니다.
  - `사용자당 준수율` = 사람마다 (준수 주 ÷ 자기 관찰 주) 를 구한 값의 중앙값.
    `연속 준수 주` = 사람마다 **가장 긴** 연속 준수 구간을 구한 값의 중앙값입니다.
  - `준수 참여자 5/24` = 자기가 관찰된 주의 80% 이상을 지킨 사람이 24명 중 5명.
    기준은 `--adherence-target` 으로 바꿉니다.
    **주의 — 사람마다 관찰된 주 수가 다르면 이 비율은 행동이 아니라 등록 시점을 반영할 수
    있습니다**(1주만 관찰된 사람은 그 1주만 지켜도 100%). 논문·군 비교에는
    `--adherence-weeks 8` 처럼 창을 고정해 **8주를 끝까지 관찰한 사람만** 비교하세요.
    관찰 주가 적으면 80% 기준은 사실상 올림됩니다(2주면 2/2 = 100% 요구).
  - 맨 위 `관찰 종료일` 을 꼭 확인하세요. 로그에 오타로 미래 날짜가 한 줄만 섞여도
    그 뒤의 빈 주가 모두 '미준수' 로 잡혀 준수율이 뚝 떨어집니다.
  - 주차는 **달력 주가 아니라 각자의 첫 활동일부터** 셉니다. 격주 규약이면 `--adherence-period 14`
    (이때 화면의 '주' 는 '기간' 으로 바뀝니다).
  - 주의: 여기서 '준수'는 *로그에 활동이 남았는가* 이지, 중재를 제대로 수행했는지가 아닙니다.
    이벤트가 하나도 없는 참여자는 로그에 없으므로 아예 집계에 들어오지 않습니다(ITT 아님).
- **활동 시간대**: 하루 중 언제(피크 시간대)·무슨 요일에 많이 쓰는지.
- **`--anonymize`**: 사용자 ID를 `U001…` 로 바꿔 출력합니다(집계 수치는 그대로). 리포트를 메일·
  공유 폴더에 올려야 할 때 쓰세요. 대응표는 저장하지 않습니다 — 원본과 다시 연결하려면
  `--anonymize` **없이** 한 번 더 돌린 뒤 사용자를 **(첫 활동 시각, 원래 ID) 오름차순**으로
  정렬하면 `U001…` 순서와 그대로 대응됩니다.
  가려지는 것은 **ID 뿐**입니다 — 이벤트 이름·군 라벨·시각은 그대로 실리므로 드문 이벤트나
  인원이 적은 군은 여전히 개인을 좁힐 수 있습니다.
- **군 비교**(`--group-col` 준 경우):
  - 맨 위 표는 군별 **사용자당 중앙값** (한 사람이 여러 번 세어지지 않게).
  - **비율 비교**: `+58.3%p [+22.5, +80.7]%p` = 중재군이 대조군보다 완주율이 58.3%p 높고,
    참값은 대략 22.5~80.7%p 사이. 구간이 0을 포함하면 "차이가 있다고 말하기 어렵다"는 뜻.
  - **분포 비교**: 효과크기(+1에 가까울수록 첫 군이 크게 많음), p 값은 순위검정(Mann-Whitney).
    "사용시간"은 각 세션의 (첫→마지막 이벤트) 시간을 합한 값입니다. 이벤트가 하나뿐인
    세션은 0분, 세션 사이의 시간은 제외 — "앱을 켜 둔 시간"이 아닙니다.
  - **이탈까지의 시간**: 마지막 활동 후 7일(기본) 이상 기록이 없으면 이탈로 봅니다.
    "절단"은 아직 이탈로 볼 수 없는(관찰이 끝난) 사람 수입니다.
  - **p(Holm)**: 여러 검정을 한꺼번에 하면 우연히 유의해 보이는 게 생기므로 보정한 값입니다.
    **판단은 p(Holm) 으로** 하세요. 검정 개수가 옵션(`--retention`/`--funnel`/`--adherence-days`)에 따라
    달라지면 이 값도 달라지니, 볼 비교를 먼저 정하고 한 번만 돌리세요.
  - `!` 로 시작하는 줄은 주의 안내입니다(군 라벨 충돌, 비교 불가 사유, 인원이 적어
    재식별 위험이 있는 군 등). 그냥 지나치지 마세요.
  - 이 비교는 탐색적(사후) 분석입니다 — 확증적 결론에 쓰지 마세요.
