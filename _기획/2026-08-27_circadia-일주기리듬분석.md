# circadia-일주기리듬분석

## 한 줄 요약

워치에서 내보낸 **연속 시계열(심박·걸음·수면구간) CSV 1~3개**를 받아 **일주기리듬
(circadian rhythm)을 정량화**하고 — 코사이너(MESOR·진폭·정점위상), 비모수 지표
(IS·IV·RA·L5/M10), 수면 규칙성(SRI·社會적 시차·중간수면), 심박 야간 강하 —
**문헌 참고범위와 대조한 한국어 건강정보 리포트 + 48시간 더블플롯 텍스트 액토그램**을
출력하는 오프라인 CLI. 진단하지 않는다: 지표를 계산하고, 문헌 범위를 보여주고,
확인 못 하는 것은 확인 못 한다고 말한다.

## 왜 필요한가

> 워치를 1년째 차고 있다. 앱은 "수면 점수 82"라고 말하지만 그 숫자가 어떻게 나왔는지,
> 지난달보다 내 **리듬**이 좋아졌는지 나빠졌는지는 알 길이 없다. 정작 워치가 가진
> 진짜 정보 — 매일 같은 시간에 자는가, 심박 리듬의 진폭이 살아 있는가, 주말마다
> 시차를 겪고 있는가 — 는 아무도 계산해 주지 않는다.

벨테라 맥락에서는 이중으로 유용하다:
1. **개인 건강정보** — 사용자 본인·가족·피험자 후보의 워치 export에서 리듬 건강도를
   즉시 판독. 수면중재(BELL-001)의 타깃인 "불규칙한 리듬"을 숫자로 보여준다.
2. **연구 파이프라인** — SERENE의 워치 데이터에서 일주기 지표(IS·RA·SRI)는 탐색적
   지표 후보다. 이 툴의 출력 CSV는 statwise/longistat에 그대로 들어가고,
   DATA_INVENTORY의 워치 HRV/HR 모달리티가 입력이 된다.

지루하고, 수식이 정해져 있고, 손으로는 못 하고(하루 1440분 × 수십 일), 앱은 근거를
안 보여준다 — 이 카탈로그가 이기는 정확히 그 자리다.

## 대안 대비 우위

| 대안 | 왜 그래도 이게 낫나 |
|---|---|
| 워치 제조사 앱 | 점수의 산출 근거 비공개, 리듬 지표(IS/IV/RA/SRI/코사이너) 자체를 안 줌, 데이터가 앱 안에 갇힘 |
| pyActigraphy 등 파이썬 패키지 | 액티그래피 연구자용 — 설치 무겁고(numpy/pandas 스택) 워치 CSV를 바로 못 먹으며 건강정보 해석·한국어 출력 없음. 이 툴은 stdlib 전용 + 해석 동봉 |
| LLM에 CSV 붙여넣기 | 수만 행 시계열의 코사이너 적합·IS 계산을 LLM은 못 한다 — 그럴듯한 숫자를 지어낸다. 결정론적 수식 계산이 압도적으로 옳은 영역 |
| 수면클리닉 액티그래피 검사 | 표준이지만 기기 대여·내원 필요. 이 툴은 이미 손목에 있는 워치로 스크리닝 |

### 인접 툴과의 경계

| | 입력 | 답하는 질문 |
|---|---|---|
| `hrvkit` | RR/IBI 간격 | 자율신경 지표(HRV)가 어떤가 — **분 단위 생리** |
| `sleepdiary` | 수면일기(주관) | CSD 표준 수면지표 — **자가보고** |
| **`circadia` (이 툴)** | 워치 연속 시계열(HR·걸음·수면구간) | **24시간 리듬**이 안정적인가·진폭이 있는가·규칙적인가 — **일 단위 리듬** |

셋은 입력도 시간 스케일도 다르다. circadia는 RR 간격을 받지 않고(HRV 계산 금지 —
hrvkit 영역), 수면일기를 받지 않는다(sleepdiary 영역). 워치의 **수면 구간
(시작~종료 타임스탬프)** 은 받는다 — 일기가 아니라 기기 기록이므로.

## 범위

### 한다 (v1)

1. **입력** — 유연한 CSV: ①심박 `timestamp,hr` ②걸음/활동 `timestamp,steps`
   ③수면구간 `start,end` (모두 선택적, 최소 1개). 열 이름 자동 인식 + `--hr-col`
   등 오버라이드. 인코딩 utf-8/utf-8-sig/cp949, 날짜 포맷 다종(기존 툴 수준),
   Apple 건강 내보내기·삼성헬스·Fitbit CSV의 대표 열 이름을 별칭 사전에 포함.
2. **코사이너(cosinor) 분석** — 24h 단일 성분 최소제곱 적합(cos/sin 선형화):
   MESOR·진폭(amplitude)·정점위상(acrophase, 시각으로 표기) + 적합 유의성(zero-
   amplitude F 검정)·결정계수. HR과 활동 각각.
3. **비모수 리듬 지표(Van Someren 계열)** — IS(일간 안정성)·IV(일내 변동성)·
   L5/M10(최저 5h·최고 10h 평균과 중앙시각)·RA(상대진폭). 시간당 빈으로 계산.
4. **수면 규칙성** — 수면구간 입력 시: SRI(Sleep Regularity Index, Phillips 2017),
   중간수면시각(midsleep)·기상/입면 시각 SD, **사회적 시차**(주중 vs 주말 중간수면
   차, Roenneberg), 수면시간 평균±SD.
5. **심박 일주기 마커** — 야간 심박 강하율(주간 평균 대비 야간 최저 구간),
   심박 최저점(nadir) 시각, 기상 전 상승 여부. (HR 입력 시)
6. **48h 더블플롯 텍스트 액토그램** — 날짜 × 48시간 축 활동/수면 밴드 시각화
   (연구자가 한눈에 패턴을 보는 표준 방식의 텍스트 버전).
7. **건강정보 해석 리포트(한국어)** — 각 지표에 ①내 값 ②문헌 참고범위(출처 명기:
   Van Someren 1999, Phillips 2017, Windred 2023, Roenneberg 2012 등) ③방향 해석
   ④일반적·비진단적 개선 팁(빛 노출·기상시각 고정 등 행동 수칙). 굵은 면책:
   "의료기기·진단 아님, 이상 소견 지속 시 수면클리닉".
8. **커버리지 자백** — 분석일수·착용률(데이터 있는 시간 비율)·갭 목록. IS/IV·SRI는
   **유효 5일(권장 7일) 미만이면 계산 거부**(값 대신 '데이터 부족' — 조용히 부정확한
   값을 주지 않는다). 착용률 임계 미만 시 exit 3.
9. **출력** — 터미널 리포트 + `리듬리포트.md`(해석 전문) + `지표.csv`(statwise/
   longistat 투입용, 1행=1지표 및 1행=1일 일별 지표) + `액토그램.txt`.
   exit 0 정상 / 2 입력·인자 오류 / 3 데이터 불충분.

### 의도적으로 안 한다

- 진단·질병 위험 점수·"당신은 OO입니다" 단정 (참고범위 대조와 방향 서술까지만)
- HRV 계산(hrvkit)·수면단계 추정·DLMO 추정(불가능한 정밀도 약속 금지)
- 결측 보간(갭은 갭으로 자백), 시간대 자동 변환(타임스탬프에 tz 섞이면 자백 후 거부)
- 다인 배치 처리(v1은 1인 — 개인 건강정보 툴. 연구 배치는 후속)
- 그림 파일(텍스트 액토그램까지만, stdlib 전용), 네트워크·클라우드 일체

## 실행 예

```bash
circadia 심박.csv --steps 걸음.csv --sleep 수면.csv --out-dir 리듬결과
# 최소: circadia 심박.csv   /   걸음만: circadia --steps 걸음.csv
```

## 완료 기준 (빌더 체크리스트)

- [ ] stdlib 전용(`dependencies = []`)·네트워크 0·입력 읽기 전용·산출물은 --out-dir 안에만
- [ ] **코사이너 손계산 대조**: 합성 사인파(진폭·위상·MESOR 기지)에서 세 파라미터 오차
      ≤1e-6, 위상은 시각 표기(예: 15:24)로 변환 검증, zero-amplitude F 검정이 무리듬
      백색잡음에서 비유의
- [ ] **IS/IV 극단 검증**: 완전 규칙 패턴 → IS=1.0 정확히, 백색잡음 → IS≈0(임계 명시),
      IV: 매시간 교대 패턴에서 하드코딩 기대값, 문헌 공식(시간당 빈) 주석에 명기
- [ ] **RA/L5/M10**: 손으로 만든 24h 프로파일에서 L5·M10 값과 중앙시각 정확 일치
- [ ] **SRI**: 동일 수면스케줄 이틀 → 100, 완전 반전 → −100 경계, 자정 넘김·낮잠 처리
      규칙 문서화+테스트
- [ ] **사회적 시차**: 주중/주말 라벨링 규칙(금·토 밤 = 주말밤) 문서화, 손계산 대조
- [ ] 심박 야간 강하: 합성 주기 신호에서 강하율·nadir 시각 손계산 일치
- [ ] 5일 미만 → IS·SRI '데이터 부족' 표기(값 출력 금지) 테스트, 착용률 임계 미만
      exit 3, 갭·일수·착용률 자백이 리포트 최상단
- [ ] 타임스탬프 역행·중복·미래날짜·tz 혼재 → 데이터 오류로 자백(추측 금지)
- [ ] 건강정보 문구: 참고범위마다 출처 표기, 진단 단정 문구 0(테스트로 grep 금지어:
      "진단", "질환이 있", "환자입니다" 류), 면책 고지 리포트·README 양쪽
- [ ] 액토그램: 48h 더블플롯, 수면구간 밴드+활동 밀도 문자, 최대 42일 표시
- [ ] 지표.csv 수식 인젝션 가드, 예시 데이터 100% 합성(현실적 패턴 — 규칙적 1주 +
      불규칙 1주 시나리오 2벌), pytest는 손계산 리터럴 고정
- [ ] README(목적 KR/EN·실제 출력 붙여넣기·공식 출처 표·한계·면책), 사용법.md,
      실행.command(합성 예시 실행), HARDENING.md, MIT LICENSE, .gitignore
- [ ] 루트 README 카탈로그 행 + IDEAS.md 완료 항목은 오케스트레이터가 처리(스킵)

## 실패할 수 있는 지점 (조기 발견법)

1. **워치 export 포맷 파편화** — 제조사마다 열 이름·단위 다름. → 별칭 사전 + 명시적
   `--*-col` 오버라이드 + `--inspect`(열 인식 결과만 보여주고 종료). 빌드 첫 30분에
   Apple/삼성/Fitbit 대표 포맷 3벌을 합성으로 만들어 파싱부터 고정.
2. **IS/IV·SRI를 짧은 데이터에 조용히 계산** — 3일치로 IS를 내면 쓰레기 값이 나오고
   사용자는 믿는다. → 최소일수 게이트가 1번 테스트(액토그램·코사이너는 짧아도 가능
   — 지표별 게이트를 다르게).
3. **건강정보가 진단으로 미끄러짐** — "리듬 장애입니다"류 문구 하나로 이 툴은 의료기기
   영역을 침범한다. → 금지어 grep 테스트 + 해석 문구는 전부 "참고범위 대비 낮음/높음"
   구조로 통일.
4. **위상(acrophase) 부호·시각 변환 실수** — cosinor의 고전적 함정. → 기지 위상 3개
   (03:00·15:00·21:30)를 심은 합성파로 시각 변환까지 검증.

## 빌더 메모

- 공식 출처를 주석에 정확히: IS/IV/RA·L5/M10 = Van Someren et al. 1999 (Chronobiol
  Int), SRI = Phillips et al. 2017 (Sci Rep) — Windred 2023 (Sleep) 계산 세부 참조,
  사회적 시차 = Roenneberg et al. 2012 (Curr Biol), cosinor = Cornelissen 2014
  (Theor Biol Med Model).
- 버리는 순서(시간 부족 시): 액토그램 → 심박 마커 → 사회적 시차. **절대 버리면 안
  되는 것**: 코사이너+IS/IV/RA의 손계산 검증, 최소일수 게이트, 비진단 문구 규율.
- 다른 툴 폴더 수정·import 금지. 예시 실행 시간 수 초 이내 유지.
