# deidaudit-비식별화점검

## 한 줄 요약

피험자 단위 CSV/XLSX를 **밖으로 내보내기 직전에** 전수 스캔해서 — 직접식별자·자유텍스트에 숨은 이름/전화/주민번호, 엑셀 숨김 시트·숨김 열·작성자 메타데이터, 그리고 **가명화해도 남는 재식별 위험(정확 날짜 + 준식별자 조합 k)** 을 파일·행·열까지 찍어 보고하고, 요청하면 분석을 깨지 않는 방식으로 가명화·날짜이동한 내보내기 사본을 만든다.

## 왜 필요한가

> 금요일 오후, 이상연 교수님 쪽에서 "그 데이터 좀 보내주세요"가 온다. `merged.csv` 하나, 수면일기 원본 하나, UT 로그 하나. 엑셀로 연다. 이름 열 지우고, 전화번호 열 지우고, ID를 S01…로 바꾸고, 메일에 첨부한다. 5분 걸렸다.
>
> 지우지 못한 것: 수면일기 `비고` 열 187행에 "○○○ 간호사한테 얘기함", UT 로그 `자유응답` 열에 본인 전화번호를 적은 피험자 1명, 방문 날짜 열 전체(2026-03-14, 2026-03-21 …) — 병원 방문 기록과 대조하면 그대로 특정된다. 그리고 XLSX 안에 숨겨진 시트 `Sheet3`에 원본 명단이 그대로 남아 있다. 이 중 어느 것도 열어봐서는 알 수 없다. 메일은 이미 나갔고, 되돌릴 방법은 없다.

**지금은 대신 뭘 하는가**: 엑셀에서 눈으로 보고 열을 지운다. 자유텍스트 열은 스크롤로 훑거나 아예 안 본다. 준식별자 조합(나이+성별+사이트+날짜)이 몇 명까지 좁혀지는지는 **계산하지 않는다** — 계산할 방법을 모르고, 손으로는 못 한다. ID 가명화는 파일마다 따로 하므로 파일 간 연결이 어긋나거나, 반대로 원본 ID가 한 파일에만 남는다.

**카탈로그 공백**: 24개 툴 중 비식별화를 다루는 것은 `logflow --anonymize` 하나뿐이고, 그것은 로그 분석 중 부수적으로 ID를 해싱하는 기능이다. "내보내기 직전 전수 감사"를 하는 툴은 없다. `joinaudit`은 합치고, `visitaudit`은 날짜 규정 준수를 보고, `tracecheck`는 원고 숫자를 본다 — **아무도 "이 파일을 밖에 보내도 되는가"를 묻지 않는다.**

**같이 검토했고 접은 대안 2개** (판단 근거를 남긴다):
- `sleepdiary` 대형 업그레이드(야간 변동성·규칙성 지표 추가) — 가치는 있으나 SERENE 효능 데이터가 아직 없어 **오늘 돌릴 입력이 없다**. 데이터가 쌓인 뒤가 맞다.
- `paperforge`에 실데이터 연결 — 아이디어 순위 매기기는 본질적으로 의미론이고, 거기서는 LLM이 이긴다. 결정론적으로 남는 부분(변수 겹침 인구조사)은 `joinaudit` 커버리지 매트릭스와 상당 부분 겹친다.

## 대안 대비 우위

| 대안 | 왜 이 툴이 이기는가 |
|---|---|
| **엑셀에서 손으로 열 삭제** | 사람은 열 헤더만 본다. 셀 4만 개를 한 칸씩 못 본다. 자유텍스트·숨김 시트·문서 메타데이터는 **구조적으로 눈에 안 띈다**. 그리고 실패가 조용하다 — 잘못했다는 사실을 영원히 모른다. |
| **Presidio / ARX / anonympy (pip)** | Presidio는 영어 NER 모델 기반이라 한글 이름·주민등록번호·010 번호를 신뢰성 있게 못 잡고, 모델 다운로드(네트워크)가 필요하다. ARX는 자바 GUI에 GDPR 일반론 도구라 우리 파일 형태(피험자×시점 다중 CSV + 야간 귀속)를 모른다. 둘 다 **엑셀 숨김 시트/작성자 메타데이터**를 보지 않는다. 이 툴은 stdlib·오프라인·한국형 패턴·우리 파일 구조에 맞춘다. |
| **LLM에 붙여넣기** ← **여기가 핵심이다** | 여기서는 편의 문제가 아니다. **식별 가능한 피험자 데이터를 LLM에 붙여넣는 행위 자체가 사고다.** 붙여넣어도 되는지 판정하는 것이 이 툴의 목적인데, 판정하려고 붙여넣으면 목적이 무너진다. 게다가 LLM은 4만 셀을 전수로 세지 못하고, 못 셌다는 사실도 모르며, 준식별자 동치류 크기는 계산이지 추론이 아니다. |
| **아무것도 안 함 (그냥 보냄)** | 실패 비용이 비대칭이다. 1000번 무사하다가 1번 터지면 IRB 사건이고 논문 철회 사유다. |

### 인접 툴과의 경계

| | 답하는 질문 | 입력 | 출력 |
|---|---|---|---|
| `joinaudit` | 이 파일들을 하나로 합쳐도 되는가 | 여러 원본 | `merged.csv` + 병합 감사 |
| `visitaudit` | 방문이 프로토콜을 지켰는가 | 방문 날짜 + 프로토콜 | 이탈 목록 |
| `logflow --anonymize` | 로그 지표는 무엇인가 (부수적으로 ID 해싱) | 이벤트 로그 | 리텐션·퍼널 |
| **`deidaudit`** | **이 파일을 밖으로 보내도 되는가** | 내보낼 파일들 | 위험 목록 + 안전한 사본 |

**경계를 지키는 강제 장치 (필수 구현)**:
1. **조인 금지.** 파일을 여러 개 받되 절대 합치지 않는다. `--link-id` 는 파일 간 **동일 피험자에게 같은 가명을 주기 위해서만** 쓰이고, 행을 결합하지 않는다. 조인/병합 관련 옵션을 주면 `exit 2` 로 "joinaudit을 먼저 쓰세요"를 출력하고 종료한다.
2. **분석 지표 계산 금지.** 평균·검정·리텐션 등 어떤 통계도 출력하지 않는다. 출력에 숫자가 나온다면 그것은 개수(건수·k·셀 수)뿐이다. 이 선을 넘는 순간 `surveyscan`/`logflow`의 재탕이 된다.
3. **키 파일은 `--out-dir` 안에 절대 쓰지 않는다.** `--pseudonymize` 사용 시 `--key-out` 필수, 그 경로가 `--out-dir` 하위(심볼릭 링크 경유 포함)이면 `exit 2`. 내보낼 폴더를 통째로 압축해 보내는 것이 정상 사용 패턴이므로, 매핑표가 그 안에 있으면 툴이 사고의 원인이 된다.
4. **리포트 자체가 PII가 되지 않는다.** `문제목록.csv` 의 증거 스니펫은 항상 마스킹해서 기록한다(`010-****-**12`, `홍○○`). 원문 그대로 쓰면 리포트를 공유하는 순간 유출이다.

## 범위

### 한다 (v1)

1. **직접식별자 전수 스캔** — 모든 파일의 모든 셀. 주민등록번호(체크섬 통과 시 치명 / 미통과 시 경고), 휴대전화(010/011/016/017/018/019), 이메일, 한글 성명(성씨 사전 + 2~3자, 자유텍스트·이름류 열에 한정), 생년월일(헤더가 생년/birth/dob 이거나 열 전체가 그럴듯한 출생일 분포일 때만), 89세 초과 연령.
2. **자유텍스트 열 자동 판별** — 평균 길이·공백 수·고유값 비율로 판정. 판별된 열은 **전 행 스캔**하고, 판별 결과 자체를 리포트에 자백한다(무엇을 자유텍스트로 봤고 무엇을 안 봤는지).
3. **엑셀 숨은 내용 적발** — 숨김 시트, 숨김 열/행, 셀 주석, `docProps/core.xml` 의 작성자/최종수정자, 정의된 이름(defined names). zipfile + ElementTree 로 직접 읽는다.
4. **재식별 위험 계산** — `--quasi age,sex,site,visit_date` 로 준식별자를 지정하면 동치류 크기 분포를 계산해 `min k`, `k=1 행 수`, `k<5 행 수`, **어느 열을 빼면 k≥5 가 되는지**를 보고한다. 지정하지 않으면 후보 열을 제안만 하고 계산은 건너뛰었다고 자백한다.
5. **정확 날짜 열 탐지** — 방문일·야간 날짜 열은 가명화해도 남는 재식별 벡터다. 무조건 경고하고 이동을 권고한다.
6. **가명화 내보내기 (`--pseudonymize`)** — 피험자별 결정론적 가명 ID(파일 간 일관), 피험자별 고정 날짜 오프셋(±180일 내) 적용. **자체 검증 필수**: 이동 전후 피험자 내 날짜 간격이 완전히 동일한지, 야간 귀속(자정 넘김) 라벨이 보존되는지 확인하고, 하나라도 깨지면 내보내기를 취소한다.
7. **열 제외 (`--drop-columns`)** — 사람이 결정한 열만 뺀다. 자동 삭제는 하지 않는다.
8. **커버리지 자백** — 검사한 파일/시트/열/셀 수, 건너뛴 열과 사유(바이너리·인코딩 실패·크기 초과 등)를 반드시 출력한다. **자백 블록을 생성할 수 없으면 리포트를 아예 출력하지 않는다.**
9. **KR/EN 문단 초안** — 무엇을 제거·변형했는지를 논문 Methods / Data Availability Statement 문장으로 뽑는다.

### 의도적으로 안 한다

- **자유텍스트 자동 치환/삭제.** 위치(파일·행·열·문자 구간)만 찍고 사람이 결정한다. 자동 마스킹은 의미를 조용히 훼손하고, 놓친 부분에 대해 거짓 안심을 준다.
- **k-익명성 자동 일반화/억제.** 나이를 5세 구간으로 묶는 등의 변형은 분석을 바꾼다. 보고만 하고 실행은 사람이.
- **파일 병합.** `joinaudit` 영역.
- **어떤 통계도.** 위 강제 장치 2.
- **PDF·DOCX 스캔.** v1은 표 형식(CSV/TSV/XLSX)만. 원고 내 식별자는 별개 문제이며 v2 1순위.
- **네트워크 호출·의존성.** stdlib 전용, 오프라인.
- **원본 수정.** 입력은 읽기 전용, 산출물은 `--out-dir` 아래에만.

## 입력 / 출력

### 입력 예 (`수면일기_원본.csv`)

```csv
subject_id,name,phone,birth,visit_date,night_date,TST_min,비고
BELL-001-007,김현중,010-2345-6789,1988-04-02,2026-03-14,2026-03-13,412,특이사항 없음
BELL-001-007,김현중,010-2345-6789,1988-04-02,2026-03-21,2026-03-20,388,새벽에 깨서 ○○○ 간호사한테 얘기함
BELL-001-012,이서연,010-9876-5432,1991-11-27,2026-03-15,2026-03-14,455,
```

### 실행 예

```bash
# 1단계: 감사만 (파일을 만들지 않는다, 5초 이내)
deidaudit 수면일기_원본.csv UT로그.xlsx merged.csv \
  --quasi birth,sex,visit_date --audit-only

# 2단계: 안전한 사본 만들기
deidaudit 수면일기_원본.csv UT로그.xlsx merged.csv \
  --quasi birth,sex,visit_date \
  --pseudonymize --link-id subject_id \
  --shift-dates --drop-columns name,phone \
  --out-dir 내보내기_2026-08-21 \
  --key-out ~/보안/키_2026-08-21.csv
```

### 출력 파일

| 파일 | 내용 |
|---|---|
| `점검결과.md` | 한국어 리포트 + 커버리지 자백 |
| `문제목록.csv` | 파일·시트·행·열·유형·심각도·**마스킹된** 증거 |
| `재식별위험.csv` | 준식별자 조합별 동치류 크기 분포, 열 제거 시나리오 |
| `비식별화_요약.md` | 무엇을 바꿨는지 + KR/EN Methods·Data Availability 초안 |
| `내보내기/` | 변환된 파일 사본 (`--pseudonymize` 시에만) |
| `--key-out` 경로 | 원본ID↔가명ID, 피험자별 날짜 오프셋. **`--out-dir` 밖 강제** |

### 종료코드

| 코드 | 의미 |
|---|---|
| 0 | 치명 0건 — 내보내도 됨 |
| 1 | 치명 발견 |
| 2 | 입력/옵션 오류 (`--out-dir` 없음, `--pseudonymize` 인데 `--key-out` 없음, `--key-out` 이 `--out-dir` 하위, 병합 옵션 사용) |
| 3 | 판정불가 (파싱 실패, 인코딩 불명, 검사 가능 셀 비율 < 80%) |

**3이 1보다 우선한다.** 다 못 봤으면 "치명 0건"은 거짓말이다.

## 실패할 수 있는 지점 (그리고 가장 싸게 조기 발견하는 법)

1. **실데이터가 이미 가명화되어 있어서 직접식별자가 애초에 0건이다.** 잘 운영되는 임상시험이면 연구자 손에는 ID만 온 파일이 온다. 그러면 이 툴의 절반이 무용지물이다.
   → **가장 싼 조기 확인**: 최근 실제로 밖으로 내보낸 파일 1개에 `--audit-only` 를 30초 돌린다. **직접식별자 0 + 자유텍스트 열 0 + 숨김 시트 0 + min k ≥ 5** 면 이 툴은 접는다. 단 정확 날짜 열은 수면 연구 특성상 거의 확실히 잡히므로, **그것마저 0이면 진짜 접는다.**
2. **오탐 폭발 — 우는 늑대.** TST 412, RR 간격 6자리, 피험자 코드 안의 `010` 같은 것이 전화번호/주민번호 패턴에 걸린다. 매번 우는 체커는 두 번 다시 안 열린다.
   → **가장 싼 조기 확인**: 완전히 깨끗한 합성 파일에 먼저 돌린다. 치명이 1건이라도 나오면 그 규칙을 좁히거나 경고로 강등하거나 **기능을 뺀다.** 넓히지 말고 좁힌다.
3. **리포트 자체가 유출 경로가 된다.** `문제목록.csv` 에 증거로 원문을 그대로 적으면, 그 파일을 공유하는 순간 정확히 막으려던 일이 일어난다.
   → **가장 싼 조기 확인**: "산출물 어디에도 원본 식별자 문자열이 등장하지 않는다"를 테스트로 못 박는다. 이건 나중에 붙이면 늦다, 첫 커밋에 넣는다.
4. **날짜 이동이 분석을 조용히 깨뜨린다.** 오프셋이 잘못되면 방문창 계산과 자정 넘김 야간 귀속이 어긋나는데, 눈으로는 안 보인다.
   → **가장 싼 조기 확인**: 이동 전/후 파일로 `visitaudit` 을 각각 돌려 이탈 판정이 **완전히 동일**한지 확인한다. 다르면 이동 로직이 틀린 것이다.
5. **결국 그냥 엑셀로 한다 (툴을 안 연다).** 보내기 직전 5분이 급한 순간이라, 설치·옵션·문서를 읽어야 하면 진다.
   → **가장 싼 조기 확인**: `--audit-only` 를 옵션 없이 파일만 던져도 돌게 하고 5초 안에 끝나게 한다. `실행.command` 더블클릭 → 파일 드래그 한 번으로 감사까지 끝나면 산다.

## 빌더를 위한 메모

- 폴더/패키지/CLI 이름: `deidaudit-비식별화점검/`, 패키지 `deidaudit`, CLI `deidaudit`. 출력 언어는 한국어(문단 초안만 KR/EN 병기).
- 기존 툴 폴더는 **절대 수정·import·복사하지 않는다.** `joinaudit` 의 `merged.csv` 를 입력으로 받는 것은 CSV 스키마 호환일 뿐이다.
- **버리는 순서** (시간이 모자랄 때): ⑨ KR/EN 문단 초안 → ⑦ `--drop-columns` → ⑥ 날짜 이동 → ④ k 계산의 "열 제거 시나리오"(min k 만 보고). 감사(①②③⑤)는 마지막까지 남긴다.
- **절대 버리면 안 되는 2가지**:
  1. **커버리지 자백** — 다 못 본 채로 "치명 0건"을 말하면 이 툴은 없느니만 못하다.
  2. **증거 마스킹 + 키 파일 격리** — 이 둘을 빼면 유출을 막으려는 툴이 유출 수단이 된다. 기능이 아니라 안전 요건이다.
