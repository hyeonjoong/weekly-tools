# jamoscore-말지각채점검증

## 한 줄 요약

사람이 손으로 채점한 **말지각검사(자음·모음·일음절·문장) 문항 단위 엑셀**을 읽어, ① 요약표의 %를 문항에서 전수 재계산하고 ② **목표음소 규칙 채점**과 사람 채점이 갈리는 문항만 골라내고 ③ 아무도 계산하지 않는 **음소 혼동 행렬**과 **개인 내 변화의 이항 임계차**를 내놓는 툴. 점수를 고치지 않고, 군간 통계를 내지 않는다.

---

## 왜 필요한가

**촉발 순간:** 병원(분당서울대·한림대)·연구보조원에게서 **채점이 끝난 엑셀**을 받아, 논문 표(`total-최종`)나 CSR에 넣을 % 를 쓰기 직전. 지금은 그 엑셀을 열어 눈으로 훑고, 요약 시트의 숫자를 그대로 믿고 다음 단계로 넘어간다.

**오늘 실제로 하는 일 (실측):** `임상데이터/B. 본실험_결과 데이터 [BELL 내부 공유].xlsx` 는 시트 **58개** — 그중 `s01`~`s35` 가 피험자별 문항 시트이고, 각 시트에 `제시자극 | 응답(전사) | 점수` 블록이 자음·모음·일음절 × 사전·사후로 6벌 들어 있다. 사람이 아이 응답을 한 글자씩 타이핑하고 0/1 을 손으로 찍은 뒤, **그 %를 손으로 `total-최종` 시트에 옮겨 적는다.** 대조 대상 셀만 **168개**, 원 문항은 **2,000개가 넘는다.** 이걸 두 번 검산하는 사람은 없다.

**이 툴이 실제로 뭘 잡는지 — 기획 세션이 실데이터로 미리 재보았다:**

1. **목표음소 규칙 채점 vs 사람 채점: 2,176문항 중 일치 2,172 · 불일치 4 (0.2%).** 규칙이 사람을 거의 완벽히 재현한다 → 남은 4건은 전부 사람이 봐야 할 진짜 후보다.
   - `s20 모음 해드→배드` 사람=0 / 규칙=1 ← 다른 곳에서는 `후드→푸드`(같은 유형: 자음만 틀림)를 **1**로 줬다. **같은 유형을 다르게 채점한 사례.**
   - `s04 호드→조`, `s15 햐드→샤드`, `s35 흐드→뜨디(휴지라고 말하는 것 같았음)` ← 마지막 건은 **응답 칸에 관찰 메모가 섞여 들어간 위생 문제**다.
2. **음소 혼동 행렬 — 현재 아무도 계산하지 않는 값.** 같은 파일에서 바로 나온다: 자음 `ㅌ→ㅍ 39회`, `ㅋ→ㅍ 21회`, `ㄲ→ㄸ 16회`, `ㄱ→ㄷ 13회` / 모음 `ㅜ→ㅗ 27회`, `ㅛ→ㅕ 27회`, `ㅟ→ㅣ 22회`, `ㅚ→ㅐ 14회`. 인공와우 사용자의 **조음위치 혼동** 패턴이 그대로 보인다. 지금 이 데이터는 오직 "자음_전 66.7 → 자음_후 77.8" 이라는 **퍼센트 두 개**로만 소비되고 있고, 그 밑의 2,000문항은 버려진다. 논문 소재이자 **와우핏이 무엇을 훈련시켜야 하는지**에 대한 제품 근거다.
3. **레이아웃이 실제로 사람을 속인다.** 기획 세션이 순진하게 열 위치를 고정해 읽었더니 168셀 중 **54셀이 불일치**로 떴다. 파보니 채점 오류가 아니라 **`일음절` 블록의 열 구성이 `자음`·`모음`과 다르다**(일음절은 0/1 이 아니라 **음소 0~3점** 계열). 즉 이 파일은 **분모가 블록마다 다르고, 그 사실이 어디에도 적혀 있지 않다.** 사람이 손으로 옮길 때 분모를 헷갈릴 수 있는 구조라는 뜻이고, 그게 이 툴이 존재할 이유다.

**앞으로 또 온다:** 소아 KoBio IRB **승인 완료**(`BELL-002/소아용 Kobio IRB 제출 문서/소아kobio IRB 승인통지서.pdf`), BELL-002 확증임상 식약처 사전검토 진행 중, K-CNC MCID 델파이 진행 중, 웹 기반 어음인지도 검사도구 신뢰도 프로토콜 초안 작성 중. **같은 모양의 채점 엑셀이 계속 들어온다.**

## 대안 대비 우위

| 대안 | 왜 그래도 이게 낫나 |
|---|---|
| **지금처럼 엑셀에서 눈으로 + 손으로 옮기기** | 2,000문항·168셀을 두 번 검산하는 사람은 없다. 실제로 `해드→배드`(0점)와 `후드→푸드`(1점)가 같은 파일 안에 공존한다 — 사람이 잡을 수 있는 종류의 오류가 아니다. |
| **문자열 비교(`응답 == 제시`)로 자동 재채점** | **즉시 쓰레기가 된다.** 실측: 문자열이 다른데 1점인 쌍이 **55종**인데 전부 정상 채점이었다(자음검사는 *가운데 자음만*, 모음검사는 *첫 음절 모음만* 맞으면 정답). 목표음소를 자모 분해해서 봐야만 0.2% 불일치까지 내려간다. |
| **`pip install` 로 해결** | 없다. `jiwer`(WER)는 ASR용이라 음절 전체를 비교하고, `jamo`/`hangul-utils`는 자모 분해만 해준다 — **청각검사 채점 규칙(목표음소·음소점수 vs 단어점수·분모)** 을 아는 패키지는 한국어에 존재하지 않는다. 이항 임계차(Thornton–Raffin 계열)도 마찬가지로 어느 패키지에도 없다. |
| **`joinaudit`** | joinaudit 은 *파일들을 붙이는 과정*을 감사한다. 붙이기 전 **한 파일 안에서 요약값이 원 문항과 맞는지**는 보지 않는다. |
| **`tracecheck`** | tracecheck 은 *원고의 숫자*가 산출물 번들에 있는지 본다. 여기서 의심스러운 건 **번들(=`total-최종`) 자체**다. jamoscore 는 tracecheck 이 닿지 못하는 **한 겹 아래**를 본다. |
| **`surveyscan` / `factorscan`** | 리커트 응답을 다룬다. 정답/오답이 있는 **수행형 검사**, 자모 단위 채점, 목표음소 개념이 없다. |
| **`statwise` / `longistat`** | 결론을 낸다. jamoscore 는 **그 입력(long CSV)을 만들고**, 그 입력이 신뢰할 수 있는지만 말한다. |

### 인접 툴과의 경계

| 툴 | 입력 | 답하는 질문 |
|---|---|---|
| `jamoscore` | **문항 단위** 채점 엑셀/CSV | "이 % 는 문항에서 다시 나오는가? 사람 채점이 자기 규칙에 일관적인가? 어떤 음소를 혼동하는가?" |
| `joinaudit` | 여러 파일 | "붙이는 과정에서 사람이 사라지거나 뻥튀기됐는가?" |
| `tracecheck` | 원고 + 산출물 폴더 | "원고 숫자가 산출물에 있는가?" |
| `statwise`/`longistat` | long CSV | "군/시점 간 차이가 있는가?" |
| `stimaudit` | 자극 **음원 파일** | "들려준 소리들이 서로 비교 가능한가?" |

**README 첫 문단이 다음 한 줄을 말하지 못하면 출시하지 않는다:** *"`tracecheck` 는 원고와 산출물을 대조하고, `jamoscore` 는 그 산출물이 원 문항에서 다시 나오는지를 본다."*

## 범위

### 한다 (v1)

1. **입력 인식과 거절.** 다중 시트 XLSX(피험자별 시트) 또는 long CSV. 열은 **헤더 이름으로 검출**하고(제시/자극/target, 응답/반응/response, 점수/score), 못 찾으면 **추측하지 않고 exit 2**. `--inspect` 로 "어느 시트를 피험자로 봤고, 어느 열을 무엇으로 봤고, 블록별 문항수는 몇인지"를 먼저 인쇄한다. 열 매핑 강제는 `--map 매핑.json`. **stdlib `zipfile`+XML 로 직접 파싱**(기존 툴 폴더 import·복사 금지).
2. **문항 → 점수 재계산.** 블록별로 정답수/문항수, **단어점수 %** 와 (음소 채점 블록이면) **음소점수 %** 를 따로 낸다. 분모는 블록마다 독립 산출하고 **리포트에 분모를 항상 명시**한다("일음절 14/18 = 77.8% (단어)", "32/54 = 59.3% (음소)").
3. **요약표 대조.** `--summary total-최종` 을 주면 셀 단위로 재계산값과 대조. 어긋난 셀은 `피험자·열이름·표값·재계산값·정답수/문항수` 를 전부 찍는다. **분모가 달라서 생긴 차이는 "값 불일치"가 아니라 `[경고] 분모 정의 불일치`** 로 따로 센다.
4. **목표음소 규칙 채점 대조.** 검사 유형별 목표음소를 **설정으로 받는다**(코드에 박지 않는다): `자음 = 2음절 초성`, `모음 = 1음절 중성`, `일음절 = 초성·중성·종성 각 1점`. 한글 자모 분해는 유니코드 산식(`0xAC00 + (초성*21+중성)*28+종성`)으로 직접 구현. 사람 점수와 **갈리는 문항만** 목록화한다.
5. **동일 (제시, 응답) 쌍이 서로 다르게 채점된 사례.** 채점 규칙이 무엇이든 **반박 불가능한** 소견이므로 규칙 대조와 **독립적으로** 항상 낸다. 실측 근거: `해드→배드`=0 vs `후드→푸드`=1.
6. **불가능값·경계값.** 모든 %는 `k/n` 이어야 한다 — 어떤 정수 k 로도 만들 수 없는 값은 `[치명]`. 0%/100% 는 `[정보] 바닥/천장` 으로 표시하고, 천장 도달 피험자는 **"사후에 개선 폭이 구조적으로 없음"** 을 명시한다.
7. **자극 리스트 정합.** 정답 시트(`언어검사_정답` 류)를 주면 피험자별 제시 열과 대조: 리스트 뒤바뀜, 순서 섞임, 문항 누락·중복, 그리고 **사전·사후에 같은 리스트를 쓴 경우**(학습효과 교란)를 `[치명]`.
8. **응답 칸 위생.** 응답 셀 안의 관찰 메모(`뜨디(휴지라고 말하는 것 같았음)`), 공백·전각·한글 외 문자, 비어 있는데 점수가 찍힌 칸, 점수 칸의 텍스트/숫자 혼재.
9. **음소 혼동 행렬.** 초성/중성/종성별 `목표 → 응답` 카운트 CSV + 상위 혼동 텍스트 표. **최소 관측수 게이트**(기본 `--min-count 3`) 미만은 표에서 빼고 자백에 적는다. 조음위치·조음방법 묶음 집계는 **참조표를 `--features 자질표.csv` 로 받을 때만** 하고, 없으면 "분류 안 함"으로 자백한다(툴이 음운론적 분류를 스스로 주장하지 않는다).
10. **개인 내 변화의 이항 임계차.** 문항수 n 과 사전 점수에서 **95% 임계차**를 정확 이항으로 계산해(Clopper–Pearson), 각 피험자의 사전→사후 변화가 **검사 오차 범위를 벗어나는지** `초과 / 미달 / 판정불가` 로만 표시. 문구는 `"개인 내 변화가 검사 재검사 오차 범위를 벗어남"` 고정 — **"유의하게 호전"이라고 쓰지 않는다.** n=18에서 2문항(11.1%) 변화가 임계차에 한참 못 미친다는 사실을 이 툴은 정직하게 말해야 한다.
11. **long CSV 출력.** `ID, 시점, 검사, 하위블록, 정답수, 문항수, 단어%, 음소%` — `statwise`·`longistat` 입력 스키마 호환(실행 검증까지 한다).
12. **KR/EN Methods 문단 초안** — 채점 규칙·분모·임계차 산출 방식을 그대로 문장화.
13. **`[커버리지 자백]`** — 시트 몇 개 중 몇 개를 피험자로 인식했는지, 문항 몇 개 중 몇 개를 대조했는지, 건너뛴 사유별 개수, 대조하지 못한 요약 셀. **이 블록 없이는 리포트가 출력되지 않는다(코드로 강제).**

### 의도적으로 안 한다

- **점수를 고치지 않는다.** 원본 XLSX 에 쓰지 않고, 수정본도 만들지 않는다. → *강제장치 1: 쓰기 경로 부재를 AST 로 확인*
- **"채점 오류"라고 판정하지 않는다.** 리포트 어휘는 `사람 채점과 규칙 채점이 다름(확인 필요)` / `동일 쌍 다른 채점` 뿐. → *강제장치 2: 금지어 grep 테스트*
- **군간·시점간 검정을 하지 않는다.** → *강제장치 3: 검정 함수 부재를 AST 로 확인 (`statwise`/`longistat` 재탕 방지)*
- **요약 % 만 든 파일은 판정 없이 exit 2** 로 거절하고 `statwise`/`longistat` 를 가리킨다. 문항 단위가 아니면 이 툴은 할 말이 없다.
- **개인정보를 다루지 않는다.** `개인정보` 류 시트(이름·연락처·생년월일 실제로 존재)를 발견하면 **읽지 않고** `[경고] 식별정보 시트 감지 → deidaudit` 만 인쇄한다. 산출물에 이름·전화·생년월일이 한 글자도 나가지 않는 것을 테스트로 강제.
- **MCID 를 추정하지 않는다**(K-CNC MCID 는 별건 델파이 프로젝트다). 리스트 난이도 **동등성 검정**도 v1 제외.
- **음원 파일을 보지 않는다** → `stimaudit`.

## 입력 / 출력

### 실행 예

```bash
jamoscore 본실험_결과.xlsx --inspect
jamoscore 본실험_결과.xlsx \
  --subtest "자음:목표=2음절초성" --subtest "모음:목표=1음절중성" --subtest "일음절:목표=초중종,만점=3" \
  --answer-key 언어검사_정답 --summary total-최종 --out-dir 채점검증_0911
```

### 실제 콘솔 출력 (이 톤으로 구현할 것)

```
[입력] 시트 58개 → 피험자 시트 35개 인식 · 정답 시트 1개 · 요약 시트 1개
[경고] `개인정보` 시트에 식별정보로 보이는 열이 있습니다 — 읽지 않았습니다. 내보내기 전 deidaudit 을 돌리세요.
```

## 실패할 수 있는 지점 (그리고 가장 싸게 조기 발견하는 법)

1. **검사마다 채점 규칙이 달라서, 규칙을 코드에 박는 순간 오탐이 폭발한다.**
   → **첫 30분에 규칙-사람 불일치율부터 잰다.** 기획 세션 실측은 자음·모음에서 **0.2%(4/2176)**. 합성 픽스처가 아니라 실파일에서 **5% 를 넘으면 규칙 대조(④)를 버리고 ⑤(동일 쌍 다른 채점)만 남긴다** — ⑤ 는 규칙과 무관하게 성립한다. 규칙은 넓히지 말고 좁힌다.

2. **레이아웃 파편화 — 이미 한 번 속았다.** `일음절` 블록은 `자음`·`모음` 과 열 수·만점이 다르고, 그 사실이 파일 어디에도 안 적혀 있다. 위치 고정 파싱은 168셀 중 54셀을 가짜 불일치로 만든다.
   → 헤더 기반 검출 + `--inspect` + 검출 실패 시 exit 2 를 **1번 테스트로** 만든다. 블록별 만점을 자동 추론하지 말고 `--subtest ...만점=3` 으로 **받는다**. 추론하는 순간 이 툴은 조용히 거짓말한다.

3. **매번 우는 체커가 된다.** 문자열이 다른데 1점인 쌍이 55종인데 **전부 정상 채점**이었다. 문자열 비교로 판정하면 첫 실행에서 55건을 토해내고 사용자는 두 번 열지 않는다.
   → 55종 전부를 **"이상 없음"으로 통과시키는** 회귀 테스트를 먼저 쓰고 그 다음에 검출기를 쓴다. 애매하면 치명이 아니라 경고, 경고가 애매하면 `대조불가`.

4. **음소 혼동 행렬이 해석 불가능한 잡동사니가 된다.** 관측 1~2회짜리 칸이 수백 개 나오면 표는 있으나 마나다.
   → `--min-count` 게이트를 기본 3으로 두고, 잘라낸 칸 수를 자백에 적는다. 실측 상위 4개(`ㅌ→ㅍ 39` 등)가 표 맨 위에 나오지 않으면 게이트 설계가 틀린 것이다.

5. **툴이 음운론을 스스로 주장한다.** "조음위치 혼동이 지배적" 같은 문장을 툴이 만들어내면, 근거 없는 해석을 사내 산출물로 굳히게 된다.
   → 자질 분류는 `--features` 로 **받을 때만** 하고, 없으면 "분류 안 함"으로 자백. 해석 문장은 생성하지 않고 카운트만 낸다.

6. **이 형식의 파일이 다시 오지 않는다면 툴은 죽는다.**
   → 이미 반증되어 있다: 소아 KoBio IRB **승인 완료**, BELL-002 확증임상 진행, K-CNC MCID 델파이 진행, 웹 기반 어음인지도 검사도구 신뢰도 프로토콜 작성 중. 그래도 **다음 채점 엑셀이 들어왔을 때 `--inspect` 가 한 번에 못 읽으면**, 그건 입력 규격을 일반화하지 못했다는 뜻이니 그때 접는 것이 맞다.
