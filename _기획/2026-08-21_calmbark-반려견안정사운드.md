# calmbark-반려견안정사운드

## 한 줄 요약

반려견이 짖으면 마이크로 감지해서, 사용자의 NBR 논문(*Acoustic Parameters for Autonomic
Arousal Modulation*, 1st revision) 티어 프레임워크대로 합성한 **저각성 안정 사운드를
자동 재생**하고, 모든 짖음 에피소드·개입 여부를 CSV로 남겨 **"소리가 실제로 우리 개의
짖음을 줄이는가"를 N-of-1 실험으로 검증할 수 있게** 하는 오프라인 브라우저 앱.
카탈로그 최초의 데이터 **수집** 도구다 — 분석은 기존 statwise/longistat가 받는다.

## 왜 필요한가

> 재택 근무 중, 옆방에서 개가 택배 기사 소리에 짖기 시작한다. 유튜브에서 "dog calming
> music"을 틀어준다. 효과가 있는지는 아무도 모른다 — 세어본 적이 없으니까. 그리고 그
> 영상이 왜 진정 효과가 있다는 건지 근거는 아무 데도 없다.

사용자는 지금 **소리→자율신경 각성 조절의 파라미터 수준 근거 프레임워크**를 NBR에
리비전 중이다. 그 논문의 산출물(티어별 설계 지침)은 지금까지 사람 대상 문장으로만
존재한다. 이 앱은 그 지침을 **실행 가능한 합성 엔진 + 자동화된 검증 테스트**로 옮기는
첫 번째 코드다: 논문 Table 1의 Tier 1/2 설계 규칙(안정 레벨, 완만한 어택, 30–150 Hz
AM 회피, 규칙적 패턴, 60–80 BPM, 고주파 제한, 음의 스펙트럼 기울기)이 전부
`node --test` 회귀 테스트로 고정된다. 논문 주장을 코드가 지키는지 기계가 확인한다.

시중 "강아지 진정 음악" 앱/영상과 결정적 차이 두 가지:
1. **파라미터가 근거 문헌에 소급 가능** — 왜 이 소리인지 논문 표 행 단위로 답할 수 있다.
2. **효과를 주장하지 않고 측정한다** — 무작위 개입 모드(에피소드 단위 50% 배정)로
   개입/비개입 에피소드 지속시간·재발 간격 CSV를 만들고, 판단은 statwise가 한다.

## 대안 대비 우위

| 대안 | 왜 그래도 이게 낫나 |
|---|---|
| 유튜브/스포티파이 진정 음악 | 항시 재생(짖음 반응형 아님), 파라미터 불명, 광고·스트리밍 필요, 효과 측정 없음 |
| 상용 짖음 감지 앱 (Barkio 등) | 감시/알림용이지 개입 실험 도구가 아님. 로그를 통계 툴에 넣을 수 없음. 클라우드 전송 |
| 짖음방지 목걸이 (초음파/진동) | 혐오 자극 — 이 앱과 정반대 접근. 불안을 늘릴 수 있음 |
| LLM에게 "진정 사운드 만들어줘" | 합성은 해줘도 논문 스펙 준수를 **검증**하지 못함. 이 앱은 준수가 테스트로 고정됨 |

### 인접 툴과의 경계

카탈로그 24개 툴은 전부 "이미 있는 데이터"에서 시작한다. calmbark는 **데이터를 만드는
쪽 끝**이다: 산출 CSV(에피소드 요약)가 statwise(개입/비개입 비교)·longistat(일차 추이)에
그대로 들어가는 스키마로 나온다. 분석 기능은 일절 넣지 않는다 — 요약 화면의 비교 표는
기술통계까지만 보여주고 "판단은 statwise로"를 명시한다.

## 범위

### 한다 (v1)

1. **짖음 감지** — getUserMedia 마이크 → 250–4000 Hz 대역 에너지가 적응형 소음 바닥
   (롤링 중앙값) + 감도(dB) 를 넘는 버스트를 짖음으로 판정. 최소 지속·불응기 적용.
   보정 흐름: 시작 시 3초 조용히(소음 바닥 측정) → 감도 슬라이더 → 실제 짖음으로 확인.
2. **에피소드 집계** — 30초 안 재짖음은 같은 에피소드. 시작/종료/짖음 횟수/지속시간 기록.
3. **안정 사운드 엔진 (전부 합성, 파일 0개)** — NBR 1st revision Table 1 설계 규칙의
   실행 가능한 번역:
   - Tier 1 Event Structure → 지속 텍스처, 순간 피크 없음, 다이내믹레인지 ≤15 dB
   - Tier 1 Onset Dynamics → 모든 온셋 10–90% 상승 ≥50 ms, 개입 페이드인 ≥1 s
   - Tier 1 Roughness → 30–150 Hz 변조 에너지 회피(Arnal 2015 편도체 선택 대역)
   - Tier 1 Predictability → 주기적 루프 구조, 급격한 구조 변화 없음
   - Tier 2 Tempo → 느린 진폭 변조 0.7–1.33 Hz(42–80 BPM), 기본 1 Hz
   - Tier 2 Sharpness/Pitch/Slope → 저역통과, 저-중역 중심, 핑크~브라운 기울기(β<0)
   - Tier 3 Semantic → 가사 없음(합성이므로 자동 충족)
   프리셋 3개: 브라운 파도(기본) / 핑크 저역 / 저주파 드론+느린 하강 음형.
4. **개입 로직** — 감지 → 페이드인 → 기본 180초 재생(재짖음 시 연장) → 페이드아웃.
5. **실험 모드 3종** — 관찰(감지만)/상시 개입/**무작위 개입**(에피소드 단위 50%,
   seed 로그 기록 → 재현 가능).
6. **CSV 내보내기** — 이벤트 로그(타임스탬프·유형)와 에피소드 요약
   (`에피소드ID, 시작, 종료, 짖음횟수, 지속초, 개입여부, 모드, seed`) 두 벌.
7. **세션 요약 화면** — 시간당 에피소드, 평균 지속, 개입/비개입 기술통계 비교 +
   "표본이 작으면 우연 — statwise로 검정하세요" 문구.
8. **볼륨 안전** — 보수적 기본 게인, 상한 경고(개 청각 민감), 초음파 성분 없음(엔진이
   저역통과라 구조적으로 차단).

### 의도적으로 안 한다

- 효과 주장·"치료" 문구 일체 (README에 종간 외삽 한계·미검증 명시, 심한 분리불안 → 수의사)
- ML 짖음 분류(휴리스틱임을 자백), 녹음 저장·전송(이벤트 타임스탬프만), 클라우드/계정
- 고양이·타 축종 모드(한계 절에 언급만), 다일 스케줄링, 모바일 패키징
- 통계 검정(statwise 영역), 그래프 라이브러리(외부 의존성 0 — CDN 포함 금지)

## 입력 / 출력 / 실행

- 입력: 마이크 스트림(저장 안 함). 설정: 감도, 프리셋, 재생 길이, 모드, seed.
- 출력: `calmbark_이벤트_YYYYMMDD_HHMM.csv`, `calmbark_에피소드_YYYYMMDD_HHMM.csv` (다운로드).
- 실행: `실행.command` → `python3 -m http.server`(127.0.0.1 전용, 임의 포트) 기동 후
  브라우저 오픈. getUserMedia가 secure context를 요구하므로 localhost 서빙이 필수
  (file:// 은 마이크 불가). 서버는 loopback 외 바인딩 금지.

## 실패할 수 있는 지점 (조기 발견법)

1. **브라우저 자동재생 정책** — 사용자 제스처 없이 AudioContext 시작 불가.
   → 시작 버튼("세션 시작")을 반드시 거치는 UX로 설계. 빌드 첫 30분에 확인.
2. **감지 민감도** — TV 소리·문 닫는 소리 오탐, 작은 낑낑거림 미탐.
   → 감도 슬라이더 + 보정 흐름 + "휴리스틱" 자백. 오탐도 로그에 남아 사후 식별 가능
   (에피소드 짖음횟수 1·지속 0초 행은 의심 행).
3. **개입음 자체가 마이크에 잡혀 자기 트리거** — 재생 중 감지 계속하면 스피커 소리를
   짖음으로 오인할 수 있다. → 재생 중에는 트리거 임계 상향 + 재생 대역(저역) 에너지를
   특징에서 차감, 그리고 "재생 중 감지" 이벤트를 별도 유형으로 로그. 이게 안 풀리면
   재생 중 감지 일시정지(연장은 페이드아웃 후 재감지로)로 후퇴 — 후퇴안도 스펙 충족.
4. **효과 없음이 결과일 수 있다** — 그래도 도구는 성공이다. 측정이 목적이지 효과 보장이
   아니며, README가 그렇게 말한다.
