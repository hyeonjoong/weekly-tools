# packlist — 투고 봉투 점검 (원고가 약속한 첨부물 ↔ 봉투에 실제로 있는 것)

## 한 줄 요약

투고·공저자 발송 **직전의 폴더 하나**를 통째로 읽어, 원고 본문이 약속한 것(Fig. 4, S5 Table, 보충자료, 커버레터)이 **봉투 안에 실제 파일로 있고 docx 안에 실제로 앵커돼 있는지**를 대조한다. 글자를 보는 게 아니라 **zip 안과 폴더 안**을 본다.

---

## 왜 필요한가

### 트리거 순간

**"이 폴더를 저널 포털에 올리기 직전"** 또는 **"이 폴더를 공저자에게 보내기 직전"**. 명령 한 줄, 1초.

이 사람의 실제 빈도:
- **2026-08-31 하루에 npj Digital Medicine 원고 판본이 21개** 만들어졌다(`수정3_재코멘트` 09:35 → `수정20` 16:21). 판본마다 공저자(현중님)와 왕복한다.
- 논문 파이프라인에 **약 20편**이 있고, PSG 논문은 **15번째 저널**에 가 있다. 저널을 갈아탈 때마다 봉투를 다시 싼다.
- IRB·식약처 패킷도 같은 모양으로 나간다(그쪽은 `irbpack` 담당).

### 오늘은 뭘 하는가 — 손으로 한다. 그리고 놓친다.

`MoA논문작성/BELL001_남은확인사항_20260831.xlsx` 는 손으로 만든 미해결 목록인데, 그 안의 항목 절반이 **봉투 자산 문제**다:

| 손으로 적어 둔 항목 | 실체 |
|---|---|
| `Fig. 4 그림 파일이 본문 삽입 참조를 잃은 상태 (image3/image30이 고아 파일)` | 앵커 소실 |
| `보충 자료 파일 3종 — 본문에 인용은 넣었으나 파일이 없음` | 약속 ↔ 실물 불일치 |

### 실측 — 투고 봉투 자체

`npjDM_투고본_2026-08-19/` 를 열어 보면:

- 폴더에 보충자료 파일은 **0개**다. (docx 1개 + 무관한 pptx 1개 + 하위폴더 3개 `_이전본`·`_이전_손상본`·`되돌리기_기준점`)

## 대안 대비 우위

| 대안 | 왜 안 되는가 |
|---|---|
| **손으로 확인** | 실제로 손으로 하고 있고, **여섯 판본을 놓쳤다.** 12MB docx 의 zip 을 열어 `word/media` 와 `document.xml.rels` 를 대조하는 건 사람이 하는 일이 아니다. Word 화면에서 고아 미디어는 **보이지 않는다** — 그림이 사라진 자리가 빈 줄로 보일 뿐이라 훑어보면 넘어간다. |
| **`python-docx` 한 줄** | `python-docx` 는 문단·런 API 다. `word/media` 전수 해시, `r:embed` → rels → 파일 역추적, 고아 판정을 **제공하지 않는다.** 직접 짜야 하고, 그게 이 툴이다. |
| **Word "문서 검사"(문서 속성 검사기)** | 개인정보·변경내용·숨겨진 텍스트만 본다. 고아 미디어·중복 미디어·끊어진 앵커 항목이 **없다.** |
| **저널 투고 시스템(Editorial Manager 등)** | (a) **업로드한 뒤에야** 검사한다 — 봉투를 다 싸고 올린 다음이다. (b) 자기네 체크리스트만 본다. (c) 애초에 이 사람은 NBR 은 교신저자 계정이라 **올릴 수조차 없다.** 폴더를 넘기는 게 끝이다. |
| **git diff / 파일 크기 눈대중** | 12.5MB 가 여섯 판본 내내 12.5MB 였다. 크기로는 안 보인다(고아 2.2MB 가 중복 6.2MB 에 묻힌다). |
| **`draftcheck`** | 원고 **텍스트 안에서** 그림 번호가 순서대로인지를 본다. 그 번호에 해당하는 **이미지가 실제로 박혀 있는지는 보지 않는다.** |

### 인접 툴과의 경계

| 툴 | 보는 것 |
|---|---|
| `draftcheck` | 원고 **한 개의 텍스트**가 스스로 말이 되는가 (번호·인용·형식) |
| `numcheck` | 원고 안 숫자의 **산술** |
| `tracecheck` | 원고의 숫자 ↔ **분석 산출물** |
| `revcheck` | **같은 원고의 다른 판본** 3종 |
| `irbpack` | **IRB 패킷 안 다른 문서의 같은 항목** (내용 정합) |
| **`packlist`** | **원고가 약속한 첨부물 ↔ 봉투 안에 실제로 있는 파일과 앵커** (패키지·파일시스템 층) |

**출시 게이트 — README 첫 문단이 이 한 줄을 말하지 못하면 출시하지 않는다:**
> *`draftcheck` 는 원고가 스스로 말이 되는지를 보고, `packlist` 는 원고가 약속한 파일이 봉투 안에 실제로 있는지를 본다.*

다른 여섯 툴은 전부 **글자**를 읽는다. `packlist` 는 저장소에서 처음으로 **zip 내부 구조와 폴더 목록**을 읽는다.

## 범위

### 한다 (v1)

**① 그림 앵커 3자 대조** — 이 툴의 심장
- `word/media/*` 전수 SHA-256 → **중복 미디어**(같은 바이트, 다른 이름) + 낭비 바이트
- `document.xml` 의 `r:embed`/`r:link` → `word/_rels/document.xml.rels` → media 파일 역추적
- **고아 미디어**(패키지에 있으나 본문에 앵커 없음) = `[치명]`
- **깨진 참조**(rels 에 있으나 media 에 파일 없음) = `[치명]`
- **외부 링크 이미지**(`TargetMode="External"`) = `[치명]` — 봉투를 옮기면 그림이 사라진다
- **본문 `Fig. N` 인용 수 ↔ 캡션 수 ↔ 앵커된 이미지 수** 3자 대조표

**② 약속 ↔ 실물 (봉투 = 폴더)**
- 본문이 부르는 보충자료 토큰(`S1 Table`, `S5 Fig`, `Supplementary Table 3`, `Appendix A`) 수집 → 폴더 안 파일명 대조
- **역방향**: 폴더에 있는데 본문 어디서도 안 부르는 파일(옛 판본, `복사본`, `(1)`, `.DS_Store`, 무관한 pptx)
- 하위폴더(`_이전본/`, `_이전_손상본/`)는 **봉투에서 제외하고 그 사실을 자백** — 같이 올라가면 사고다

**③ 번호 체계**
- Fig/Table/S-항목 번호 **빠짐·중복·순서 역전**(본문 첫 등장 순 ≠ 번호 순)
- 캡션 패널 라벨 `(a)(b)(c)` ↔ 본문이 부르는 패널(`Fig. 2a`) — 본문이 부르는데 캡션에 없는 패널

**④ 봉투 위생 · 회차 대장**
- 파일별·총 용량, **중복·고아로 낭비되는 바이트**
- **문단 수 · 코멘트 수 · 변경내용(ins/del) 수** — 지금 `수정N_정리.xlsx` 에 손으로 적고 있는 그 숫자다
- 작성자·최종수정자(`docProps`) 잔존 — **세기만 하고 지우지 않는다**

**⑤ 이전 봉투 대비 (`--baseline 이전폴더/`)** — 수정5 사고를 잡는 검출기
- **지난 회차엔 앵커돼 있었는데 이번에 고아가 된 그림** = `[치명]`
- 미디어 바이트 증감(공저자 왕복 후 재팽창), 없어진 첨부물

**⑥ 표제 3종 동기화** (봉투 안 `.docx` 들 사이)
- **제목 · 저자 순서 · 원고번호(MS#)** 만. NBR 의 `and Norms` 사례.
- **이건 `irbpack` 과 같은 축이다.** 그래서 **3항목으로 못 박고** 내용 정합으로 넓히지 않는다. 넓히는 순간 `irbpack` 재탕이다. → *강제장치 5: 비교 항목 상수가 3개임을 테스트로 고정*

### 의도적으로 안 한다

1. **고친다** — 고아 삭제·중복 병합·용량 최적화 전부 안 한다. 감사와 수정을 한 툴에 넣으면 사람이 리포트를 안 보고 수정만 돌린다(저장소 관례). → *강제장치 1: zipfile 쓰기 모드·`shutil` 부재를 AST 로 확인*
2. **저널 규정을 코드에 박는다** — 용량 상한·필수 제출물 목록은 `--limits 저널.json`·`--expect 제출목록.json` 으로 **받을 때만** 판정. 없으면 "검사 안 함" 자백. (jamoscore 기획이 "투고 패키지 조립기"를 떨어뜨린 이유가 *저널 규정이 외부 지식*이라는 것이었다. 규정을 **입력으로 받아** 그 벽을 피한다.) → *강제장치 2: 저널명·수치 상한 리터럴이 코드에 0건임을 grep 테스트*
3. **원고 텍스트 품질·숫자·인용 DOI 를 본다** → `draftcheck`/`numcheck`/`citecheck`. 폴더에 원고 1개만 있으면 exit 2.
4. **그림 이미지 안의 글자를 읽는다** — OCR 없음. `남은확인사항` 의 *"Fig.4 이미지 안 부등호 `*p < 0.012`"* 같은 항목은 **못 잡는다고 자백**한다. → *강제장치 3: 이미지 디코딩·OCR 라이브러리 import 부재 AST*
5. **PDF 조판을 본다** — v1 은 `.docx` 만. PDF 는 목록·용량만 세고 "내부 미검사" 자백.
6. **`.hwp` 를 연다** — 목록에만 올리고 판정에서 제외, 자백.
7. **판정을 만들어낸다** — 애매하면 `[치명]` 이 아니라 `[경고]`, 경고가 애매하면 `대조불가`.

## 입력 / 출력

### 실행 예

```bash
# 0) 봉투가 어떻게 읽혔는지부터 인쇄 — 사람이 1초에 틀렸음을 안다
packlist npjDM_투고본_2026-08-19/ --inspect

# 1) 기본
packlist npjDM_투고본_2026-08-19/ --out-dir 봉투점검_0911

# 2) 지난 회차 대비 (앵커 회귀 검출 — 이게 수정5를 잡는다)
packlist _이전본/수정10/ --baseline _이전본/수정4/ --out-dir 봉투점검_수정10

# 3) 저널 규정·제출목록을 받아서
packlist 투고본/ --limits npjDM.json --expect 제출목록.json --out-dir 봉투점검_0911
```

## 실패할 수 있는 지점 (그리고 가장 싸게 조기 발견하는 법)

1. **항상 깨끗하게 나온다.** 최신본(`수정20`)은 고아 0·중복 0 이다. 현재 상태만 보면 이 툴은 할 말이 없다.
   → **빌드 첫 30분에 `_이전본/` 21개 판본을 전수로 돌린다. 치명이 뜨는 판본이 6개 미만이면 그 자리에서 접는다.** (기획 세션 실측: 6개 — 수정5~10. 경고까지 포함하면 18개.) 숫자를 늘려 만회하려 들지 말 것.

2. **매번 운다 — 보충자료 오탐이 제일 위험하다.** 보충자료를 저널 포털에 따로 올리는 게 정상 워크플로면 "폴더에 없음"이 매 회차 치명으로 뜨고, 사용자는 두 번 열지 않는다.
   → `--expect` 가 없으면 실물 대조는 **`대조불가`**, 있을 때만 `[치명]`. 이 규칙을 회귀 테스트로 먼저 박고 검출기를 쓴다.

3. **중복 미디어가 Word 의 상수라면 뉴스가 아니다.**
   → 실측상 `수정11` 에서 0으로 떨어졌으니 상수가 아니다. 그래도 **경고 고정**. 치명으로 올리는 순간 매 회차 운다.

4. **헤더/푸터/각주 이미지를 고아로 오판한다.** `document.xml` 만 보면 로고·워터마크가 전부 고아로 잡힌다 — 첫 실행에서 오탐 폭발.
   → `header*.xml` · `footer*.xml` · `footnotes.xml` · `endnotes.xml` 의 rels 까지 **전부** 훑고 나서 고아를 판정한다. 21판본 전수에서 고아가 정확히 0 또는 2 로만 나와야 한다(실측값). 다른 수가 나오면 이 처리가 빠진 것이다.

5. **Fig 인용 정규식이 필드코드·상호참조를 못 잡는다.**
   → `--inspect` 가 "본문 Fig 인용 N건 · 캡션 M건 · 앵커 K건"을 먼저 인쇄한다. 기준값 21/5/4 와 어긋나면 사람이 1초에 안다. 못 잡으면 **넓히지 말고 좁힌다** — 못 읽은 건 자백으로 보낸다.

6. **"봉투"가 뭔지 애매하다.** `MoA논문작성/` 처럼 21개 판본 + 15개 엑셀이 한 폴더에 섞여 있으면 무엇이 봉투인지 모른다.
   → 하위폴더는 제외하고 자백. docx 가 2개 이상이면 **추측하지 말고** `--manuscript` 를 요구하며 exit 2.

7. **한 번 고치면 다시 안 열린다.**
   → 반증되어 있다: 공저자 편집본이 **왕복마다** 중복을 재생산하고(rev13·15·18), 논문 20편·PSG 15번째 저널·NBR 2라운드가 대기 중이다. 그래도 **다음 봉투 세 번 연속 치명 0건이면 접는 게 맞다.**
