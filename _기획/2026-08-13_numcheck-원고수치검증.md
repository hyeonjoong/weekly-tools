# numcheck-원고수치검증

## 한 줄 요약

원고(.docx/.md/.tex/.txt) 하나를 받아서 **본문에 적힌 숫자들을 전부 다시 계산해보는** 오프라인 CLI. 비율이 분자/분모와 맞는지, 보고된 검정통계량(t/F/χ²/r/z)과 자유도에서 나오는 p가 적힌 p와 같은지, 하위군 N의 합이 전체 N과 맞는지, 정수 척도(ISI·단어인지도 등)의 평균이 그 N에서 **산술적으로 가능한 값인지**(GRIM), 변화량이 사후−사전과 맞는지를 전수 대조하고 줄번호가 붙은 한국어 지적 목록을 낸다. 데이터 파일은 필요 없고 원고만 있으면 돈다.

## 왜 필요한가

> **트리거 모먼트.** 금요일 밤, 공동저자가 보낸 리비전 원고를 연다. 3주 전에 데이터가 한 번 갱신되면서 최종 분석 N이 48 → 46으로 바뀌었다. Results 표는 새로 붙여넣었다. 그런데 Abstract의 `23/48 (47.9%)`, Discussion의 "약 절반", Table 2 하위군 합계(20+14+14=48)는 예전 그대로다. 통계는 다시 돌렸으니 맞고, 표도 나오고, 문장도 읽힌다. **틀린 건 숫자뿐이고, 그건 티가 안 난다.**

**지금은 대신 뭘 하는가.** 아무것도 안 한다. 정확히는 — 눈으로 훑고 넘어간다. 논문 한 편에 숫자 claim이 100~300개인데, 사람이 전수 재계산하는 일은 실제로 일어나지 않는다. 리비전마다 반복되면 더더욱 안 한다. 그러다 리뷰어가 "Abstract의 47.9%와 Table 2가 다릅니다"를 잡으면, 그건 논문의 신뢰도 문제로 번진다.

**이 문제의 모양이 이 저장소가 잘하는 그 모양이다.** 지루하고, 전수 대조가 필요하고, 실수가 조용히 통과되고, 리비전마다 반복된다. `draftcheck`와 `joinaudit`이 각각 "참고문헌 60개를 세는 일", "300행이 어디서 사라졌는지 세는 일"에서 이겼던 것과 같은 이유로 이긴다.

**BELL 데이터에 정확히 붙는 부분이 하나 있다.** ISI는 7문항 0–4점 정수 합(0–28)이고, 와우핏 단어인지도는 고정 목록 대비 정답 수의 백분율이다. 둘 다 **평균이 아무 값이나 될 수 없다.** N=23에서 ISI 평균이 `14.37`이면 14.37×23=330.51 — 정수가 아니므로 그 평균은 존재할 수 없다(GRIM). 오탈자든 이전 버전 잔재든, 이건 사람이 절대 못 잡고 기계는 한 줄로 잡는다. SERENE 1차 지표가 ISI라는 점에서 이건 장식이 아니라 실전 항목이다.

## 대안 대비 우위

| 대안 | 왜 지는가 |
|---|---|
| **손으로 검산** | 100~300개를 다시 계산하는 일은 실제로 일어나지 않는다. "안 하는 것"이 진짜 현재 상태다. |
| **statcheck (R 패키지)** | 가장 가까운 경쟁자. 하지만 (a) **p 재계산만** 한다 — 비율·N 합계·GRIM·변화량은 전혀 안 본다, (b) **APA 영문 표기만** 파싱한다(`t(45) = 2.31, p = .03`), 한국어가 섞인 원고나 표 안의 숫자는 통째로 놓친다, (c) R 설치가 필요하다, (d) 단측검정·보정 p에서 오탐이 많기로 유명하다. 이 툴은 그 4개를 전부 정면으로 다룬다. |
| **LLM에 원고 붙여넣기** | **여기가 핵심이다.** LLM은 t=2.31, df=45에서 p를 계산하지 못한다 — 그럴듯한 값을 지어내고 "확인해보니 일치합니다"라고 말한다. 23/48을 47.9%로 반올림하는 것도 자주 틀리고, 100개 중 몇 개를 검사했는지 세지 못하며, 세지 못했다는 사실도 말하지 않는다. **전수 산술 대조는 결정론적 계산이 압도적으로 옳다.** |
| **Excel에 옮겨서 검산** | 숫자를 다시 타이핑해야 한다. 다시 타이핑하는 것이 바로 원래 오류의 원인이다. |
| **저널 편집부/리뷰어가 잡아줌** | 잡히면 그때는 이미 늦었다. 이 툴의 존재 이유가 "그전에 잡는 것"이다. |

### 인접 툴과의 경계

| | `draftcheck-원고투고점검` | **`numcheck` (이 툴)** |
|---|---|---|
| 묻는 질문 | **형식이 갖춰졌는가** — 인용이 참고문헌에 있는가, Figure 번호가 이어지는가, df가 빠지지 않았는가, 약어를 정의했는가, 단어수를 넘었는가 | **산술이 맞는가** — 적힌 p가 그 통계량에서 나오는 값인가, 47.9%가 23/48인가, 하위군 합이 전체와 같은가, 그 평균이 그 N에서 가능한가 |
| 계산 | 안 한다 (존재·일치 여부만) | **한다** (분포 CDF, 반올림 허용 범위, GRIM) |
| 남의 논문에 쓰나 | 아니다 (내 투고 직전용) | **그렇다** (공동저자 초고, 심사 의뢰, 인용하려는 논문) |

겹치는 것 하나: draftcheck의 "Abstract↔본문 N 불일치". **빌더는 이걸 재구현하지 말고**, numcheck에서는 N을 "다른 계산의 분모"로만 쓴다. 두 툴은 서로를 import하지 않는다(집 규칙). 출력 CSV 스키마만 draftcheck의 지적 목록과 같은 모양으로 맞춘다.

## 범위

### 한다 (v1)

1. **비율 재계산** — `23/48 (47.9%)`, `n = 23 (47.9%)` + 근처 문맥의 분모, `47.9% (23/48)` 등 표기 변형. 반올림 관례(반올림/버림/올림, 소수 0~2자리)를 **모두** 허용하고, 어떤 관례로도 그 값이 안 나올 때만 지적한다.
2. **p 재계산** — `t(45) = 2.31, p = .03` / `F(2, 88) = 4.12` / `χ²(1) = 6.44` / `r(38) = .41` / `z = 2.05`. 자체 구현 CDF(불완전 베타·불완전 감마). 양측 기본, **단측·보정(Bonferroni/Holm/Greenhouse–Geisser) 키워드가 근처에 있으면 자동으로 "경고"로 강등**한다.
3. **유의성 경계 위반** — `p = .07`인데 "유의하게 감소했다/significantly"가 같은 문장에 있는 경우. 반대로 `p < .001`인데 "차이가 없었다"인 경우.
4. **N 합계** — `총 48명 (치료군 24, 대조군 23)` 처럼 괄호 안 하위군 합이 전체와 다른 경우. Table 1 스타일 열 합계 포함.
5. **GRIM / GRIMMER** — 정수 척도 평균(그리고 가능하면 SD)이 그 N에서 산술적으로 존재 가능한지. **척도는 추측하지 않는다.** 내장 표(ISI 0–28/7문항, PSQI 0–21, ESS 0–24, HADS 0–21, 단어인지도 = 목록 길이 지정 필요)를 쓰되, 매칭이 확실할 때만 적용하고 `--scale ISI=0:28:7` 로 덮어쓸 수 있게 한다. 모르면 **건너뛰고 건너뛰었다고 적는다.**
6. **변화량 일치** — `기저 18.4 → 12주 11.2 (변화 −7.4)` 에서 −7.2여야 하는 경우. 사전/사후/변화 세 값이 한 문맥에 있을 때만.
7. **신뢰구간 정합** — 점추정치가 CI 안에 있는가, 대칭 CI에서 `mean ± 1.96·SE`가 맞는가, CI가 0(또는 비율 1)을 포함하는데 "유의"라고 썼는가.
8. **커버리지 자백** — 리포트 맨 위에 `숫자 claim 후보 214개 중 재계산 가능 137개 / 건너뜀 77개(사유별 내역)`를 반드시 찍는다. 몇 개를 못 봤는지 말하지 않는 체커는 만들지 않는다.

### 의도적으로 안 한다

- **통계 방법이 옳은지 판단하지 않는다.** t-검정을 썼어야 했는지, 다중비교 보정이 필요한지는 사람의 일이다.
- **원본 데이터를 읽지 않는다.** CSV 없이, 원고만으로 돈다. 데이터에서 다시 분석하는 건 statwise/longistat의 일이다.
- **참고문헌↔본문 대조, Figure/Table 번호, 약어, 단어수** — 전부 `draftcheck`. 재구현 금지.
- **DOI 검증** — `citecheck`. 네트워크를 아예 안 쓴다.
- **영문 교정·문장 다듬기** — 이 저장소가 이미 명시적으로 배제한 영역.
- **PDF 파싱** — v1에서 뺀다. stdlib만으로 PDF 텍스트 레이아웃을 신뢰성 있게 뽑는 건 한 세션 안에 안 끝나고, 반쯤 되는 파서는 8번(커버리지)을 거짓말로 만든다. **v2 1순위**로 README 한계 절에 명시한다.
- **원고를 고쳐주지 않는다.** 입력은 읽기 전용, 출력은 `--out-dir`에만.

## 입력 / 출력

**입력:** 원고 파일 1개. `.docx`(zipfile+ElementTree로 직접 파싱, 표 셀 포함), `.md`, `.tex`, `.txt`. 선택적으로 척도 설정 `--scale-config scales.json`.

```bash
numcheck 원고_revision2.docx --out-dir ./검토 --scale ISI=0:28:7 --lang ko
```

```json
// scales.json (선택)
{ "ISI": {"min": 0, "max": 28, "items": 7},
  "단어인지도": {"min": 0, "max": 100, "items": 50, "percent_of_count": true} }
```

**출력 (콘솔):**

```
numcheck — 원고 수치 재계산 검증
입력: 원고_revision2.docx (본문 6,214 단어, 표 3개)

숫자 claim 후보 214개 · 재계산 137개 · 건너뜀 77개
  건너뜀 사유: 분모 없음 42 · 척도 미상 19 · 표기 불명확 11 · 참고문헌 인용 5

■ 치명 3건
[L88   Abstract]  23/48 (47.9%)
      → 23/48 = 47.92% (일치). 그러나 L412 Table 2의 총 N은 46.
        분모 48이 본문 어디에도 재등장하지 않음. N 갱신 누락 의심.
[L142  Results]   ISI 평균 14.37 (N = 23)
      → GRIM 위반. 14.37 × 23 = 330.51 (정수 아님).
        ISI는 0–28 정수 합이므로 이 평균은 존재할 수 없음.
[L207  Results]   t(45) = 2.31, p = .003
      → 재계산 p = .0255 (양측). 보고값과 8.5배 차이.
        유의성 판정(.05)은 뒤집히지 않으나 값이 틀림.

■ 경고 5건
[L233  Results]   F(2, 88) = 4.12, p = .04
      → 재계산 p = .0194. 다만 같은 문단에 "Greenhouse–Geisser 보정" 있음 → 보정 df 사용 시 정상일 수 있음. 확인 요망.
[L251  Results]   총 48명 (능동자극 24, 대조 23)
      → 24 + 23 = 47 ≠ 48. 미배정 1명 또는 오탈자.
... (3건 생략, 문제목록.csv 참조)

■ 정보 2건
[L119] 척도 "수면효율" — 정수 척도 여부 불명, GRIM 건너뜀.
       --scale 로 지정하면 검사합니다.

출력: ./검토/문제목록.csv, ./검토/재계산표.csv
종료코드 1 (치명 있음)
```

**출력 파일**
- `문제목록.csv` — `줄번호,절,등급,항목,원문,보고값,재계산값,판정,설명` (draftcheck 지적 목록과 같은 모양)
- `재계산표.csv` — 건너뛴 것 포함 **모든** claim 후보와 그 처리 결과. 커버리지를 사람이 검증할 수 있어야 한다.

**종료코드:** `0` 문제 없음 · `1` 치명 있음 · `2` 경고만 · `3` 입력 처리 불가(파싱 실패, 또는 재계산 가능 claim이 5개 미만 — 조용히 "이상 없음"을 내지 않는다).

## 완료 기준 (빌더가 만족시켜야 하는 체크리스트)

- [ ] `dependencies = []` — stdlib 전용. `.docx`는 `zipfile` + `xml.etree.ElementTree`로 직접 파싱하며 **표 셀 안의 숫자까지** 읽는다.
- [ ] 네트워크 호출 0. 테스트도 완전 오프라인.
- [ ] 입력 파일 읽기 전용. 출력은 `--out-dir`에만.
- [ ] 자체 구현 CDF(t, F, χ², 정규, r→t 변환)가 **scipy 대비 p값 ≤1e-9 일치**. statwise가 세운 이 저장소의 기준을 그대로 만족시킨다. (검증 스크립트는 개발용으로만 쓰고 런타임 의존성에는 넣지 않는다.)
- [ ] 반올림 허용 범위 구현: 보고값이 **어떤 표준 반올림 관례로도** 재계산값에서 나올 수 없을 때만 지적. 예: 실제 47.916%는 `47.9`, `48`, `47.92` 모두 통과.
- [ ] **오탐 테스트(필수)** — 의도적으로 깨끗하게 만든 합성 원고에서 치명 0건·경고 0건. 하나라도 나오면 **규칙을 넓히지 말고 좁힌다.**
- [ ] **조용한 통과 테스트(필수)** — 오류 8종(비율/p/N합/GRIM/변화량/CI/유의성문구/CI-p모순)을 심어둔 합성 원고에서 8종 전부 검출, 종료코드 1.
- [ ] **커버리지 자백** — 리포트 첫머리와 `재계산표.csv`에 검사한 개수·건너뛴 개수·사유별 내역을 반드시 출력. 재계산 가능 claim < 5개면 종료코드 3으로 실패하고 "이 원고를 제대로 파싱하지 못했다"고 말한다.
- [ ] 단측검정·보정 p 키워드(one-tailed, 단측, Bonferroni, Holm, Greenhouse–Geisser, corrected) 근접 탐지 시 치명 → 경고로 자동 강등하고, 강등했다고 출력에 적는다.
- [ ] GRIM은 척도가 **확실히 식별될 때만** 적용. 모르면 건너뛰고 "정보" 등급으로 "지정하면 검사 가능"을 안내. 척도를 추측해서 GRIM을 돌리지 않는다.
- [ ] 등급 3단계(치명/경고/정보)와 각 등급의 판정 근거가 README에 명시.
- [ ] 합성 예제 3종: `examples/clean_manuscript.md`(오류 0), `examples/flawed_manuscript.md`(오류 8종), `examples/serene_style.docx`(BELL-001 SERENE를 흉내낸 ISI·HRV·호흡 결과 문단이 든 실제 .docx — GRIM 경로 검증용). **실제 환자 데이터 절대 금지, 전부 합성.**
- [ ] 집 폴더 구조: `numcheck/`(cli.py 포함), `tests/`, `examples/`, `README.md`, `사용법.md`, `실행.command`(chmod +x), `HARDENING.md`, `pyproject.toml`, `LICENSE`, `.gitignore`.
- [ ] README 순서: 제목 → 목적(한/영) → 설치 → **실제 명령과 실제 출력** → 한계. 한계 절에 PDF 미지원·표 파싱 한계·단측검정 오탐 가능성을 **솔직하고 길게**.

## 실패할 수 있는 지점 (그리고 가장 싸게 조기 발견하는 법)

1. **매번 우는 체커가 된다.** 반올림·유효숫자·표기 변형 때문에 깨끗한 원고에서도 지적이 쏟아지면, 그 순간 두 번 다시 안 열린다. 이게 이 툴의 1번 사망 원인이다.
   → **가장 싼 조기 확인:** 파서를 다 만들기 전에, 손으로 쓴 깨끗한 합성 원고 1개(30줄)에 먼저 돌린다. 치명이 1건이라도 나오면 그 규칙을 **좁힌다.** 넓히지 않는다.

2. **아무것도 파싱 못 하고 "이상 없음"을 낸다.** 실제 원고는 숫자가 표 안, 그림 캡션, 각주에 있다. `.docx` 표 셀을 못 읽으면 사실상 아무것도 검사하지 못하면서 통과 도장을 찍는다. 조용히 통과시키는 체커는 없느니만 못하다.
   → **가장 싼 조기 확인:** 커버리지 자백을 **1일차에 먼저 구현한다.** 실제 .docx 하나에 돌려서 "claim 후보 214개"가 아니라 "3개"가 나오면 파서부터 고친다. 검사 로직은 그다음이다.

3. **진짜 원고에서 0건이 나온다 — 즉, 이 툴이 필요 없었다.** 통계를 statwise로 돌리고 표를 자동 생성해왔다면 p와 비율은 이미 맞을 수 있다.
   → **가장 싼 조기 확인:** 완성 직후 **본인의 과거 논문 1편**에 돌린다. 치명 0건·경고 0건이면 이 툴은 접거나 검사 항목을 재설계한다. 30초면 안다. (다만 리비전을 거친 원고일수록 걸릴 확률이 높으니, 초고가 아니라 **최종 제출본**에 돌릴 것.)

4. **p 재계산 오탐이 신뢰를 태운다.** statcheck이 실제로 겪은 문제다. 단측검정, 보정된 df, 반올림된 통계량(t=2.31은 실제로 2.305~2.315)에서 다 갈린다.
   → **가장 싼 조기 확인:** 보고된 통계량의 **반올림 구간 전체**로 p 범위를 계산해서, 보고 p가 그 범위 밖일 때만 지적하도록 처음부터 설계한다. 이걸 나중에 붙이면 이미 오탐이 나온 뒤다.

5. **GRIM이 엉뚱한 숫자에 발동한다.** "평균 연령 42.7세(N=23)"에 ISI 규칙을 적용하면 헛소리가 된다.
   → **가장 싼 조기 확인:** GRIM은 **척도명이 명시적으로 매칭될 때만** 켠다. 기본값은 꺼짐에 가깝게. 깨끗한 원고 테스트에 나이·BMI·수면시간 같은 연속형 평균을 일부러 넣어두고 GRIM이 침묵하는지 본다.

## 빌더를 위한 메모

- 폴더/패키지/CLI 이름: `numcheck-원고수치검증` / `numcheck` / `numcheck`. `draftcheck`·`citecheck`와 같은 이름 계열이며, 이는 의도된 것이다 — 셋은 "원고 3종 세트"로 같이 쓰인다.
- **기존 툴 폴더를 절대 건드리지 않는다.** draftcheck를 import하지 않는다. `.docx` 파싱 코드는 draftcheck에도 있겠지만, 참고만 하고 이 폴더 안에 다시 쓴다(집 규칙: 통합은 스키마 호환으로만).
- 시간이 모자랄 때 **버리는 순서**: ① CI 정합(7번) → ② 변화량 일치(6번) → ③ N 합계(4번) → ④ 유의성 경계 문구(3번).
- **절대 버리면 안 되는 것 둘:** (a) **커버리지 자백** — 이게 없으면 이 툴은 거짓말하는 체커가 된다. (b) **반올림 허용 범위** — 이게 없으면 오탐으로 죽는다. 나머지를 다 버리고 비율 재계산 + p 재계산 두 개만 남더라도, 이 둘은 남긴다.
- 언어: 리포트 기본 한국어(`--lang en` 지원). 지적 문구는 "무엇이 왜 틀렸는지"를 한 줄로 — 등급만 찍고 마는 출력은 만들지 않는다.
