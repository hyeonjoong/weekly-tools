# doseaudit — 훈련노출량점검 (부제: 로그는 27,868행인데, 보고서의 순응도는 재현되지 않는다)

## 한 줄 요약

앱이 피험자별로 토해낸 **엑셀 30개(시트 180장·27,868행)** 를 통째로 읽어, "이 피험자가 처방된 훈련을
**실제로 얼마나 받았는가**(노출량·dose)"를 **정의를 선언받아** 다시 세고, 손으로 관리하던 참여현황
트래커·보고서 숫자와 **어긋나는 곳만** 찍는다. 순응/비순응을 판정하지 않고, 노출량과 결과의 관계도
보지 않는다 — **분모가 무엇이었는지를 드러내고 끝난다.**

---

## 왜 필요한가

### 트리거 순간

> 벤더(M&Q)가 피험자별 엑셀 한 묶음을 보내온다. 또는 데이터컷을 끊는다. 또는 CSR·논문의
> "adherence" 문단을 쓰려고 앉는다. 엑셀 30개를 하나씩 열어 `[요약]` 블록을 베끼거나,
> 날짜를 눈으로 세어 `참여현황.xlsx` 의 `완료일수` 칸을 채운다. 30명 × 6모듈이다.

BELL-002(와우핏)는 **확증임상**을 앞두고 있고(`002 확증임상 및 사전검토/`), 같은 앱이 같은 형식의
로그를 더 많은 N으로 다시 뱉는다. `[WF 1.9] 로그 데이터 리스트.xlsx` 에는 `연구팀_분석 예정 리스트`
시트가 이미 들어 있다. 이건 끝난 일이 아니라 **다음 시험에서 더 큰 N으로 반복될 일**이다.

### 오늘은 뭘 하는가 — 손으로 한다. 그리고 어긋난다.

`참여현황_2026-06-21.xlsx` 는 **열 153개 중 145개가 `D1`…`D145` 일자별 `참여`/`미참여` 격자**다.
사람이 손으로 유지한 표다. 그 안의 `완료일수` 가 진행률(%)을 낳고, 진행률이 CSR 의 adherence 문단을 낳는다.

### 실측 — 코드 0줄 상태에서 이미 확인한 것 (2026-09-17, 기획 세션)

전부 실제 파일을 읽어 센 값이다. 예상이 아니다. **빌더는 이 숫자를 회귀 테스트로 먼저 박고 구현한다.**

| 확인한 것 | 실측값 |
|---|---|
| 파일·형식 | `wowfit_project17_excels/` **30개**, 전부 동일 6시트(`소리그림감상`·`소리스케치북`·`사전자가진단`·`사후자가진단`·`음소쌍`·`발성훈련`) |
| 헤더 | **180/180 시트 전부** `날짜 · 레벨 · 훈련유형 · 반복횟수 · 소요시간(초)` — 예외 0 |
| 데이터행 | **27,868행**, 날짜 범위 `2026.01.31 ~ 2026.06.21` |
| **소요시간 0초 행** | **9,933행 = 35.6%** |
| **빈 모듈** | `발성훈련` 이 **30개 파일 전부에서 데이터 0행** |
| 훈련유형 | `REGULAR` 25,948 · `INDIVIDUAL` 1,920 (섞여 있다) |
| 벤더 `[요약]` 블록 | 150개 시트 전수 재계산 — **불일치 0건.** 산수는 맞다 |
| **트래커 vs 로그** | `완료일수` ↔ 로그 고유 날짜수: **30명 중 23명 불일치**, 차이 **+1 ~ +7일**, **전원 트래커가 더 작다** |

두 가지가 중요하다.

**① 벤더 요약은 산수가 맞고, 의미가 틀렸다.** `[요약] 평균 소요시간 0초` 는 계산 실수가 아니라
**0초 행 35.6%를 결측과 구분하지 않고 평균한 값**이다. `발성훈련` 은 `평균 0회 · 평균 0초` 로 인쇄되는데
실제로는 **행이 하나도 없다.** 그대로 베끼면 "수행량이 0이었다"가 되고, 진실은 "**측정되지 않았다**"이다.
이 둘은 논문에서 전혀 다른 문장이다.

**② 트래커 불일치는 오타가 아니라 정의 차이다.** 차이가 23명 전원에서 **한 방향(트래커 ≤ 로그)** 이다.
누군가 "완료"를 "행이 하나라도 있는 날"이 아닌 다른 기준으로 셌다. **그 기준이 어디에도 적혀 있지 않다.**

### 같은 사고가 이미 보고서에 들어가 있다

`Main-Clinical Study Report v0.6.docx` §3.4 *Adherence and dose–response*:

> "App adherence was low and variable: **median 61% of the ≥3-days/week target (range 11–100%),
> 11/23 below 50%** and only 7 at the full target. Adherence did not predict the MCI gain
> (Spearman ρ = **−0.02**, n = 18)."

기획 세션에서 이 숫자를 재현해 보았다. **재현되지 않는다.**

| 정의 | 중앙값 | 범위 | <50% | N |
|---|---|---|---|---|
| 로그 고유일수 ÷ (3×주) | **52%** | 2–190% | 15/30 | 30 |
| 트래커 완료일수 ÷ (3×주) | **46%** | 2–184% | 16/30 | 30 |
| **CSR v0.6 보고값** | **61%** | **11–100%** | **11/23** | **23** |

세 가지가 선언되지 않았다: **(a) 분모의 창**(가입일→데이터컷? 가입일→마지막 로그? 처방된 주수?),
**(b) 100% 상한 절단 여부**(보고 범위가 100%에서 끝나는데 로그로는 **190%** 가 나온다),
**(c) 30명 중 왜 23명인가**(빠진 7명의 사유). 같은 문서가 스스로 남긴 TODO 가 이걸 자백한다 —
*"Confirm with the clinical team the authoritative adherence-to-participant mapping."*

그리고 **노출량은 이 문단의 결론을 떠받치는 변수**다. 노출 변수에 계통 오차가 있으면 상관은 0 쪽으로
희석된다 — `ρ = −0.02` 라는 **귀무 결론이 측정 잡음의 산물일 수 있다.** 리뷰어가 물어볼 자리이고,
이 사람은 **이미 같은 종류로 맞은 적이 있다**: Digital Health(DHJ-26-1629) R2 가 "Supplementary Table 4의
n 이 본문과 맞지 않는다"를 지적했고, PSG 논문 desk-reject 진단서는 "arithmetically unreconciled" 를 적었다.
**파생 숫자의 재현 가능성**이 이 저자의 반복 상처다.

## 대안 대비 우위

| 대안 | 왜 안 되는가 / 왜 그래도 이게 낫나 |
|---|---|
| **손으로 한다 (현재)** | 실제로 손으로 하고 있고, **30명 중 23명이 어긋났다.** 엑셀 30개 × 시트 6장을 눈으로 세는 일은 N이 커지면 더 틀린다 |
| **`pip install` 한 번** | **없다.** `pandas.read_excel` 은 30개 워크북을 읽어 주지만 `[요약]` 블록과 헤더가 4행째 있는 구조를 알지 못하고, **0초의 의미·빈 모듈·분모의 창**을 묻지 않는다. 그건 라이브러리가 아니라 판단 규약이다 |
| **벤더 `[요약]` 블록을 믿는다** | 산수는 맞다(150/150). 그런데 **0을 결측과 구분하지 않는다.** `발성훈련 평균 0초` 를 그대로 베끼면 "0을 측정했다"고 보고하게 된다 |
| **`logflow` 를 쓴다** | 단일 이벤트 로그 CSV를 받아 세션화·DAU/리텐션·퍼널을 낸다. **제품 지표**다. 30개 워크북을 펼치지 못하고, 처방 대비 노출량이라는 임상 질문을 묻지 않는다 |
| **LLM에 엑셀 30개를 붙여넣는다** | 27,868행이 들어가지 않고, 들어가도 **재현되지 않는다.** 무엇보다 **못 본 파일을 못 봤다고 말하지 않는다** |
| **엑셀 피벗** | 한 파일 안에서는 된다. 30개 파일 × 6시트를 가로지르지 못하고, 정의를 바꿔 다시 돌리는 비용이 매번 처음과 같다 |

### 인접 툴과의 경계

| 툴 | 입력 | 답하는 질문 |
|---|---|---|
| `logflow` | 이벤트 로그 CSV 1장 | 제품이 **얼마나 쓰이는가** (DAU·리텐션·퍼널) |
| `joinaudit` | 이미 평평한 여러 CSV | 피험자×시점으로 **붙일 때 무엇이 깨지는가** |
| `jamoscore` | 손채점 문항 엑셀 | 보고된 **정답률 %가 문항에서 다시 나오는가** |
| `visitaudit` | 방문일 CSV + 프로토콜 창 | 방문이 **프로토콜 창 안에 있는가** |
| **`doseaudit`** | **피험자별 앱 로그 워크북 묶음** | **처방된 훈련을 실제로 얼마나 받았는가 — 그 분모는 무엇인가** |

`doseaudit` 의 산출물 `피험자별노출량.csv` 는 `joinaudit` 의 입력이 되고, `statwise`·`longistat` 로 이어진다.
**노출량을 만드는 자리가 비어 있었다** — 카탈로그 32개 중 워크북 묶음을 펼치는 툴이 하나도 없다.

**출시 게이트 — README 첫 문단이 이 한 줄을 말하지 못하면 출시하지 않는다:**
> *`logflow` 는 제품이 얼마나 쓰였는지를 보고, `doseaudit` 는 이 피험자가 처방된 훈련을 실제로 얼마나
> 받았는지를 — 정의를 선언받아 — 다시 센다.*

## 범위

### 한다 (v1)

1. **`--inspect` 가 먼저다.** 판정 이전에 먼저 인쇄한다: 읽은 파일 수, 파일별 시트 목록, 헤더 5열이
   기대와 같은지, 파일명에서 뽑은 피험자 코드, `[요약]` 블록 위치, 그리고 **선언된 정의 전문**.
   사람이 1초 안에 "잘못 읽었다"를 알 수 있어야 한다.
2. **정의를 선언받는다 — 절대 추론하지 않는다.** `--active-day` 는 필수 인자다:
   `any-row` / `min-rows=N` / `min-modules=K` / `min-seconds=S`. **미선언이면 판정 없이 exit 2.**
   분모의 창도 선언받는다: `--window enroll-to-cut --cut 2026-06-23` / `--window enroll-to-last` /
   `--window fixed-weeks=8`. 상한 절단은 `--cap 100` 을 **줄 때만** 하고, 주면 절단된 인원 수를 인쇄한다.
3. **0의 의미를 구분한다.** 모든 평균을 **세 값으로 나란히** 인쇄한다: `전체평균 · 0제외평균 · 0행비율`.
   한 모듈의 0행 비율이 100%면 `0으로 기록됨 — 미측정과 구분 불가` 로 표기하고, 그 모듈의 평균을
   **단일 숫자로 내보내지 않는다.**
4. **빈 모듈을 판정한다.** 데이터 0행 모듈은 `데이터 없음`. **`평균 0` 으로 인쇄하지 않는다.**
   (실측: `발성훈련` 30/30)
5. **훈련유형을 분리한다.** `REGULAR` / `INDIVIDUAL` 을 따로 센다. 합치려면 `--pool-types` 를 주어야 하고,
   주면 리포트 머리에 "합산함"을 인쇄한다.
6. **노출 기간을 정규화한다.** 피험자마다 가입일이 다르다(01-31 ~ 06-21). 원시 합계는 비교 불가다 →
   활동일수 · 관찰일수 · 주당 활동일 · **최장 공백(일)** · 첫/마지막 활동일을 낸다.
7. **중복 의심행을 센다.** `(날짜·레벨·훈련유형·반복횟수·소요시간)` 이 완전히 같은 행의 반복을
   `중복의심 N건` 으로 보고한다. **제거하지 않는다** (실제로 같은 날 6회 반복이 정상일 수 있다).
8. **트래커와 대조한다** (`--tracker 참여현황.xlsx`). 선언된 규칙으로 `완료일수`·`진행률(%)` 을 재계산해
   **부호 붙은 차이**와 함께 불일치만 나열한다. 트래커에만 있는 코드 / 로그에만 있는 코드도 양쪽으로 센다.
9. **정의 민감도.** 선언된 `--active-day` 규칙 하나와, 미리 정해진 대조 규칙들로 **중앙값 adherence 가
   몇 %p 움직이는지**를 한 표로 보여 준다. 어느 값이 옳은지는 말하지 않는다 —
   **"정의를 안 적으면 이만큼 달라진다"** 만 보여 준다.
10. **출력**: `피험자별노출량.csv` (`joinaudit`/`statwise` 스키마 호환) · `모듈별요약.csv` ·
    `트래커불일치.csv` · `노출량점검.md` (KR/EN Methods 초안 포함, 선언된 정의가 문장에 박힌다).
11. **`[커버리지 자백]`** 없이는 리포트가 출력되지 않는다.

### 의도적으로 안 한다

1. **고치지 않는다** — 중복 제거·결측 대체·트래커 수정본 생성 전부 안 한다.
   → *강제장치 1: 입력 경로 쓰기 함수 부재를 AST 로 확인*
2. **순응/비순응을 판정하지 않는다** — 순응도 임계값을 코드에 박지 않는다. 프로토콜 기준은
   `--criterion` 으로 **받을 때만** 판정하고, 없으면 숫자만 낸다.
   → *강제장치 2: 금지어 grep 0건 — `순응함`·`비순응`·`adherent`·`non-adherent`·`충분히 사용`*
3. **효과를 보지 않는다** — 노출량 ↔ 결과(자가진단·MCI·CNC) 상관/회귀/군간검정 안 한다.
   → `statwise`·`longistat`·`medpath`. *강제장치 3: 검정·상관 함수 부재를 AST 로 확인*
4. **세션을 추론하지 않는다** — "30분 무활동이면 새 세션" 같은 세션화는 `logflow` 영역이다.
   이 툴의 최소 단위는 **날짜**다.
5. **이름을 읽지 않는다** — 트래커의 `환자명` 열은 열지 않고 `Access Code` 로만 조인한다.
   → *강제장치 4: 전 출력에서 한글 성명·ID 패턴 0건을 테스트로 고정*
6. **탈락 시점을 추정하지 않는다** — 마지막 활동일만 인쇄한다. "탈락했다"고 말하지 않는다.
7. **판정을 만들어내지 않는다** — 애매하면 `[치명]` 이 아니라 `[경고]`, 경고가 애매하면 `대조불가`.

## 입력 / 출력

### 실행 예

```bash
# ① 먼저 어떻게 읽었는지 본다 (판정 없음)
python3 -m doseaudit --inspect --logs "M&Q임상 결과/wowfit_project17_excels/"

# ② 정의를 선언하고 센다
python3 -m doseaudit --logs wowfit_project17_excels/ \
    --active-day any-row --window enroll-to-cut --cut 2026-06-23 \
    --out-dir 결과/

# ③ 손으로 관리한 트래커와 대조한다
python3 -m doseaudit --logs wowfit_project17_excels/ --tracker 참여현황_2026-06-21.xlsx \
    --active-day any-row --window enroll-to-cut --cut 2026-06-23 --out-dir 결과/

# ④ 정의 미선언 → 판정 없이 exit 2
python3 -m doseaudit --logs wowfit_project17_excels/
```

### 실제 콘솔 출력 (이 톤으로 구현할 것)


## 실패할 수 있는 지점 (그리고 가장 싸게 조기 발견하는 법)

1. **확증임상에서 로그 형식이 바뀐다.** 앱이 개편되면 6시트 5열 규격이 깨지고 파서가 죽는다.
   → 규격이 다르면 **틀린 판정 대신 exit 2**(추론 금지)로 설계했으므로 조용히 거짓말하지는 않는다.
   빌드 중 **헤더 1열만 바꾼 합성 파일로 exit 2 를 먼저 확인**한다. 그래도 **형식이 두 번 연속
   바뀌면 이 툴은 접고 벤더에게 CSV 규격을 요구하는 게 맞다.**
2. **"두 번 여는가"** — M&Q 연구는 CSR v0.6 까지 갔다. 이 툴의 재사용은 **확증임상(같은 앱, 더 큰 N)**
   과 `[WF 1.9] 로그 데이터 리스트.xlsx` 의 분석 예정 리스트에 걸려 있다. 이건 **가정이지 실측이 아니다.**
   → 가장 싼 확인: 빌드 첫 30분에 **CSR §3.4 의 `n=23`·`61%` 가 어느 정의에서 나오는지 역산**해 본다.
   역산되면 그 정의가 `--active-day` 프리셋으로 박히고, 역산되지 않으면 **그 사실 자체가 이 툴의
   존재 이유**다(현재 기획 세션에서는 52%·46% 둘 다 61%를 재현하지 못했다).
3. **매번 우는 체커가 된다.** 트래커 불일치 23명을 첫 실행에 쏟아내면 두 번 열지 않는다.
   → 불일치는 **한 줄 요약 + CSV로 밀어내고**, 콘솔에는 **최대 5행 + "전체는 CSV"** 로 고정한다.
   부호가 전원 같으면 **"오타가 아니라 정의 차이로 보입니다"** 한 문장으로 묶는다(23행이 아니라 1행이다).
4. **항상 깨끗하게 나온다.** 다음 데이터셋에서 불일치가 0이면 툴이 할 말이 없다.
   → 반증되어 있다: 지금 **23/30 · 빈 모듈 30/30 · 0초 35.6%** 가 잡혀 있다. 그래도 **다음 두 데이터셋
   연속 치명 0건이면 접는 게 맞다.**
5. **정의를 선언하라는 요구가 귀찮아서 안 쓴다.** `--active-day` 를 필수로 두면 진입 장벽이 된다.
   → `--inspect` 가 **선언 가능한 규칙 목록과 각각의 결과값을 먼저 보여 주고**, 사용자는 보고 고른다.
   고르는 행위 자체가 이 툴의 산출물이다 — Methods 문장에 그대로 들어간다.
6. **BELL-001 로그에도 되게 만들고 싶어진다.** `sleepthera` 의 `session_data.csv` 는 299만 행이고
   구조가 완전히 다르다. → **v1은 워크북 묶음 하나만** 본다. 넓히면 `logflow` 재탕이 된다.

- **트래커 주의**: 첫 열이 `환자명`(실명)이다. **이 열은 열지 않는다.** `Access Code` 열로만 조인하고, 출력에 실명이 0건인지 테스트로 고정한다(`deidaudit`·`jamoscore` 전례).
- **`D1`…`D145` 격자**는 v1에서 **읽지 않는다.** `완료일수` 와 로그만 대조하면 충분하고, 145열 격자의 일자 기준점(가입일? 연구 시작일?)이 어디에도 적혀 있지 않다 — 추론하면 조용히 거짓말한다. 커버리지 자백에 `검사 안 함`으로 적는다.
- **오탐 억제를 먼저 쓴다**: 일치한 7명(`4J5ZLMYV`·`RM6Q9V6X`·`YN9ZXX18VO`·`YQ67XE5P`·`YVYY3V5J`·`ZD2V7EYQ`·`ZE9ARRVNZR`)에서 치명 0건이 나오는 테스트를 **검출기보다 먼저** 작성한다.
- **진행률(%)은 트래커 안에서 정합적이다** — `완료일수 ÷ 현재까지 일수` 로 재현된다. 즉 손으로 잘못 들어간 값은 `완료일수` **하나**이고, 나머지는 그로부터 파생됐다. 이 사실을 리포트에 인쇄하면 사용자가 어디를 고쳐야 하는지 1초에 안다.
