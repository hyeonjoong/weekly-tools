# stalecheck — 제출본세대점검 (부제: 재현성 예치 번들 안의 코드가, 그 숫자를 만든 코드가 아니다)

## 한 줄 요약

투고 봉투(`submission/`·`제출용/`) 안의 파일들이 **작업 폴더의 최신 원본과 같은 세대인지**를 내용 해시로
대조해, **한 세대 뒤처진 파일만** 찍는다. PDF·DOCX의 생성시각 메타데이터를 먼저 지우고 비교해
"다시 렌더했을 뿐 내용은 같음"을 오탐으로 내보내지 않는다. 고치지 않고, 복사하지 않고,
원고 내용도 저널 규정도 보지 않는다 — **봉투가 며칠 전 세계를 담고 있는지만 말하고 끝난다.**

## 왜 필요한가

### 트리거 순간

> 투고 버튼을 누르기 직전. 저널에서 리젝돼 **B저널 패키지로 갈아탈 때**. 리비전을 재제출할 때.
> `11_Reproducibility_Deposit/` 를 만들어 저널에 올릴 때. — 폴더를 열어 "이게 최신 맞나?" 를
> 눈으로 확인한다. 그림 8장 × 2포맷 + 분석 스크립트 21개 + 원고·커버레터를 하나씩.

이건 드문 일이 아니다. 지금 **투고 중·작성 중 원고가 10편 이상**이고, POC_PSG 논문은 **15번째 저널**이며,
NHANES 논문은 Frontiers/IJA **두 벌을 병행**하고, BELL_Paper3 는 `SUBMISSION/`·`SUBMISSION_BRM/`·
`SUBMISSION_JPBA/` **세 벌**을 유지한다. 봉투를 다시 싸는 일은 **논문당 여러 번** 일어난다.

## 대안 대비 우위

| 대안 | 왜 안 되는가 / 왜 그래도 이게 낫나 |
|---|---|
| **손으로 한다 (현재)** | 실제로 손으로 하고 있고, **이미 두 군데서 자백이 파일로 남아 있다**(`00_어느파일이_최신인가.txt`, `README_저널별_구분.md`). 41쌍을 매 투고마다 눈으로 대조하는 일이다 |
| **`diff -r 작업폴더 봉투폴더`** | ① 폴더 구조가 달라 짝이 안 맞는다(`figures/` vs `submission/05_Figures/`) ② 이름이 바뀐 사본(`fig1_checksum_corruption.png` → `Figure1.png`)을 못 따라간다 ③ PDF·DOCX는 **다시 렌더만 해도 "differ"** — 실측에서 **11건이 전부 이 오탐**이었다 ④ 무엇보다 **어느 쪽이 낡았는지 말하지 않는다** |
| **`fdupes`/`jdupes`** | **정반대 질문**에 답한다. 같은 파일을 찾아 준다. 우리가 찾는 건 *같아야 하는데 갈라진 쌍*이다 |
| **git** | **이 트리는 git 이 아니다.** 11,472개 파일 중 git 저장소는 2개뿐이고, 원고 버전이 가장 심하게 난립하는 `MoA논문작성/` 은 비-git 이다(`수정3`…`수정20`, `수정6_Fig4코멘트전` 등 7개 분기). git 을 도입하자는 제안이 아니다 — **지금 상태에서 답을 주는 도구**가 필요하다 |
| **`pip install` 한 번** | **없다.** "제출 봉투가 작업 폴더보다 낡았는가"를 묻는 패키지는 존재하지 않는다. 해시 비교는 쉽지만, **메타데이터 정규화 + 이름 바뀐 사본 짝짓기 + 방향 판정**이 이 문제의 전부다 |
| **`packlist` 를 쓴다** | `packlist` 는 **봉투 안을 본다** — 원고가 약속한 것이 봉투에 있는지, 저널 한도를 넘는지. **봉투 밖(작업 폴더)을 보지 않는다.** 봉투 안이 완결적이면서 동시에 전부 구버전인 상태를 통과시킨다 |

### 인접 툴과의 경계

| 툴 | 입력 | 답하는 질문 |
|---|---|---|
| `packlist` | 봉투 폴더 + 원고 | 봉투가 **약속한 것을 담고 있는가** (저널 한도·앵커·고아 파일) |
| `tracecheck` | 원고 + 산출물 번들 | 원고의 **숫자가 산출물에 있는가** |
| `revcheck` | 제출본·개정본·응답서 | 응답서가 **개정본과 맞는가** |
| `draftcheck` | 원고 1편 | 원고가 **자기 자신과 맞는가** |
| **`stalecheck`** | **작업 폴더 + 봉투 폴더** | **봉투 안 파일이 작업 폴더 원본과 같은 세대인가 — 어느 쪽이 낡았는가** |

**출시 게이트 — README 첫 문단이 이 한 줄을 말하지 못하면 출시하지 않는다:**
> *`packlist` 는 봉투 안이 약속대로 채워졌는지를 보고, `stalecheck` 는 그 봉투가 며칠 전 세계를
> 담고 있는지를 본다. 봉투는 완벽하게 채워진 채로 한 세대 낡을 수 있다.*

## 범위

### 한다 (v1)

1. **`--inspect` 가 먼저다.** 판정 전에 인쇄한다: 스캔한 파일 수·확장자별 분포, 봉투로 인식한 폴더 목록과
   **그 판단 근거**, 짝지어진 쌍 수, 짝을 못 지은 파일 수. 사람이 1초 안에 "잘못 읽었다"를 알아야 한다.
2. **메타데이터 정규화를 먼저 구현한다 — 검출기보다 먼저.**
   - PDF: `/CreationDate`·`/ModDate`·`/ID` 제거 후 해시
   - DOCX/XLSX(zip): `docProps/` 제외하고 엔트리명+내용으로 해시
   - 그 외: 원시 바이트
   **실측 11건이 이 단계에서 사라져야 한다**(전부 PDF). 사라지지 않으면 이 툴은 매번 우는 체커가 된다.
3. **짝짓기 — 보수적으로.** ① 내용 해시 일치 → 같은 파일 ② 파일명 완전 일치(대소문자·NFD 정규화) →
   쌍 ③ **이름이 다른 사본은 v1에서 짝짓지 않는다.** 대신 `짝없음.csv` 에 **"봉투에만 있음"**·
   **"작업폴더에만 있음"** 으로 자백한다. 유사 이름 추측은 조용히 거짓말하는 경로다.
4. **방향을 판정한다 — 증거가 있을 때만.**
   - `[치명] 봉투가 구세대`: 정규화 해시가 다르고 **작업본 mtime > 봉투 mtime**
   - `[경고] 봉투가 더 최신`: 반대 방향 — 봉투에서 손으로 고쳤다는 뜻이고, **그 수정은 작업 폴더에 없다**
   - `[판정불가]` mtime 이 같거나 역전 판단이 불가능한 경우. **추측하지 않는다.**
5. **텍스트 파일은 몇 줄이 다른지까지 센다.** `.py`·`.md`·`.csv` 는 `difflib` 로 `+N/-N` 행수와
   **첫 3행의 diff 요약**을 낸다. 실측 ①②가 그래서 잡혔다. 바이너리는 크기 차이만.
6. **`.md` ↔ `.docx` 형제 점검.** 같은 basename 의 `.md` 가 `.docx` 보다 최신이면 **`[경고] 빌드 누락`**.
   (트리 전체에 이런 형제쌍이 52개 있다.)
7. **PNG/PDF 형제 점검.** `Figure2.png` 와 `Figure2.pdf` 의 mtime 이 서로 다른 세대면 `[경고]`.
   그림은 늘 쌍으로 나오는데, 한쪽만 다시 만드는 일이 생긴다.
8. **일치는 한 줄로 요약한다.** 196쌍이 일치하면 `일치 196쌍` **한 줄**. 목록을 쏟지 않는다.
9. `[커버리지 자백]` — 읽은 파일 수/못 읽은 파일, 크기 초과로 건너뛴 파일, 짝 못 지은 파일 수,
   그리고 **검사 안 함** 목록(각각 어느 툴로 가야 하는지 화살표와 함께).

### 의도적으로 안 한다

- **고치지 않는다.** 복사·덮어쓰기·이동·삭제 없음. `shutil`·`os.replace`·`open(...,'w')` 가 입력 경로에
  대해 존재하지 않음을 **AST로 강제**한다. 이 툴의 출력은 "어느 파일을 다시 복사해야 하는가" 목록뿐이다.
- **원고 내용·숫자를 보지 않는다.** → `tracecheck`·`numcheck`
- **저널 규정을 보지 않는다.** 한도·필수 항목은 → `packlist`
- **픽셀/의미 비교를 하지 않는다.** 그림이 "같아 보이는지"는 묻지 않는다. 바이트가 다르면 다르다고만 한다.
- **유사 파일명 추측 짝짓기를 하지 않는다.** (v2 후보)
- **`.hwp` 를 읽지 않는다.** 해시는 되지만 내용 diff 불가 — `대조불가` 로 자백한다.
- **어느 것이 "옳은" 버전인지 말하지 않는다.** 방향만 말한다. 고르는 건 사람 일이다.

## 입력 / 출력

### 실행 예

```bash
python3 -m stalecheck \
  --work   "논문작업/8.DTx피벗_대조맹검_증거기준 (2026-07-23)" \
  --package "논문작업/8.DTx피벗_대조맹검_증거기준 (2026-07-23)/submission" \
  --out-dir ~/Desktop/세대점검_20260918
```

`--package` 를 생략하면 `--work` 아래에서 봉투로 보이는 폴더를 **찾아서 인쇄하고 확인을 요구**한다
(추론해서 바로 판정하지 않는다).

```

  작업 폴더 : analysis/ · figures/ · manuscript/       (파일 312개)
```

## 실패할 수 있는 지점 (그리고 가장 싸게 조기 발견하는 법)

1. **매번 우는 체커가 된다 — 1순위 위험.** PDF 11건이 이미 증명했다. 정규화 없이 돌리면 투고 때마다
   "다 다릅니다"가 나오고 두 번 열지 않는다.
   → **빌드 첫 30분에 정규화만 먼저 구현하고, 그 11쌍이 조용해지는지부터 확인한다.** 조용해지지 않으면
   (예: 폰트 서브셋 ID가 렌더마다 바뀐다) **그 자리에서 접는 게 맞다.**
2. **mtime 을 믿을 수 없다.** 클라우드 동기화·`cp` 는 mtime 을 갈아 치운다. 실측에서는 방향이 일관됐지만
   (7/30 봉투 < 7/31 작업, 21건 전부) 다음 폴더에서 깨질 수 있다.
   → 그래서 방향 판정은 **`[치명]`/`[판정불가]` 두 갈래**다. mtime 이 못 미더우면 판정불가로 떨어지고,
   불일치 사실 자체는 여전히 보고된다. **불일치는 mtime 없이도 참이다.**
3. **봉투 폴더를 못 찾는다.** 이 트리에는 명명 규약이 **세 가지** 공존한다(`submission/`,
   `01_제출용_SUBMISSION/`, `제출패키지`). 추론이 틀리면 전부 헛짚는다.
   → **추론해서 판정하지 않는다.** 후보를 인쇄하고 `--package` 를 요구한다(미특정 → exit 2).
4. **이름이 바뀐 사본을 놓친다.** `fig1_checksum_corruption.png` → `Figure1.png` 같은 개명 복사는
   v1이 짝짓지 못하고 "양쪽에만 있음"으로 빠진다. **이건 알려진 사각지대이고 커버리지 자백에 적는다.**
   → 실측 245쌍이 이미 잡히므로 v1의 가치는 성립한다. 개명 추적은 v2 1순위.
5. **항상 깨끗하게 나온다.** 다음 논문에서 불일치가 0이면 할 말이 없다.
   → 반증되어 있다: **6/16 폴더 · 38쌍**이 지금 걸려 있다. 그래도 **다음 두 번의 투고에서 연속 치명
   0건이면 접는 게 맞다.**
6. **"고쳐 주지 않아 불편하다"** — 목록만 주고 복사를 안 해 준다는 불만이 나온다.
   → 의도적이다. 어느 쪽이 옳은지는 **사람만 안다**(봉투에서 손으로 고친 경우가 실제로 있다 — `[경고]
   봉투가 더 최신`). 자동 복사는 그 수정을 덮어써서 되돌릴 수 없게 만든다. README 한계 절에 명시한다.
