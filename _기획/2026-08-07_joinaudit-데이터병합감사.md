# joinaudit-데이터병합감사

## 한 줄 요약

워치 HRV, 호흡밴드, EEG 요약, 수면일기, ISI 설문, UT 로그처럼 **출처가 다른 여러 CSV/XLSX를 피험자 × 시점 기준으로 한 장의 분석용 표로 병합**하고, 그 과정에서 **누가 왜 빠졌고 N이 왜 이 숫자가 되었는지를 증거로 남기는** 오프라인 CLI. 병합 결과물(`merged.csv`)은 이 저장소의 `statwise`/`table1`/`longistat`에 그대로 넣을 수 있는 모양으로 나온다.

---

## 왜 필요한가

> **트리거 모먼트**: 장비 엔지니어가 워치 export CSV를 주고, 호흡밴드 로그는 따로 오고, 수면일기는 엑셀이고, ISI는 설문 플랫폼에서 받은 또 다른 CSV다. 분석을 시작하려면 이걸 **한 장의 표**로 만들어야 한다. 분석은 그 다음이다.

지금은 대신 뭘 하는가 — 엑셀에서 VLOOKUP을 하거나, pandas `merge`를 그때그때 세 줄 짜서 돌린다. 그리고 **둘 다 조용히 틀린다**:

- 피험자 ID가 한 파일은 `S01`, 다른 파일은 `S1`, 또 다른 파일은 `BELL-001-01`, 어떤 행은 뒤에 공백이 하나 붙어 있다 → VLOOKUP은 `#N/A`, pandas는 **아무 말 없이 행을 버린다**.
- 같은 피험자·같은 날짜가 한 파일에 두 번 들어 있다(재측정, 재업로드) → pandas `merge`는 경고 없이 **행을 곱한다**. 최종 N이 부풀고, 아무도 눈치채지 못한 채 논문 표에 들어간다.
- 수면 데이터는 자정을 넘긴다. 03:20의 HRV 값은 **어느 날 밤에 속하는가**. 손으로 하면 어떤 파일은 취침일 기준, 어떤 파일은 기상일 기준이 되어 하루씩 어긋난다.
- 날짜 포맷이 파일마다 다르고(`2026-01-03` / `03/01/2026` / `26.1.3`), 엑셀은 날짜를 숫자로 내보내고, 인코딩은 cp949다.

**이 실수들의 공통점은 티가 안 난다는 것이다.** 병합이 성공한 것처럼 보이고, 표가 나오고, 통계도 돌아간다. 틀린 건 N뿐이다. 사람이 가장 못하고 기계가 가장 잘하는 조합이 또 여기다.

그리고 카탈로그를 보면 이 자리가 정확히 비어 있다. 18개 툴은 **이미 깨끗한 표 한 장이 있다는 전제**에서 시작한다 — `table1`은 1행=1피험자를, `longistat`은 long/wide 정돈본을, `statwise`는 값·그룹 열을 요구한다. 여러 파일을 읽어 합치는 툴은 **하나도 없다**. 즉 카탈로그는 2단계부터 끝까지를 두껍게 덮고 있는데, 실제 시간이 가장 많이 새는 **1단계(분석 가능한 표 만들기)** 가 통째로 비어 있다.

`DATA_INVENTORY.md`가 BELL-001의 모달리티를 **EEG, HRV(워치/PPG), 호흡, ISI, 수면일기, UT 로그** 여섯 개로 적어 놓은 것 자체가 이 툴의 존재 이유다. 모달리티가 여섯 개라는 말은 곧 **파일이 여섯 개고 병합이 매번 필요하다**는 뜻이다.

## 대안 대비 우위

| 대안 | 왜 이걸로는 부족한가 |
|---|---|
| 엑셀 VLOOKUP | ID 표기 차이에서 바로 무너진다. 중복 키를 알려주지 않는다. 자정 넘김 처리는 손으로 열을 하나 더 만드는 수밖에 없다. 무엇보다 **왜 300행이 240행이 됐는지 기록이 남지 않는다**. |
| pandas `merge` / R `dplyr::left_join` | 병합 자체는 세 줄이다. 문제는 **조용하다**는 것 — `validate="1:1"`을 쓰는 사람은 드물고, 안 쓰면 중복 키에서 카테시안 폭발이 경고 없이 일어난다. 매번 즉석 스크립트라 다음 연구에서 같은 실수를 반복한다. |
| `ydata-profiling` 등 프로파일링 패키지 | **한 개** 데이터프레임의 분포·결측을 본다. **조인 자체**를 감사하지 않는다. "어느 피험자가 어느 파일에 없는가"는 이 계열 도구의 관심사가 아니다. |
| REDCap / EDC 내장 병합 | 사내 MoA·UT 데이터는 애초에 EDC에 안 들어간다. 엔지니어가 준 CSV다. |
| LLM에 파일 붙여넣기 | 여기가 핵심이다. **LLM은 300행을 세지 못하고, 세지 못했다는 사실도 말하지 않는다.** 키를 하나하나 대조하고 개수를 세는 일은 결정론적 파싱의 영역이다. |

**이 툴이 이기는 지점은 병합이 아니라 감사다.** 병합 결과 `merged.csv`는 pandas도 만든다. pandas가 절대 안 주는 것은 "**입력 312행 → 최종 248행, 차이 64행의 내역: ID 미매칭 31, 중복 키 제거 18, 시점 윈도우 이탈 15**" 라는 문장과, 그 근거가 되는 행 단위 목록이다. 이건 논문 Methods와 IRB 자료에 그대로 들어간다.

### 인접 툴과의 경계

- `sleepdiary-수면일기지표`: **수면일기 한 파일**을 읽어 지표를 계산한다. joinaudit은 지표를 계산하지 않고, 수면일기를 **다른 모달리티와 붙이는** 일만 한다. 산출물이 서로의 입력이 될 수 있으나 **코드를 import하거나 수정하지 않는다.**
- `logflow-사용자로그분석`: 이벤트 로그 한 종류의 세션화/리텐션. 다중 파일 병합이 아니다.
- `paperforge-논문아이디어발굴기`: 매니페스트에 **사람이 적어 넣은** 데이터 규모를 읽는다. 실제 파일을 읽지 않는다. joinaudit은 실제 파일만 읽는다.
- 하류 연계는 **스키마 일치로만** 한다: `merged.csv`가 `statwise --value/--group`, `longistat --id --time --value`, `table1 --group`에 추가 가공 없이 들어가야 한다.

## 범위

### 한다

1. **다중 파일 읽기** — CSV/TSV/XLSX(2개 이상, 상한 없음). 구분자 자동, BOM/cp949/UTF-16, 엑셀 날짜 시리얼, 천단위 콤마·유럽식 소수점.
2. **피험자 키 정규화** — 공백/대소문자/제로패딩(`S1`↔`S01`)/공통 접두어(`BELL-001-`)/전각 문자. **결정론적 규칙만 적용한다. 편집거리 기반 추측은 하지 않는다.** 규칙으로 못 붙이는 건 `--alias alias.csv`로 사람이 명시한다.
3. **시점 정렬** — 셋 중 하나를 `--align`으로 고른다.
   - `night`: 자정 넘김 귀속. `--night-cutoff 12:00`(기본 정오) 기준으로 하루를 잘라, 그 구간의 타임스탬프를 **앞선 날짜의 밤**에 귀속시킨다. 규칙은 리포트에 문장으로 명시된다.
   - `visit`: 방문 라벨 정규화(`BL`/`baseline`/`기저`/`V1`/`방문1` → 사전 정의된 별칭표만. 모르는 라벨은 추측하지 않고 보고).
   - `date`: 날짜 그대로.
   - 날짜 매칭 허용오차 `--tolerance-days N`(기본 0). 2개 이상 후보가 동률로 걸리면 **충돌로 보고하고 그 행은 병합하지 않는다.**
4. **중복 키 탐지** — 기본 정책은 `--dup-policy error`(중단). `first`/`last`/`mean`을 명시적으로 골라야 진행된다. **묵시적 카테시안 조인은 어떤 경우에도 하지 않는다.**
5. **병합 실행** — `--how inner|outer|left`(기준 파일 `--base`). 출력은 기본 wide(1행 = 피험자×시점, 열 이름은 `파일접두어_원본열`), `--long`도 지원.
6. **병합 감사 리포트** — 파일별 행수/고유 피험자 수, 파일 간 교집합·차집합, **드롭 사유별 카운트와 행 목록**, N-흐름(입력→최종), 피험자×파일 커버리지 매트릭스.
7. **기본 위생 점검** — 완전 결측 열, 상수 열, 날짜 파싱 실패 행, 옵션 `--spec spec.json`의 범위 이탈, **단위 의심**(같은 이름의 변수가 두 파일에 있고 중앙값이 약 60배/1000배 차이 → 분 vs 시간, ms vs s 의심을 *보고만* 한다. 자동 변환은 하지 않는다).
8. **Methods 문장 초안** — N 흐름을 한국어/영어 한 문단으로.

### 의도적으로 안 한다

- **통계를 하지 않는다.** 평균도 비교도 없다. 그건 `statwise`/`table1`/`longistat`의 몫이다.
- **결측 대체(imputation)를 하지 않는다.** 비어 있으면 비운 채로 넘긴다.
- **신호 파일을 읽지 않는다.** EDF·원시 EEG·PPG 파형은 대상 밖(`eegband`/`hrvkit`이 요약한 CSV를 받는다).
- **퍼지 매칭을 하지 않는다.** 임상 데이터에서 편집거리로 ID를 붙이는 건 조용히 틀리는 최악의 방법이다.
- **원본 파일을 수정하지 않는다.** 읽기 전용. 출력은 `--out-dir`에만.
- **타임존/서머타임 변환을 하지 않는다.** 단일 타임존 가정. 오프셋이 섞여 있으면 **보고하고 중단**한다.
- **DB·API 연결을 하지 않는다.** 네트워크 호출 0.
- **자동 단위 변환을 하지 않는다.** 의심만 보고한다.

## 입력 / 출력

### 입력

병합할 파일 2개 이상(CSV/TSV/XLSX). 옵션으로 별칭표와 스펙 파일.

```
joinaudit watch_hrv.csv diary.xlsx isi.csv \
  --key subject_id --align night --night-cutoff 12:00 \
  --how outer --dup-policy error \
  --alias alias.csv --spec spec.json \
  --out-dir 결과 --prefix hrv,diary,isi
```

`--key`/`--date`/`--visit`는 생략 시 자동 탐지하되, **자동 탐지 결과를 반드시 화면에 출력하고, 확신이 없으면 병합하지 않고 종료코드 3(병합 불가)으로 끝낸다.**

`alias.csv` (사람이 명시하는 ID 대응표):
```csv
파일,원본ID,표준ID
diary.xlsx,피험자1,S01
isi.csv,BELL-001-01,S01
```

`spec.json` (선택):
```json
{
  "id_prefixes": ["BELL-001-"],
  "visit_aliases": {"baseline": ["BL", "기저", "V1", "방문1"], "week4": ["W4", "4주", "V2"]},
  "ranges": {"isi_total": [0, 28], "tst_min": [120, 720], "rmssd_ms": [1, 300]}
}
```

### 출력

`--out-dir`에 4개 파일 + 화면 요약.

- `merged.csv` — 분석용 표. 1행 = 피험자×시점. 하류 툴에 그대로 투입 가능.
- `병합감사.md` — N-흐름, 파일별 요약, 드롭 사유, 커버리지 매트릭스, 적용된 규칙 문장, Methods 초안.
- `문제목록.csv` — `파일,행번호,키,심각도,유형,설명,권고` (CSV 수식 인젝션 방어 포함).
- `키매칭표.csv` — 피험자 × 파일 커버리지(1/0), 어느 피험자가 어느 파일에 없는지 한눈에.

화면 요약 예:

```
[입력]
  watch_hrv.csv   312행  피험자 26명  날짜열: measured_at (자동 탐지)
  diary.xlsx      298행  피험자 24명  날짜열: 날짜 (자동 탐지)
  isi.csv          52행  피험자 26명  시점열: visit (baseline/week4)

[키 정규화] S1→S01 형태 정규화 11건, 접두어 BELL-001- 제거 26건, 별칭표 적용 3건
[야간 귀속] 정오(12:00) 기준. 00:00~11:59 타임스탬프 47건을 전날 밤에 귀속.

[!] 중복 키 18건 (--dup-policy error → 중단하지 않고 목록만 보고, 정책 지정 필요)
      S07 2026-03-11 (watch_hrv.csv 2행)  ... 외 17건 → 문제목록.csv

[N 흐름]
  입력 행 합계 ......................... 662
  키 정규화 후 미매칭 피험자 ........... -2명 (S19, S23: diary.xlsx에만 존재)
  날짜 파싱 실패 ....................... -4행
  시점 윈도우 이탈(tolerance 0일) ...... -15행
  중복 키 ............................. 18행 (정책 미지정 → 보류)
  ------------------------------------------------
  병합 가능 ........................... 피험자 24명 / 248행

[!] 단위 의심: tst (diary.xlsx 중앙값 7.1) vs tst_min (watch_hrv.csv 중앙값 421) — 시간 vs 분 가능성. 자동 변환하지 않음.

종료코드 2 (경고 있음). 결과/문제목록.csv 를 먼저 확인할 것.
```

종료코드: `0` 문제 없음 / `1` 병합 실패 / `2` 경고 있음(병합은 됨) / `3` **병합 불가**(키·시점 자동 탐지 실패, 타임존 혼재 등 — 추측해서 붙이느니 멈춘다).

## 실패할 수 있는 지점 (그리고 가장 싸게 조기 발견하는 법)

1. **실제 파일이 상상보다 훨씬 이상해서 첫 실행에서 죽는다.** 병합된 셀, 헤더가 3행, 시트 앞에 안내문, 열 이름이 중복.
   → **가장 싼 조기 확인**: 감사 리포트를 만들기 전에 `--inspect` 모드(파일별로 탐지한 키/날짜/행수만 출력)를 **첫 30분 안에** 만들고 실제 파일 한 벌에 돌려본다. 여기서 죽으면 나머지는 의미가 없다.
2. **자동 탐지가 엉뚱한 열을 키로 잡아 조용히 틀린 병합을 만든다.** 이 툴이 가장 크게 실패하는 방식이다 — 틀린 표를 자신 있게 내놓는 것.
   → **가장 싼 조기 확인**: 탐지 결과를 항상 화면 첫 블록에 출력하고, 후보가 2개 이상이거나 신뢰도가 낮으면 **종료코드 3으로 멈춘다.** 규칙을 넓히지 말고 좁힌다. 애매하면 사람에게 `--key`를 요구한다.
3. **"그냥 pandas 세 줄이면 되는데"로 판명난다.** 병합만 보면 맞는 말이다.
   → **가장 싼 조기 확인**: 첫 실행에서 `문제목록.csv`가 **비어 있으면 이 툴은 가치가 없다.** 실제 파일 한 벌에서 중복 키나 ID 미매칭이 한 건도 안 나온다면, 그 순간 이 툴을 접거나 감사 항목을 재설계한다. 반대로 한 건이라도 나오면 이 툴은 그날로 값어치를 한 것이다.
4. **위생 점검이 거짓양성 폭탄이 된다.** 특히 단위 의심 탐지.
   → **가장 싼 조기 확인**: 깨끗한 예제 세트에서 경고가 하나라도 뜨면 그 항목을 `경고`에서 `정보`로 내리거나 v1에서 뺀다. **조용히 통과시키는 체커도 나쁘지만, 매번 우는 체커는 두 번 다시 안 열린다.**

## 빌더를 위한 메모

- 기존 툴 폴더는 **어떤 것도 수정하지 않는다.** 하류 연계는 **스키마 일치로만** 한다(`draftcheck`→`citecheck` 선례).
- 시간 압박 시 **버리는 순서**: 위생 점검의 단위 의심(7-단위) → `--long` 출력 → `visit` 정렬 모드. 
- **절대 버리면 안 되는 두 가지**: (a) 중복 키에서 카테시안 조인이 일어나지 않는다는 보장, (b) N-흐름 산술 일치(어떤 행도 사유 없이 사라지지 않는다). 이 둘이 이 툴의 존재 이유이며, 나머지를 다 빼도 툴은 값어치를 한다.
- 자동 탐지는 `sleepdiary`의 한/영 열 이름 자동 인식 방식을 참고하되 **코드를 복사하지 말고 독립 구현**한다.
- 합성 예제는 BELL-001 모달리티(워치 HRV 요약, 수면일기, ISI)를 흉내 내되, 값은 전부 난수 기반 합성이어야 한다.
