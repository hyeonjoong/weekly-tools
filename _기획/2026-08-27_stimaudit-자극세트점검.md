# stimaudit-자극세트점검

## 한 줄 요약

실험에 쓸 **소리 파일 여러 개를 한꺼번에** 읽어, ① 각 파일이 사람에게 들려줄 수 있는 상태인가(클리핑·DC·무음·클릭·좌우 불균형)와 ② **이 세트가 유효한 대조인가** — 조건 간 **레벨이 맞춰져 있는가**, 의도한 차이 말고 **의도하지 않은 차이**가 끼어 있지 않은가 — 를 전수 대조하고, 설계서가 **주장하는 파라미터가 실제 신호에 있는지**까지 확인합니다. 소리 하나하나에 점수를 매기지 않습니다 — 그건 DEBUSSY 와 `bell_acoustic_qc.py` 가 하고, 이 툴은 **파일들 사이**만 봅니다.

## 왜 필요한가

> 2026-08-03. 원우님이 싱잉볼 버전 3개를 다시 보내왔다(`싱잉볼_bi_(360+400Hz).wav` 외 2개).
> 7월 28일에 받은 5개 중 3개를 고쳐 만든 것이다. **새 버전이 더 나아졌는지** 확인해야 하는데,
> 두 폴더를 번갈아 열어 Audacity 로 파형을 눈으로 보다가 만다. 24bit/48kHz 스테레오 54 MB 짜리다.
>
> 그리고 더 큰 것. RESONATE 는 `S1_SO-CLAS` / `S2_spindle-target` / `S3_pink` / `S6_breath-pacing`
> **4조건 비교**이고 `S3_pink` 가 대조군이다. 만약 S1 이 S3 보다 2 dB 크다면,
> **"SO-CLAS 가 효과 있다"는 결론은 "소리가 더 컸다"는 결론과 구분되지 않는다.**
> 이건 리뷰어가 반드시 묻는 질문이고, 데이터를 다 모은 뒤에는 고칠 방법이 없다.

**지금은 대신 뭘 하는가**: (a) 아무것도 안 한다 — 사운드 디자이너가 알아서 노멀라이즈했겠거니 한다. 이게 대부분이다. (b) Audacity 로 파형을 눈으로 본다 — 파형 높이는 **피크**이지 음량이 아니다. (c) "피크 노멀라이즈 했다"는 말을 음량이 맞춰졌다는 뜻으로 받아들인다. **이게 가장 위험하다**: 핑크노이즈와 드론은 피크가 같아도 체감 음량이 6 dB 넘게 차이 날 수 있다(파형 충실도(crest factor)가 다르기 때문). 즉 (c)는 틀린 안심이다.

**카탈로그 공백**: 저장소의 27개 툴 중 소리를 다루는 건 `calmbark` 하나뿐이고, 그마저 **오디오 파일을 한 개도 읽지 않는다**(자기가 합성한 PCM 을 자기 테스트 안에서만 검사한다). BELL-001 은 **소리가 곧 중재(intervention)인 기기**인데, 저장소의 어떤 툴도 **실제로 전달된 자극 그 자체**를 측정한 적이 없다. `visitaudit` 은 방문 날짜가 프로토콜을 지켰는지 보고, `joinaudit` 은 결과 데이터를 합치지만, **중재가 설계대로였는지는 아무도 묻지 않는다.**

## 대안 대비 우위

| 대안 | 왜 이 툴이 이기는가 |
|---|---|
| **DEBUSSY** (같은 저자, JOSS 준비 중, `07_JOSS_package/debussy_repo`) | DEBUSSY 는 **파일 하나**에서 11개 지표를 뽑는 추출기다. 세트 개념이 없다. stimaudit 은 지표를 **다시 뽑지 않고** DEBUSSY 매니페스트 CSV(`A1A3_manifest.csv` 스키마)를 **입력으로 받아** 조건 간 비교만 한다. 경쟁이 아니라 후단이다. |
| **`bell_acoustic_qc.py`** (RESONATE·VALIDATE 에 2벌 존재) | `ap.add_argument("wav")` — **위치인자 1개, 파일 하나**. Tier-1/2 준수 여부를 파일별로 판정한다. 파일 A 와 파일 B 를 비교하는 코드가 없다. 그리고 numpy·scipy·**mosqito** 를 요구해 환경이 깨지면 안 돌아간다. |
| **Audacity / 손으로 보기** | 파형은 피크만 보여준다. 음량(LUFS)·DC·클리핑 구간·좌우 RMS 차·앞뒤 무음 길이는 눈으로 안 보인다. 파일 4개면 몰라도 **60개(표준화 코퍼스)·290개(청력검사 자극)** 는 원리적으로 불가능하다. |
| **ffmpeg `-af ebur128`** | 음량 하나는 준다. 하지만 (a) 조건별로 묶어 **차이가 허용범위 안인지 판정**해 주지 않고, (b) 클릭·DC·좌우 불균형·주장 대조를 안 하고, (c) 논문에 붙일 자극 기술표를 안 만든다. 판정과 보고가 이 툴의 본체다. |
| **librosa 로 직접 스크립트** | 매번 새로 쓴다. 허용오차를 얼마로 잡을지, 무엇을 치명으로 볼지 — **판단 규칙이 바로 이 툴의 내용물**이고, 그게 매번 달라지면 스터디 간 비교가 안 된다. |
| **LLM에 붙여넣기** ← **여기가 핵심이다** | LLM 은 54 MB WAV 를 못 듣는다. 더 나쁜 건, **못 들었다는 사실을 말하지 않는다는 것이다.** "두 버전 모두 저각성 설계에 부합해 보입니다" 라고 답할 것이고, 그 문장은 검증 불가능하다. |

### 인접 툴과의 경계

| | 답하는 질문 | 입력 | 출력 |
|---|---|---|---|
| DEBUSSY | 이 소리의 음향 지표 11개는 얼마인가? | WAV 1개 | 지표 CSV |
| `bell_acoustic_qc.py` | 이 소리 **하나**가 논문 Tier-1/2 규칙을 지키는가? | WAV 1개 | QC 카드 JSON |
| calmbark | 규칙대로 소리를 **만들고** 짖음을 기록 | (없음) | 실험 CSV |
| **stimaudit** | **이 소리들이 서로 비교 가능한 세트인가? 주장한 대로 만들어졌는가?** | **WAV 여러 개 + 설계 JSON (+ DEBUSSY 매니페스트)** | **세트 판정 + 자극 기술표** |

**경계를 지키는 강제 장치 (필수 구현)**

1. **파일이 1개면 아무 판정도 하지 않고 exit 2** 로 멈추고 `bell_acoustic_qc.py` / DEBUSSY 를 가리킨다. 세트가 아니면 이 툴의 질문 자체가 성립하지 않는다. (`tracecheck` 가 `--outputs` 없이 멈추는 것과 같은 규율.)
2. **심리음향량(asper 러프니스·acum 샤프니스·ISO 532 라우드니스)을 절대 자체 계산하지 않는다.** 필요하면 `--manifest` 로 받아 쓰고, 없으면 **"해당 축은 검사 안 함"으로 자백**한다. 프록시로 흉내 내는 순간 이 툴은 DEBUSSY 의 열등한 사본이 된다.
3. **Tier 준수 여부를 파일별로 판정하지 않는다.** 그건 `bell_acoustic_qc.py` 다. stimaudit 은 **조건 간 차이**만 말한다.
4. **"어느 자극이 더 좋다"고 말하지 않는다.** 음량이 맞았는지, 주장이 사실인지만 말한다. 우열 판단은 사람이 한다.
5. **논문의 숫자를 임계값(threshold)으로 쓰지 않는다 — 이건 타협 불가다.** ← **1st revision 의 핵심 쟁점이다.** Reviewer 2 가 "간접 증거에서 보편적 설계 처방으로 건너뛴다"고 지적했고, 개정본은 **모든 숫자를 "reference value / exemplar" 로 재라벨하고 `target < 0.3 asper`·`gradual onsets (> ~50 ms)` 같은 문구를 그림에서까지 삭제**했다. 그런데 사내 기존 스크립트 `acoustic_params.py`(APET)와 `bell_acoustic_qc.py` 는 **개정 전 임계값을 `tier1_compliant` 불리언으로 하드코딩**하고 있다 — 즉 지금 그 스크립트들이 뱉는 판정은 **논문이 스스로 철회한 프레이밍**이다. stimaudit 은 그것을 절대 따라 하지 않는다: 논문 유래 수치는 **측정값 + 참조값 + 출처 문헌**을 나란히 인쇄할 뿐 `준수/위반` 을 찍지 않는다(`50 ms` → Foley 2022 / Hailstone 2009, `0.3 asper` → Arnal 2015, `60–80 BPM` → Bretherton 2019 / Watanabe 2017). **테스트로 강제한다**: 리포트 어디에도 논문 수치에 대한 치명/경고 등급이 붙지 않아야 한다. 치명 판정은 오직 **툴 자신의 방법론적 기준**(조건 간 음량 불일치·클리핑·죽은 파일·주장 불일치)에만 붙는다.

## 범위

### 한다 (v1)

1. **파일 읽기 (stdlib)** — `wave` 로 WAV 를 읽는다. 16bit/24bit/32bit-float, 모노/스테레오. **24bit 는 `struct` 에 포맷이 없어 3바이트씩 손으로 부호확장해야 한다**(실물 자산이 24bit/48kHz 이므로 필수). MP3 등은 **`ffmpeg` 가 PATH 에 있을 때만** WAV 로 디코드해 읽고, 없으면 그 파일을 **읽지 못한 것으로 세고 exit 3**.
2. **파일 위생 (시간영역, 파일별)** — 클리핑(연속 3샘플 이상 |x| ≥ −0.1 dBFS 인 구간의 개수·위치), DC 오프셋(|평균| > −60 dBFS), 앞뒤 무음 길이, **시작/끝 클릭**(첫·끝 10 ms 의 램프 시간, 급격한 시작은 논문 Tier-1 Onset Dynamics 위반 방향), 좌우 채널 RMS 차, 길이·샘플레이트·비트depth 불일치, 전부 무음/전부 DC 인 죽은 파일.
3. **레벨 측정 — 두 계통을 모두 낸다.** 이게 이 툴의 심장이다. 피크가 아니라 **레벨**로 비교한다.
   - **(a) 논문 단위 (Table 2 항목 1)**: **LAeq**(A-weighting biquad), **Lmax/LAmax**, **다이내믹 레인지**(100 ms 프레임 p95−p5). 논문이 쓰는 단위는 이쪽이고, Czempik 2020 에서 수면시간과의 상관은 **LAmax(r = −0.64)가 LAeq(r = −0.50)보다 강하다** — 즉 평균보다 **순간 최대치**가 더 중요하다는 게 논문 자신의 근거다. 그래서 Lmax 를 평균과 나란히 반드시 인쇄한다.
   - **(b) 조건 간 매칭용**: **통합 라우드니스(LUFS, 자체 구현 ITU-R BS.1770 K-weighting + 400 ms 게이팅)**, LRA, **트루피크 근사**(4배 오버샘플).
   - **정직 고지 (README·리포트에 명시)**: **LUFS/EBU R128 은 논문에 한 번도 나오지 않는다.** 논문은 라우드니스를 파라미터로 채점하지 않았다("그 자율신경 효과는 event structure 가 포착하는 이벤트의 시간적 분포와 최대 레벨이 실어 나른다"는 이유로). LUFS 는 **논문 유래가 아니라 실험 통제 관행**으로서 쓰는 것이다 — 조건 간 체감 음량을 맞추는 표준 수단이기 때문. 이 구분을 흐리면 안 된다.
4. **세트 대조 (조건 간)** — 설계 JSON 이 파일→조건을 지정하면 조건별로 묶어 **모든 쌍의 LUFS 차이 행렬**을 만든다. 차이 > `--lufs-tol`(기본 1.0 LU) 경고, > 2.0 LU **치명**. 설계 JSON 이 없으면 조건 없이 **전 파일 쌍 행렬**만 낸다(판정 없이 정보만).
5. **주장 대조 (claim check)** — 설계 JSON 의 `claims` 에 적힌 값이 실제 신호에 있는지 확인한다. 지원: `carrier_hz`(채널별 스펙트럼 피크), `beat_hz`(좌우 피크 차 — `bi_(360-400Hz)` 가 정말 40 Hz 맥놀이인가), `mod_hz`(포락선 변조 주율), `duration_s`. **파일명에서 자동 추출하지 않는다** — 추측은 하지 않고, 설계 JSON 에 적힌 것만 검사한다.
6. **교란 후보 (매니페스트 있을 때만)** — `--manifest` 로 DEBUSSY 스타일 지표 CSV 를 받으면, 설계 JSON 의 `contrast`(의도한 차이 축, 예: `modulation_peak_hz`)를 제외한 **나머지 지표들이 조건 간에 맞춰져 있는지** 표로 보여준다. **통계 검정은 하지 않는다** — 조건당 파일이 1~2개인 세트에서 p값은 의미가 없다. 차이 값과 방향만 적는다.
7. **버전 대조 (`--baseline`)** — 이전 폴더를 주면 같은 이름(또는 설계 JSON 의 `pairs`)끼리 짝지어 **무엇이 달라졌는지** 낸다. 원우님 v1 → 싱잉볼 v2 가 이 경로다.
8. **자극 기술표 + 문장 초안** — Methods 에 그대로 붙일 자극 기술표(Markdown/CSV)와 **KR/EN 문단 초안**("All stimuli were loudness-matched to −23.0 LUFS (max between-condition difference 0.4 LU) …"). 측정하지 않은 축은 문장에서 **빼고**, 뺐다는 사실을 리포트에 남긴다.
9. **커버리지 자백** — "N개 파일 중 읽음 M / 못 읽음 K(사유별) · 검사한 축 / 검사 안 한 축(사유)". **이 블록이 없으면 리포트를 출력하지 않는다**(코드로 강제).

### 의도적으로 안 한다

- **음향 지표 추출 일반** — 러프니스·샤프니스·스펙트럼 기울기·HNR 등은 DEBUSSY 소관. 받아 쓰기만 한다.
- **파일별 Tier 준수 판정** — `bell_acoustic_qc.py` 소관.
- **소리 합성·생성** — `calmbark` 소관. 이 툴은 파일을 만들지 않는다(원본 읽기 전용, 디코드 임시파일은 종료 시 삭제).
- **음량 보정본 출력** — "맞춰 주는" 기능은 넣지 않는다. 감사와 수정을 한 툴에 넣으면 사람이 결과를 안 보고 수정만 돌린다. 얼마나 어긋났는지만 말하고, 고치는 건 사운드 담당자가 한다.
- **절대 SPL(dB HL/dB SPL)** — 재생 체인 보정 없이는 알 수 없다. 요구하면 exit 2 로 거절하고 이유를 말한다.
- **통계 검정** — 조건당 n=1~2 에 검정을 붙이면 거짓 정밀도다. `statwise` 를 가리킨다.
- **스펙트로그램·그림** — 저장소 관례상 텍스트/CSV.
- **청력검사 자극(mp3 290개)의 임상적 타당성 판단** — 레벨이 맞는지는 보지만, 그 검사가 옳은지는 이 툴의 질문이 아니다.

## 입력 / 출력

### 입력 (예) — `설계.json`

```json
{
  "study": "RESONATE-pilot",
  "conditions": {
    "active":  ["S1_SO-CLAS.wav", "S2_spindle-target.wav"],
    "control": ["S3_pink.wav"],
    "pacing":  ["S6_breath-pacing.wav"]
  },
  "contrast": "modulation_peak_hz",
  "claims": {
    "S6_breath-pacing.wav": { "mod_hz": 0.1, "duration_s": 20.0 },
    "S3_pink.wav":          { "duration_s": 20.0 }
  }
}
```

### 실행 예

```bash
# 1단계: 설계 JSON 없이 훑기 — 무엇이 얼마나 어긋났는지 먼저 본다 (파일 안 만듦)
stimaudit results/sound_samples/*.wav --inspect

# 2단계: 세트 판정 + 자극 기술표
stimaudit results/sound_samples/*.wav --design 설계.json --out-dir 자극점검_202608

# 3단계: 버전 대조 (원우님 v1 → 싱잉볼 v2)
stimaudit "OPGG_원우님 사운드/싱잉볼버전_20260803/"*.wav \
  --baseline "OPGG_원우님 사운드/" --design 설계_opgg.json --out-dir 버전대조

# 교란 축까지 보려면 DEBUSSY 매니페스트를 붙인다
stimaudit 표준화코퍼스/*.wav --design 설계.json \

```

## 완료 기준 (빌더가 만족시켜야 하는 체크리스트)

- [ ] `dependencies = []` — stdlib 전용. 네트워크 0. `ffmpeg` 는 **있으면 쓰고 없으면 자백**하는 선택적 디코드 통로일 뿐, 분석은 한 줄도 맡기지 않는다.
- [ ] **기존 툴 폴더를 수정·import·복사하지 않는다.** FFT 는 자체 구현한다(`eegband`·`hrvkit` 전례).
- [ ] `wave` 로 **16bit·24bit·32bit-float · 모노/스테레오 · 44.1k/48k** 를 모두 읽는다. **24bit 3바이트 부호확장을 테스트로 고정**(실물 자산이 24bit/48kHz다).
- [ ] **자체 구현 LUFS 가 `ffmpeg -af ebur128` 대비 ≤0.1 LU 일치**함을 테스트로 증명(ffmpeg 는 **테스트에서만**, 하드코딩된 기대값 비교 허용). BS.1770 K-weighting 계수와 게이팅(절대 −70 LUFS, 상대 −10 LU)을 문서에 명시. **LAeq 는 IEC 61672 A-weighting 으로 별도 구현**하고 1 kHz 에서 0 dB 보정, 100 Hz/10 kHz 감쇠를 규격값과 대조.
- [ ] **논문 수치에 등급을 붙이지 않음을 테스트로 강제** (강제 장치 5번). 리포트에서 `50 ms`·`0.3 asper`·`60–80 BPM`·`1.5 acum` 이 등장하는 줄에 치명/경고 마크가 없고 **출처 문헌이 반드시 함께** 인쇄되며 "reference value / 임계값 아님" 고지가 붙는지 검증. `tier1_compliant` 같은 불리언 필드가 코드·CSV 스키마 어디에도 없어야 한다.
- [ ] README·리포트에 **"LUFS 는 논문 유래가 아니다"** 고지가 있고, 논문 단위(LAeq·LAmax·다이내믹 레인지)가 LUFS 와 **나란히** 출력됨을 테스트로 확인.
- [ ] **음성 대조 테스트**: 일부러 어긋뜨린 합성 세트(음량 3 LU 차 / 클리핑 주입 / DC 0.05 / 1 ms 시작 클릭 / 좌우 2 dB 차 / 주장과 다른 반송주파수)를 **각각 정확히 그 항목으로** 잡는지 검증. `calmbark` 의 음성 대조 8종 전례를 따른다.
- [ ] **깨끗한 세트에서 0건**이 나오는 것을 테스트로 고정(오탐 억제). 음량이 0.2 LU 안에 맞은 세트에 경고를 뱉으면 안 된다.
- [ ] **파일 1개 입력 시 아무 판정 없이 exit 2**, 메시지에 `bell_acoustic_qc.py`/DEBUSSY 를 가리킴. 테스트로 강제.
- [ ] **심리음향량을 자체 계산하지 않음**을 테스트로 강제(asper/acum/ISO 532 계산 함수가 코드에 존재하지 않음).
- [ ] **커버리지 자백 블록 없이는 리포트가 출력되지 않는다**(코드로 강제). "검사 안 한 축"이 항상 명시된다.
- [ ] 못 읽은 파일이 하나라도 있으면 비율로 봐주지 않고 **exit 3**.
- [ ] 문장 초안이 **측정하지 않은 축을 언급하지 않음**을 테스트로 강제(`--manifest` 없이 돌린 뒤 초안에 "roughness"/"sharpness" 가 없어야 한다).
- [ ] 원본 파일 읽기 전용. 출력은 `--out-dir` 에만. 디코드 임시파일은 종료 시(예외 경로 포함) 삭제. CSV 수식 인젝션 방어(`= + - @` 앞 `'`). 경로 순회·심볼릭/하드링크·대소문자·NFD 방어.
- [ ] 큰 파일 방어: 54 MB / 200초 / 24bit 스테레오를 **스트리밍(블록 단위)으로** 처리해 메모리가 파일 크기에 비례해 터지지 않게 한다. 실측 자산으로 시간·메모리를 리포트에 기록.
- [ ] `examples/` 에 **합성** WAV 세트 3종(맞은 세트 / 어긋난 세트 / 판정불가 세트) + 설계 JSON. 생성 스크립트 `_make_examples.py` 동봉. **실제 회사 자산은 절대 커밋하지 않는다**(용량·권리 양쪽 문제).
- [ ] pytest 스위트(관례상 200개 이상 목표). 경계: 0.5초 파일, 전부 무음, 전부 DC, 모노↔스테레오 혼합 세트, 샘플레이트 혼합 세트, 조건에 파일 1개, 설계 JSON 이 없는 파일명을 가리킴.
- [ ] 적대적 서브에이전트 하드닝 최소 2라운드 → `HARDENING.md`.
- [ ] 루트 `README.md` 카탈로그 표 **맨 위**에 행 추가 (`2026-08-XX (목)` 형식).
- [ ] 루트 `IDEAS.md` 완료 목록 **맨 위**에 `- [x] YYYY-MM-DD ... (stdlib 전용) → \`stimaudit-자극세트점검\`` 추가.

## 실패할 수 있는 지점 (그리고 가장 싸게 조기 발견하는 법)

1. **사운드 담당자가 이미 음량을 맞춰 놨다.** 요즘 DAW 는 −14/−16 LUFS 로 라우드니스 노멀라이즈하는 게 기본이다. 그러면 이 툴은 매번 "치명 0건"을 뱉고 두 번 다시 안 열린다.
   → **가장 싼 조기 확인**: 코드를 한 줄도 쓰기 전에, `ffmpeg -af ebur128 -f null -` 로 `RESONATE_Sound_Zolpidem/results/sound_samples/` 4개와 `OPGG_원우님 사운드/` 5개의 통합 LUFS 를 **10분 안에 재 본다**. RESONATE 4개가 **0.5 LU 안에** 들어오고 OPGG 도 맞으면 ①번 축(음량)은 이 툴의 심장이 될 수 없다. 그때는 ⑤ 주장 대조와 ② 파일 위생을 심장으로 재배치하고 음량은 부수 지표로 내린다. **툴을 접는 건 그다음이다** — 주장 대조까지 전부 맞으면 진짜 접는다. 내 예상은 RESONATE(자체 `sound_synthesis.py` 산출, RMS 정규화 가능성 높음)와 24bit 외부 반입 파일에서 어긋남이 나온다는 쪽이지만, **이건 예상일 뿐이고 10분이면 사실이 된다.**
2. **매번 우는 체커가 된다.** 허용오차를 1.0 LU 로 잡으면 실무 세트 대부분이 걸릴 수 있다. 그러면 ①과 반대 방향으로 죽는다.
   → **가장 싼 조기 확인**: 위 10분 측정에서 나온 실측 분포를 보고 기본값을 정한다. 규칙을 넓히지 말고 **좁힌다** — 애매하면 치명이 아니라 경고, 경고가 애매하면 정보로 내린다. 치명은 **음량 2.0 LU 초과·클리핑·죽은 파일·주장 불일치** 넷으로 못 박는다.
3. **설계 JSON 을 아무도 안 쓴다.** 조건 매핑을 손으로 적어야 한다면 그 자체가 장벽이라 툴이 안 열린다.
   → **대응은 설계에 이미 넣었다**: 설계 JSON 을 **필수로 만들지 않는다**(`visitaudit` 이 프로토콜 JSON 을 필수로 요구하는 것과 반대 선택 — 거기선 프로토콜 없이 판정이 불가능하지만, 여기선 파일 위생과 전 파일 쌍 행렬만으로도 절반의 가치가 나온다). `--inspect` 한 방으로 값을 먼저 보여주고, **그 출력에서 설계 JSON 뼈대를 자동 생성**(`--emit-design`)해 채워 넣기만 하게 한다.
4. **`bell_acoustic_qc.py` 가 세트 비교로 확장된다.** 그러면 이 툴은 중복이 된다.
   → **가장 싼 조기 확인**: 317줄 프로토타입이고 위치인자가 1개다. 확장 계획이 있는지 30초면 안다. 있으면 이 기획은 **그 스크립트를 저장소 툴로 승격시키는 방향**으로 바꾸는 게 맞다 — 새로 만드는 것보다 그게 정직하다.
5. **BS.1770 구현이 미묘하게 틀린다.** K-weighting biquad 계수·게이팅 순서·채널 가중(L/R 1.0, 서라운드 1.41)을 하나만 어긋뜨려도 값이 조용히 0.5 LU 씩 밀린다. 그런데 이 툴의 치명 판정이 전부 이 숫자에 걸려 있다.
   → **가장 싼 조기 확인**: 구현 첫날에 −20 dBFS 1 kHz 사인(정답 −20.0 LUFS)과 실물 파일 3개를 `ffmpeg -af ebur128` 과 대조한다. **≤0.1 LU 가 안 나오면 그 자리에서 멈추고 계수부터 고친다.** 여기서 대충 넘어가면 나머지 전부가 거짓 정밀도가 된다.

## 빌더를 위한 메모

- **먼저 10분을 쓴다.** 실패지점 1번의 ffmpeg 실측이 이 기획 전체의 전제다. 결과를 `HARDENING.md` 첫머리에 기록하고 시작한다.
- **버리는 순서** (한 세션에 다 안 들어가면 이 순서로 버린다): ⑧ 문장 초안 EN → ⑦ `--baseline` 버전 대조 → ⑥ 교란 후보(`--manifest`) → ⑤ 주장 대조의 `mod_hz` (`carrier_hz`/`beat_hz` 는 남긴다 — FFT 피크 하나면 되고 `bi_` 파일들이 바로 쓴다).
- **절대 버리면 안 되는 4가지**: ③ 자체 구현 레벨 지표의 ffmpeg/규격 대조 검증, ⑨ 커버리지 자백("검사 안 한 축" 명시 포함), 강제 장치 2번(심리음향량 자체 계산 금지), 그리고 **강제 장치 5번(논문 수치를 임계값으로 쓰지 않기)**. 넷 중 하나라도 없으면 이 툴은 만들지 않는 편이 낫다 — 첫째가 없으면 숫자가 거짓이고, 둘째가 없으면 안 본 것을 봤다고 하는 것이며, 셋째가 없으면 DEBUSSY 의 열등한 사본이고, **넷째가 없으면 저자 자신이 1st revision 에서 리뷰어에게 철회한 프레이밍을 사내 툴로 되살리는 것이다.**
- **논문 상태 참고**: NEUBIOREV-D-26-01521, Major Revision, **제출 마감 2026-09-05**. 개정본은 `0.3 asper`·`50 ms` 같은 수치를 전부 "reference value" 로 재라벨했고 Figure 6 에 구워져 있던 `Tier-1 parameters set to safe targets` 문구까지 지웠다. 빌드 시점에 개정본이 이미 제출됐을 수 있으니, 참조값·출처를 코드에 박기 전에 `2.NBR_1st_Revision/Source/manuscript_revised.md` 의 Table 1 을 **직접 열어 최신 문구로 확인**한다. 사내 기존 스크립트(`acoustic_params.py`, `bell_acoustic_qc.py`)의 숫자는 **개정 전 값이므로 출처로 삼지 않는다.**
- **테스트 자산은 전부 합성**으로 만든다. 실물(54 MB × 8)은 커밋하지 않고, 성능 측정에만 로컬 경로로 쓴 뒤 수치만 기록한다.
- 좋은 결과가 나오면 HF Space 게시를 검토한다(단 `hf` CLI 인증돼 있을 때만). 다만 오디오 업로드가 필요하므로 **오프라인 데모(합성 예제 세트)만** 올린다.
