# calmbark 사용법

## 0. 준비

- macOS + 최신 브라우저(Safari/Chrome). 마이크가 있는 컴퓨터를 개가 주로 짖는
  공간에 둡니다.
- 스피커는 개에게서 **2 m 이상** 떨어뜨리고, 개를 향해 직사하지 않게 둡니다.
- `실행.command` 더블클릭 → 브라우저가 `http://127.0.0.1:포트/` 로 열립니다.
  (127.0.0.1 전용 서버 — 같은 와이파이의 다른 기기에서도 접근할 수 없습니다.)

## 1. 첫 세션 (기기 확인 — 5분)

1. **미리듣기**로 프리셋 3종을 들어보고 볼륨을 조정합니다. 사람 귀에 "대화를
   방해하지 않는 배경음" 수준이면 충분합니다. **개가 소리에 놀라거나 회피하면
   그 프리셋은 쓰지 마세요.**
2. **세션 시작** → 마이크 허용 → **3초간 조용히** (소음 바닥 보정).
3. 감도 확인: 개가 짖을 때(없으면 박수·"멍!" 흉내) 레벨바가 **빨갛게** 문턱을
   넘는지 봅니다. 안 넘으면 감도 값을 낮추고(민감하게), TV 소리에도 넘으면
   올립니다(둔감하게).
4. **상시 개입** 모드로 몇 번 짖게 해 감지→페이드인→재생→페이드아웃 흐름이
   도는지 확인하고 세션을 종료합니다. 이 데이터는 분석에 쓰지 않습니다.

## 2. 실험 설계 (권장)

효과 검정이 목적이면 이 순서를 권합니다:

| 단계 | 모드 | 기간 | 목적 |
|---|---|---|---|
| A | 관찰 | 2–3일 (짖음이 잦은 시간대) | 기저선: 시간당 에피소드·평균 지속 |
| B | **무작위** | 1–2주 이상 | 개입/비개입 50% 비교 — 본 실험 |

- **seed 를 기록하세요** (자동 생성값을 그대로 두면 CSV에 남습니다). 같은 seed 는
  같은 배정 순서를 재현합니다. 자동 seed 는 **검증 시드 목록**(합성음이 논문 준수
  테스트를 통과함이 확인된 16종)에서 뽑힙니다 — 직접 바꾸면 이벤트 로그에
  `시드(미검증)` 이 남고, 그 시드의 합성음은 테스트 보장 밖입니다.
- 하루 안의 연속 에피소드는 서로 독립이 아닐 수 있습니다(택배 기사가 계속 있는
  경우 등). 여러 날, 같은 시간대에 수집할수록 비교가 깨끗해집니다.
- **대조군 오염을 아세요.** 재생(기본 180초)이 에피소드 간격(30초)보다 길어서,
  개입 에피소드의 재생이 아직 나오는 중에 시작된 "비개입" 에피소드는 실제로는
  소리에 노출됩니다. 이런 행은 CSV `재생겹침초` > 0 으로 표시되고 화면에도
  ⚠오염 으로 나옵니다 — per-protocol 비교에서 제외하세요. **1차 비교 지표는
  `후속180초짖음수`**(에피소드 시작 후 180초 고정 창의 짖음 수 — 두 군 동일 창)
  입니다. 지속시간 지표는 재생 길이에 좌우될 수 있어 2차로만 쓰세요.
- 세션 중에는 **탭을 전면에** 두세요. 백그라운드 탭은 감지 주기가 초당 1회
  수준으로 느려져 짧은 짖음을 놓칩니다. 화면 잠자기도 꺼두세요 — 5초 이상 프레임
  공백(절전·정지)이 생기면 `갭(N초)` 이벤트가 기록되고 그 공백에 걸친 버스트는
  폐기됩니다(2시간 절전이 "7200초 짖음"이 되는 것 방지). 갭이 낀 세션의 구간
  기록은 신뢰하지 마세요.

## 3. 세션 중 화면 읽는 법

- **상태**: 보정 중 → 감시 중 → 개입 재생 중 (재생 중에는 감지 문턱이 +6 dB
  올라가고 소음 바닥 갱신이 동결됩니다 — 스피커 소리 자기 감지 완화).
- **에피소드 표**: 마지막 짖음 종료 후 30초 안의 재짖음은 같은 에피소드로
  묶입니다. "진행중" 행은 아직 닫히지 않은 에피소드입니다.
- **배정**: 무작위 모드에서 에피소드가 "비개입"으로 배정되면 짖어도 소리가 나지
  않습니다 — 그게 대조군입니다. 걱정되면 관찰 모드부터 쓰세요.
- **요약**: 개입/비개입 기술통계 비교까지만 보여줍니다 — 1차 지표(후속180초
  짖음수)가 맨 앞 열이고, 오염된 비개입 에피소드는 ⚠오염 으로 표시되며 요약
  아래에 그대로 복사해 쓸 statwise 명령이 나옵니다. **표본이 작으면 차이는
  우연입니다 — statwise 로 검정하세요.**

## 4. 세션 종료와 CSV

**세션 종료**를 누르면 열린 에피소드가 닫히고, 두 버튼으로 CSV 를 내려받습니다:

- **에피소드 CSV** —
  `에피소드ID,시작,종료,짖음횟수,지속초,개입여부,모드,seed,재생겹침초,후속180초짖음수`
  - `개입여부`: 1=재생함, 0=안 함. `지속초`: 첫 짖음 시작 → 마지막 짖음 종료.
  - `재생겹침초`: 이 에피소드가 (누구의 것이든) 가청 재생과 겹친 초 — 비개입인데
    0 보다 크면 **오염**, per-protocol 에서 제외.
  - `후속180초짖음수`: 에피소드 시작 후 180초 고정 창의 짖음 수 — **1차 지표**.
    세션 종료 직전 180초 이내에 시작된 에피소드는 창이 잘려 과소집계될 수
    있으니(두 군 모두), 마지막 에피소드는 민감도 분석에서 빼 보세요.
- **이벤트 CSV** — `타임스탬프,유형,에피소드ID,상세` (감사용 원장)
  - `배정` 행: 에피소드별 개입 결정과 seed. `짖음(재생중)` 행: 재생 중 감지 —
    자기 트리거 의심 여부를 사후 감사할 수 있습니다.
  - `재생연장` 행: 새 에피소드가 기존 재생을 연장한 기록(어느 에피소드의 재생인지
    원장에서 추적 가능). `에피소드재개` 행: 30초 경계에 걸친 짖음의 재병합.
  - `갭(N초)`·`오류(보정실패)`·`오류(마이크종료)`·`시드(미검증)` 행: 데이터 품질
    감사용 — 이 행들이 있는 세션은 해석에 주의하세요.

오탐 청소: `짖음횟수 1 · 지속초 0.x` 행은 문 소리·박수일 가능성이 있습니다.
이벤트 CSV의 시각과 대조해 의심 행을 제외한 민감도 분석을 권합니다(제외 전후
결론이 같아야 견고한 결과입니다 — robustcheck 참고).

## 5. 하류 분석

```bash
# 1차 비교: 개입 vs 비개입 의 후속 180초 짖음 수 (에피소드 단위)
statwise calmbark_에피소드_20260821_1200.csv --value 후속180초짖음수 --group 개입여부

# 2차 (참고용 — 지속시간 계열은 재생 길이 편향 가능, README 참조)
statwise calmbark_에피소드_20260821_1200.csv --value 지속초 --group 개입여부

# 여러 날 추이: 에피소드 CSV들을 합치고 `시작` 열 앞 10글자로 `날짜` 열을 만든 뒤 —
# 군(개입여부)이 "대상", 날짜가 "시점". 같은 날 여러 에피소드는 --duplicates mean
# 이 하루 평균으로 요약합니다. (이 명령은 합성 데이터로 실행 확인됨)
longistat 병합_날짜열추가.csv --id 개입여부 --time 날짜 --value 후속180초짖음수 --duplicates mean
```

- per-protocol 민감도: `재생겹침초 > 0` 인 비개입 행을 빼고 statwise 를 한 번 더
  돌려 두 결과를 함께 보고하세요.
- longistat 추이는 대상이 2개(개입/비개입)뿐인 **기술적** 용도입니다 — 확증 검정은
  에피소드 단위 statwise 로 하세요.

## 6. 문제 해결

| 증상 | 조치 |
|---|---|
| 마이크 권한 거부 화면 | 브라우저 주소창 자물쇠 → 마이크 허용 → 세션 시작 다시. 마이크 소리는 저장·전송되지 않습니다 |
| "마이크가 음소거이거나 입력이 없습니다" | 보정 3초간 입력이 사실상 무음(≤−100 dB)이었습니다. 입력 장치 선택·음소거 스위치·입력 레벨을 확인하고 다시 시작하세요 — 이대로 진행하면 모든 잡음이 짖음으로 기록되기 때문에 앱이 거부합니다 |
| "마이크 입력이 끊겼습니다" | 장치가 뽑혔거나 권한이 회수됐습니다. 세션은 자동 종료·기록됩니다 — 마이크 연결 후 새 세션을 시작하세요 |
| 짖는데 감지 안 됨 | 감도 값을 낮추기(민감), 마이크를 개 쪽으로, 다른 앱의 마이크 점유 해제 |
| TV·문 소리가 자꾸 잡힘 | 감도 값을 올리기(둔감). 그래도 남는 오탐은 CSV에서 사후 제외 |
| 재생음이 짖음으로 기록됨 | `짖음(재생중)` 행이 비정상적으로 많으면 볼륨을 낮추거나 스피커를 마이크에서 멀리 |
| 소리가 안 남 | 미리듣기로 출력 장치 확인(세션 중에는 미리듣기가 잠깁니다 — 감지 오염 방지). 비개입 배정 에피소드는 원래 안 납니다 |
| 이벤트 CSV에 `갭(N초)` | 절전/백그라운드로 프레임이 끊겼던 세션입니다. 그 공백 구간 기록은 신뢰하지 마세요 |
| 서버가 안 뜸 | `python3 --version` 확인. 터미널에서 `bash 실행.command` 로 오류 확인 |

## 7. 안전 수칙 (다시)

- 개의 청각은 사람보다 민감합니다. **낮은 볼륨에서 시작**하고, 불안 반응
  (회피·헐떡임·떨림)이 보이면 즉시 중단하세요.
- 이 앱은 수의학적 조언이 아닙니다. 심한 분리불안이 의심되면 전문가와 상담하세요.
