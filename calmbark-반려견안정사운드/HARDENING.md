# HARDENING — 적대적 검증 기록

이 파일은 calmbark 를 조용히 틀리게 만들 수 있(었)는 지점들의 기록입니다.
형식은 라운드 단위입니다: 라운드 0 은 빌드 세션의 자체 점검이고, 이후 라운드는
독립 리뷰어(적대적 패널)가 추가합니다.

---

## 라운드 0 — 빌드 시점 자체 점검 (2026-08-21)

### A. 빌드 중 실제로 잡은 결함

1. **브라운 캐리어의 엔벨로프 랜덤워크가 논문 준수 테스트 ④⑦ 을 깨뜨림.**
   최초 구현은 교과서식 브라운 잡음(누설 적분기, 코너 ~8 Hz)이었다. 에너지가
   DC 근처에 몰리면 신호의 레벨 자체가 비주기적으로 느리게 방황한다(가우스
   엔벨로프 요동 σ/μ≈0.52 의 저주율 성분). 그 결과 예측가능성 자기상관이
   r≈0.4 로 떨어지고, 5–7 dB 짜리 빠른 가짜 "온셋"이 수십 개 검출됐다.
   이것은 지표 결함이 아니라 **소리 설계 결함**이다 — 레벨이 방황하는 텍스처는
   실제로 덜 예측가능하다. 수정: (a) 스펙트럼 기울기(β≈−2)는 유지하면서
   대역폭을 넓혀(one-pole 코너 300 Hz) 요동을 빠른 주율로 밀어냈고, (b) 느린
   AGC(3 Hz 추적기로 나눗셈)로 3 Hz 미만 레벨 방황을 제거했다. 의도적 진폭변조는
   AGC **이후에** 곱하므로 억제되지 않는다. 핑크 캐리어도 80 Hz 고역통과로 같은
   문제를 예방했다.

2. **러프니스 지표 1판이 물리적으로 불가능한 요구였음.** 처음에는 "30–150 Hz
   변조 대역 파워 비율 ≤ 15%"로 썼는데, 광대역 가우스 잡음은 엔벨로프 요동이
   제거 불가능해(위 σ/μ) 어떤 정상 잡음 텍스처도 이 기준을 못 넘는다는 것이
   측정으로 드러났다. 스펙 문구("유의 **피크** 없음")에 맞게 재정의: (a) 대역 내
   이산 피크가 주변 중앙값보다 +10 dB 이상 솟지 않을 것(트레몰로 검출), (b) 대역
   평균 PSD 가 인접한 더 느린 대역(5–25 Hz)보다 높지 않을 것(대역 융기 검출).
   재정의가 지표를 물렁하게 만들지 않았음은 음성 대조 2종(70 Hz 트레몰로,
   30–150 Hz 대역 제한 잡음 변조)이 여전히 걸리는 것으로 증명했다.

3. **엔벨로프 추종기 웜업이 가짜 거대 온셋을 만듦.** 추종기 상태가 0에서
   출발하므로 버퍼 첫 ~0.3 s 에 50–60 dB짜리 가짜 상승이 잡혔다. 측정을 0.5 s
   이후부터 시작하도록 수정. 실제 재생은 앱이 1.5 s 페이드인을 걸므로 버퍼
   첫머리는 어차피 온셋이 아니다.

4. **드론 부분음 구성이 하마터면 Arnal 대역 한복판에 맥놀이를 넣을 뻔함.**
   f + 2f 구성이면 부분음 간격 = f0 = 84–104 Hz — 회피해야 할 30–150 Hz
   러프니스 대역 정중앙에 엔벨로프 변조가 생긴다. 설계 단계에서 계산으로 잡아
   f + 3f(간격 2·f0 = 168–208 Hz > 150 Hz)로 확정했다. 저주파 화성 드론의
   일반적 함정이라 기록해 둔다.

5. **purity grep 이 자기 주석에 걸림.** 순수 모듈 소스에 금지 식별자
   (`Date.now` 등)가 없어야 한다는 테스트가, "Date.now 를 쓰지 않는다"는 주석의
   문구 자체에 걸렸다. 주석을 다른 표현으로 바꿨다. 이 grep 은 주석과 코드를
   구분하지 못한다 — 우회(문자열 조립으로 `window` 참조 등)도 못 잡는다.
   패널은 이 테스트를 "1차 방어선"으로만 취급할 것.

6. **빌드 도중 외부 프로세스가 작업 폴더를 삭제함.** 13:00 경 상위 git 저장소의
   `.git` 이 갱신되면서 미추적 상태였던 calmbark 폴더가 통째로 사라졌다(아마
   외부의 git clean 류 동작). 컨텍스트에 남아 있던 전체 파일로 재생성했고, 이후
   마일스톤마다 스크래치패드에 백업을 떴다. 이 저장소에서 빌드하는 세션은
   같은 위험을 가정해야 한다.

### B. 설계로 미리 막은 함정

- **재생음 자기 트리거 (기획 실패지점 3).** 3중 완화: ① 재생 중 감지 문턱
  +6 dB, ② 재생 중 소음 바닥 갱신 동결(재생음이 바닥을 끌어올려 이후 감도가
  조용히 무뎌지는 2차 함정까지 차단), ③ 재생 중 감지는 `짖음(재생중)` 유형으로
  분리 기록 — 제거가 아니라 **정직한 표시**다. 페이드아웃 중에도 스피커에서
  소리가 나므로 playbackActive 는 페이드아웃 종료까지 유지된다. 전부
  `tests/detector.test.mjs` 로 고정.
- **CSV 수식 인젝션.** `=`, `+`, `-`, `@` 로 시작하는 문자열 셀은 `'` 접두,
  숫자는 비가드(−3.5 가 망가지면 안 됨), RFC 4180 인용. 테스트 고정.
- **루프 경계 클릭.** 잡음: 등파워 크로스페이드(경계 이행 = 인접 샘플 이행).
  드론: 음형 주파수 궤적의 구간 평균을 정수 사이클로 설계(94 Hz × 15 s = 1410)해
  위상이 루프에서 이어짐. 진폭변조는 루프당 정수 사이클. 테스트 고정.
- **`echo | bash 실행.command` 무한 대기.** stdin 이 TTY 가 아니면 스모크
  테스트(기동→curl 확인→종료)만 하고 즉시 exit 0. 포트는 OS 에서 빈 포트를
  직접 받아 충돌을 원천 회피. 서버는 127.0.0.1 전용 바인딩.
- **에피소드 경계값.** "30초 안 재짖음 = 같은 에피소드"의 경계(정확히 30000 ms)는
  새 에피소드로 정의하고 경계값 테스트로 고정.
- **마이크 프라이버시.** 오디오 경로는 AnalyserNode 특징 추출뿐. MediaRecorder /
  fetch / XHR / WebSocket / sendBeacon 은 소스 grep 테스트로 금지. 산출물은
  타임스탬프·dB 숫자뿐이다.
- **백그라운드 탭 감지 정지.** rAF 는 백그라운드에서 완전히 멈추므로 setInterval
  (40 ms)로 구동 — 백그라운드에서도 초당 1회 수준으로는 돈다(거칠어질 뿐).
  사용법에 "탭 전면 유지" 명시.

### C. 알면서 남긴 것 (패널에 미리 자백)

1. **온셋 지표는 8 dB 미만 돌출을 이벤트로 치지 않는다.** 가우스 텍스처의 자체
   요동이 4σ≈7.5 dB 까지 관측되므로(시드 10종 스윕) 그 아래는 원리적으로 구분
   불가라고 판단했다. 6–8 dB 사이의 빠른 팝을 엔진에 심으면 이 테스트는 못
   잡는다 — 텍스처 요동에 마스킹된다는 논거이나, 반박 가능하다.
2. **② 대역 융기 지표의 여유가 얇다.** 시드 10종 스윕에서 worst 0.947 (기준
   1.0). 고정 시드 테스트는 결정론적으로 통과하지만, 임의 시드에서 1.0 을 스치는
   시드가 존재할 수 있다. 기준을 낮추는 대신(원리: "융기 없음" = 1.0) 여유를
   기록으로 남긴다.
3. **app.js(WebAudio 접착층)는 자동 테스트 밖.** 마이크가 차단된 빌드 환경에서는
   수동 스모크(페이지 로드·미리듣기 3종·마이크 거부 경로)만 했다. 특징 추출
   (`bandDbFromAnalyser`)의 대역 합산이 잘못되면 순수 로직이 전부 옳아도 앱은
   틀린다 — 실기기 검증 항목.
4. **프록시 ≠ 심리음향 단위.** asper/acum/DIN 45692 를 계산하지 않는다. 논문
   Table 2 의 정식 파이프라인(Essentia/mosqito)과의 교차검증은 DEBUSSY 로
   가능하지만 이 저장소 범위 밖.
5. **논문 준수는 44.1 kHz 기준.** 48 kHz 는 렌더 스모크만. AudioContext 가
   44.1/48 이외의 샘플레이트를 주는 기기(일부 블루투스)는 미검증.
6. **mulberry32 가 engine.js 와 study.js 에 중복 정의.** 모듈 자기완결(상호
   import 금지)을 위해 의도적으로 중복했다. 두 구현이 어긋나면 각자의 결정론
   테스트가 잡지만, "같은 시드가 두 모듈에서 같은 수열"이라는 교차 보장은 없다
   (필요하지도 않다 — 용도가 다르다).
7. **AGC(레벨 안정화)는 순수한 논문 번역이 아니라 공학적 추가다.** Tier 1
   Event Structure("안정 평균 레벨")의 실행이라고 판단했지만, 원문에 "AGC 를
   쓰라"는 문장은 없다. 정당화는 README 대응표와 engine.js 주석에 있다.
8. **무작위 배정은 블록화가 없다.** 단순 베르누이 50%라 짧은 세션에서 개입/비개입
   불균형이 날 수 있다(예: 6 에피소드가 5:1). 블록 무작위화는 v1 범위 밖 —
   에피소드 수가 적으면 statwise 결과 해석에 주의.
