# visitaudit 빠른 사용법

## 0. 제일 빠른 길

폴더 안의 **`실행.command` 를 더블클릭**하세요. 번들 합성 예제(피험자 20명, 결함을
일부러 심어 둔 것)를 돌려 보여 주고, 종료코드 2·3 이 언제 나오는지까지 시연합니다.

한 번만 설치해 두면 어디서나 `visitaudit` 로 부를 수 있습니다:

```bash
cd ~/Downloads/02_프로젝트/깃헙/visitaudit-방문일정이탈점검
python3 -m pip install -e .
```

## 1. 내 데이터로 — 3단계

### ① 프로토콜 JSON 을 한 번만 만든다

`examples/프로토콜.json` 을 복사해서 우리 연구 값으로 고칩니다. 방문마다
**오프셋**(기준방문일로부터 며칠)과 **창**(예정일 기준 허용 범위, 경계 포함)을
프로토콜 문서의 visit window 표에서 그대로 옮기면 됩니다. 이 파일이 판정 규칙의
전부라서, 이게 없으면 툴은 아무 판정도 하지 않고 종료코드 2로 죽습니다.

두 가지만 지키면 됩니다 — **기준방문의 오프셋은 0**, 그리고 **방문은 시간
순서(오프셋 오름차순)로** 나열. 어기면 종료코드 2로 알려 줍니다. (기준방문일이
곧 0일이고, 순서 위반·'마지막 방문' 판정이 나열 순서를 그대로 쓰기 때문입니다.)

### ② 돌린다 — `--as-of` 를 꼭 명시

```bash
visitaudit 방문기록.csv --protocol 프로토콜.json \
  --subjects 피험자.csv --as-of 2026-08-14 --out-dir 결과_202608
```

`--as-of` 는 "이 날짜 기준으로 판정"입니다(형식은 `YYYY-MM-DD` 만). 이게 있어야
아직 창이 안 닫힌 방문이 '미도래'로 정확히 분류되고, 다음 달에 같은 명령을 돌려도
결과가 재현됩니다. 빼면 오늘 날짜로 돌고 리포트 머리에 경고가 크게 박힙니다.
as-of 이후의 탈락일·등록일은 이번 판정에서 없는 것으로 다루고 자백합니다.

`피험자.csv`(군·등록일·탈락일·age 등)가 없으면 빼도 됩니다 — 방문창·순서·결측
판정은 그대로 되고, CONSORT/선정기준/등록곡선은 생략됐다고 자백합니다.
결과 파일 없이 화면 출력만 보려면 `--no-files` 를 붙이세요.

### ③ 리포트 맨 위의 [커버리지 자백] 부터 읽는다

이탈 개수보다 먼저 봐야 합니다. **몇 건을 판정 못 했고 왜**가 여기에 다 나옵니다.
판정률이 임계(기본 70%) 미만이면 종료코드 3이고, 그때의 이탈 개수는 믿으면 안 됩니다.

## 2. 결과 읽는 법

```
[커버리지 자백]   ← 몇 건 판정했고 몇 건을 왜 못 했나. 여기가 나쁘면 아래를 믿지 마세요.
[이탈]            ← 창 이탈(며칠 밖인지) · 필수방문 결측 · 순서 위반
[데이터 오류]     ← 중복 행·깨진 날짜 — 이탈로 세지 않고 원본 확인을 요구
[선정/제외기준]   ← 무작위배정자 중 기준 위반자 색출
[CONSORT]         ← 스크리닝→제외→배정→완료/탈락, ITT/PP 후보, 정합성 검사
[등록 진행]       ← 월별 등록 수, 목표 도달 예상 (단순 외삽)
```

**종료코드**

| 코드 | 뜻 | 할 일 |
|---|---|---|
| 0 | 이탈 없음 | 이번 달 회의는 이 리포트로 끝 |
| 1 | 이탈 발견 | `이탈목록.csv` 를 열고 건별로 확인 |
| 2 | 입력·프로토콜 오류 | 메시지 대로 파일/열 이름을 고치세요 |
| 3 | **판정률 임계 미만** | 이탈 개수를 믿지 말고, 자백에 나온 판정불가 사유부터 해결 |

**만들어지는 파일 4개** (전부 `--out-dir` 안)

- `진행점검.md` — 리포트 전문 + **논문에 붙일 KR/EN 문장 초안**
- `이탈목록.csv` — 건별 근거(예정일·창·실제일·창밖일수·심각도)
- `피험자별요약.csv` — 1행 = 1피험자, PP 포함/제외/판정불가와 사유
- `CONSORT.txt` — 텍스트 흐름도

## 3. 자주 만나는 상황

### "프로토콜 JSON 이 없습니다" (종료코드 2)
이 툴의 판정 기준은 전부 프로토콜에서 옵니다. `examples/프로토콜.json` 을 복사해
시작하세요. 프로토콜 문서에 visit window 가 아예 없다면 창을 `[0, 0]` 으로 두면
되지만, 그러면 하루만 어긋나도 이탈로 잡히므로 실제 운영 허용 범위를 정해 넣는
편이 낫습니다.

### "판정률 N% → exit 3"
기준방문 날짜가 없는 피험자가 많거나, 날짜가 깨졌거나, 같은 방문이 두 번 들어
있는 경우입니다. 자백 블록의 사유별 목록을 보고 원본을 고친 뒤 다시 돌리세요.
어느 행이 맞는지 툴이 대신 고르지 않습니다.

### "방문일 칸이 비어 있는 행이 잔뜩 있는데요"
그대로 두셔도 됩니다. 빈 칸은 '아직 기록 없음'으로 읽어서, 창이 닫혔으면 결측·
아직이면 미도래로 판정합니다. 깨진 날짜로 세지 않으니 판정률이 깎이지 않습니다.
몇 건이었는지는 자백에 남습니다.

### "미도래 29건이 나왔는데 이탈은 0건?"
정상입니다. 창이 아직 안 닫힌 방문은 이탈이 아니라 미도래입니다. 등록 초기에는
미도래가 많은 게 당연하고, 그걸 이탈로 세지 않는 것이 이 툴의 제 1 원칙입니다.

### "열을 못 찾습니다"
`--id-col 환자번호 --visit-col 회차 --date-col 일자` 처럼 직접 지정하세요.
joinaudit 의 `merged.csv`(subject_id/timepoint)는 그대로 읽힙니다.

### 방문기록이 1행 = 1피험자 (방문명이 열 이름)
`--wide` 를 붙이세요. 프로토콜의 방문명과 정확히 같은 열만 읽습니다.

### 다음 달에 또 돌릴 때
`--as-of` 만 새 날짜로 바꿔 돌리면 됩니다. 숫자가 달라지는 것이 정상이고
(창이 새로 닫혔으니), 왜 달라졌는지는 모든 CSV 에 박힌 `기준시점` 열이 설명합니다.

## 4. 안심해도 되는 것

- **원본 파일을 절대 수정하지 않습니다.** 산출물은 `--out-dir` 에만 쓰고, 입력이
  그 폴더 안에 있으면 실행을 거부합니다.
- **네트워크를 쓰지 않습니다.** 피험자 데이터가 밖으로 나가지 않습니다.
- **추측하지 않습니다.** 중복 행·깨진 날짜·없는 기준방문은 전부 '판정불가'로
  자백되지, 조용히 어느 한쪽으로 처리되지 않습니다.
- **CSV 수식 인젝션을 막습니다.** `=`/`+`/`-`/`@` 로 시작하는 비숫자 셀 앞에 `'` 를
  붙입니다(숫자는 그대로라 `창밖일수 -2` 는 안 망가집니다).
- **번들 예제는 전부 합성 데이터입니다.** 실제 피험자 자료가 아닙니다.
