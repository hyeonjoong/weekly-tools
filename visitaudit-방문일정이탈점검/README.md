# visitaudit — 방문일정 이탈 점검

피험자별 방문 날짜 표와 프로토콜(방문창) JSON 을 받아 **"이 시험이 계획대로 굴러가고
있는가"를 전수 대조**하고, 그 결과를 CONSORT 흐름 숫자·PP 집합 후보·KR/EN 문장 초안으로
내보내는 오프라인 CLI 입니다. 유효성 데이터는 한 줄도 필요 없습니다.

---

## 목적 / Why this exists

**한국어.** 월간 모니터링 회의 전날 밤, 등록 트래커 엑셀을 열어 놓고 피험자 수십 명 ×
방문 5회의 날짜를 눈으로 훑으며 "V2가 창 안에 들어왔나"를 하나씩 뺄셈하는 일 — 두 번
세면 두 번 다 숫자가 다르고, 어느 쪽이 맞는지 알 방법이 없습니다. 그리고 이 계산은 논문
쓸 때 CONSORT flow diagram 과 protocol deviations 문단을 채우느라 **한 번 더** 하게
되는데, 종료 후 1년 치 엑셀을 거슬러 재구성한 숫자는 모니터링 때 보고한 숫자와 거의
항상 다릅니다. visitaudit 은 판정 규칙을 프로토콜 JSON 파일로 고정하므로 **같은 입력 +
같은 `--as-of` → 항상 같은 숫자**가 나오고, 등록이 진행되는 지금부터 같은 규칙으로
뽑아두면 그 불일치가 애초에 생기지 않습니다. 이 툴이 가장 공들인 부분은 판정 자체보다
**세지 않는 것**입니다 — 창이 아직 안 닫힌 방문(미도래)과 중도탈락 이후 방문(해당없음)을
이탈로 세는 순간 첫 실행에서 "이탈 37건"이 뜨고 사용자는 두 번 다시 이 툴을 열지 않기
때문입니다.

**English.** During enrollment, a Phase-3 trial produces one recurring, error-prone chore:
checking every subject's every visit date against the protocol's visit windows. Done by eye
in a spreadsheet, the count changes each time you repeat it — and it gets redone from scratch
at manuscript time for the CONSORT diagram and the protocol-deviations paragraph, almost
always yielding different numbers than the monitoring reports did. visitaudit fixes the rules
in a protocol JSON file and does the date arithmetic exhaustively and deterministically:
window compliance (inclusive bounds, days-out-of-window), sequence violations, missed
mandatory visits, dropout handling, an eligibility re-check, CONSORT flow numbers with
internal consistency checks, a candidate per-protocol set, and draft KR/EN sentences for the
Methods section. Its most load-bearing design decision is what it refuses to count: visits
whose window has not yet closed and visits after withdrawal are never deviations, anything
ambiguous (duplicate rows, unparseable dates) becomes "unjudgeable" rather than a guess, and
every unjudged visit is confessed — loudly, at the top of the report, with exit code 3 when
coverage falls below threshold.

> **joinaudit 과의 경계**: joinaudit 은 "파일을 합쳤을 때 누가 왜 빠졌나"(병합 상 N),
> visitaudit 은 "프로토콜 대비 무엇이 어긋났나"(프로토콜 상 N)를 답합니다. 같은 CONSORT
> 상자를 서로 다른 쪽에서 채우며, 겹치지 않습니다. 그래서 이 툴은 **프로토콜 JSON 없이는
> 아무 판정도 하지 않고 exit 2 로 죽습니다.** joinaudit 의 `merged.csv`(subject_id /
> timepoint)는 스키마 호환으로 그대로 읽습니다.

## 설치

```bash
cd ~/Downloads/02_프로젝트/깃헙/visitaudit-방문일정이탈점검
python3 -m pip install -e .
```

외부 의존성 **0개**(표준 라이브러리만), 네트워크 호출 **0회**. Python 3.9+.
설치하지 않고 쓰려면 폴더 안에서 `python3 -m visitaudit ...`, 또는 **`실행.command`
더블클릭**.

## 입력

**방문기록.csv** (long, 1행 = 1 피험자-방문. `--wide` 로 1행 = 1피험자도 허용):

```csv
피험자ID,방문명,방문일,상태
BELL-0007,Screening,2026-03-16,완료
BELL-0007,Baseline,2026-03-30,완료
BELL-0007,V1,2026-04-27,완료
```

열 이름은 한국어 기본 + 흔한 별칭(joinaudit 의 `subject_id`/`timepoint` 포함)을
인식하고, `--id-col --visit-col --date-col --status-col` 로 직접 지정할 수 있습니다.
별칭 후보가 둘 이상 잡히면 고르지 않고 멈춥니다. 인코딩은 utf-8(-sig) → cp949 순서로
시도합니다(BOM 이 있으면 utf-16 우선). 상태가 `예정/scheduled` 인 행은 기록으로 세지 않습니다(자백만 남김).

**프로토콜.json** — 판정 규칙의 전부. `examples/프로토콜.json`:

```json
{
  "연구명": "SERENE (합성 예제)",
  "기준방문": "Baseline",
  "목표N": 120,
  "방문": [
    {"이름": "Screening", "오프셋": -14, "창": [-14, 13], "필수": true},
    {"이름": "Baseline",  "오프셋": 0,   "창": [0, 0],    "필수": true},
    {"이름": "V1",  "오프셋": 28, "창": [-3, 3], "필수": true},
    {"이름": "V2",  "오프셋": 56, "창": [-5, 5], "필수": true},
    {"이름": "EOT", "오프셋": 84, "창": [-7, 7], "필수": true}
  ],
  "선정기준": [
    {"항목": "age", "연산": ">=", "값": 19},
    {"항목": "age", "연산": "<=", "값": 65},
    {"항목": "ISI_baseline", "연산": ">=", "값": 15}
  ],
  "제외기준": [{"항목": "OSA진단", "연산": "==", "값": "Y"}],
  "PP제외규칙": {"필수방문결측": true, "창이탈일수초과": 7}
}
```

**피험자.csv** (선택) — `피험자ID, 군, 등록일, 탈락일, 탈락사유, 제외사유` + 선정/제외기준
항목 열(`age`, `ISI_baseline`, …). 없으면 방문창·순서·결측 판정만 하고, CONSORT 는 계산
가능한 부분만 내며 무엇을 건너뛰었는지 자백합니다.

## 써 보기 — 번들 예제 (전부 합성 데이터)

```bash
visitaudit examples/방문기록.csv --protocol examples/프로토콜.json \
  --subjects examples/피험자.csv --as-of 2026-08-14 --out-dir 결과_예제
```

실제 출력 (그대로 붙여넣음):

```
visitaudit — 방문일정 이탈 점검
연구: SERENE (합성 예제)   기준시점(as-of): 2026-08-14   프로토콜: examples/프로토콜.json

[커버리지 자백]
  피험자 20명 중 19명 판정 / 1명 판정불가

  방문기록 81행 읽음

[이탈]  총 6건 (방문 단위 5건 / 판정완료 76건 = 6.6%)
  창 이탈  4건

    BELL-0011  V2         창 2026-06-03~2026-06-13 마감, 기록 없음, 탈락 기록도 없음
  순서 위반  1건

[데이터 오류]  2건 — 이탈로 세지 않음. 원본 확인 필요.
    BELL-0013  V1         중복 방문행: 같은 방문 기록 2행(46행 '2026-06-01', 47행 '2026-06-02') — 어느 행이 맞는지 추측하지 않음
    BELL-0015  V2         날짜 파싱 실패: 53행 형식 인식 불가: '07-06-2026'

[선정/제외기준 재점검]  위반 1건 / 판정불가 1건 (판정 79건)
    위반     BELL-0016  ISI_baseline = 13 (선정기준 >= 15)
    판정불가 BELL-0021  ISI_baseline 값 없음
```

## 산출물 4종 (전부 `--out-dir` 안에만)

| 파일 | 내용 |
|---|---|
| `진행점검.md` | 위 리포트 전문 + **KR/EN 문장 초안** (protocol deviations 문단 · CONSORT 캡션 · PP 정의) |
| `이탈목록.csv` | `피험자ID, 방문명, 이탈유형, 예정일, 창시작, 창종료, 실제일, 창밖일수, 심각도, 근거, 기준시점` |
| `피험자별요약.csv` | `피험자ID, 군, 완료방문수, 이탈건수, 최대창밖일수, PP포함여부, PP제외사유, 판정가능여부, 기준시점` |
| `CONSORT.txt` | 텍스트 흐름도 + 정합성 검사 결과 |

모든 CSV 에 `기준시점`(as-of) 열이 박혀 있어, 다음 달에 같은 파일을 다시 돌려 숫자가
달라져도 왜 달라졌는지 한 줄로 설명됩니다. `진행점검.md` 는 공유용이라 프로토콜
경로를 파일 이름만으로 표기합니다. 파일 없이 화면 출력만 보려면 `--no-files`.

**종료코드**: `0` 이탈 없음 · `1` 이탈 발견 · `2` 입력·프로토콜 오류 · `3` 판정률 임계
미만(이탈이 있어도 3 이 우선 — 그 개수 자체를 믿을 수 없으므로).

## 판정 규칙 (정확한 정의)

- **창 경계 포함**: `창 [-3, 3]` 이면 예정일−3일과 예정일+3일은 **창 안**입니다.
  `창밖일수`는 창 종료 다음날이 +1, 창 시작 전날이 −1 (부호 있는 정수).
- **미도래**: 창 종료일이 `--as-of` **이후이거나 같으면**(당일 방문이 아직 가능) 미도래
  — 이탈로 세지 않습니다. 창 종료일 < as-of 인 방문만 "창이 닫혔다"고 봅니다.
- **결측**: 필수 방문 + 창이 닫힘 + 기록 없음 + 탈락 아님. 넷 다 만족해야 결측입니다.
  탈락일이 **창 마감일까지(당일 포함)** 이면 결측이 아니라 **해당없음**입니다.
- **as-of 격리**: 탈락일·등록일이 `--as-of` 이후면 이번 기준시점에서는 각각
  '미탈락'·'미등록'으로 다룹니다(자백 표시). 같은 파일을 과거 기준일로 돌려도
  그 시점의 사실만으로 판정되도록 하기 위해서입니다. 탈락일이 등록일(등록일이
  없으면 기준방문일)보다 앞서면 모순 데이터로 보고 그 피험자를 판정불가로 강등합니다.
- **판정률(coverage rate)** = 판정완료 / (판정완료 + 판정불가). 미도래·해당없음은
  *정당한* 판정 제외이므로 **분모에 넣지 않습니다** — 넣으면 등록 초기의 젊은 시험이
  항상 exit 3 이 되기 때문입니다. 원시 건수는 사유별로 자백 블록에 전부 찍힙니다.
  분모가 0 이면(전부 미도래 등) 판정률은 계산 불가로 두고 임계 검사를 건너뜁니다.
  임계 기본 70%, `--min-coverage` 로 조정.
- **등록일 이전 검사는 기준방문 *이후* 방문에만** 겁니다. 기준방문일이 곧 0일을
  정의하므로, 기준방문과 등록일의 앞뒤는 프로토콜 위반이 아니라 기관의 기재 관행입니다
  (등록일을 무작위배정일로 적어 기저방문 다음 날이 되는 곳이 흔합니다).
- **판정불가로 보내는 것들** (추측 금지): 같은 방문 2행(어느 행이 맞는지 고르지 않음),
  날짜 파싱 실패, as-of 이후의 완료 기록, 등록일 이전의 기저 이후 방문, 기준방문
  날짜가 없거나 중복이거나 깨진 피험자 전체, 탈락일이 깨진 피험자 전체.
- **순서 위반**: 판정된 기록끼리 프로토콜 순서로 인접 비교, 뒤 방문 날짜가 앞 방문보다
  빠르면 1건. 같은 날은 위반 아님. 개별 방문의 창 이탈과는 **별도로** 셉니다(한 사건이
  두 결함일 수 있음).
- **심각도**: 창이탈이 PP 제외 기준(`창이탈일수초과`)을 넘으면 중대, 이하면 경미.
  프로토콜에 그 기준이 없으면 **미정**입니다(기준이 없는데 '경미'라고 적으면 86일
  지각도 가벼운 일로 읽히기 때문). 결측·순서위반은 중대.
- **PP 제외 규칙**: `필수방문결측`·`창이탈일수초과`(명시된 값 **초과**) 외에,
  `선정기준위반`·`탈락` 은 명시하지 않으면 **켜져** 있습니다(JSON 에서 `false` 로 끌 수
  있음). 한 사람이 여러 사유면 1명으로 셉니다("중복 N명 제거").
- **선정/제외기준 재점검**은 무작위배정된 피험자만 대상입니다. 항목 열이 없으면
  위반이 아니라 판정불가입니다.
- **방문일이 빈 칸**이면 '기록 없음'입니다(파싱 실패가 아닙니다). 아직 안 온 방문을
  미리 깔아 둔 트래커가 흔하기 때문입니다 — 창이 닫혔으면 결측, 아직이면 미도래로
  판정하고, 빈 칸이 몇 건이었는지는 자백에 남깁니다. `--wide` 의 빈 칸과 같은 뜻입니다.
- **프로토콜 방문은 시간 순서(오프셋 오름차순)로** 적어야 하고, **기준방문의 오프셋은
  0** 이어야 합니다. 둘 다 어기면 exit 2 로 멈춥니다 — 순서 위반 판정과 '마지막 방문'
  판정이 나열 순서를 그대로 쓰고, 기준방문일이 곧 0일이기 때문입니다.
- **날짜 형식** (연도-먼저만): `2026-03-02` / `2026/03/02` / `2026.3.2` /
  `2026년 3월 2일` / `20260302` / 엑셀 시리얼(20000~80000) / 위 형식+시각(시각은 버리고
  자백). `07-06-2026` 같은 일·월-먼저는 해석하지 않습니다.
  단, `--as-of` 만은 더 엄격하게 **YYYY-MM-DD 만** 받습니다(기준시점이 조용히
  엉뚱한 날이 되는 것을 막기 위해).
- **프로토콜 스키마는 엄격**합니다: 알 수 없는 키는 어느 레벨에서든 exit 2 이며,
  가장 비슷한 유효 키를 제안합니다(`창이탈일수초괴` → "혹시 '창이탈일수초과'?").
  오타가 규칙 하나를 조용히 끄는 일을 막기 위해서입니다.
- **⚠ 창 정의 주의**: 창은 항상 **예정일(기준일+오프셋) 기준**입니다. 예를 들어
  `"오프셋": -14, "창": [-28, -1]` 로 쓰면 창이 기준일−42일~−15일이 되어 예정일
  자체가 자기 창 밖이 되고, 제때 온 스크리닝이 전부 +14일 이탈로 찍힙니다.
  "기준일 −28~−1일 사이 스크리닝"을 원하면 번들 예제처럼
  `"오프셋": -14, "창": [-14, 13]` 으로 쓰세요.

## 한계 (솔직하게)

- **판정이지 확정이 아닙니다.** PP 후보·CONSORT 숫자·문장 초안은 전부 "이 규칙을
  기계적으로 적용하면 이렇다"이며, 최종 확정은 눈가림 해제 전 데이터 검토 회의의
  몫입니다. 리포트에도 그렇게 박혀 있습니다.
- **유효성·안전성 분석을 하지 않습니다.** 이상반응 코딩(MedDRA/CTCAE)도 하지 않습니다
  — 사전이 없고, 심각도 판정을 흉내내면 위험합니다.
- **파일 병합을 하지 않습니다.** ID 표기가 파일 간 다르면(`S01` vs `BELL-001-01`)
  joinaudit 으로 먼저 정리하세요. 이 툴은 ID 를 정규화하지 않고 그대로 비교합니다.
- **결측 대치·날짜 추정을 하지 않습니다.** 기준방문 날짜가 없으면 그 피험자는 통째로
  판정불가입니다. 등록일로 대신 추정하지 않습니다.
- **시각·타임존을 다루지 않습니다.** 날짜 단위로만 판정하고, 시각이 있으면 버렸다고
  자백합니다.
- **등록 외삽은 단순 선형입니다.** 최근 **최대 3개**(있는 만큼) 완결월 평균으로 나눈
  나눗셈이며 신뢰구간이 아닙니다. as-of 가 속한 달(부분 월)은 평균에서 빼고, 실제로
  몇 개월을 썼는지는 리포트에 적습니다. 완결된 달이 하나도 없으면 예측하지 않습니다.
- **상태 열 해석은 보수적입니다.** `예정/scheduled` 와 `취소/미실시` 만 특별 취급하고,
  모르는 상태값은 기록으로 간주합니다.
- **`완료` 판정의 기준은 마지막 프로토콜 방문 기록의 존재**입니다(창 안팎 무관).
  방문은 다 왔지만 마지막 방문 창이 아직 안 닫힌 피험자는 "진행중"입니다.
- **CSV 수식 인젝션 가드**: `= + - @` 로 시작하는 비숫자 셀 앞에 `'` 를 붙입니다.
  숫자는 그대로 두므로 `창밖일수 -2` 가 망가지지 않습니다.
- **번들 예제는 전부 손으로 설계한 합성 데이터**입니다. 실제 피험자 자료가 아닙니다.
