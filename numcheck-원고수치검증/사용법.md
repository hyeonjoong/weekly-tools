# numcheck 빠른 사용법

## 30초 안에 써 보기

폴더 안의 **`실행.command` 를 더블클릭**하세요. 예제 5종이 순서대로 돌면서
이 툴이 무엇을 잡는지 바로 보여 줍니다.

## 내 원고에 돌리기

한 번만 설치하면 어디서나 `numcheck` 명령을 쓸 수 있습니다.

```bash
cd ~/Downloads/02_프로젝트/깃헙/numcheck-원고수치검증
python3 -m pip install -e .
```

### 예 1) 그냥 보기

```bash
numcheck ~/Desktop/원고_revision2.docx
```

### 예 2) 결과를 파일로 남기기 (공동저자에게 보낼 때)

```bash
numcheck ~/Desktop/원고_revision2.docx --out-dir ~/Desktop/검토_20260813
```

`문제목록.csv`(지적 목록) · `재계산표.csv`(검사한 것 + 건너뛴 것 전부) ·
`요약.txt`(콘솔에 나온 그대로) 3개가 만들어집니다.

### 예 3) ISI·PSQI 평균까지 검사하기 (GRIM)

ISI 처럼 **정수 합 척도**는 평균이 아무 값이나 될 수 없습니다.
내장된 척도(ISI, PSQI, ESS, PHQ-9, GAD-7, HADS, BDI-II, MMSE …)는 자동으로 켜지고,
그 밖의 척도는 알려 주면 켜집니다.

```bash
numcheck 원고.docx --scale 단어인지도=0:100:50 --percent-of-count 단어인지도
```

## 결과 읽는 법

```
검사 후보 18개 · 재계산 14개 · 건너뜀 4개          ← ① 먼저 여기를 봅니다
  건너뜀 사유: 검정통계량 없음 1 · 분모 없음 1 …

■ 치명 6건                                          ← ② 반드시 고쳐야 하는 것
[L19   Abstract]  ...23/48 (45.2%)...
      → 23/48 = 47.92% 인데 45.2% 로 적혀 있습니다.

■ 경고 4건                                          ← ③ "확인해 보라"는 뜻
        ↓ 등급 강등: 단측검정 가능성(단측)           ← 왜 치명이 아닌지 항상 적힙니다

■ 정보 1건                                          ← ④ 지정하면 검사할 수 있는 것

종료코드 1 (치명 있음)
```

**① 커버리지를 먼저 봅니다.** "재계산 14개"가 원고 규모에 비해 터무니없이 적으면
파싱이 잘 안 된 것입니다. `numcheck 원고.docx --dump-text | less` 로 무엇을 읽었는지
직접 확인하세요. 재계산이 5개 미만(`--min-checked`)이면 아예 종료코드 3(입력 처리
불가)으로 멈춥니다 — **조용히 "이상 없음"을 내지 않습니다.**

> **건너뜀이 많은 것 자체는 정상입니다.** `80%`(검정력), `10%`(탈락률),
> `8.9%p`(백분율점), 척도를 안 알려 준 평균처럼 **애초에 재계산 대상이 아닌**
> 숫자가 원고에는 많습니다. 위험 신호는 건너뜀 비율이 아니라 *후보 수 자체가
> 한 자리인 경우*입니다. 원고를 잘라 읽었을 때(아주 긴 표 행 등)도 종료코드 3
> 으로 멈추고 그 사실을 메모에 적습니다.

**② 치명**은 반올림·버림·올림을 모두 허용해도 산술이 맞지 않는 것입니다.

**③ 경고**는 정당한 사유가 있을 수 있는 것입니다(단측검정, 다중비교 보정,
문맥에서 추정한 분모 등). 왜 강등했는지 항상 함께 적힙니다.

**④ 정보**는 "척도를 알려 주면 검사할 수 있다"는 안내입니다.

## 자주 쓰는 옵션

| 옵션 | 하는 일 |
|---|---|
| `--out-dir 폴더` | CSV 2종 + 요약 저장 |
| `--scale 이름=최소:최대:문항수` | GRIM 용 정수 척도 추가 |
| `--percent-of-count 이름` | 그 척도를 "고정 목록 대비 정답 %"로 취급 (`--scale` 과 함께) |
| `--scale-config scales.json` | 척도를 파일로 관리 |
| `--lang en` | 영문 리포트 |
| `--alpha 0.01` | 유의성 문구 검사 기준 변경 |
| `--tolerance 0.5` | 반올림만 허용(지적↑, 오탐도↑) |
| `--min-checked 10` | 재계산 가능 claim 이 이보다 적으면 종료코드 3 (기본 5) |
| `--no-grimmer` | SD 기반 GRIMMER 검사를 끔 |
| `--no-quote` | 리포트에 원고 문장을 넣지 않음 |
| `--force` | 출력 폴더에 남의 파일이 있어도 덮어씀 |
| `--dump-text` | 원고를 어떻게 읽었는지 줄번호·절과 함께 출력 |
| `--quiet` | 한 줄 요약만 |

## 알아 두면 좋은 것

- **원본 원고는 절대 수정되지 않습니다.** 읽기만 합니다.
- **네트워크를 쓰지 않습니다.** 원고가 밖으로 나가지 않습니다.
- **PDF 는 지원하지 않습니다.** `.docx` / `.md` / `.tex` / `.txt` 만.
- Word 의 **추적 변경으로 삭제된 문장**은 세지 않습니다(최종본 기준).
- 표는 **행 단위**로 셀까지 읽습니다. 다만 머리행의 N 이 어느 열에 걸리는지는
  추측하지 않습니다 — 셀 안에 `(N = 23)` 이 있을 때만 GRIM 이 돌아갑니다.
- 통계 방법이 옳은지는 판단하지 않습니다. **산술만** 봅니다.
- 각 숫자를 **자기 안에서만** 대조합니다. 초록의 `23/48 (47.9%)` 는 그 자체로 맞으므로,
  본문 최종 N 이 46 이어도 여기서는 통과합니다. 절 사이의 N 불일치는 `draftcheck` 담당입니다.
- GRIM 은 **N 이 작을 때만** 판별력이 있습니다(소수 2자리면 N ≲ 50). N 이 크면
  리포트에 `판별력 없음` 으로 찍히고 넘어갑니다.
- 출력 폴더에 같은 이름의 남의 파일이 있으면 **덮어쓰지 않고 멈춥니다**(`--force` 로 강제).
- 형식 점검(인용↔참고문헌, 그림/표 번호, 약어, 단어수)은 `draftcheck`,
  DOI 실재 확인은 `citecheck` 가 합니다. 셋이 원고 3종 세트입니다.

## 종료코드

| 코드 | 뜻 |
|---|---|
| 0 | 문제 없음 |
| 1 | 치명 있음 |
| 2 | 경고만 있음 |
| 3 | 입력 처리 불가 (파싱 실패 또는 재계산 가능 claim 부족) |
