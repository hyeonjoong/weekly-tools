### 치명 (조용히 틀린 값을 내던 것)

**1. χ² 가 큰 자유도에서 최대 48% 틀렸다.** `mathx.py` 의 반복 상한이 500 이었는데,
`_gser` 는 a 가 클수록 더 많은 항이 필요하다(a = 5×10⁵ → 약 5,400항). 초과해도
**조용히 break** 해서 틀린 값을 반환했다.

| 입력 | 옛 값 | scipy | 상대오차 |
|---|---|---|---|
| `chi2_sf(1e6, 1e6)` | 0.7393 | 0.4998 | **0.48** |
| `chi2_sf(1e5, 1e5)` | 0.5121 | 0.4994 | 0.025 |

저장소 기준(≤1e-9)은 df ≈ 13,500 부터 깨졌고, `_DF = \d{1,6}` 이 df 999999 까지
받으므로 원고에서 도달 가능했다. 개발용 검증 격자가 df ≤ 5000 에서 멈춘 탓에
못 잡았다.

→ **조치.** 반복 상한을 200,000 으로 올리고, **수렴하지 못하면 예외를 던진다**
(틀린 값을 '재계산값'으로 싣느니 그 claim 을 건너뛴다). 자유도 상한 `MAX_DF = 10⁶`
를 두어 정확도를 보장할 수 없는 값은 계산하지 않는다. 개발 격자를 df 10⁶ 까지
넓혔고, README 의 정확도 수치를 실측값으로 갱신했다
(t 8.7e-10 · F 1.6e-10 · χ² 2.6e-10 · z 1.3e-13 · r 3.3e-13).
회귀 테스트: `tests/test_dists.py::test_large_df_stays_within_the_repository_tolerance`.
**→ 라운드 2 에서 보정됨(R2-11): 이 상한도 여전히 관대해 df ≈ 7×10⁵ 에서 기준을
넘었다. `MAX_DF = 50,000` 으로 다시 낮추고 검증 격자에 무작위 4,000점을 넣었다.**

**2. 변화량 검사가 "군간 차이"를 사후−사전으로 읽었다.** 산술이 완벽한 문장에서
치명이 쏟아지는 경로였다 — 이 툴의 1번 사망 원인.
`능동자극군의 ISI 평균은 18.4에서 11.2로 감소하였다 (군간 차이 -2.1, p = 0.031).`
→ 치명. `대조군과의 차이 3.6%p`, `최소 임상적 중요 차이 3.0`, `상대위험 감소 46.6%`,
`목표 대비 차이 2 mmHg`, `a difference of 2.1 versus sham` 모두 같은 모양으로 터졌다.

→ **조치.** 변화량 후보 주변 26자에 `군간·대조군과·versus·상대위험·최소 임상적·
목표 대비·compared with` 등이 있으면 버린다. 그러고도 후보가 둘 이상이면
**어느 쪽인지 모르므로 검사하지 않는다.** 회귀 테스트 6종.
**→ 라운드 2 에서 보정됨(R2-1, R2-2): 이 수정이 과잉이라 새 오탐과 미탐을 만들었다.**

**3. CI–p 정합이 CI 를 양방향으로 넓혀 판정해, 있지도 않은 모순을 보고했다.**
`0.5 (95% CI 0.1 to 0.9), p = 0.02` 에 대해 "구간이 0 을 포함하는데 유의하다"고
말했다 — 원고에 대한 **거짓 진술**이다. 반대로 `HR 0.7 (95% CI 0.5 to 0.9), p = 0.30`
같은 진짜 모순은 놓쳤다. 합성 3,000건에서 오탐 40 · 미탐 40 (각 1.3%).

→ **조치.** "확실히 포함"(넓힌 하한의 위끝 ≤ 귀무값 ≤ 넓힌 상한의 아래끝)과
"확실히 불포함"(귀무값이 넓힌 구간 밖)을 나누고, **그 사이의 경계 구간은 판정을
보류**하고 건너뜀 사유를 적는다. 오탐이 미탐보다 비싸다는 이 툴의 원칙에 맞춘 선택.

**4. `.tex` 원고의 백분율이 통째로 보이지 않았다.** LaTeX 에서 백분율은 `\%` 로
쓰는데 정규식이 `%` 만 봤다. 못 본 것이 **"건너뜀"에도 안 잡혀** 커버리지 자백이
거짓말이 됐다.
→ **조치.** 주석 제거 뒤 `\%` `\pm` `\times` `\leq` 등을 푼다.

**5. 20,000자를 넘는 줄을 조용히 잘랐다.** 잘린 뒤에 있던 진짜 치명 2건이 사라지고
`종료코드 0 (이상 없음)` 이 나왔다. 넓은 `.docx` 표 행(셀을 `|` 로 잇는다)에서 실제로
도달 가능하다.
→ **조치.** 잘랐으면 리포트 메모에 "그 뒤의 숫자는 검사되지 않았습니다"라고 적는다.
`.docx` 표 행의 조기 자르기도 제거해 한 곳에서만 자르고 기록한다.

**6. GRIM 이 다른 문장의 N 을 끌어다 썼다.** `ISI 평균은 14.25 였다. 이 연구에는
총 46명이 참여하였다.` → 하위군 평균에 전체 N 을 붙여 헛된 GRIM 위반. `.docx`
문단은 여러 문장을 담으므로 흔한 모양이다.
→ **조치.** 줄 전체에서 N 을 끌어오는 것은 **그 줄에 문장이 하나뿐일 때만** 허용.

### 높음 (성능·안전)

**7. 문장 분할이 O(N²)~O(N³) 였다.** 축약어 판정이 `text[:i]` **전체**를 정규식에
넘겼다. 16,000자 한 줄에 **50.8초**, `.docx` 한 개로 수십 시간까지 갈 수 있었다.
→ **조치.** 직전 8자만 본다 + 줄 단위 `lru_cache`. 같은 입력 50.8초 → **0.001초**.
시간 상한 테스트 추가.

**8. `.docx` 노드 폭탄.** 압축 해제 '크기'만 재서, 60 KB 파일로 `ElementTree` 에
800 MB~1.2 GB 를 쓰게 할 수 있었다.
→ **조치.** 파싱 **전에** XML 노드 수 상한(10⁶)을 검사한다.
**→ 라운드 2 에서 보정됨(R2-13): 속성으로 우회된다. 파트 크기 상한 + 속성 합산.**

**9. DTD 폭탄 가드가 인코딩으로 우회됐다.** `b"<!DOCTYPE" in data` 는 바이트 검사라,
`word/document.xml` 을 UTF-16 으로 넣으면 통과했다.
→ **조치.** `.docx` 파트의 UTF-16 BOM 자체를 거부한다(정상 .docx 는 UTF-8).
**→ 라운드 2 에서 보정됨(R2-12): BOM 만 막으면 뚫린다. NUL 바이트로 판정한다.**

**10. 남의 파일을 조용히 덮어썼다.** `--out-dir .` 로 원고 폴더를 주면 거기 있던
`요약.txt` 가 경고 없이 사라졌다. 출력 대상이 심볼릭 링크면 **`--out-dir` 바깥**을
썼다(감사자가 실수로 `$HOME` 을 오염시켰다).
→ **조치.** 쓰기 전에 세 대상 파일을 검사한다. 이전 numcheck 산출물이면 덮어쓰고,
아니면 멈춘다(`--force` 로 강제). 심볼릭 링크면 거부한다.
**→ 라운드 2 에서 보정됨(R2-14): 접두사 매칭이라 draftcheck 결과를 지웠다. 첫 줄
전체 일치로 바꿨다.**

**11. CSV 수식 인젝션이 앞 공백으로 우회됐다.** `csv_safe` 가 `text[:1]` 만 봤고,
게다가 `\r → 공백` 치환을 먼저 해서 **스스로 우회로를 만들었다.** Excel/Sheets 는
앞 공백을 버리므로 `" =1+1"` 이 살아 있는 수식이 된다. 원고 **파일명**을 통해
오늘 당장 도달 가능했다.
→ **조치.** 공백·제어문자·BOM·제로폭 공백을 벗겨 낸 뒤 첫 글자를 본다. 7종 회귀 테스트.
**→ 라운드 2 에서 보정됨(R2-15): 손으로 고른 목록이라 U+2000 등이 빠져 있었다.
유니코드 카테고리로 판정한다.**

**12. 척도 설정이 O(n²) 이고, 별칭 정규식에 ReDoS 가 있었다.** 1,000개 척도 로딩에
57.8초(사실상 멈춤), 공백 12개짜리 별칭에 36초(2^N 백트래킹).
→ **조치.** `add_many()` 로 패턴을 한 번만 재생성(58초 → **0.12초**), 별칭의 공백
연속을 하나로 접는다. 시간 상한 테스트 추가.
**→ 라운드 2 에서 보정됨(R2-17): `add()` 는 여전히 O(n²) 였다. 증분 갱신으로 교체.**

**13. 인자 오류의 종료코드가 2 였다.** 2 는 이 툴에서 "경고만 있음"이다 — CI 가
**실행되지도 않은 run 을 통과로 읽는다.**
→ **조치.** 인자 오류·저장 거부는 3.

### 중간

**14. 정수만으로 적힌 값에 ±1 ulp 는 지나치게 관대했다.** `2 (95% CI 4 to 9)` 가
통과하고, `from 20 to 12, a reduction of 5` 도 통과했다.
→ **조치.** 비교에 관련된 값이 **전부** 정수 표기이면 허용 폭을 절반(통상 반올림)으로
좁힌다. 비율 재계산은 기존대로(`48%` 로 47.9% 를 적는 일이 실제로 흔하다).
**→ 라운드 2 에서 보정됨(R2-5): 3항 비교인 변화량에서는 이 축소가 오탐 5.3% 를
만들어, 변화량 검사에서는 쓰지 않는다.**

**15. `" or "` 가 비(ratio) 지표로 인식됐다.** "measured by the ISI or the PSQI" 같은
평범한 접속사가 귀무값을 1 로 바꿔 헛된 경고를 냈다.
→ **조치.** 약어는 대문자 + 등호/숫자 인접일 때만 인정하는 정규식으로 교체.

**16. 완곡한 유의성 표현이 치명으로 찍혔다.** "marginally/borderline significant
(p = .058)" 는 관례적 표기지 오류가 아니다. 한 문장에서 두 결과를 대비하면
(while/whereas/반면) 하나뿐인 p 가 어느 쪽 것인지 알 수 없다.
→ **조치.** 완곡 표현·대조 접속사가 있으면 검사하지 않는다.
**→ 라운드 2 에서 보정됨(R2-3, R2-4): 목록이 넓어 한국어 결과문의 절반이 검사에서
빠졌다. 진짜 대비 접속사만 남기고, 완곡 예외는 경계 근처에서만 적용한다.**

**17. 문맥 분모를 앞 문장에서 끌어왔다.** "총 120명이 선별되었다. 이 중 15명
(65.2%)…" 에서 선별 N 을 반응률 분모로 삼았다.
→ **조치.** 분모는 **같은 문장 안**에서만 찾는다.

**18. `2025/03 (12.5%)` 를 분수로 읽었다.** → 날짜 형태(연도/월)는 손대지 않는다.

**19. `(SD 3.4, N = 23)` 형태가 후보로도 안 잡혔다.** SD 뒤에 곧바로 `)` 를
요구했기 때문. 커버리지 자백에 "건너뜀"으로도 안 나오는, 가장 나쁜 종류의 누락.
→ **조치.** 정규식을 넓혀 인식한다(이제 이 형태에서 GRIM 이 정상 동작).

**20. utf-16 이 인코딩 폴백 목록에 있었다.** 짝수 길이의 거의 모든 단일바이트
파일이 utf-16 으로 "성공"해서, 파일 크기의 **홀짝에 따라** 읽기 결과가 달라지고
인코딩 메모가 거짓말을 했다.
→ **조치.** utf-16 은 BOM 이 있을 때만.

**21. 같은 오류가 본문과 표에 있으면 두 번 세었다.** 실제 원고에서는 핵심 숫자가
본문·초록·표에 모두 나오므로 치명 건수가 두세 배로 부풀었다.
→ **조치.** 동일한 (등급, 항목, 보고값, 재계산값, 문구) 는 한 건으로 합치고
다른 위치를 "같은 내용이 L16 에도 있습니다"로 덧붙인다.
**→ 라운드 2 에서 보정됨(R2-6): 같은 줄의 서로 다른 지적까지 합쳤다. 줄이 다를 때만.**

**22. `--lang en` 이 반쪽이었다.** `--quiet` 한 줄, 강등 사유, p 재계산의 결정적
마지막 문장("단측으로 계산하면 맞습니다")이 전부 한국어였다.
→ **조치.** 셋 다 영문화.

**23. 배수 표기가 폭주했다.** `보고값과 1165097444403439170975372809338880.0배 차이`.
→ **조치.** 1000배 이상은 "1000배 이상", 보고 p 가 0 이면 "비교 불가".

**24. `--out-dir ''` 가 조용히 무시됐고, NUL 이 든 경로는 traceback 을 냈다.**
→ **조치.** 둘 다 종료코드 3 + 사람이 읽을 메시지.

**25. `_FUZZ` 가 절대값이었다.** p = 1.2×10⁻¹⁰ 처럼 ulp 가 1e-18 인 값에서 여유가
ulp 의 100만 배가 됐다. → 상대 여유로 교체.

**26. `1,23` 을 123 으로 읽었다.** 원고의 오탈자가 정상 숫자로 둔갑했다.
→ 천단위 쉼표는 자리가 맞을 때만 뗀다.

### 문서 정직성

**27. README 의 도입 시나리오가 이 툴이 잡을 수 없는 오류였다.** "초록의

**R2-1. 변화량 차단 목록이 '남은 하나'를 통과시켰다.** 걸러 낸 후보를 그냥 건너뛰고

difference of 0.4.` → 진짜 변화량 -7.2 는 `versus` 로 차단되고 무관한 0.4 가 유일
후보가 되어 **치명**. 라운드 1 이 없애려던 바로 그 실패 유형이 형태만 바꿔 돌아왔다.
→ **조치.** 차단된 후보가 하나라도 있으면 그 문장은 애매한 것이므로 **검사하지 않고
건너뜀으로 기록한다.**

**R2-2. 차단 목록이 지나치게 넓고, 창이 절 경계를 넘었다.** `보다`·`표준편차`·`이내`
같은 평범한 한국어 토큰이 들어 있었고, ±26자 고정 창이 이웃 절을 삼켰다. 진짜
변화량 오류 24개 표현 중 **5개(21%)가 미탐**됐다 — `(변화 -6.2, 표준편차 4.1)` 같은
표준 보고 형태 포함.
→ **조치.** 평범한 토큰을 제거하고, 임상 문턱값 표현(`minimal important difference`,
`smallest detectable change`, `최소검출가능`, `반응 기준`, `margin`, `비열등` …)을
추가했다. 창은 **절 단위**(쉼표·괄호·`and`·`및` 로 자름)로 바꿨다.

**R2-3. 대조 접속사 목록이 한국어 결과문의 절반을 검사에서 뺐다.** `에 비해`·`그러나`·
`한편` 은 대비가 아니라 담화 표지다. `능동자극군은 위약군에 비해 유의하게 감소하였다

유의성 문구 오류 20개 표현 중 7개 미탐.
→ **조치.** 진짜 대비 접속사(`while`, `whereas`, `although`, `, but `, `반면에`)만 남겼다.

**R2-4. 완곡 표현 예외가 무조건이었다.** `marginally significant (p = 0.51)` 은 완곡이
아니라 오류인데 통째로 넘어갔다.

  그 대가로 오탐이 0 이다. 이 툴의 우선순위가 그렇다.
- **문맥 분모는 같은 문장 안에서만.** 앞 문장의 선별 N 을 반응률 분모로 삼는
  오탐(라운드 1 #17)이 더 비싸다. 놓친 것은 "분모 없음"으로 기록된다.
- **`.docx` 문단에 문장이 여럿이면 GRIM 은 그 문장 안의 N 만 쓴다.** 문장 밖 N 을
  끌어오면 하위군 평균에 전체 N 을 붙이는 오탐이 난다(라운드 1 #6).
- **TOCTOU.** `check_targets` 와 실제 쓰기 사이에 심볼릭 링크를 심으면 따라간다.
  단일 사용자 데스크톱 도구의 위협 모델에서 감수한다.

### 치명 — 스스로 금지한 일을 하고 있던 것

**#R3-1 잘라 낸 원고에 "이상 없음" 도장.** 20,000자를 넘는 문단·표 행은 뒷부분을

**#R3-2 산술적으로 불가능한 통계량을 조용히 버림.** `r(38) = 1.5`, `t(0) = 2.3`,

없음"** 으로 기록되는데 — 같은 줄에 통계량이 버젓이 인쇄돼 있다. 감사용 CSV 가 원고에
대해 거짓을 말한 것이다. 산술 오류를 잡는 툴이 산술적으로 불가능한 값을 못 본 척한 셈.
→ `Statistic.invalid` 사유를 싣고 **치명(항목: 검정통계량)** 으로 지적한다. 음수 χ²/F 는
정규식이 부호를 안 받아 인식조차 못 했으므로 `[-+]?` 를 열었다.

### 높음 — 크래시·행·성능

- **#R3-4 zip 폭탄 우회.** `zf.read()` 는 zip 중앙 디렉터리에 **적힌** 크기를 믿는다.
  148바이트라고 선언한 1MB `.docx` 가 실제로 1GB 로 풀려도 상한 검사를 전부 통과했다
  (RSS 2.03GB 측정, 오류·경고 없음). 파일 크기 상한 120MB × deflate 1032:1 ≈ 124GB.
  → 선언값이 아니라 **실제로 읽는 바이트**에 상한을 건다(`zf.open(...).read(N+1)`).
- **#R3-5 정규식 역추적 폭발.** `_INT = \d{1,3}(?:,\d{3})+|\d{1,7}` 의 무한 반복이
  자리 구분 숫자 열에서 터졌다. 20KB 한 줄 = 16초, 400KB 파일 = 6분 33초.
  → 반복을 `{1,4}` 로 묶었다(자리 구분 5개를 넘는 표본수는 없다).
- **#R3-6 분모 탐색이 세제곱.** `_context_denominators` 가 후보마다 `blocked` 목록을
  선형으로 훑어 한 문장의 `24명 (27.0%)` 토큰 수 M 에 대해 M³. 17KB 한 줄에 **53초**.
  → 정렬 + 이분 탐색 + 끝점 누적 최대. 같은 입력이 **2.1초**.
- **#R3-7 `1e400` 이 트레이스백.** `parse_number` 의 지수가 무제한이라 OverflowError 가
  그대로 올라갔고 종료코드가 **1**(= 치명 있음)이 되어, CI 가 크래시를 "지적 있음"으로
  읽었다. → 지수 범위를 막고 `OverflowError` 를 잡는다.
- **#R3-8 `--scale-config` 트레이스백 4종.** `unit`/`aliases` 처리가 try 밖에 있어
  `"unit": null`, `"items": 0`, `"aliases": 5` 가 전부 날 트레이스백. `"max": "inf"` 는
  조용히 통과해 척도 범위 검사를 무력화했고, `"aliases": [1,2,3]` 은 숫자 하나만 있으면
  매칭되는 정규식을 만들었다. → 전부 `ScaleError` 로 묶고, 유한성·별칭에 글자 요구를 추가.
- **#R3-9 FIFO·문자장치에서 무한 대기.** `st_size` 가 0 이라 크기 상한을 통과한 뒤
  `read()` 에서 멈춘다. `numcheck <(pandoc ...)` 로 평범하게 도달한다.
  → `is_file()` 이 아니면 거부하고, 읽기에도 상한을 건다.

- **#R3-10 보정·대체된 평균에 GRIM.** 가드가 **전혀 없었다.** `다중대입 후 PSQI 평균
  7.28 (N = 31)`, `MMRM 으로 추정한 ISI 평균`, `조정평균`, `기하평균`, `LOCF` 전부 치명이
  났다. 다중대입 후 개인값은 정수가 아니므로 GRIM 의 전제 자체가 없다. **SERENE 의 1차
  지표(ISI)가 정확히 이 형태로 보고된다** — 여기서 오탐이 한 번 나면 이 툴은 두 번 다시
  안 열린다. → 단서 목록을 만들어 **같은 문단**에 있으면 건너뛰고 `원자료 평균 아님` 으로
  기록한다. 문단 범위로 넓힌 것은 의도적이다(진짜 위반 일부를 놓치는 대가로 오탐 0).
- **#R3-11 문항 평균을 총점 평균으로 단정.** `PSS 평균 2.37 ± 0.50 (N = 23)` 에 치명.
  PSS 는 10문항 0–4점이므로 문항평균 2.37 은 총점 545/230 = 2.3696 으로 **가능하다.**
  0 에서 시작하는 척도(ISI·PHQ-9·MMSE…)는 문항평균 범위를 통째로 포함해 범위 가드가
  안 걸린다. → 두 해석 중 하나라도 가능하면 지적하지 않는다.
- **#R3-12 `M` 에 단어 경계가 없음.** `ISI SEM 1.37`, `총점의 sum 2.37` 의 m 이 평균으로
  읽혀 치명이 났다. t/F/χ²/r/z 패턴엔 다 있는 경계가 여기만 빠졌다. → `\bM\b`.
- **#R3-13 절대량 CI 에 귀무값 0.** `ISI 평균은 8.20점 (95% CI 7.10 to 9.30) 으로
  감소하였고 … p = 0.42` 에서 **CI 뒤에 나오는** "감소" 가 걸려 차이의 CI 로 오인,
  헛된 경고. 이 모듈 docstring 이 하지 않겠다고 명시한 바로 그 행동이다.
  → 단서를 CI **앞쪽**에서만 찾고, 바로 앞 어절이 평균/중앙값이면 판정을 접는다.
- **#R3-14 F 의 p 구간 과소산정.** `F(2.1, 5.3) = 1.41, p = .320` 에 경고. 진짜 가능
  구간은 0.3195–0.3304 라 `.320` 은 맞는 값이다. F 의 p 는 df1 에 증가·df2 에 감소하므로
  극값이 **대각** 코너에 있는데 (low,low)/(high,high) 두 점만 봤다(무작위 400건 중 77건에서
  과소산정 확인). → `itertools.product` 로 네 코너 전부.
- **#R3-15 `r = 1` 이 어떤 p 와도 "일치".** 정수 표기에 ±1 ulp 를 그대로 줘 |r| 구간이
  [0, 1] 이 되고 p 구간이 [0, 1] 이 됐다. `r(38) = 1, p = 0.99` 를 재계산값 6.7e-110 과
  함께 **"일치"** 로 인쇄했다. → r 에 `effective_k` 를 적용하고 [0,1] 로 먼저 자른다.
  덧붙여 p 구간이 0.98 을 넘게 벌어지면 "일치"라 말하지 않고 `판별력 없음` 으로 건너뛴다.

  없는데 "분모 없음"으로 세어, 깨끗한 원고에서 건너뜀이 잔뜩 쌓이고 사용자가 파싱

### 메시지가 실제 계산과 달랐던 것

- **#R3-22 percent-of-count GRIM 의 등식이 거짓.** `71.0 × 7 = 248.5` 라고 인쇄했다.
  71.0 × 7 은 497 이다(248.5 는 497/2). `(정수)/7` 도 틀렸다 — 증분이 2 이므로
  `(정수)×2/7` 이다. 영문은 무조건 "integer sum score" 라고 했다. 판정 자체는 옳았지만,
  **손으로 검산하는 사용자가 툴을 불신하게 되는** 종류의 오류다. → 척도 종류별로 분기.
- **#R3-23 F·χ² 의 상측 확률을 "양측 p" 로 표기.** 값은 정확했고(scipy 대조 일치) 라벨만
  t/z 용을 그대로 썼다. → `_tail_label()`.
- **#R3-24 `p > .001` 에 "유의성 판정이 뒤집힙니다".** 보고값도 재계산값(1.2e-10)도
  α=.05 에서 유의하므로 뒤집히는 것이 없다. `_decision` 이 `>` 를 "유의하지 않다는
  주장"으로 읽은 탓. → 주장하지 않는 경우 `None` 을 돌려 flips 판단에서 뺀다.
- **#R3-25 p 구간 표시가 4자리 고정.** 작은 p 에서 `0.0004–0.0004` 처럼 무의미했다.

### 문서

- README 첫 문장의 **"숫자를 전부 다시 계산해"** 를 고쳤다. 현실적인 원고 3편에서 측정한
  재계산 비율은 10/32, 11/27, 16/26 이었고 그 분모조차 *인식된 후보*다. → "알아볼 수 있는
  것을 전부" + 실제 비율 명시.
- **p 허용폭이 문서에 없었다.** `t(45) = 2.31`(참값 .0255)에서 `.026`·`.024`·`.03`·`.02`
  가 모두 통과한다 — 소수 2자리 p 는 사실상 ±.01 까지만 검사된다. 의도된 설계지만 적어
  두지 않으면 사용자가 민감도를 과대평가한다. → 한계 절에 명시 + `--tolerance 0.5` 안내.
- **draftcheck 와의 경계**에서 겹치는 두 항목(초록↔본문 N 일관성, 통계 보고 형식)만
  빼고 나열하고 있었다. → 겹친다는 사실을 그대로 적고, 무엇이 다른지(존재·일치 vs 산술)를
  밝혔다.
- 보정·대체 평균 제외, 잘림 시 종료코드 3, 불가능한 통계량 항목을 한계·검사표에 추가.

### 검토자가 "문제 없음"으로 확인한 것 (라운드 3)

- **수치 커널.** scipy + mpmath 로 t/F/χ²/r/z 각 2~3만 점 무작위 격자 + 극단값
  (df=1·2·49999, t=1e-8~1e15, χ²=0~1e8, r→1, z=37). 꼬리 영역 최대 상대오차 **4e-10**.
  폐형식 대조(df=1 Cauchy, df=2 t, df=2 χ² 지수, F(1,d)≡t², Φ 분위수) 전부 통과.
  **수렴 미달·분기 오류 없음.**
- **GRIM/GRIMMER 산술.** n=2..199 × 소수 1~3자리 × round/trunc/ceil 전수 → 오탐 0.
  GRIMMER 는 완전열거(n=4..7) + 무작위 40만 조합(표본/모집단 SD 양쪽) → 오탐 0.
- **네트워크 0.** 패키지 전체에 `socket/urllib/requests/http/subprocess/eval/exec/pickle/
  ctypes` 없음. **`os` 모듈조차 없다.** 20개 모듈을 막는 import 훅 + socket 몽키패치
  아래에서 출력이 바이트 단위로 동일.
- **쓰기 지점 3곳뿐**, 전부 `out_dir` 상대. `open()` 은 **한 곳, 모드 `"rb"`**.
  원고 sha256 은 실행 전후 동일하고 `chmod 444` 로도 정상 동작.
- **CSV 인젝션 양방향.** `=cmd|'/c calc'!A1`, `+1+1`, `-2+3`, `@SUM(A1)`, 한국어 `=…`,
  탭 접두 전부 `'` 로 중화. **그리고 `-7.2` 같은 정상 숫자는 따옴표가 안 붙는다** —
  과잉 이스케이프로 표를 못 쓰게 만드는 반대 방향 결함도 없다.
- **PII.** 주민번호를 심은 원고로 8개 오류 경로를 강제 → 원고 본문 유출 0. XML 오류는
  줄·열 번호만. `--no-quote` 는 콘솔·CSV 2종·요약.txt 전부에서 발췌를 제거한다.
- **.docx 공격.** zip 아님, document.xml 없음, billion-laughs, XXE(`file:///etc/passwd`),
  400단계 중첩, 6,000멤버, 31MB XML, 손상 XML — 전부 종료코드 3 + 사람이 읽을 메시지.
  2,500회 XML 퍼즈 + 35,000회 구조화 텍스트 퍼즈에서 #R3-7 외 크래시 0.
- **인코딩.** UTF-8/BOM, UTF-16 LE/BE, CP949, EUC-KR, Latin-1, 중간에 깨진 UTF-8,
  NUL, CRLF/CR/LF 혼용 — 전부 읽거나 **정직하게 실패**. BOM 없는 UTF-16 은 후보 0개 →
  종료코드 3 + "'이상 없음'으로 읽지 마세요" 배너.
- **테스트 품질.** `assert True` / `is not None` / `len(x) >= 0` 형태 **0건**. 구현을
  기대값으로 쓰는 자기참조 테스트 없음. `test_dists.py` 는 scipy 를 import 하지 않고
  27개 기준 상수를 `rel=1e-9` 로 고정하며, `F(1,k) == t(k)²`·단측=양측/2·df→∞ 시 t→z
  수렴을 독립적으로 교차검증한다. `PYTHONHASHSEED` 를 바꿔도 결과 동일.

### 남겨 둔 것 (라운드 3, 의도적)

- **`--out-dir` 자체의 경로 탐색은 막지 않는다.** `--out-dir ../../tmp/x` 는 사용자가
  명시적으로 준 인자이므로 그대로 쓴다. 다만 out-dir **안의 세 파일**이 심볼릭 링크면
  거부한다(그건 사용자가 지정한 곳 바깥을 쓰는 길이므로).
- **큰 파일의 메모리 증폭 ~18배.** 42MB `.md` → RSS 770MB. `MAX_LINES` 가 상한을
  주므로 무한히 자라지는 않는다. 데스크톱 단일 사용자 도구의 위협 모델에서 감수한다.
- **한 줄에 같은 지적이 100건이면 100건으로 센다.** 중복 병합은 줄 번호가 다를 때만 한다
  (라운드 2 의 규칙). 표시는 25건에서 끊지만 집계와 CSV 는 전부 남긴다.
- **`Of 112 participants, 56 received A and 55 received B` 형태의 N 합계는 놓친다.**
  쉼표 목록을 하위군 분해로 받으면 평범한 열거가 전부 걸린다. 괄호형·콜론형만 받는다.
