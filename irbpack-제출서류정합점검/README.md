# irbpack — 제출서류 정합점검

IRB·식약처에 **한 봉투로 같이 내는 서류들**(연구계획서 · 동의서(ICF) · 승낙서(Assent) · 증례기록서(CRF) · 모집공고)을 폴더째 읽어, **서류들끼리 말이 다른 곳**만 찍어 줍니다. 문서 하나의 품질은 보지 않습니다 — **문서 사이**만 봅니다.

`revcheck` 는 *같은 문서의 다른 버전*을, `irbpack` 은 *다른 문서의 같은 항목*을 봅니다.

---

## 목적 / Why this exists

**한국어.** 목요일 밤, 연구계획서를 v1.2 로 고쳤습니다. 방문을 2회에서 3회로 늘렸고, 소요시간이 바뀌었고, 보상 문구를 손봤습니다. 이제 동의서 3종(성인용·보호자용·Assent), CRF, 모집공고를 열어 같은 값을 전부 따라 고쳐야 합니다. 6개 문서 × 12개 값 = 72칸. 워드 창 6개를 띄워놓고 눈으로 왕복합니다. 한 칸을 놓칩니다. 3주 뒤 IRB 보완요청서가 옵니다: *"연구계획서에는 2회 방문으로 되어 있으나 보호자용 설명문에는 '1회 또는 다회기'로 기재되어 있습니다. 정정하여 재제출 바랍니다."* 재제출·재심의로 2~4주가 날아갑니다. `irbpack` 은 그 72칸을 표로 펴서 전수 출력하고, 어긋난 칸에 **근거 문단 번호**를 붙입니다. 어느 쪽이 맞는지는 말하지 않습니다 — 다르다는 사실만 말합니다.

**English.** Before an IRB / MFDS submission, this tool reads the whole packet — protocol, informed-consent forms, assent, CRF, recruitment ad (`.docx`, `.md`, `.txt`, text-layer `.pdf`) — and compares twelve fixed items *across* documents: title, version/date, PI, contact, sample size, age range, visit count, session duration, compensation, data-retention period, inclusion/exclusion criteria, assessment list. It reports only inter-document disagreements with paragraph-level evidence, confesses what it could not compare, masks phone numbers in the report, never edits a document, never judges regulatory compliance, and never predicts the review outcome. Standard library only, fully offline.

### 이 가설은 이미 검증됐습니다 (코드 0줄 상태에서)

기획 단계에서 **이미 IRB 승인이 난** 실제 패킷 6종에 12개 항목 정규식을 30분 돌렸습니다. 승인 패킷에서도 이만큼 남았습니다:

| 항목 | 연구계획서 | ICF 성인용 | ICF 보호자용 | Assent | CRF | 모집광고 |
|---|---|---|---|---|---|---|
| **방문 횟수** | `2회 방문` | `2회 방문` | **`1회 또는 다회기 방문`** | — | **Visit 1~6 폼 존재** | `방문 1` |
| **소요시간** | — | `90분` / `120분` | **`60분` / `180분`** | `30분` / `1시간` | — | — |
| **보상** | `교통비 실비 지급` | **`시간당 10,000원(사례비 포함)`** | 동일 | — | — | — |
| **연락처** | — | 사무실 번호 | 동일 | — | — | **개인 휴대전화** |
| 표본수 | 90/30/20명 | 동일 | 동일 | — | — | 30/20명 (총 90명 없음) |
| 연령 · 보관기간 · 제목 · 버전 | 전부 일치 | | | | | |

같은 연구의 성인용과 보호자용 동의서가 **서로 다른 시간을 고지**하고 있었습니다. 동시에 연령·표본수·보관기간·제목·버전은 완전히 일치했습니다 — 이 툴은 "전부 불일치"를 뱉는 종류가 아닙니다. 이 실측(익명화한 문장만)이 `tests/test_kobio.py` 회귀 테스트로 박혀 있습니다: **치명 3 · 경고 2 · 일치 4** 가 정답이고, 규칙을 넓히다 이 숫자가 늘어나면 테스트가 깨집니다.

## 다른 방법 대비 무엇이 다른가

| 대안 | 왜 이 툴이 이기는가 |
|---|---|
| **눈으로 대조** (현실의 기본값) | 72칸을 개정 때마다 반복. 사람은 "값이 다른 것"보다 **"한쪽에만 있는 것"** 을 훨씬 못 봅니다. 이 툴은 전수 출력 + 근거 문단으로 사람이 1초에 검증합니다. |
| **Word 문서 비교** | *같은 문서의 두 버전* 용입니다. 계획서와 동의서를 비교하면 문서 전체가 빨간 줄이 됩니다. 이 툴은 다른 문서에서 **같은 항목만** 뽑아 값끼리 맞춥니다. |
| **python-docx + 직접 스크립트** | 텍스트는 나옵니다. "이 서류들에서 뭘 대조해야 하는가"(항목 12종·정규화·심각도)가 도메인 지식이고, 그게 이 툴의 실체입니다. 파싱은 부수적입니다. |
| **CTMS / eTMF** | 문서 버전·승인 상태를 관리합니다. *내용이 서로 맞는지*는 보지 않습니다. |
| **LLM 에 6개 문서 붙여넣기** | 잘 찾습니다. 그런데 재현되지 않고, 근거 문단을 지어내며, **못 본 항목을 못 봤다고 말하지 않습니다.** 이 툴은 결정론적 규칙 + `[커버리지 자백]` 필수입니다. |

### 저장소 안 인접 툴과의 경계

| 툴 | 무엇을 보나 | irbpack 과의 차이 |
|---|---|---|
| `revcheck` | 원고 제출본·개정본·응답서 | 같은 문서의 **다른 버전**. irbpack 은 같은 시점의 **다른 문서** (`--baseline` 은 부수적) |
| `draftcheck` `numcheck` | 원고 1개의 자기 정합성 | irbpack 은 원고를 읽지 않습니다 — 원고를 감지하면 exit 2 |
| `visitaudit` | 실제 방문 날짜 vs 프로토콜 JSON | irbpack 은 그 JSON 을 손으로 쓰기 **전 단계**, 문서 자체를 봅니다 |
| `deidaudit` | 데이터 파일의 개인정보 | irbpack 은 모집공고의 **직접 연락처 한 가지만** 경고합니다 |
| `powerplan` | 설계 → 표본수 | irbpack 은 적힌 표본수가 **서로 같은지만** 봅니다 (재계산 금지, AST 테스트로 강제) |

**경계를 코드로 강제합니다 (tests/test_guards.py).**

1. **원고 감지 시 exit 2.** `Abstract`/`Discussion`/`References` 구조나 `.tex` 가 보이면 아무 판정도 하지 않고 `draftcheck`·`numcheck`·`revcheck` 를 가리킵니다.
2. **표본수·검정력을 재계산하지 않습니다.** 관련 함수가 코드에 없음을 AST 검사로 고정.
3. **문서를 고치지 않습니다.** 정정본·보완답변서·변경대비표를 만드는 코드 경로가 없습니다. 쓰는 파일은 리포트 4종뿐입니다.
4. **규정 준수 여부를 판정하지 않습니다.** 그런 판정 문구는 금지어 테스트로 차단.
5. **어느 값이 맞는지 추론하지 않습니다.** 두 문서가 다른 말을 한다는 사실만, 근거 문장과 함께.

## 설치

```bash
cd ~/Downloads/02_프로젝트/깃헙/irbpack-제출서류정합점검
python3 -m pip install -e .
```

외부 의존성이 없습니다(`dependencies = []`). Python 3.9+ 이면 그대로 돕니다. **또는 폴더 안의 `실행.command` 를 더블클릭**하세요.

## 사용

```bash
irbpack SUNRISE_IRB_v1.2/ --out-dir 정합점검_20260828
irbpack SUNRISE_IRB_v1.2/ --baseline SUNRISE_IRB_v1.1/ --out-dir 개정점검
irbpack 패킷/ --role 프로토콜=계획서_v1.2.docx --role "동의서=ICF_*.docx"
```

한글 상세 안내는 [`사용법.md`](사용법.md).

## 대조 항목 12종 (닫힌 목록 — 늘리지 않습니다)

| # | 항목 | 불일치 시 | 정규화 |
|---|---|---|---|
| 1 | 연구제목(국문/영문) | 치명 | 공백·문장부호 제거 |
| 2 | 문서 버전·날짜 | **치명** (구버전 오첨부) | `Version No: 1.0`≡`v1.0`, `260518`≡`2026-05-18` |
| 3 | 연구책임자·기관 | 치명 | |
| 4 | 연락처 | 경고 | 공고에 개인 휴대전화(01X)가 동의서 연락처에 없으면 경고 |
| 5 | 대상자 수 (총·군별) | 치명 | 일부만 있으면 **전파 누락 경고** |
| 6 | 연령 범위 | 치명 | `만 5~12세`≡`만 5-12세`≡`５∼１２세`, **`만 5~12세`≠`만 6~12세`** |
| 7 | 방문·회기 횟수 / 참여 기간 | 치명 | `2회`≡`두 번`, CRF 는 `Visit 1~N` 칸 개수 |
| 8 | 소요시간 | 치명 | `1시간 30분`≡`90분` |
| 9 | 보상 | 치명 | `1만원`≡`10,000원`, 실비/정액/없음 범주 |
| 10 | 개인정보 보관기간 | 치명 | `3년`≡`36개월` |
| 11 | 선정·제외기준 | 경고 | 개수만 대조, 항목 단위는 `항목추출표.csv` 를 사람이 |
| 12 | 평가·검사 항목 | 경고 | CRF 폼이 프로토콜·동의서 본문에 없으면 **동의 범위 밖** |

**판정 규칙 (전부 결정론적).** 둘 이상의 문서가 같은 항목을 말하는데 값이 서로 부분집합이 아니면 **값 충돌**(항목별 심각도). 한 문서의 값이 다른 문서 값의 일부이면 **전파 누락**(경고). 값이 아예 없는 문서는 울지 않습니다 — 안 적는 게 맞는 문서도 있습니다. 한 문서에만 있는 값은 **대조불가**로 자백합니다. 정규화 때문에 같다고 본 쌍의 개수를 커버리지 블록에 셉니다.

**개정 축 (`--baseline`).** 프로토콜에서 값이 바뀐 항목만 골라, 부속문서가 기준 패킷의 옛 값을 그대로 갖고 있으면 `개정 미반영` 치명. 바뀌지 않은 항목은 보지 않습니다 — 전체 diff 가 되면 이 툴은 죽습니다.

## 정직성 — 이 툴이 말하지 않는 것

- **`[커버리지 자백]` 블록 없이는 리포트가 나오지 않습니다** (`ReportIntegrityError`, 코드로 강제). 12항목 중 대조 성립 개수, 대조불가 항목과 사유, 못 읽은 문서가 반드시 들어갑니다.
- **읽지 못한 문서가 하나라도 있으면 exit 3.** 비율로 봐주지 않습니다. 다 못 읽었으면 "치명 0건"은 거짓말입니다.
- **역할 판별이 애매하면 추측하지 않고 exit 2.** 판별 근거(어떤 키워드가 몇 점)를 리포트 첫 블록에 인쇄합니다 — 사람이 첫 줄만 보고 1초에 틀렸음을 압니다.
- **문서가 1개면 exit 2.** 문서 사이를 보는 툴이라 혼자서는 할 말이 없습니다.
- **리포트가 유출 경로가 되지 않습니다.** 전화·주민번호·이메일은 항상 마스킹(`010-****-6844`), 리포트 파일은 소유자만 읽기(0600), `--out-dir` 을 서류 폴더로 주면 거부.
- **원본은 읽기 전용.** 심볼릭·하드링크·경로 순회·CSV 수식 인젝션·파일명 개행으로 가짜 `[치명]` 줄 심기를 전부 막습니다.
- **cp949 콘솔에서 인코딩 오류가 "치명 발견"(exit 1)으로 둔갑하지 않습니다.**

## 한계 · 면책

- **이 툴은 IRB·식약처 심의 결과를 예측하지 않습니다.** 규정 준수 여부도 판정하지 않습니다. 「의약품 임상시험 관리기준」·기관 SOP 조문 대조를 하지 않습니다.
- 어느 문서의 값을 채택할지 정하지 않습니다. 실비와 시간당 정액 중 무엇이 맞는지는 연구자와 IRB 가 정합니다.
- `.hwp`/`.hwpx`, 스캔 PDF, 암호 문서는 읽지 않습니다. 못 읽은 문서로 세고 변환 안내를 냅니다.
- 선정·제외기준(11)과 평가항목(12)은 서술형이라 가장 약합니다. 개수와 이름 존재 여부만 봅니다.
- 문서 서식이 기관마다 달라 정규식이 못 잡는 항목은 `대조불가` 로 나옵니다. 그때 항목을 늘려 만회하지 않습니다 — 기획서의 원칙입니다.
- 변경내용 추적이 켜진 docx 는 모두 수락한 상태로 읽습니다.
- 예제 패킷과 테스트 픽스처는 전부 합성·익명화이며 실제 환자·실제 IRB 문서가 아닙니다.
