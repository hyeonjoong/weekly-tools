# irbpack — 제출서류 정합점검

IRB·식약처에 **한 봉투로 같이 내는 서류들**(연구계획서 · 동의서/Assent · CRF · 모집공고 · 등록정보)을 폴더째 읽어, **서류들끼리 말이 다른 곳**만 찍어 줍니다. 문서 하나의 품질은 보지 않습니다 — **문서 사이**만 봅니다.

> `revcheck` 는 **같은 문서의 다른 버전**을 봅니다. `irbpack` 은 **다른 문서의 같은 항목**을 봅니다.

---

## 목적 / Why this exists

**한국어.** 연구계획서를 v1.2로 고치면 동의서 3종·CRF·모집공고의 같은 값도 전부 따라 고쳐야 합니다. 6개 문서 × 12개 값 = 72칸을 워드 창 여러 개 띄워 놓고 눈으로 왕복하다 한 칸을 놓치고, 3주 뒤 *"연구계획서에는 2회 방문으로 되어 있으나 보호자용 설명문에는 '1회 또는 다회기'로 기재되어 있습니다"* 라는 보완요청서를 받습니다. 재제출·재심의로 2~4주가 날아가고 등록 개시가 그만큼 밀립니다. irbpack 은 그 72칸을 표로 펴서 **다른 값을 말하는 곳만** 근거 문장과 함께 뽑아 줍니다. IRB 제출 직전, 그리고 개정판(v1.1 → v1.2)을 낼 때마다 한 번씩 돌리는 도구입니다.

**English.** When a Korean IRB/MFDS submission packet is revised, the same numbers must be propagated by hand across the protocol, every consent/assent form, the CRF and the recruitment ad. Nobody checks whether the attached consent form actually says the same thing as the protocol — CTMS/eTMF systems track document versions and approvals, not whether the documents agree with each other. irbpack reads a packet folder offline, extracts 12 closed-list items from every document, and prints only the places where the documents disagree, with the supporting sentence and its location. It never edits a document, never recomputes a sample size, and never predicts an IRB decision.

**이 툴이 실제로 찾은 것.** 개발 중 **이미 IRB 승인이 난** 실제 패킷 6종(연구계획서·ICF 성인용·ICF 보호자용·Assent·CRF·모집광고)에 돌려, 치명 3건 · 경고 2건을 찾았습니다 — 성인용과 보호자용 동의서가 서로 **다른 검사 소요시간**을 고지하고 있었고, 계획서는 *교통비 실비*·동의서는 *시간당 정액 사례비* 로 보상 범주가 갈렸으며, CRF에는 계획서에 없는 **Visit 6까지의 회기 폼**이 있었고, 모집공고에 **개인 휴대전화**가 공개 게시물로 실려 있었습니다. (그 값들의 익명화 문장이 `tests/test_kobio_regression.py` 에 회귀 테스트로 박혀 있습니다.)

## 설치

```bash
cd irbpack-제출서류정합점검
python3 -m pip install -e .
```

외부 의존성이 없습니다(표준 라이브러리만). Python 3.9+.

---

## 사용법

```bash
# 패킷 폴더 하나를 통째로
irbpack 제출패킷/ --out-dir 정합점검_20260910

# 개정 축 — 이전 판과 비교해 '프로토콜만 바뀌고 부속문서가 안 따라온 곳'을 찾는다
irbpack SUNRISE_IRB_v1.2/ --baseline SUNRISE_IRB_v1.1/ --out-dir 개정점검

# 역할 자동판별이 애매할 때 직접 지정 (점검에서 빼려면 제외=)
irbpack 패킷/ --role 프로토콜=연구계획서_v1.2.docx --role 제외=참고자료.docx
```

번들 예제로 바로 확인:

```bash
irbpack examples/불일치_패킷 --out-dir /tmp/점검
```

## 무엇을 대조하는가 — 항목 12종 (닫힌 목록)

| # | 항목 | 대조 단위 | 불일치 시 |
|---|---|---|---|
| 1 | 연구제목 | 제목 | 치명 |
| 2 | 문서 버전·날짜 | 버전(본문) / 버전(파일명) / 문서날짜(본문) / 문서날짜(파일명) | 치명 |
| 3 | 연구책임자·기관 | 연구책임자 / 실시기관 | 치명 |
| 4 | 연락처 | 전화 / 이메일 | 경고 |
| 5 | 대상자 수 | 총N / 군별N | 치명 |
| 6 | 연령 범위 | 연령범위 | 치명 |
| 7 | 방문·회기 횟수 / 참여기간 | 방문횟수 / 참여기간 | 치명 |
| 8 | 1회 및 총 소요시간 | 소요시간 | 치명 |
| 9 | 보상 | 금액 / 형태 | 치명 |
| 10 | 개인정보 보관기간 | 보관기간 | 치명 |
| 11 | 선정·제외기준 | 군 구성 | 경고 |
| 12 | 평가·검사 항목 | CRF 전용 폼만 | 경고 |

부속문서끼리의 불일치(위 단서 참조)는 항목 심각도와 무관하게 **경고**입니다.

대조 규칙은 넷뿐이고 전부 결정론적입니다.

1. **값 충돌** — 기준 문서(프로토콜)에 **없는 값**을 말하는 문서가 있다.
2. **전파 누락** — 프로토콜에 있는 값이, 그 항목을 다루고 있는 부속문서에 빠져 있다 → 경고.
3. **동의 범위 밖** — CRF 에만 있는 검사 폼이 프로토콜·동의서 어디에도 없다 → 경고.
4. **공고 연락처** — 모집공고의 개인 휴대전화가 동의서 대표 연락처와 다르다 → 경고.

부속문서가 프로토콜의 *일부만* 적는 것은 정상이므로(성인용 동의서가 소아 그룹을 안 적는 것처럼) **조용히 넘어갑니다.** "같은 항목을 둘 이상이 말할 때만 비교" 라는 규칙 하나가 오탐의 대부분을 막습니다.

연구 전체에서 값이 하나여야 하는 대조단위(**버전·날짜·제목·보관기간·연구책임자**)에서는 부속문서끼리도 맞대 보고, 어긋나면 **경고**로 알립니다 — 프로토콜이 3년과 10년을 둘 다 언급하면 동의서(3년)와 CRF(10년)가 서로 다른 말을 해도 둘 다 "기준 안"이 되어 조용히 넘어가기 때문입니다. 치명이 아니라 경고인 이유는, 두 문서가 *같은 대상*을 말하는지(동의서 원본 vs 전자자료) 툴이 알 수 없기 때문입니다.

**총 대상자 수와 보상 금액은 여기서 제외했습니다.** 성인용 동의서가 60명·20,000원을, 소아 승낙서가 24명·10,000원을 적는 것은 각자 자기 군을 말하는 정상적인 문서이기 때문입니다(그 둘이 정말 어긋나면 프로토콜의 값과 달라져 기준 규칙이 잡습니다).

## 정직성 — 이 툴이 하지 않는 것

- **IRB 심의 결과를 예측하지 않습니다.** 승인·보완·반려를 점치지 않고, 「의약품 임상시험 관리기준」이나 기관 SOP 조문과 대조하지도 않습니다.
- **어느 값이 옳은지 말하지 않습니다.** "실비와 시간당 1만원 중 뭐가 맞나"에 답하지 않고, **두 문서가 다른 말을 한다는 사실**만 근거 문장과 함께 제시합니다.
- **문서를 고치지 않습니다.** 정정본·변경대비표·보완답변서 초안을 만들지 않습니다(감사와 수정을 한 툴에 넣으면 사람이 결과를 안 보고 수정만 돌리게 됩니다).
- **표본수를 재계산하지 않습니다.** "90명이 적정한가"는 `powerplan` 의 일입니다. 검정력 계산 함수가 코드에 **존재하지 않음**을 테스트가 AST로 강제합니다.
- **논문 원고를 읽지 않습니다.** Abstract/Introduction/Discussion 구조가 보이면 판정 없이 exit 2 로 멈추고 `draftcheck`·`numcheck`·`revcheck` 를 가리킵니다.
- **개인정보를 전수 스캔하지 않습니다.** 연락처 항목은 모든 문서에서 전화·이메일을 뽑아 대조하고 (리포트에는 마스킹해 인쇄), 그 밖의 개인정보 스캔은 하지 않습니다 — 그건 `deidaudit` 의 일입니다. 모집공고의 개인 휴대전화만 별도 규칙으로 경고합니다.

## 한계

- **`.hwp`/`.hwpx` 는 읽지 않습니다.** 조용히 무시하지 않고 "읽지 못한 문서"로 세어 **exit 3(판정 불가)** 을 냅니다. Word(.docx)로 변환해 주세요. (BELL 저장소의 IRB 계열 문서 확장자를 전수로 세어 보면 `.docx` 17 · `.pdf` 3 · `.md` 2 · `.hwp` 1 이고, 그 `.hwp` 1건은 IRB 문서가 아니라 정부과제 서류였습니다.)
- **`.pdf` 는 텍스트 레이어만** 읽습니다. 스캔 이미지 PDF·암호화 PDF·폰트 ToUnicode 정보가 없는 PDF 는 "읽지 못한 문서"로 자백합니다(깨진 글자를 점검에 넣는 쪽이 훨씬 위험합니다).
- **변경내용 추적(tracked changes)** 이 켜진 .docx 는 **수정 반영(최종본) 상태**로 읽고, 그 사실을 리포트 맨 위에 인쇄합니다.
- **정규식 추출입니다.** 문서 서식이 크게 다르면 값을 못 찾을 수 있습니다. 그래서 **"이 항목을 말하고는 있는데 값이 안 잡힌 문서"** 는 `[정보] 일치 확인` 줄에 이름이 같이 찍히고(`… CRF_통합.docx 에서는 값을 찾지 못했습니다 — 일치가 아닙니다`), `대조불가.csv` 에도 남습니다. **리포트에 안 나온 항목이 "일치"라는 뜻은 아닙니다.** 값을 못 찾은 문서가 하나라도 있으면 그 줄의 "일치"는 나머지 문서들 사이의 일치일 뿐입니다.
- **주제어조차 나오지 않는 문서는 "안 다룬 문서"로 보고 아무 말도 하지 않습니다.** 예를 들어 모집공고에 보관기간 얘기가 아예 없으면 경고하지 않습니다 — 안 적는 게 맞는 항목도 있기 때문입니다.
- 서술형 문장에서 **선정·제외기준의 항목 개수**를 세거나 **검사 명칭 목록**을 대조하지는 않습니다(표기가 문서마다 달라 오탐이 됩니다). 대신 군 구성과 CRF 전용 폼만 봅니다.
- 방문 횟수만 **범위 포괄**을 적용합니다(`1~2회` 안의 `2회` 는 같은 말). 연령·소요시간은 적힌 그대로 대조합니다 — `만 20~65세` 와 `만 20~64세` 는 절대 같지 않습니다.
- **버전은 파일명 축과 본문 축을 따로 봅니다.** 같은 문서의 파일명 버전과 본문 버전이 다른 경우(문서 *안*의 불일치)는 이 툴의 범위가 아니라서, 두 축을 각각 다른 문서들과 대조합니다.
- **전화번호는 가운데 자리를 가리되 첫 숫자는 남깁니다**(`010-1***-5678`). 주민등록번호는 생년월일까지 전부 가립니다(`******-1******`). 그래도 가운데 두 번째 자리부터만 다른 두 번호는 같아 보일 수 있으니, `← 다름` 표시가 붙었는데 값이 같아 보이면 원문 문서를 여세요.
- **하위 폴더는 보지 않습니다.** 대신 "하위 폴더 안의 파일 N개는 보지 않았습니다"를 커버리지 자백에 인쇄합니다. 패킷은 폴더 하나에 평평하게 모아 주세요.
- **모르는 형식(.odt·.rtf 등)은 읽지 않되 "읽지 못한 문서"로 셉니다** — 조용히 사라지지 않습니다(exit 3).
- **선정기준의 연령은 `만 19~65세`·`만 19세 이상 만 65세 이하` 형태까지만 값으로 읽습니다.** 서술형("스무 살에서 예순네 살")은 값으로 못 읽지만, **못 읽었다고 말합니다**(해당 문서 이름이 일치 줄과 `대조불가.csv` 에 찍힙니다).
- **`레이블: 값` 형태도 읽습니다** — `검사 소요시간: 약 60분`, `개인정보 보관기간: 3년` 처럼 레이블과 값이 콜론으로 갈린 문장까지 봅니다.
- **원본은 읽기만 합니다.** 산출물은 `--out-dir` 에만 쓰고, 그 경로가 심볼릭·하드링크면 거부합니다. 리포트의 전화번호·주민번호 형태는 항상 마스킹(`010-****-6844`)하고, 문서 이름은 파일명만 싣습니다(절대경로 유출 방지).

## 인접 툴과의 경계

| 툴 | 무엇을 보나 | irbpack 과의 차이 |
|---|---|---|
| `revcheck` | 원고 제출본·개정본·응답서 | 같은 문서의 **다른 버전**. irbpack 은 같은 시점의 **다른 문서** |
| `draftcheck`·`numcheck` | 원고 1개의 자기 정합성 | 대상이 논문 원고. irbpack 은 원고를 읽지 않음 |
| `visitaudit` | 실제 방문 날짜 CSV vs 방문창 JSON | 데이터를 봄. irbpack 은 그 JSON 을 쓰기 **전 단계**의 문서를 봄 |
| `deidaudit` | 데이터 파일의 개인정보 | 데이터 셀 전수 스캔. irbpack 은 공고 연락처 한 가지만 |
| `powerplan` | 설계 → 표본수 | 숫자를 **만듦**. irbpack 은 적힌 표본수가 서로 같은지만 봄 |
