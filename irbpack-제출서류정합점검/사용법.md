# 사용법 (한글 빠른 시작)

## 0. 제일 빠른 길

폴더 안의 **`실행.command` 를 더블클릭**하세요. 합성 패킷 3종(정합 / 불일치 / 판정불가)과
개정 축(`--baseline`)을 한 번에 보여 주고, 임시 폴더에 쓴 뒤 지웁니다.

## 1. 한 번만 설치

```bash
cd ~/Downloads/02_프로젝트/깃헙/irbpack-제출서류정합점검
python3 -m pip install -e .
```

이후 어느 폴더에서나 `irbpack` 명령을 씁니다. (설치가 귀찮으면 `python3 -m irbpack` 도 같습니다.)
외부 의존성이 없습니다. Python 3.9 이상이면 그대로 돕니다.

## 2. 제출 직전 30초

IRB 에 **한 봉투로 같이 내는 서류**를 한 폴더에 모아 두고 그 폴더를 던집니다.

```bash
irbpack SUNRISE_IRB_v1.2/
```

```
SUNRISE_IRB_v1.2/
├── SUNRISE-K_MCI_연구계획서_v1.2_2026-08-25.docx     ← 프로토콜 (필수)
├── ICF_성인용_v1.2_260825.docx
├── ICF_보호자용_v1.2_260825.docx
├── Assent_v1.1_260811.docx
├── CRF_통합_v1.2_260825.docx
└── 모집공고안_v1.2.docx
```

화면에 `[문서 역할]` → `[치명]` → `[경고]` → `[정보] 일치 확인` → `[커버리지 자백]` 순으로 나오고
마지막 줄이 `치명 N건. → exit X` 입니다. **첫 블록 `[문서 역할]` 을 먼저 보세요** — 역할 판별이
틀렸으면 나머지는 전부 쓰레기입니다. 틀렸으면 3절로.

파일을 나열해도 됩니다: `irbpack 계획서.docx 동의서.docx CRF.docx`

## 3. 역할 판별이 애매할 때 (`--role`)

파일명·본문 키워드로 자동 판별하되, 애매하면 **추측하지 않고 exit 2** 로 멈추고 `--role` 을 요구합니다.

```bash
irbpack 패킷/ --role 프로토콜=SUNRISE-K_MCI_연구계획서_v1.2_2026-08-25.docx --role "동의서=ICF_*.docx"
```

역할 값: `프로토콜` · `동의서` · `동의서(소아)` · `CRF` · `모집공고` · `등록정보`
(영문 별칭 `protocol` `icf` `assent` `crf` `ad` `reg` 도 됩니다). 파일 패턴은 글로브(`*`)를 씁니다.

## 4. 파일로 남기기 (`--out-dir`)

```bash
irbpack 패킷/ --out-dir 정합점검_20260828
```

| 파일 | 내용 |
|---|---|
| `정합점검.md` | 콘솔 전문 + **항목 12종 × 문서 대조표** + 역할 판별 근거 + 정규화·마스킹·판정 규칙 부록 |
| `불일치목록.csv` | 항목, 심각도, 문서A, 값A, 근거위치A, 문서B, 값B, 근거위치B |
| `항목추출표.csv` | 문서 × 항목 × 추출값 × 정규화값 × 문단번호 × 원문 문장 — **사람이 1초에 검증하는 표** |
| `대조불가.csv` | 항목, 사유 (한 문서에만 존재 / 추출 실패 / 단위 상이) |

`--out-dir` 을 서류 폴더 자체로 주면 거부합니다 (다음 실행이 리포트를 문서로 읽게 되므로).
원본 서류는 절대 수정하지 않습니다.

## 5. 개정 축 (`--baseline`)

프로토콜을 v1.1 → v1.2 로 고쳤을 때, **프로토콜에서 바뀐 값이 동의서·CRF·공고에도 따라 바뀌었는지**만 봅니다.

```bash
irbpack SUNRISE_IRB_v1.2/ --baseline SUNRISE_IRB_v1.1/ --out-dir 개정점검
```

프로토콜에서 바뀌지 않은 항목은 보지 않습니다 (전체 diff 가 아닙니다). 프로토콜은 바뀌었는데
부속문서가 **기준 패킷 값 그대로**면 `개정 미반영` 치명으로 잡습니다.

## 6. 종료코드

| 코드 | 뜻 |
|---|---|
| 0 | 치명 0건 |
| 1 | 치명 발견 |
| 2 | 판정하지 않음 — 프로토콜 없음/못 읽음, 역할 판별 실패, 원고 감지, 문서 1개, 인자 오류 |
| 3 | 판정 불가 — 부속문서 중 못 읽은 것이 있음(`.hwp` 등) 또는 대조 성립 항목 < 4 |

**3 이 1 보다 우선합니다.** 서류를 다 못 읽었으면 "치명 3건"이 아니라 "판정 불가"입니다.

## 7. 읽는 형식

`.docx`(표 포함) · `.md` · `.txt` · `.pdf`(텍스트 레이어만). **`.hwp`/`.hwpx` 는 읽지 않습니다** —
한글에서 "다른 이름으로 저장 → DOCX" 로 바꾼 뒤 다시 실행하세요. 스캔 PDF 도 못 읽습니다.
못 읽은 문서는 조용히 넘어가지 않고 커버리지 블록에 적고 exit 3 을 냅니다.

변경내용 추적이 켜진 docx 는 **모두 수락한 상태**로 읽고, `[문서 역할]` 줄에 그 사실을 적습니다.

## 8. 자주 묻는 것

- **"경고: 전파 누락"이 뭔가요?** 한 문서의 값이 다른 문서 값의 일부입니다 (모집공고에 군별 인원만 있고 총 인원이 없음). 충돌은 아니라 경고입니다. 값이 아예 없는 문서는 울지 않습니다 — 안 적는 게 맞는 문서도 있습니다.
- **"대조불가"는 뭔가요?** 한 문서에만 있어서 비교할 상대가 없거나, 서술형이라 정규식이 못 잡은 항목입니다. 치명이 아닙니다. `대조불가.csv` 에 사유가 있습니다.
- **어느 문서가 맞는지 알려 주나요?** 아니오. 두 문서가 다른 말을 한다는 사실과 근거 문단만 보여 줍니다.
- **IRB 통과 여부를 예측하나요?** 아니오. 규정 준수 판정도 하지 않습니다.
- **원고(논문)를 넣으면?** `Abstract`/`Discussion` 구조가 보이면 판정 없이 exit 2 — `draftcheck`·`numcheck`·`revcheck` 를 가리킵니다.
