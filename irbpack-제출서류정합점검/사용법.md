# 사용법 (한글 빠른 안내)

## 1. 제일 빠른 확인

`실행.command` **더블클릭** → 번들 예제(정합 / 불일치 / 판정불가 / 개정 축)를 차례로 돌려 보여 줍니다.
(터미널이 열리고, 마지막에 엔터를 누르면 닫힙니다.)

## 2. 설치 (한 번만) — 안 해도 됩니다

설치 없이 바로:

```bash
cd irbpack-제출서류정합점검
python3 -m irbpack "제출패킷" --out-dir "정합점검_20260910"
```

`irbpack` 이라고 짧게 치고 싶으면 한 번만 설치하세요(안 하면 `command not found` 가 납니다):

```bash
python3 -m pip install -e .
```

## 3. 내 서류로 돌리기

제출할 서류를 **폴더 하나에 모아** 놓고(하위 폴더는 보지 않습니다):

```bash
python3 -m irbpack "제출패킷" --out-dir "정합점검_20260910"
```

폴더 안에 있어도 되는 것: `.docx` · `.pdf`(텍스트 레이어) · `.md` · `.txt`
엑셀·이미지는 알아서 건너뜁니다. **`.hwp` 는 못 읽습니다** — 조용히 넘어가지 않고 "읽지 못한 문서"로 세어 판정을 보류합니다(Word 로 변환해 주세요).

### 자주 쓰는 두 가지

```bash
# ① 개정판을 낼 때 — 이전 판과 비교해 "계획서만 고치고 동의서를 안 고친 곳"을 찾는다
python3 -m irbpack "패킷_v1.2" --baseline "패킷_v1.1" --out-dir "개정점검"
#    번들 예제로 미리 보기:
python3 -m irbpack examples/개정_이후_패킷 --baseline examples/개정_이전_패킷 --out-dir /tmp/개정점검

# ② 문서 역할을 잘못 잡았을 때 — 직접 지정
python3 -m irbpack "패킷" --role 프로토콜=연구계획서_v1.2.docx --role 제외=참고자료.docx

# ③ 소견에서 접힌 줄까지 전부 보고 싶을 때
python3 -m irbpack "패킷" --out-dir "점검" --all-rows
```

## 4. 결과 읽는 법

콘솔에 이런 순서로 나옵니다.

1. **[문서 역할]** — 어떤 파일을 무엇으로 봤는지, 그 **근거 키워드**까지.
   → **여기부터 보세요.** 역할이 틀렸으면 아래 내용은 전부 의미가 없습니다. `--role` 로 고쳐 주세요.
2. **[치명]** — 서류들이 다른 값을 말하는 곳. 재제출 사유가 되는 것들입니다.
   각 줄에 `역할 · 값 · 어느 문서 / 몇 번째 문단 · 원문 문장` 이 같이 나옵니다. **원문을 1초 보고 직접 판단하시면 됩니다.**
   (단, 연락처는 리포트에서 가려집니다 — `010-1***-5678` 처럼 나오니 번호 자체를 확인할 때는 원본 문서를 여세요.)
   `← 기준` 은 프로토콜(기준 문서), `← 다름` 이 손봐야 할 곳입니다.
3. **[경고]** — 전파 누락(계획서엔 있는데 공고엔 없음), CRF 전용 검사 폼, 공고의 개인 휴대전화.
4. **[정보] 일치 확인** — 맞은 것은 맞다고 조용히 알려 줍니다.
5. **[커버리지 자백]** — **못 본 것을 말하는 칸입니다.**
   `[정보] 일치 확인` 줄 끝에 *"○○.docx 에서는 값을 찾지 못했습니다 — 일치가 아닙니다"* 가 붙어 있으면,
   그 문서는 표현이 달라 못 읽은 것이니 **직접 열어 확인**하세요. 몇 개 문서를 못 읽었는지, 12항목 중 몇 개나 대조했는지, 어떤 항목은 왜 대조 못 했는지.
   → 리포트에 안 나온 항목이 "일치"라는 뜻이 아닙니다. 이 칸을 꼭 보세요.

마지막 줄이 결론입니다.

- `치명 0건 (경고 N건). → exit 0` — 값은 서로 맞습니다.
- `치명 N건. → exit 1` — 고칠 곳이 있습니다.
- `판정 불가 … → exit 3` — 못 읽은 문서가 있어 결론을 낼 수 없습니다(보통 `.hwp`·스캔 PDF).
- **리포트가 아예 안 나오고 빨간 메시지만 나오는 경우 (exit 2)** — 입력이 애매해서 툴이 추측을 거부한 것입니다. 가장 흔한 세 가지:
  - `프로토콜로 판별된 문서가 2개입니다` — 계획서와 **연구계획서 국문요약본**처럼 둘 다 계획서로 보이는 파일을 같이 넣은 경우
    → `python3 -m irbpack "패킷" --role 제외=연구계획서_국문요약본.docx`
  - `문서 역할을 확정하지 못했습니다` — 역할 키워드가 약한 파일(예: `국문요약본.docx`)이 섞인 경우.
    메시지가 두 가지를 제안합니다: 점검 대상이 아니면 `--role 제외=파일명`, 맞으면 `--role 동의서=파일명`.
  - `이건 논문 원고입니다` → 원고가 섞였습니다. 원고는 `draftcheck`·`numcheck`·`revcheck` 로.

## 5. 저장되는 파일

`--out-dir` 폴더에 4개가 생깁니다.

| 파일 | 언제 여나 |
|---|---|
| `정합점검.md` | 전체 결과 + **12항목 × 문서 대조표** — 이걸 팀에 공유하면 됩니다 |
| `불일치목록.csv` | 고칠 목록을 엑셀로 정리할 때 |
| `항목추출표.csv` | "이 값을 어디서 읽었지?" 를 확인할 때 (문서 × 항목 × 원문) |
| `대조불가.csv` | 못 본 것 목록 |

전화번호는 리포트에서 `010-****-6844` 처럼 가려집니다.

## 6. 이 툴이 **안 하는** 일

- 문서를 고쳐 주지 않습니다(정정본·보완답변서 초안 없음).
- IRB 가 승인할지 예측하지 않습니다.
- 어느 값이 맞는지 판단하지 않습니다 — 다르다는 사실만 보여 줍니다.
- 표본수가 적정한지 계산하지 않습니다(그건 `powerplan`).
- 논문 원고를 넣으면 판정 없이 멈춥니다(그건 `draftcheck`·`numcheck`·`revcheck`).
