# circadia — 일주기리듬(circadian rhythm) 분석기

워치에서 내보낸 **연속 시계열 CSV 1~3개**(심박 `timestamp,hr` · 걸음
`timestamp,steps` · 수면구간 `start,end`)를 넣으면 **24시간 리듬을 정량화**합니다 —
코사이너(MESOR·진폭·정점위상 + zero-amplitude F 검정), 비모수 지표(IS·IV·RA·L5/M10),
수면 규칙성(SRI·중간수면·사회적 시차), 심박 야간 강하 — 그리고 **문헌 참고범위와
대조한 한국어 리포트**와 **48시간 더블플롯 텍스트 액토그램**을 출력합니다.
numpy 없이 **표준 라이브러리만**으로 동작합니다. 오프라인 전용, 네트워크 0.

**진단하지 않습니다.** 지표를 계산하고, 출처 있는 참고범위를 보여주고, 방향만
서술하고("참고범위 대비 낮음/높음"), 확인 못 하는 것은 확인 못 한다고 말합니다.

---

## 목적 / Why this exists / Who it's for

> **BELL-001 이란?** 이 저장소가 상정한 **사내 가상 수면 디바이스 프로젝트
> 코드명**입니다 — 실재하는 승인 제품이 아니고, 문서에 인용된 임상 근거도
> 없습니다. SERENE 은 그 가상 프로젝트의 가상 3상 시험명입니다. 아래 문헌
> 인용(Van Someren, Phillips, Roenneberg, Cornelissen 등)은 **실재하는 방법론
> 논문**이며, 이 도구가 검증하는 것은 계산이지 기전이 아닙니다.

**한국어.** 워치는 이미 1년치 심박·걸음·수면 기록을 갖고 있지만, 앱이 보여주는
것은 근거 불명의 "수면 점수"뿐입니다. 정작 리듬 건강의 표준 지표 — 매일 같은
시간에 자는가(SRI), 활동 리듬의 진폭이 살아 있는가(RA·코사이너 진폭), 주말마다
시차를 겪는가(사회적 시차), 밤에 심박이 제대로 내려가는가(야간 강하) — 는 아무도
계산해 주지 않습니다. 수식은 문헌에 고정돼 있고, 하루 1440분 × 수십 일이라 손으로는
못 하며, LLM 에 CSV 를 붙여넣으면 그럴듯한 숫자를 지어냅니다. 결정론적 수식 계산이
이기는 정확히 그 자리에 이 도구가 있습니다. 벨테라 맥락에서는 이중으로 쓰입니다:
① 개인·가족·피험자 후보의 워치 export 에서 **BELL-001 의 타깃인 '불규칙한 리듬'을
숫자로** 보여주는 스크리닝, ② SERENE 워치 데이터의 탐색적 지표 후보(IS·RA·SRI)를
`지표.csv` 로 계산해 두는 연구 파이프라인 앞단 — 여러 사람 분을 모아 그룹 열을
붙이면 statwise/longistat 입력이 됩니다(실행 검증된 절차는 사용법.md,
DATA_INVENTORY 의 워치 HR/HRV 모달리티가 입력이 됩니다).

**English.** Your watch already holds a year of heart-rate, step and sleep data,
but the vendor app only shows an unexplained "sleep score". The standard rhythm
metrics — sleep regularity (SRI), rhythm amplitude (RA, cosinor), social jetlag,
nocturnal heart-rate dipping — are never computed for you. The formulas are fixed
in the literature, the data is far too long for hand calculation, and pasting a
CSV into an LLM produces plausible fabrications. `circadia` runs the deterministic
pipeline offline — parsing vendor-flavored CSVs (Apple Health / Samsung Health /
Fitbit-style column names), cosinor fit, Van Someren non-parametrics, SRI, HR
markers — and writes a Korean health-information report that compares each value
against **cited** reference ranges, plus a machine-readable `지표.csv` per person
that you aggregate across subjects into statwise/longistat inputs (the verified
recipe is in 사용법.md). Zero dependencies, Python 3.9+.

## 계산하는 지표 / What it computes

| 지표 | 정의 | 공식 출처 |
|---|---|---|
| MESOR·진폭·정점위상(acrophase) | 단일 성분 24h 코사이너 최소제곱 적합, zero-amplitude F 검정·R² | Cornelissen 2014, *Theor Biol Med Model* 11:16 |
| IS (일간 안정성) | 시간당 빈, 24h 평균 프로파일의 분산비 — 0~1, 매일 같은 패턴이면 1 | Witting 1990 정의, Van Someren 1999 (*Chronobiol Int* 16:505) 관례 |
| IV (일내 변동성) | 연속 시간 빈 차분 제곱합 비 — 교대 패턴 극단에서 4 | 같은 논문 |
| L5 / M10 / RA | 평균 프로파일의 최저 5h·최고 10h 평균과 중앙시각, RA=(M10−L5)/(M10+L5) | 같은 논문 |
| SRI (수면 규칙성 지수) | 24h 간격 분 단위 수면/각성 상태쌍 일치율, −100~100 | Phillips 2017 (*Sci Rep* 7:3216); 계산 세부는 Windred 2023 (*Sleep* 47:zsad253) |
| 중간수면·입면/기상 SD | 정오 기준 프레임 산술 통계 (자정 wrap 안전) | Roenneberg 관례 |
| 사회적 시차 | \|주말밤(금·토) 중간수면 − 주중밤 중간수면\| (MSFsc 아님 — 원식) | Roenneberg 2012 (*Curr Biol* 22:939) |
| 심박 야간 강하·nadir·기상 전 상승 | (주간−야간)/주간, 시간당 프로파일 최저 빈 | ABPM dipping 관례 준용 — 심박 고유 확립 기준 아님(리포트에 명기) |
| 48h 더블플롯 액토그램 | 하루 = 그날 0–24h + 다음날 0–24h, 30분 슬롯 문자 | 액티그래피 표준 표시 관례 |

수면시간 참고범위는 Hirshkowitz 2015 (*Sleep Health* — National Sleep Foundation
권고)를 인용합니다.

## 실행 / How to run

```bash
# 설치 없이
python3 -m circadia 심박.csv --steps 걸음.csv --sleep 수면.csv --out-dir 리듬결과

# 최소 입력은 1개 — 심박만, 걸음만, 수면만도 됩니다
python3 -m circadia --sleep 수면.csv
python3 -m circadia --steps 걸음.csv

# 열 인식이 궁금하면 (분석 없이 인식 결과만)
python3 -m circadia 심박.csv --inspect

# 열 이름이 안 잡히면 지정
python3 -m circadia 기록.csv --hr-col avg_hr --hr-time-col measured_at
```

설치하면 `circadia` 콘솔 명령이 생깁니다: `python3 -m pip install -e .`

macOS 에서는 `실행.command` 더블클릭으로 번들 예시 2종(규칙적/불규칙 1주)이
바로 돌아갑니다.

### 입력 형식

- **심박/걸음**: `시각 열 + 값 열` CSV. 열 이름은 자동 인식 — Apple 건강식
  (`startDate,value,unit`), 삼성헬스식(`start_time,heart_rate`/`step_count`),
  Fitbit식(`Time,Heart Rate`/`Steps`), 한국어(`시각,심박수`/`걸음수`) 별칭을
  포함합니다. 후보가 둘이면 **추측하지 않고 에러**를 냅니다(`--*-col` 로 지정).
- **수면구간**: `시작 열 + 종료 열`(한 행 = 한 구간). Apple 건강처럼 단계(stage)
  열이 있으면 InBed/Awake 행은 제외하고 Asleep 계열 행을 병합합니다. 알 수 없는
  단계 라벨이 나오면 추측하지 않고 거부합니다.
- **인코딩** utf-8 / utf-8-sig / cp949, **구분자** `,` `;` 탭 자동.
- **타임스탬프**: ISO(`2026-08-03 23:30:00[.000][+09:00]`), 미국식
  (`8/3/2026 11:30:00 PM`), 점 표기(`2026.08.03 23:30`). epoch 숫자는 시간대를
  추측해야 하므로 **거부**합니다. 파일 전체가 동일한 고정 오프셋이면 그 로컬
  시각으로 읽고(변환 없음), 오프셋이 섞이면(여행·DST) 거부합니다.
- 벤더별 대표 열 이름은 **대표값**입니다 — 실제 export 는 앱 버전마다 다르니
  `--inspect` 로 확인하세요. 예시 폴더에 세 벤더 표기의 동일 데이터가 있습니다.

### 산출물 (`--out-dir`)

| 파일 | 내용 |
|---|---|
| `리듬리포트.md` | 해석 전문(터미널 리포트와 동일 + 액토그램) |
| `지표.csv` | 긴 형식(1행=1지표): `구분(요약/일별),날짜,지표,값,단위,비고` — 1인분입니다. 여러 사람 분을 모아 그룹 열을 붙이고 지표 1개로 필터하면 statwise/longistat 입력이 됩니다(사용법.md에 실행 검증된 예). 수식 인젝션 가드 적용 |
| `액토그램.txt` | 48h 더블플롯 텍스트 액토그램 |

exit code: **0** 정상(일부 지표가 '데이터 부족'이어도 0) / **2** 입력·인자
오류(열 모호, 타임스탬프 역행·중복·미래·시간대 혼재 등) / **3** 데이터 불충분
(주 시계열 착용률이 `--min-wear`, 기본 50% 미만).

(발췌 — 전체 리포트는 커버리지 자백·코사이너·심박 마커·면책까지 포함):

```
…(전략: 커버리지 자백·코사이너 섹션 생략)…

L5(최저 5h) = 10.77 (중앙 03:30, 시작 01시) · M10(최고 10h) = 1131.54 (중앙 13:00, 시작 08시) — 유효일 7일 평균 프로파일
```

## 인접 툴과의 경계 / Scope boundaries

| | 입력 | 답하는 질문 | 시간 스케일 |
|---|---|---|---|
| `hrvkit` | RR/IBI 간격 | 자율신경 지표(HRV) | 분 단위 생리 |
| `sleepdiary` | 수면일기(자가보고) | CSD 표준 수면지표 | 밤 단위 주관 |
| **`circadia`** | 워치 연속 시계열 | 24h 리듬의 안정성·진폭·규칙성 | 일 단위 리듬 |

circadia 는 RR 간격을 받지 않고(HRV 계산은 hrvkit 영역), 수면일기를 받지
않습니다(sleepdiary 영역). 워치가 기록한 **수면구간(시작~종료)** 은 기기 기록이므로
받습니다.

## 정직성 장치 / Honesty devices

계산만큼 중요합니다:

- **커버리지 자백이 리포트 최상단** — 분석일수·착용률·3시간 이상 갭 목록·제외
  행 수와 사유가 어떤 지표보다 먼저 나옵니다.
- **지표별 최소일수 게이트** — IS/IV·SRI 는 유효 5일(권장 7일) 미만이면 숫자
  대신 `데이터 부족(N일<5일)` 을 출력합니다. 3일치로 IS 를 내면 쓰레기 값이
  나오고 사용자는 그걸 믿기 때문입니다. 코사이너·액토그램은 짧아도 계산됩니다
  (게이트가 지표별로 다릅니다). 착용률 임계 미만이면 아예 exit 3.
- **보간 없음** — 빈 시간은 평균으로 메우지 않습니다. 24/24 시간 빈이 채워지지
  않은 날은 비모수 지표에서 통째로 빠지고, 어느 날이 왜 빠졌는지 리포트에
  적힙니다.
- **추측 없음** — 열 이름 후보가 둘이면 에러, 타임스탬프 역행·중복·미래·시간대
  혼재면 에러, 알 수 없는 수면 단계 라벨이면 에러. 조용히 고치지 않습니다.
- **비진단 문구 규율** — 모든 해석은 ①내 값 ②출처 있는 참고범위 ③"참고범위 대비
  낮음/높음/범위 내" 3요소 구조입니다. 진단 단정형 문구는 테스트가 금지어
  grep 으로 강제합니다(`tests/test_report.py`).
- **참고범위의 한계도 자백** — 활동 기준 참고범위(IS/IV/RA)를 심박으로 계산한
  경우 방향 판정을 하지 않고 이유를 적으며, 걸음수 기반 IV 가 가속도계 기준보다
  높게 나오는 경향도 리포트에 적습니다.

## Notes / limitations

- **단일 성분 코사이너**입니다 — 12h 고조파를 넣는 다성분 적합, 기간 추정
  (period estimation)은 하지 않습니다. 정점위상은 τ=24h 고정 가정 하의 값입니다.
- IS/IV 는 **완전한 날(24/24 빈)만** 사용합니다. 문헌 구현 중에는 결측 빈을
  프로파일 평균으로 메우는 것도 있으므로, 갭 많은 데이터에서는 다른 도구와 값이
  다를 수 있습니다(우리는 보간을 하지 않는 쪽을 선택했습니다).
- 유효일이 달력에서 비연속이면 IV 차분은 연속 구간 안에서만 취합니다 — 리포트에
  표기됩니다.
- SRI 는 수면구간 파일 기반이므로 **기기가 수면을 어떻게 판정했는지에
  종속**됩니다. 관측 구간은 [첫 구간 시작, 마지막 구간 종료], 구간 밖 상태는
  쌍에서 제외, 1분 해상도입니다.
- 사회적 시차는 **원식 |MSF−MSW|** 입니다 — 수면부채 보정판(MSFsc)이 아니며,
  '주말밤 = 금·토요일 밤' 라벨링은 표준 근무 주간 가정입니다(교대근무에는 부적합).
- 야간 심박 강하의 참고범위(10–20%)는 혈압 문헌 관례의 준용이며 심박 고유의
  확립 기준이 아닙니다 — 리포트에도 같은 문장이 붙습니다.
- 참고범위는 특정 연구 코호트(대학생, 중년 코호트 등)의 기술통계입니다. 연령·
  직업·계절이 다르면 분포가 다릅니다 — 그래서 방향만 서술합니다.
- 시간대 변환·DLMO 추정·수면단계 추정·다인 배치 처리는 하지 않습니다(v1 범위 밖).
