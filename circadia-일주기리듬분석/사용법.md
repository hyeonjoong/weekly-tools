## 0. 3분 만에 확인하기

**macOS**: 폴더 안의 `실행.command` 를 **더블클릭**하세요. 규칙적 1주 /
불규칙 1주 합성 예시 2벌이 차례로 분석되고, 마지막에 엔터를 누르면 창이

## 1. 내 데이터 내보내기

셋 중 **아무거나 1개**만 있어도 됩니다. 셋 다 있으면 가장 풍부한 리포트가
나옵니다.

| 파일 | 무엇 | 필요한 열 |
|---|---|---|
| 심박 | 연속 심박(bpm), 5~10분 간격이면 충분 | 시각 + 심박 값 |
| 걸음 | 구간별 걸음수(분·10분·시간 단위 등) | 시각 + 걸음 값 |
| 수면 | 수면구간 (한 행 = 한 구간) | 시작 시각 + 종료 시각 |

- **Apple 건강**: 건강 앱 → 프로필 → 모든 건강 데이터 내보내기 → XML 을 CSV 로
  바꿔 주는 앱/스크립트를 거치면 보통 `startDate,endDate,value,unit` 형태가
  됩니다 — 그대로 넣으면 됩니다(수면 단계 행도 알아서 처리).
- **삼성헬스**: `start_time,heart_rate` / `step_count` 열을 인식합니다. 단,
  실제 데이터 다운로드 CSV 는 **1행에 메타데이터(버전 줄)** 가 있고 열 이름에
  `com.samsung.health.…` 접두가 붙은 파일도 있습니다 — 그 경우 첫 줄을 지우고
  `--hr-col`/`--hr-time-col` 등으로 열 이름을 지정하세요(`--inspect` 로 확인).
- **Fitbit 식**: `Time,Heart Rate` / `Time,Steps` / `Start Time,End Time` 을
  인식합니다. 단, Fitbit 공식 내보내기(Google Takeout)의 분 단위 심박은
  **JSON** 입니다 — CSV 로 변환하는 도구를 한 번 거쳐야 합니다.
- 한국어 열 이름(`시각,심박수,걸음수,취침,기상`)도 인식합니다.
- 위 열 이름은 **대표값**이고 실제 export 는 앱 버전마다 다릅니다 — 먼저
  `--inspect`, 안 잡히면 `--*-col` 지정이 정석입니다.

> 열 이름이 위와 다르면? `--inspect` 로 무엇이 인식됐는지 먼저 보고,
> `--hr-col`/`--hr-time-col`/`--steps-col`/`--steps-time-col`/
> `--sleep-start-col`/`--sleep-end-col` 로 지정하세요.

**타임스탬프 주의 두 가지**
1. epoch 숫자(예: `1754236200`)는 받지 않습니다 — 시간대를 추측해야 하기
   때문입니다. 내보내기 앱에서 로컬 시각 문자열로 바꿔 주세요.
2. 여행이나 DST 로 **시간대 오프셋이 섞인** 기록은 거부됩니다 — 단일 시간대
   구간으로 잘라서 넣어 주세요.

## 2. 실행

```bash
# 전체 (권장)
python3 -m circadia 심박.csv --steps 걸음.csv --sleep 수면.csv --out-dir 리듬결과

# 부분 입력
python3 -m circadia 심박.csv                 # 심박만 — IS/IV 를 심박으로 계산(방향 판정 없음)
python3 -m circadia --steps 걸음.csv         # 걸음만
python3 -m circadia --sleep 수면.csv         # 수면만 — SRI·사회적 시차·액토그램

# 옵션
--min-days 7      # IS/IV·SRI 최소 유효일수 올리기 (기본 5)
--min-wear 0.6    # 착용률 임계 (기본 0.5 — 미만이면 exit 3)
--inspect         # 열 인식 결과만 보고 종료
```

설치해서 쓰려면:

```bash
python3 -m pip install -e .
circadia --help
```

## 3. 결과 읽는 법

리포트는 위에서 아래로 이렇게 읽으세요.

1. **데이터 커버리지(최상단)** — 몇 일치인지, 착용률이 몇 %인지, 갭이 어디에
   있는지. **여기가 나쁘면 아래 숫자를 믿지 마세요.** 그래서 맨 위에 있습니다.
2. **코사이너** — 24h 리듬 성분이 통계적으로 존재하는가(zero-amplitude 검정),
   진폭이 얼마고 정점이 몇 시인가.
3. **비모수 지표** — IS(매일 같은 패턴인가), IV(리듬이 조각나 있는가),
   L5/M10/RA(밤은 조용하고 낮은 활동적인가).
4. **수면 규칙성** — SRI, 중간수면과 그 SD, 사회적 시차.
5. **심박 마커** — 야간 강하율, 최저점 시각, 기상 전 상승.
6. **액토그램** — 숫자 대신 눈으로: Z(수면) 띠가 매일 같은 자리에 오는지.
   한 줄이 102자입니다 — **터미널 폭을 105자 이상**으로 두어야 줄이 안 꺾입니다.

모든 해석 줄은 `내 값 — 참고범위 (출처) → 참고범위 대비 낮음/높음/범위 내`
구조입니다. **참고범위는 진단 기준이 아니라** 특정 연구 코호트의 분포입니다.

`데이터 부족(N일<5일)` 이 보이면: 그 지표는 그 일수로 계산하면 불안정해서
일부러 계산하지 않은 것입니다. 며칠 더 모아서 다시 돌리세요.

### 지표.csv 를 통계에 쓰기

`--out-dir` 의 `지표.csv` 는 긴 형식입니다(아래 두 줄은 번들 규칙적 1주
예시의 실제 출력):

```
구분,날짜,지표,값,단위,비고
요약,,IS,0.989599,,
일별,2026-08-03,심박_평균,65.9757,bpm,
```

**이 파일을 그대로 statwise/longistat 에 넣을 수는 없습니다** — `지표.csv` 는
한 사람 분이고, 통계 도구는 여러 사람(또는 여러 시점)의 값 열 + 그룹/대상
열을 원합니다. 연결 절차:

1. 사람마다 circadia 를 돌려 각자의 `지표.csv` 를 얻는다.
2. 쓰려는 지표 1개(예: SRI)의 `구분=요약` 행 `값` 을 사람별로 뽑아, 그룹
   열과 함께 모음 CSV 를 만든다. `값` 이 `데이터 부족` 인 사람은 결측 처리.
3. 군 비교면 statwise, 일별(`구분=일별`) 행에 대상·시점 열을 붙인 반복측정이면
   longistat 에 넣는다.

실제로 실행되는 예 — 2번 모음 파일 `sri_모음.csv` (합성 8명, 2군):

```
SRI,군
97.2,규칙군
93.5,규칙군
89.1,규칙군
91.8,규칙군
58.9,불규칙군
64.2,불규칙군
71.5,불규칙군
55.3,불규칙군
```

```bash
cd ~/Downloads/02_프로젝트/깃헙/statwise-그룹비교통계
python3 -m statwise.cli /경로/sri_모음.csv --value SRI --group 군
```

이 명령은 이 조합 그대로 실행해 확인했습니다(exit 0) — Student's t 선택,
평균차 30.4 [95% CI 20.9, 40.0], Hedges' g 4.79 가 출력됩니다.

## 4. 문제 해결

| 증상 | 원인·해결 |
|---|---|
| `열 후보가 여러 개입니다` | 시각/값으로 보이는 열이 둘 이상 — `--*-col` 로 지정 |
| `타임스탬프 역행` | export 가 시간순이 아님 — 내보내기 앱에서 정렬 후 다시 |
| `시간대 오프셋이 섞여` | 여행/DST 구간 포함 — 단일 시간대 구간으로 잘라서 |
| `epoch 숫자 타임스탬프` | 로컬 시각 문자열로 변환해서 다시 |
| exit 3 (착용률) | 갭이 너무 큼 — 착용이 좋은 구간만 잘라서 넣기 |
| `데이터 부족(N일<5일)` | 오류 아님 — 유효일수가 모자라 그 지표만 보류 |
| 알 수 없는 수면 단계 라벨 | 각성 행을 지우고 `start,end` 두 열로 만들어 넣기 |
