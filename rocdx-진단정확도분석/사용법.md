# rocdx 사용법 (한국어)

> 검사값 한 열 + 기준 진단 한 열 → ROC·AUC·절단점·민감도/특이도 보고서.
> 설치 없이 Python 3.9 이상만 있으면 됩니다.

---

## 1. 가장 빠른 시작

1. **`실행.command` 를 더블클릭**하세요. 번들 예제로 전체 기능이 한 번에 돕니다.
   (macOS에서 "확인되지 않은 개발자" 경고가 뜨면 파일을 **우클릭 → 열기**)
2. 내 데이터로 돌리려면 터미널에서:

```bash
cd ~/Downloads/02_프로젝트/깃헙/rocdx-진단정확도분석
python3 -m rocdx.cli 내파일.csv --score 검사값열 --truth 진단열
```

열 이름이 기억나지 않으면 먼저:

```bash
python3 -m rocdx.cli 내파일.csv --list-columns
```

---

## 2. 내 데이터를 어떻게 만들어야 하나요

**한 행 = 한 사람(한 검체)** 이고, 아래 두 열만 있으면 됩니다.

| 필요한 열 | 설명 | 예 |
|---|---|---|
| 검사값 | 평가하려는 **연속형 점수** (수치가 클수록 또는 작을수록 질환) | `crp_mg_L`, `설문총점`, `AI확률` |
| 기준 진단 | 참으로 간주하는 **정답 판정** (두 가지 값) | `sepsis`, `치매진단` |

```csv
patient_id,crp_mg_L,sepsis
P0001,82.4,Yes
P0002,9.6,No
P0003,,No          ← 검사값 결측 → 자동 제외(건수 보고)
```

**결과 열에 쓸 수 있는 값** (자동 인식):
`1/0`, `Yes/No`, `Y/N`, `positive/negative`, `case/control`,
`양성/음성`, `질환/정상`, `환자/대조`, `있음/없음` 등.

그 외의 값(예: `재발/무재발`)이면 질환 쪽 값을 직접 알려 주세요:

```bash
python3 -m rocdx.cli 내파일.csv --score 점수 --truth 상태 --positive-label 재발
```

> **주의.** `--positive-label` 만 지정하면 **그 값이 아닌 모든 값이 비질환군으로
> 처리됩니다** — `판정보류`, `borderline`, `미확진` 까지 대조군에 들어갑니다. 그러면
> 특이도와 PPV가 부풀려집니다. 보고서에는 "…이(가) 아닌 값 N건을 모두 비질환군으로
> 처리했습니다"라는 줄이 뜨니 반드시 확인하세요. 판정보류를 **제외**하려면 두 값을
> 모두 지정하세요:
>
> ```bash
> python3 -m rocdx.cli 내파일.csv --score 점수 --truth 상태 \
>     --positive-label 재발 --negative-label 무재발
> ```

세 가지 이상의 값이 섞여 있는데 아무것도 지정하지 않으면 도구가 멈추고 물어봅니다.

**엑셀에서 저장할 때**: `CSV UTF-8` 로 저장하는 것이 가장 안전하지만, 한글 Windows의
`CSV(쉼표로 분리)`(CP949)나 세미콜론 구분자도 그대로 읽습니다.

## 3. 자주 쓰는 상황별 명령

### (1) 값이 **낮을수록** 질환인 지표

인지검사 점수, 폐활량, 알부민처럼 낮을수록 나쁜 지표는 반드시 알려 주세요.

```bash
python3 -m rocdx.cli 내파일.csv --score 인지검사점수 --truth 치매진단 --direction lower
```

절단점은 원래 단위 그대로 `인지검사점수 <= 22` 로 출력됩니다.

> 지정하지 않으면(`--direction auto`) 데이터를 보고 방향을 자동으로 정하고 경고를
> 띄웁니다. 자동 판정은 마커가 쓸모없을 때 AUC를 위쪽으로 부풀리므로, **방향은
> 임상 지식으로 정해서 명시**하는 편이 정확합니다.

### (2) 임상 요구조건이 있는 절단점

```bash
# 특이도 95% 이상을 지키면서 가장 민감한 절단점 (확진 목적)
python3 -m rocdx.cli 내파일.csv --score crp --truth sepsis --min-spec 0.95

# 민감도 99% 이상을 지키면서 가장 특이한 절단점 (선별/배제 목적)
python3 -m rocdx.cli 내파일.csv --score crp --truth sepsis --min-sens 0.99
```

비율은 **0~1 사이 소수**로 씁니다(`95` 가 아니라 `0.95`).

> 조건이 지나치게 엄격하면 "조건은 만족하지만 쓸모없는" 절단점이 선택될 수 있습니다
> (예: 약한 지표에 `--min-spec 0.99` → 민감도 3%). 반드시 함께 출력되는 2x2 표를
> 확인하세요. 조건을 만족하는 절단점이 아예 없으면 그렇다고 표시합니다.

### (3) 이미 정해진 절단점의 성능만 알고 싶을 때

```bash
python3 -m rocdx.cli 내파일.csv --score crp --truth sepsis --cutoff 10 --cutoff 20
```

이렇게 **미리 정한** 절단점은 보고서에 `[사전 지정]` 으로 표시되며, 데이터에서 고른
절단점과 달리 낙관 편향이 없습니다.

### (4) 선별검사 — 유병률이 다른 집단에 적용할 때

```bash
python3 -m rocdx.cli 내파일.csv --score crp --truth sepsis --prevalence 0.02
```

민감도·특이도는 유병률과 무관하지만 **PPV/NPV는 유병률에 통째로 좌우**됩니다.
지정한 유병률에서 베이즈 정리로 다시 계산하며, 이때는 신뢰구간을 주지 않습니다
(이 표본의 불확실성만으로는 그 구간을 정당화할 수 없기 때문).

- **정확도(Accuracy)도** 같은 가정으로 다시 계산됩니다(민감도·특이도의 유병률 가중
  평균). 균형정확도만 표본 그대로입니다.
- 이 계산은 **민감도·특이도가 그 인구집단에서도 동일하다는 가정**에 의존합니다.
  환자 구성이 다르면(스펙트럼 편향) 실제 PPV/NPV는 달라집니다.

### (5) 절단점 선택의 낙관(부풀림) 확인

```bash
python3 -m rocdx.cli 내파일.csv --score crp --truth sepsis --bootstrap 2000
```

출력 예:

```
   ── 절단점 선택까지 포함한 부트스트랩 (2000/2000회, seed 20260806)
      절단점 95% 구간 : [35.9, 52.3]   (2000회 기준)
      민감도 95% 구간 : [77.4%, 90.3%]   (재선택한 절단점을 원자료에 적용한 분포)
      특이도 95% 구간 : [87.9%, 94.8%]
      낙관 보정 J     : 0.759 (관측 0.783 − 낙관 0.023)
      낙관 보정 민감도/특이도 : 88.6% / 87.3%
```
(위 숫자는 `examples/sepsis_biomarker.csv` 의 CRP 결과 그대로입니다.)

같은 데이터에서 절단점을 골랐기 때문에 관측 성능은 부풀려져 있습니다. 위 숫자는
**얼마나 부풀려졌는지의 추정치**이며, 부풀림을 없애 주지는 않습니다. 진짜 검증은
독립된 검증 표본입니다.

### (6) 두 검사 비교 (같은 환자에서 둘 다 측정한 경우)

```bash
python3 -m rocdx.cli 내파일.csv --score pct --truth sepsis --compare crp
```

DeLong **짝지은** 검정으로 AUC 차이·95% CI·p를 냅니다. 두 검사 중 하나라도 값이
없는 행은 공정한 비교를 위해 양쪽 모두에서 제외됩니다(건수 표시).

> `--direction` 은 비교 검사 열에도 **똑같이** 적용됩니다. 두 검사의 방향이 서로
> 다르면(한쪽은 높을수록, 다른 쪽은 낮을수록 질환) 지금 버전에서는 한 번에 비교할 수
> 없습니다. 방향을 지정하지 않으면 비교 검사도 데이터를 보고 자동으로 뒤집히며,
> 그 사실이 경고로 출력됩니다.

> p가 크다고 "두 검사가 같다"는 뜻은 아닙니다. 신뢰구간의 폭을 함께 보세요.

### (6-1) 검사 여러 개를 한 번에 비교할 때 (다중비교)

```bash
python3 -m rocdx.cli 내파일.csv --score crp --truth sepsis \
    --compare procalcitonin --compare wbc
```

`--compare` 를 **2개 이상** 지정하면 각 비교의 원래 p와 함께 **Holm 보정 p**가
출력됩니다. 검사 세 개를 서로 비교하면 "우연히 유의한" 결과가 나올 확률이 그만큼
커지므로, 논문에는 보정 p를 함께 적는 편이 안전합니다.

> 보정은 **여기(AUC 비교)에만** 적용됩니다. 절단점 규칙을 여러 개 보거나 하위군을
> 따로 돌린 경우, 그리고 **비열등성 단측 p**는 보정되지 않으므로 사용자가 직접
> 계획해야 합니다. 분산을 추정할 수 없어 p가 나오지 않은 비교는 보정 대상 수에서
> 제외되며, 보고서에는 실제로 보정한 건수가 표시됩니다.

### (6-2) 비열등성 — "새 검사가 기존 검사보다 나쁘지 않다"

```bash
# 기존 검사보다 AUC가 0.05 이상 낮지 않으면 비열등으로 본다
python3 -m rocdx.cli 내파일.csv --score new_marker --truth sepsis \
    --compare crp --ni-margin 0.05
```

차이의 95% 신뢰구간 **하한**이 −0.05보다 높으면 비열등성이 성립합니다(단측 α =
0.025). 하한이 0보다도 높으면 우월성까지 확인됩니다.

> ⚠️ 한계(0.05)는 **자료를 보기 전에 임상적 근거로 정해야** 합니다. 결과를 본 뒤
> 한계를 고르면 아무것도 증명하지 못합니다. 도구는 한계의 타당성을 검증할 수
> 없습니다. 비열등이 성립해도 "더 좋다"는 뜻은 아닙니다.

### (6-3) 실제로 쓰는 구간만 평가 — 부분 AUC (pAUC)

선별검사는 특이도가 90% 아래로 내려가는 구간에서는 쓰지 않습니다. 그런 구간까지
평균한 전체 AUC는 두 검사를 잘못 줄 세울 수 있습니다.

```bash
# 특이도 0.90~1.00 구간만 적분 + 부트스트랩 신뢰구간
python3 -m rocdx.cli 내파일.csv --score crp --truth sepsis \
    --pauc-min-spec 0.90 --bootstrap 2000

# 구간의 상한도 지정 (특이도 0.80~0.95)
python3 -m rocdx.cli 내파일.csv --score crp --truth sepsis \
    --pauc-min-spec 0.80 --pauc-max-spec 0.95 --bootstrap 2000
```

- **표준화 pAUC (McClish)**: 그 구간 안에서만 0.5=우연, 1.0=완벽이 되도록 환산한
  값입니다. **전체 AUC와 숫자 크기를 직접 비교하지 마세요.**
- **원시 면적**: 구간 폭에 따라 최대값이 달라지므로(예: 폭 0.1이면 최대 0.1) 다른
  구간의 값과 비교할 수 없습니다. 그래서 우연·완벽 값을 함께 출력합니다.
- pAUC에는 해석적 신뢰구간이 없어 **`--bootstrap` 이 필요**합니다. 없으면 그 사실을
  경고로 알려 줍니다(출력되는 구간에도 "부트스트랩 백분위"라고 표시됩니다).
- 표준화 pAUC는 위로 1이 상한이지만 **아래로는 경계가 없습니다.** 그 구간에서 검사가
  우연보다 나쁘면 음수가 나오고(예: −9.000), 그때는 경고가 뜨며 논문 문장 초안이
  성능 주장 대신 "판별력이 확인되지 않았다"고 씁니다.
- 비질환군이 적으면 구간이 계단 몇 개로만 결정되어 매우 불안정합니다. 관측된
  위양성률이 3가지 미만이면 경고가 뜨고, 논문 문장 초안은 "사실상 보간값"이라며
  보고를 권하지 않습니다.

### (6-4) 한 환자가 여러 행을 내는 자료 (군집 / 반복측정)

병변마다 한 행, 방문마다 한 행, 판독자마다 한 행 — 이런 자료에서 행을 서로 독립으로
보면 **신뢰구간이 실제보다 좁아집니다**(표본이 실제보다 큰 것처럼 계산됨).

```bash
# 단위만 알려 주면 중복을 찾아 경고합니다
python3 -m rocdx.cli 내파일.csv --score 초음파점수 --truth 조직검사 \
    --positive-label 악성 --negative-label 양성 --cluster-col 환자ID

# 군집 단위로 재표본해 보정된 AUC 구간까지 계산
python3 -m rocdx.cli examples/lesion_multi_reader.csv \
    --score 초음파점수 --truth 조직검사 --positive-label 악성 --negative-label 양성 \
    --cluster-col 환자ID --cluster --bootstrap 2000
```

DeLong 구간과 군집 보정 구간을 나란히 출력합니다. **차이가 클수록 같은 환자의 행들이
서로 닮았다는 뜻**입니다. 논문에는 군집 보정 구간을 보고하세요.

> 독립 가정이 어느 쪽으로 틀리는지는 설계에 따라 다릅니다. 한 환자의 행들이 같은
> 결과를 공유하면(반복측정) DeLong 구간이 **좁아지고**, 한 환자가 질환 1건·비질환
> 1건을 내면(양쪽 눈, 짝지은 대조) 오히려 **넓어집니다**. 도구가 자료를 보고
> 어느 쪽인지 판정해 경고 문구를 바꿉니다.

> 군집이 20개 미만이면 경고가 뜨고, 군집이 너무 적어 모든 재표본이 같은 AUC를 주면
> (예: 군집 2개) 폭 0인 "95% 구간" 대신 구간을 아예 표시하지 않습니다.
> 환자ID가 `1` 과 `1.0` 처럼 섞여 있으면 같은 단위로 묶고 그 사실을 보고합니다
> (대소문자만 다른 `P01`/`p01` 은 서로 다른 환자로 남겨 둡니다).

> 큰 자료에서 `--bootstrap` 은 오래 걸립니다(20만 행 × 2000회 ≈ 30분, 진행 표시
> 없음). 먼저 `--bootstrap 200` 으로 확인하세요.

> 군집 보정은 **AUC와 부분 AUC 구간에만** 적용됩니다. 절단점별 민감도·특이도의
> Wilson 구간과 DeLong 비교 검정은 여전히 행 독립을 가정하며, 그 사실이 보고서의
> 절단점 블록 아래에 표시됩니다.

### (7) 논문·발표용 산출물

```bash
python3 -m rocdx.cli 내파일.csv --score crp --truth sepsis --markdown          # 표
python3 -m rocdx.cli 내파일.csv --score crp --truth sepsis --points-csv pts.csv # 곡선 좌표
python3 -m rocdx.cli 내파일.csv --score crp --truth sepsis --plot-svg roc.svg   # 그림
python3 -m rocdx.cli 내파일.csv --score crp --truth sepsis --json out.json      # 전체 결과
python3 -m rocdx.cli 내파일.csv --score crp --truth sepsis --no-curve           # 곡선 생략
```

`pts.csv` 에는 모든 절단점의 TP/FP/FN/TN·민감도·1−특이도가 들어 있어 엑셀이나
GraphPad로 ROC 곡선을 그릴 수 있습니다.

`roc.svg` 는 **바로 논문·발표에 쓸 수 있는 벡터 그림**입니다. 브라우저·Word·
PowerPoint·Illustrator에서 열리고 글자 크기와 색을 그대로 편집할 수 있습니다.
비교 검사 곡선(`--compare`)과 부분 AUC 구간(`--pauc-min-spec`)도 함께 그리며,
그림 아래에 n과 "절단점을 같은 자료에서 골랐다"는 주의 문구가 **같이 들어가서**
슬라이드에 붙여도 경고가 떨어지지 않습니다. 색은 색약자도 구분할 수 있는
Okabe-Ito 팔레트를 씁니다.

`out.json` 은 모든 수치(신뢰구간·경고 포함)를 담은 기계 판독용 파일입니다.
`--json -` 으로 지정하면 사람용 보고서 없이 **표준출력으로만** 내보내므로
`| jq` 나 파이썬 스크립트로 바로 넘길 수 있습니다. 여러 지표를 반복 실행해 표로
모을 때 편합니다. NaN/∞ 는 JSON 표준에 맞게 `null` 로 나갑니다(그래서
`lr_positive: null` 은 "계산 불가"라는 뜻입니다).

보고서 마지막의 **논문용 문장 초안**은 숫자만 확인하고 그대로 붙여 넣을 수 있게
써 두었습니다. 절단점이 데이터에서 선택되었다는 문장은 **지우지 말고 두는 편이
정직합니다.**

## 4. 보고서 읽는 법

| 지표 | 의미 | 읽는 법 |
|---|---|---|
| AUC | 무작위 질환자 1명이 무작위 비질환자 1명보다 높은 값을 가질 확률 | <0.6 거의 없음, 0.6~0.7 낮음, 0.7~0.8 보통, 0.8~0.9 우수, 0.9+ 매우 우수 — **관례적 구간일 뿐 임상 기준이 아니며, 신뢰구간이 0.5를 포함하면 등급 자체를 표시하지 않습니다** |
| 민감도 | 질환자 중 검사가 잡아낸 비율 | 놓치면 안 되는 병일수록 중요 |
| 특이도 | 비질환자 중 정상으로 판정한 비율 | 불필요한 정밀검사·불안을 줄임 |
| PPV | 양성 판정 중 진짜 질환의 비율 | **유병률에 크게 좌우됨** |
| NPV | 음성 판정 중 진짜 정상의 비율 | 배제(rule-out) 능력 |
| LR+ | 양성일 때 질환 오즈가 몇 배 되는가 | 10 이상이면 확진에 유용 |
| LR− | 음성일 때 질환 오즈가 몇 배 되는가 | 0.1 이하면 배제에 유용 |
| Youden J | 민감도+특이도−1 | 절단점 선택 기준(0~1) |
| DOR | 진단오즈비 | 절단점 전체의 요약, 임상 해석은 제한적 |
| 표준화 pAUC | 지정한 특이도 구간 안에서만 환산한 AUC | 0.5=우연, 1.0=완벽. **전체 AUC와 숫자 크기를 직접 비교하지 마세요** |
| 군집 보정 AUC CI | 같은 대상의 행을 한 덩어리로 재표본한 구간 | DeLong 구간보다 넓으면 그 차이가 행 간 상관의 크기 |
| Holm 보정 p | 비교를 여러 번 한 것에 대한 보정 | 보정 후에도 유의한지가 보고 기준 |
| 비열등성 하한 | 차이 신뢰구간의 하한 | 한계(−M)보다 높으면 비열등. **한계는 사전에 정해야 유효** |

**신뢰구간이 넓으면 표본이 작다는 뜻입니다.** 점추정치만 인용하지 마세요.

## 5. 자주 나오는 오류와 해결

| 메시지 | 뜻 / 해결 |
|---|---|
| `'xxx' 열을 찾을 수 없습니다` | 열 이름 오타. `--list-columns` 로 확인하거나 `#3` 처럼 번호로 지정 |
| `결과 열에 N가지 값이 있습니다` | 결과 열에 값이 3개 이상. `--positive-label` (필요하면 `--negative-label`) 지정 |
| `두 값이 양성/음성 중 무엇인지 알 수 없습니다` | 예: `A/B`. `--positive-label A` 처럼 알려 주기 |
| `결과 열에 한 가지 값만 있습니다` | 질환군 또는 비질환군이 없음. ROC 분석 자체가 불가능 |
| `--min-spec 은(는) 0과 1 사이` | `95` 가 아니라 `0.95` |
| 한글이 깨져 보임 | `--encoding cp949` 또는 `--encoding utf-8` 로 강제 지정. 그 인코딩이 아니면 "…인코딩으로 파일을 읽을 수 없습니다"라고 알려 줍니다 |
| 열이 하나로 붙어서 읽힘 | `--sep ";"` 또는 `--sep "\t"` 로 구분자 강제 지정 (`\t` 를 그대로 입력해도 탭으로 인식) |
| `--list-columns` 에 값이 안 보임 | 환자정보 보호를 위해 기본은 열 이름만 표시합니다. 값 미리보기가 필요하면 `--show-samples` (8자까지) |
| 쉼표를 소수점으로 해석했다는 안내 | 유럽식 표기(`1,06`)로 판단한 경우입니다. 천단위 구분자였다면 원본을 수정하세요 |

  쓰지 마세요.

  시행되었다면(검증 편향) 별도의 방법이 필요합니다.
